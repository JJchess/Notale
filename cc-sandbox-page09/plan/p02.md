# page-02 · 神经元的第一次发声 · **90 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `NEURON · FORWARD PASS` |
| 主标题 | 一个神经元：把输入乘一乘、加一加，挤过一道闸门 |
| 收束句 | 神经元没有魔法：输入乘权重求和、加偏置、过激活函数，就吐出一个数字 |
| 下一问 | 这个数字离目标还差多少？错多少，怎么算出来？ |

## 知识结构：process

关系不变量：输入、权重、加权和、偏置、激活函数、输出必须沿同一条水平轴线依次排列，形成不可跳步的因果链；每次拖动某个权重，只有它对应的那条连线粗细和加权和读数框跟着变，其余环节保持原值直到求和步骤，凸显"一个改变只影响一条支流,最终汇入一个数"。

共享原语：`.k-process` 骨架承担主干——`.step` 依次是"输入→乘权重→求和→加偏置→激活→输出"，`.arw` 连接每一步，箭头粗细随权重绝对值变化（母题2：手绘箭头，粗细代表影响大小）；每个数值用 `.panel` 内的 `.big`/`.num` 呈现为读数框（母题1）；输入与输出节点用圆圈表示（母题3），圆圈内不写字，外部贴 DOM 标签。

## 表征形式

交互（拖拽两个权重滑块 + 一个偏置滑块），DOM/SVG 原生实现：左栏是三个 `input[range]` 控件（w1, w2, bias），右栏是一条横向排布的 `.k-process` 因果链，用 SVG 画箭头连线、圆圈节点，配合 `.panel` 读数框实时显示中间值。数据规模小（2输入+1输出），不需要 ECharts/D3，原生 SVG 足够清晰且能精确控制箭头粗细映射权重大小。

## 主工作流

build-interaction ← 拖拽权重时因果链上多个读数框需联动实时重算并可视化箭头粗细变化，这是本页可复用、有明确状态的核心交互难点

## 不许碰

不出现损失、目标值或"对不对"的判断（p04 首次引入损失读数框）；不出现权重如何调整变好（p05 起）；不切换激活函数种类，本页固定用 sigmoid（激活函数对比归 p03）。

## 神经元的一次计算

| 环节 | 符号 | 默认值 | 说明 |
|---|---|---|---|
| 输入1 | x1 | 1.0 | 固定输入，不可拖动 |
| 输入2 | x2 | 0.5 | 固定输入，不可拖动 |
| 权重1 | w1 | 0.6 | 可拖，范围 -2 ~ 2 |
| 权重2 | w2 | -0.3 | 可拖，范围 -2 ~ 2 |
| 偏置 | b | 0.1 | 可拖，范围 -2 ~ 2 |
| 加权和 | z = x1·w1 + x2·w2 + b | 调用 `Lec.P.neuronForward([x1,x2],[w1,w2],b,'sigmoid')` 取返回的 `z` | 读数框实时显示，等宽数字 |
| 激活函数 | sigmoid(z) | 固定为 sigmoid | 本页不切换 |
| 输出 | a | 取返回的 `a` | 终端圆圈旁的读数框，钢笔蓝显示 |

参照点：`Lec.K.SIGMOID_AT_ZERO = 0.5`（当 z=0 时输出应为 0.5，可用于核对）。

## 交互

学习者拖动三个滑块：w1（-2~2，默认0.6）、w2（-2~2，默认-0.3）、b（-2~2，默认0.1）。任一滑块移动时，立即调用 `Lec.P.neuronForward([1.0, 0.5], [w1,w2], b, 'sigmoid')`，同步更新：加权和读数框数值、激活前后的箭头粗细（映射 |w1|、|w2| 大小）、最终输出读数框数值。目标是让学习者建立"权重变大→那条箭头变粗→加权和跟着变→输出跟着变"的连续直觉，没有正确答案，无需成功/失败反馈。提供一个"重置"按钮回到默认值，状态可逆。

## 核对

- w1=0.6, w2=-0.3, b=0.1 → z = 1.0×0.6 + 0.5×(-0.3) + 0.1 = 0.55 → a = sigmoid(0.55) ≈ 0.634
- w1=0, w2=0, b=0 → z = 0 → a = 0.5（对照 `Lec.K.SIGMOID_AT_ZERO`）
- w1=2, w2=2, b=2 → z = 1.0×2 + 0.5×2 + 2 = 5 → a = sigmoid(5) ≈ 0.993（验证滑块上限时输出趋近1，箭头应显示为最粗状态）
