Workflow Architecture · 工作流架构

多视角覆盖规划驱动的讲义生成流水线

整条流水线是一条单向的确定性工作流，分为前后两段：蓝图设计阶段先通过"多视角覆盖规划法" 确立教学覆盖面并综合出整份讲义骨架，随后单向桥接进入内容实现阶段——骨架上的每个内容槽位被 有界并发地填充，质量由校验器驱动的自修回路把关，而非模型互评。两个阶段之间没有反向回路： 生成不回头修改蓝图，唯一的闭环是末尾可选的覆盖度审查，且它只出具报告、不再回流。

阶段数 2 段 · 单向桥接 蓝图步骤 4 步 · 串联 教学视角 3–4 个 · 单次调用并列提出 内容填充 逐槽位 · 有界并发 质量机制 校验器自修 · 无 LLM 评审
01 / OVERVIEW

端到端总览：两段式流水线，单向桥接

上泳道为蓝图设计阶段：四步串联，每步下方的虚线框标注该步注入的提示词； 视角发现在一次调用内并列提出 3–4 个互补视角（视角间无对话），汇成覆盖清单注入骨架综合。 下泳道为内容实现阶段（蛇形自右向左阅读）：槽位有界并发填充， 回环只存在于生成段内部的两级自修，由确定性校验器驱动——没有模型评审回路。 两段之间由唯一产物——讲义骨架 + 视角清单——单向桥接；末尾覆盖度审查只读核对、不回流。

主数据流（串联） 单向桥接（无回流） 可选 · 只读路径 虚线框该步注入的提示词 含模型调用 纯确定性计算 自修 ≤ N 轮校验器驱动的修复回路
KEY INSIGHT · 阶段关系 蓝图设计与内容实现不是两个对等的智能体回路，而是同一条确定性流水线的前后两段： 蓝图先行、一次成型（重试仅限单步失败），随后骨架被当作不可变契约交给生成段填充。 唯一的跨阶段闭环是末尾可选的覆盖度审查——它对照蓝图期的必讲点逐条核对成品， 但只出具报告，不触发任何重新生成。
02 / BLUEPRINT

蓝图设计阶段：多视角覆盖规划法

核心思想：动笔之前，先让多个互补的教学视角各自申明"这堂课必须讲清什么"， 汇成覆盖清单，再据此综合出整份讲义骨架。四步严格串联； 视角的"多"体现在一次调用内的并列提出，而非多个智能体并行对话。

STEP ① 视角发现 模型调用 × 1

以课程设计专家的身份，针对课题一次性提出 3–4 个互补的教学视角。 每个视角回答三个问题：它最在意什么（焦点）、它认为必须讲清什么（必讲点）、 学习者在此最常卡住的疑问与误区（疑问清单）。三者汇成后续骨架的覆盖清单。

注入提示词
  • 角色设定：课程设计专家
  • 指令：列举 3–4 个互补教学视角，各给焦点 / 必讲点 / 疑问三要素
  • 上下文：课题、受众、页数预算、浓缩素材
  • 输出约束：只输出结构化结果，不写散文
输出
视角清单（3–4 项，随结果一路带到末尾的覆盖度审查）
失败策略
静默降级为空清单（不阻断流程）；页数极少时整步跳过
视角画像示例（实际由模型按课题即时生成）

Critical Inquirer

爱追问的学习者：最在意反例、边界情形与"为什么不能换个做法"之类的疑问是否被回应。

STEP ② 骨架综合 模型调用 × 1 · 失败重试 ≤ 3

把上一步的覆盖清单系统组织进一条连贯递进的叙事线，产出整份讲义骨架： 一个页面序列，每页携带若干内容槽位（类型 + 写作意图 + 体量信号），但尚不含正文。

注入提示词
  • 覆盖清单：全部视角的必讲点与疑问（步骤①产物，渲染为清单文本）
  • 组件菜单：各内容家族（图示 / 图表 / 表格 / 模拟演示 / 可运行代码 等）的用途与选用准则
  • 主题菜单：可用视觉主题的风格描述
  • 全局创作硬规则：一页一观点、具体优先、难点需具象锚点、排版与公式规范、不写死颜色、动效克制
  • 结构规范：骨架格式、页数硬约束、封面点题、槽位体量信号与页面节奏、讲者备注与答疑入口要求
输出
讲义骨架（页面序列 + 内容槽位占位符）
失败策略
指数退避重试至多 3 次；全部失败则中止——骨架是整条流水线的单点
▼
STEP ③ 章节切分 模型调用 × 1 仅长讲义触发

以讲义编排师的身份审视骨架：内容页是否自然分成 2–3 个部分？ 若是，则在分界处确定性插入章节分隔页，并带页数预算保护防止超编。快速档直接关闭此步。

注入提示词
  • 角色设定：讲义编排师
  • 指令：判断内容页的自然分段，输出各部分的起止与标题
  • 上下文：骨架的页面标题序列
输出
插入章节分隔页后的骨架
▼
STEP ④ 版式节律编排 纯确定性 · 零模型

依据骨架期每个槽位的体量信号（特大 / 大 / 中 / 小），用固定规则为每页分配版式—— 主从、旁注、整幅、对半、索引、计算演示等——并施加节奏约束： 同类版式至多连用两页，防止视觉单调。全程无任何模型调用。

输入
带体量信号的骨架
输出
最终蓝图：页面序列 + 槽位 + 版式，作为不可变契约桥接给内容实现阶段
SERIAL, NOT PARALLEL · 串并联关系 蓝图阶段四步严格串联，前一步的产物是后一步的输入。 多视角并非多个智能体并行跑对话，而是一次调用内并列提出—— 视角之间无需交互，其价值在于合并出的覆盖清单互补无遗漏。
03 / REALIZATION

内容实现阶段：并发填充 + 校验驱动的自修

蓝图被当作不可变契约：遍历骨架上的每个内容槽位，放入有界并发池逐槽生成； 每个槽位内部有一条"生成 → 校验 → 自修"的小回路，整档组装后再过一次 "校验 → 按错误路径路由回槽位"的大回路。所有质量门由确定性校验器把守。

STEP ⑤ 内容填充（有界并发扇出） 模型调用 × 槽位数 并发上限 4 · 快速档 8

骨架上每个槽位按类型路由到对应内容家族的契约，多个槽位并行生成（并发上限可控，可整档关闭退回串行）。 每个槽位内部是一条校验驱动的自修回路：初稿 → 结构校验 → 截断 / 占位检测（零模型的确定性门禁） → 若不合格，把具体错误反馈给模型重写，至多 3 轮；末轮保底收下，宁可留瑕疵也不丢内容。

注入提示词
  • 角色设定：单个内容槽位的生成器
  • 家族契约：该槽位类型对应的结构化模板与填写要求
  • 全局创作硬规则：与蓝图期同一份规则，保持一致文风
  • 定位上下文：课题锚点、所在页、槽位意图、浓缩素材
自修反馈
仅两类具体反馈——"内容被截断，请补全" / "校验未过，按此错误修正"
特例 A · 交互组件的"契约先行"两阶段子流程

交互组件是唯一拥有两阶段子配方的槽位类型：

① 契约规划——先产出一份结构化设计契约：核心洞察、渲染媒介、状态模型、交互方式、 状态更新逻辑、初始画面。② 构建实现——严格忠实于契约写出组件，附交互设计规范与硬规则复述； 随后结构校验（含反套路检查），错误喂回修复，至多 3 轮。 此子流程有意不注入全局创作硬规则（其中"禁原始标记"条款与组件实现相冲突）。

特例 B · 工具档下的计算工具回路

开启工具档时，槽位生成首轮可走一条"思考 → 调用计算工具 → 观察结果"的小回路（至多 4 回合）， 用于需要精确数值的内容。默认档位不开放。

▼
STEP ⑥ 组装回填 纯确定性

按槽位编号把成稿回填进骨架：失败的槽位丢弃并如实记录；整页尽败时补一张占位说明卡。 随后确定性匹配图标配图；仅媒体档才调用图库 / 文生图为封面配图。

▼
STEP ⑦ 整档校验与路由自修 按需重生 ≤ 2 轮

对组装后的整份文档做一次结构校验：发现的槽位级错误按文档路径精确路由回对应槽位重新生成， 至多 2 轮；页面级结构问题不硬修、只如实上报。单遍档关闭此回路（消融基线）。

▼
STEP ⑧ 讲者备注增强 模型调用 × 页数 逐页并行 · 软超时

以资深讲者的身份为每页写 2–4 句讲稿：展开要点、给出直觉、提示误区、承上启下。 逐页并行、软超时保护，失败页保留占位备注，不阻断交付。

▼
STEP ⑨ 覆盖度闭环审查 可选 · 只读

取出蓝图期各视角申明的必讲点，逐条核对成品是否充分覆盖，输出"已覆盖 / 缺失"清单。 这是多视角规划法的闭环——但它是只读的：报告呈现给使用者，不触发任何重新生成。

NO LLM CRITIC · 没有模型评审回路 生成路径上不存在"评委模型给意见 → 作者模型据此修改"的评审回路。 所有质量门都是确定性校验器：结构校验、截断 / 占位检测、反套路检查。 模型收到的自修反馈永远是校验器给出的具体、可执行的错误描述，而非另一个模型的主观评价。 （离线实验另有成对比较、多样性等评测体系，不在生成路径上。）

06 / TIERS

运行档位：消融开关即架构开关

四个预置档位对应同一架构的不同机制组合，用于日常生成与消融实验。

完整档

FULL · 默认质量上限
  • 多视角覆盖规划（3–4 视角）
  • 章节切分
  • 块级 + 整档两级自修
  • 封面配图（图库 / 文生图）

快速档
