## 已确认的失败与边界

- 空交付：13、22 各两次响应。第一次 Read 参考材料，第二次直接给问候语并结束，无 Write。这是交付失败，不是主题技术校验拒绝；仅凭 trace 尚不能确定上游为何丢失任务意图。
- CSS 消费：14、32 的 `.nt-data-line` 用 SVG `stroke` 属性表达不同系列，但主题 class 的 CSS 声明优先级更高，两条线都变蓝，图例仍酒红/灰色。主题有 validation 状态，但 INTERFACE 没有公布；既有提示未阻止 Builder 用被覆盖的属性。
- 字体：18 将大批数字显式设为 Times，实际命中系统 Tinos；29、33、35、44 的少量数学特殊字符回退系统字体，不能将它们等同大段字体承接失败。
- 交互：19 的 16 格卷积结果及鼠标填表正确，但方向键会跳到上一页；07 的双单元 XOR 可解，所谓“单层”模式仍把二值隐藏输出送入 1.5 阈值，预测恒零；44 的输入门按钮被说明文字拦截，键盘可操作，改答案后“已解决”计数不会立即清除。
- 内容：21 通用卷积输出尺寸式漏 floor；31 图按六次相乘，文案却用七次结果；33 把 tanh 候选值标成 1.20；37 将“最大权重”推成“读出一定最接近该值”，独立向量计算给出反例；44 用新状态 ≥0.65 判断“保留旧记忆”，会把遗忘 90% 旧值、主要写入新值的组合判为正确。
- 证据诚实性：25 手绘 16×16 输入和固定分数呈现为 28×28 MNIST 识别结果；27 源码称 illustrative 的手写核在页面标成“真实学到的权重”，没有训练或来源证据。03 则明确标了固定教学模型，不能一并误判。
- 页面布局：12、17 等标题与导语重叠；33 标题切成四行且图被控件盖住；36 标题压到序列标注；40 底部文本/控件相挤；44 文本覆盖可点击区域。19 的巨大局部 box-shadow 实际压暗整页，是页面实现问题，不是背景变体切换错误。
- 慢页不能一概归因主题：06 把 `Deck.onStep` 的最大 step 值误当状态个数，导致末态数组越界，44 次响应后交付。15 的回退检查存在确定性判据过严：独立复现前后 DOM/文字相同，仅一个像素不同，但 Check 按 PNG 字节完全相等报失败，诱发反复排查；原始复现另见 `verification/rewind-diagnostic.json`。本次只诊断留证，未在生成过程中修改生产 Check。
