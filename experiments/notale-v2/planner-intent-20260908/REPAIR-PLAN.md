# Planner × ImageSearch：精简整修方案

2026-09-08 · 已按用户确认实施并完成最小回归，结果与剩余问题见[实施报告](../planner-simple-20260908/REPORT.md)。以下保留原方案范围。

## 判断

上一版方向基本正确，但把日志、提示词假设和实验设计展开成了项目。收敛为：**两项产品修改，一组随改动进行的验证。**

已证实的缺陷是取图兜底会换成无关图片，却保留原候选描述；神经网络“有图却没用”的具体动机仍不确定。前者修代码，后者做最小对照，不用新机制替模型作决定。

## 只改两件事

| 项目 | 具体改动 | 修改位置 |
| --- | --- | --- |
| 1. 取图不换对象 | 删除“og:image／全部 img 中第一张能下载的图”兜底。Commons 文件页只取明确主图或该文件的栅格预览；其他来源下载返回的图片直链，失败就报告失败。撤掉上一轮新增的“在 title 中描述图片”要求，不另加描述规则。 | `core/image_search.py` |
| 2. 规划交接说清一次 | 完整 query 只输入一次；图片需求写法归工具参数描述；Planner 流程只说明拟定内容、批量取图、看图分配、定稿。纠正“Planner 只决定顺序、标签和主题”的职责句，明确包含素材分配。 | `prompts/deck.md`、`core/media.py` |

保留现有 `query: string | string[]`、`FinalizePlan(pages_md, media_by_page)` 和逐图“需求＋路径”标签。搜索工具不接收页号，Planner 不负责网站解析；Planner 的素材分配不依赖 Builder，Builder 已有的取图能力不改。

### 取图边界

- Commons 主图定位只是在现有取图函数里的一个窄分支，不建网站适配框架。这是已检查过真实 HTML 的修法，不是为假想网站预留扩展。
- 相比直接下载成功的路径，Commons 可能多一次普通网页请求，不增加模型调用。
- 普通文章没有可用直链时不猜封面；这会失去部分旧兜底成功结果，也可能增加补搜。不能把下载更少自动称为更省。
- 定位文件不等于核验内容：直链本身也可能指错图，是否支撑讲解仍由 Planner 看图决定。撤掉描述要求不保证模型不再误述。
- 原有网络、重定向、解码和路径安全检查保留；不增加图片尺寸、数量或费用门禁。

### 只保留必要的交接文案

ImageSearch 的 query 参数描述：

> 要找的图片及用途，说明主体与图片类型；多个需求用数组一次提交。

Planner 流程段（替换原段，不追加）：

> 先拟定页表草稿，按主题需要取图；首轮搜图需求合入一次 ImageSearch，草稿不另行提交。查看图片，将选中的素材分配到它实际支持的页面；有缺口可补搜，不合适可不用。最后用 FinalizePlan 提交完整页表与素材映射，无图页省略。

职责句：

> Planner 决定顺序、页型、主题及素材分配；页面内的实现与呈现交给 Builder。

现有页表格式、ImageGen 能力和内容 guidelines 保留。第二次 `{query}` 改成“用户给出的主题和大纲”。不删用户关于事实、来源或版权不确定性的要求，空素材映射仍合法。

## 验证跟着改动走，不建设新系统

1. **取图回归**：用真实 HTML 覆盖“图标排在主图前”“SVG 栅格预览”“没有主图但有 logo”。主图缺失必须报告失败，不能以另一张图片顶替；继续跑现有消息对应及安全测试。
2. **定稿对照**：复用神经网络六张候选与对应页表，冻结图片、顺序和模型，当前文案与精简文案各做一次独立分配测试。不再搜图，不伪造旧会话回放。检查相关图的采用、错误标题图片的拒绝及合法空映射，不规定必须选哪一张。
3. **端到端检查**：沿用已有脚本，以相同模型与原神经网络、集成学习、光合作用 query 各跑一次；人工核对最终图与页面的关系，列出补搜、模型调用、token 和耗时。定稿问题若仍出现，记录为未解决，不靠反复改词刷到成功。

实验脚本只补存每轮已有输入，上下文中的图片沿用现有格式；已有工具参数记录继续用。不建设 payload 去重、签名归档或完整网络回放，不记录认证信息，也不把诊断记录回灌给模型。

这是最小回归，不是统计证明。结果不一致或无法判断时，才针对该不确定项补测；不预设上一版“12 次定稿＋6 次完整规划”的实验套餐。不能用下载数或采用数代替内容正确性。
