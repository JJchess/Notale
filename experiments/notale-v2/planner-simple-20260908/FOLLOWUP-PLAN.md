# 接口对齐整改 · refined 版

2026-09-08 · 已实施并完成回归，见[本轮测试报告](../planner-align-20260908/REPORT.md)。下文保留审批时的方案与预期，不将预期改写成实验结论。本方案针对神经网络 6 次模型调用的两处额外开销；不重做已实施的主图定位、提示词去重或图片标签。

## Critic：上一版还欠什么

| 判断／做法 | 问题 | 本版取舍 |
| --- | --- | --- |
| 删除普通网页兜底就完成了取图整改 | 下载器不再接受只有文章链接的候选，但搜索模型仍被允许交这种结果 | 对齐工具内部搜索指令，不恢复无目标抓图 |
| 把 image_url 改为全局必填 | 会排除现有 Commons 文件页解析，还可能诱导模型猜 URL | 保留字段结构，明确两种可交付候选 |
| 让模型牢记 page-03 就够了 | 纯格式错误已真实出现；仅补文案不能避免整份重交 | 工具描述给出标准示例，同时本地规范化已出现的简单写法 |
| 取消页号校验，或者出错时丢掉那项映射 | 会把不存在的页、错误路径或素材丢失变成“成功” | 保留语义与安全校验，只放宽无歧义的表示差异 |
| 增加只修映射的工具／新一轮修复流程 | 为一个分隔符增加协议、状态与调用，处理过重 | 不增加工具；在现有 validate_media 中规范化并返回映射 |

## 修改范围

### A. 搜索端知道下载器实际能接收什么

位置：`core/image_search.py::request_body`，替换现有候选交付说明，不再向 Planner 的 deck 提示词重复解释下载细节。

> 寻找符合图片需求、可由本工具取得的候选。每项提供来源页，以及实际找到的 PNG/JPEG/WebP/GIF 图片直链；Wikimedia Commons 的 File 文件详情页可只提供页面地址，由工具解析主图。普通文章或 PDF 页面地址本身不能作为可取图候选。找不到这两类候选时，该需求返回空结果；不要猜测 URL。

保留现有 query 数组、候选 schema、来源与实际错误记录。Commons 规则与下载分支同属此模块；不让 Planner 或 Builder 学习网站解析规则。不把普通文章限定为禁止来源——有实际图片直链的普通文章仍可用。

**限度：**这是交付约定修正，不证明模型一定找到图。它也可能只是把三条失败候选变为零条候选，Planner 仍需补搜；若如此，应报告首轮取图未改善，不能包装成省调用。403、错误直链及人物身份错配不由这句说明解决，不新增自动重试或来源审核模型。

### B. 简单页号写法由本地代码规范化

位置：`core/planner.py::FINALIZE_SPEC` 与 `validate_media`。参数描述给出 `page-03` 示例；校验函数返回统一格式，不修改模型原始参数。

只兼容已有证据的形式：

- 已正确的 `page-03` 原样保留。
- `page_03` 可规范为 `page-03`；纯数字 `3`／`03` 可规范为 `page-03`，前提是唯一对应当前页表中的真实页。
- `chapter3`、不存在的页、非法路径仍失败；不做模糊匹配，不改图片路径或选择。
- 两个输入键规范成同一页时，不静默覆盖或擅自合并，仍报告冲突。空映射合法。

这是一处有明确范围的格式兼容，不是通用纠错器。原始调用参数继续留在已有 trace，交付使用规范后的映射，能区分模型输出与 harness 处理。格式已修正且所有原有校验通过，就直接定稿，不再请求模型重复整份页表。

本地模拟已验证：将本轮首次定稿的三个 `page_XX` 键规范后，所得映射与模型下一次交付完全相同，页表逐字不变。因此能确定消除这条已发生的纯格式修复：9.77 秒、16,104 输入 token、825 输出 token。模拟未改生产代码，未调用模型；不把这些数字外推成未来每次节省。

### C. 能直接删除的门禁，不另建兼容层

| 现有检查 | 处理 | 依据与边界 |
| --- | --- | --- |
| 素材映射键必须逐字等于 `page-03`，否则整份定稿失败 | 删除“拼写不同即失败”的要求，按 B 统一页号后检查实际页面是否存在 | 本轮 `page_03` 已导致无内容变化的重交；直接去掉所有页号检查则会让映射无法交给正确页面 |
| `_valid_pages` 中 `len(nn) > N_CEIL` | 删除不可达分支，不加替代检查 | `split_pages` 已只返回 1–60 范围内的唯一页号，因此这里永远不超过 60；这是死代码清理，不会减少本轮模型调用 |
| 未知页型、空主题、未知页面、无效素材路径 | 保留 | 分别支撑建页路由、任务内容和素材交付，并非单纯文案偏好 |
| 图片必须来自已返回结果、路径不能越界、文件必须存在 | 保留 | 检查的事实不同；结果记录存在不等于磁盘文件仍存在。此次未发现它们误拦有效交付的证据 |

页数范围本身与“首篇必须为标题页”等规则，不混入此次无行为变化的清理。尤其当前解析器会忽略范围外的页：删掉不可达分支不代表解决了这个已有问题，也不据此宣称取消了页数上限。若要改变这些行为，应单独明确需求，而不是顺手放宽或新增门禁。

## 验证与边界

1. 不付费回归：用真实首次定稿验证规范化后直接通过；覆盖空映射、未知页、冲突、非法路径及不修改原始参数。搜索测试继续覆盖 Commons 无直链成功、普通来源无直链失败及真实主图定位；提示词测试只能证明约定被发送，不能证明模型遵守。
2. 正常 Planner 验证：沿用原三题、相同 profile 和已有实验入口。搜索、补搜、选图、定稿均由 harness 自行执行，不手工补搜索词、候选或中途指令；观察记录不回灌。仍明确标注这是 Planner-only，主题冻结，未运行 Builder／Style Director，不冒充整套课件自然运行。
3. 分别记录首批有效素材覆盖、补搜、纯格式修复、错误采用和真实模型调用数。若需要定位搜索变化，可用保存的首轮 query 单独测试工具，但必须另列为工具测试，不计作自然 Planner 结果。

不新增日志框架、固定候选模型对照、新工具、预算门禁或强制用图。不会为保证“3 次”取消合法补搜或隐藏失败。

**可承诺的范围：**已发生的简单页号错误无需再付一次模型调用；搜索约定与下载能力不再相互矛盾。**不能预先承诺神经网络从 6 次降到 3 次**：仅消除已知页号修复，按原轨迹是 6→5；是否进一步省掉补搜的两次调用，必须看实际取图结果。
