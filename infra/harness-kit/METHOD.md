# 怎么搭一个 harness

> **harness 不是设计出来的,是量出来的。**
>
> 先让最强的模型在没有任何约束的环境里把事做成一次,把它的轨迹完整录下来,
> 然后**照抄**它的行为搭 harness。凡是没在轨迹里出现过的结构,都不要加。

这套方法的产出是:一个能让**较弱的模型**跑出**接近最强模型质量**的流水线。
省下来的是钱,保住的是质量。

---

## 三条规矩

**一、不预设方法论。**
不要因为"这样看起来更工程化"就往 harness 里加东西。每一处结构都要能指到轨迹里的
某个观测。加不上的就不加 —— 一个从严谨测量得出的架构,被一次没有判断依据的改动
污染之后,你就再也不知道它为什么是对的了。

**二、减法不是发明。**
上下文 schema 从 Claude Code 实际发出的请求上**删减**得到,不要另起炉灶设计。
字段名逐字照抄(包括 camelCase),这样测量脚本能同时审计"它"和"我们",两边的
数字可以直接摆在一起比。

**三、观测不能干扰被测对象。**
采集工具挂掉、变慢、吞异常,都会让被测对象重试或超时 —— 你测到的就不再是它的
真实行为。`proxy.py` 里那些防御性代码全是为这条服务的,别删。

---

## 五步

### 一、放它自己做一遍

给最强模型一份**只写目标和判据、不写做法**的任务书,在一个干净的工作目录里跑。

```bash
./capture/reset.sh ~/exp/zero                          # 每轮之前
./capture/run.sh exp-01 ~/exp/zero ./tasks/01-derivative.md
```

这一步的关键在"干净":工作目录**必须在本仓库外面**(祖先目录的 `CLAUDE.md` 会被
注入,被试就读到研究计划了),user 级 skill 要挪走(否则白名单形同虚设),memory 要
挪走(它会带着上一轮的结论起跑),预置件要逐字节校验没被上一轮改过。
`reset.sh` 和 `run.sh` 都会查。

还有一条容易漏:`run.sh` 用 `--setting-sources project,local`,这**排掉了**
`~/.claude/settings.json` —— 你自己那边设的模型在被试身上不生效。被试跑哪个模型
只能由**工作目录里**的 `.claude/settings.json` 决定(`preset/` 里那份)。
不钉死就会出现「以为在测 Opus 5、其实测的是默认模型」这种整轮作废。

**同一个题目至少跑两轮。** 只跑一轮你分不清"它就是这么做的"和"它这次碰巧这么做"。

### 二、做减法,得到 schema

```bash
python3 measure/fields.py --calls  runs/exp-01
python3 measure/fields.py --session runs/exp-01.session.jsonl
```

拿到两张表,逐行问「我们的 harness 需要它吗」,不需要的划掉。剩下的就是 schema。

两张表是**两份记录,不是一份的两种写法**:请求体里没有任何时间戳,transcript 里
没有完整请求体。把它们拍成一个扁平结构,两边都会记不全 —— 这个错误已经犯过一次。

划掉的通常是三类:CLI 自省(版本、分支、权限模式)、界面用(标题、进度)、
文件回滚(快照、备份)。留下的通常不到三成。

**有一样东西别顺手划掉:`system` 块里的 `cache_control`。** 它是缓存断点。有一轮的
主 agent 59 次调用只付了 104 个新 input token,对着 885 万次缓存读 —— 全靠这几个断点。
断点位置变了、历史被就地改写了,缓存立刻全废。

### 三、分层:哪一段固化,哪一段循环

```bash
python3 measure/trajectory.py --session runs/exp-01.session.jsonl --calls runs/exp-01
```

看两个数,它们决定 harness 的全部形状:

**主 agent 的动作序列。** 把两轮的序列并排比对。
- 一致 → 这一段**固化成流水线**。模型在这里没有做决策,只是在按顺序干活,
  那就不必每轮再花钱让它重新想一遍。
- 不一致 → 只能写成**循环**,让模型自己决定下一步。

**子任务的步数分布。** 极差超过 2× 就别想固化。有一轮实测每个子任务 16–73 步,
差 4.6 倍,工具配比也各不相同(一个是 Bash×22,另一个是 Edit×26)—— 这种只能循环。

循环靠什么收敛,也是数出来的:如果 `Write` 恒等于 1、之后全是 Edit + Bash,而 Bash
的三分之二是自检脚本,那么模式就是「**写一次 + 闸驱动收敛**」。终止条件照抄
Claude Code:模型不再要求调工具就算交付。

### 四、装闸

闸要装在**模型自己永远不会发现的地方**。判断标准很简单:翻遍轨迹,它主动检查过
这件事吗?一次都没有,那就是盲区,必须由 harness 来查。

已经验证过有效的三类:

- **机制闸** —— 该用的机制到底走没走。它可能引了共享底盘却又自己重写一遍。
- **死代码闸** —— 残留的失效代码。它自己会回头清,但清一次就是一轮 API 钱,
  而且清不干净的会活到交付。
- **量化地板** —— "把内容缩小塞进一屏"是查不到溢出的,因为它总在溢出之前就先缩了。
  要量的是**缩到了多小**。

闸由 harness 跑,**不要写进 prompt** —— 写进去只会和正文抢注意力。

### 五、换弱模型跑

前四步做完,harness 就成型了。这时把模型换成便宜的那一档,用闸和 skill 把质量差距
补回来。跑通了,单位成本就降下来了。

弱模型缺的通常不是能力而是**判断**:它不知道该用哪种做法。所以 skill 由**规划阶段
按每一页实际的需要指派**,而不是给一个"每人至少读一个"的配额 —— 配额是在规定方法,
指派是在补判断。

## 已经踩过的坑

**采集**

- **祖先目录的 `CLAUDE.md` 会被注入被试的上下文。** 哨兵实测:父目录写一个暗号,
  子目录里 `claude -p` 问它,照答不误;加上 `--setting-sources project,local` 也一样
  —— 那个 flag 只管 settings.json,不管 CLAUDE.md。所以工作目录放在
  `<repo>/zero` 这种地方,被试就读到了整份研究计划,**那一轮作废而且轨迹上看不出来**。
  软链接绕不过去:claude 认 realpath。同理素材要**拷**进工作目录,软链接过去的话
  被试从 realpath 往上 `ls ..` 就看见仓库了。
- **`--setting-sources project,local` 排掉了 `~/.claude/settings.json`。** 被试的模型
  只能由工作目录里的 `.claude/settings.json` 决定。不钉死 → 测的不是你以为的那个模型。
- 还原类的 trap 要记「是不是我挪的」。无条件 `mv skills.parked skills` 会把**上一轮
  遗留的**未还原状态也悄悄抹掉,于是「上一轮没还原干净」那道 die 永远触发不了。
- `resp.read(n)` 会阻塞到攒满 n 字节才返回。慢速流上实测第一次返回要 6.08 秒,
  `read1(n)` 是 0.00 秒。扩展思考期间模型只发极小的 ping,客户端等的不是模型,
  是你的缓冲区 —— 然后它判超时。**必须用 `read1`。**
- 中继函数一定要包异常。裸奔时上游一抖,socket 就被关掉且没有状态码,客户端
  算出的退避是 0,于是原地猛刷。观测工具把被测对象打挂,是最不能接受的一类 bug。
  出错要回一个带 `retry-after` 的正经 502。
- 流被截断的响应会记成 status 200、usage 停在占位值(见过 out=3 的 Write)。
  **它把故障伪装成正常样本。** 必须单独标记出来。
- proxy 中途重启时序号从 0001 重来,会静默覆盖上半场的记录。要从已有文件接着编号。
- 子 agent 的记录不在主 jsonl 里,在同名目录的 `subagents/` 下。忘了拷不会报错,
  只会让统计悄悄变短。

**统计**

- 一次 API 响应会落成三四行。**按行数算并行度会得出「其实是串行的」这种错误结论。**
  并行度只能按 `requestId` 分组之后看时间重叠。
- 同一组 `requestId` 里只有一行的 usage 是完整的。取 `output_tokens` 最大的那一行,
  不能取第一行,也不能取字面上的最后一行 —— 并发写入下行序不保证。
- 主 transcript 里 Agent 的 tool_result 时间戳是**派发**时刻,不是完成时刻。用它算
  子任务时长会得到一片 0:00。完成时刻只能取子 agent 自己的最后一行。
- 一条消息里的多个 Agent 调用是**边流式输出边派发**的,不是同时起跑。实测 14 个
  子任务的派发时刻拉开了 6 分 24 秒 —— 这段纯串行的"把简报写出来"的代价,
  常常是最大的一块隐藏成本。

**安全**

- 采集数据必然带密钥:proxy 抓完整请求头,trajectory 逐字记着模型跑过的 shell 输出。
  实测有一轮的记录里就混进了一个真实 API key,推 GitHub 之前才被内容级扫描拦下。
- 靠 `.gitignore` 躲开是绕过不是修复。**每次采集完先跑一遍 `redact.py`。**
- 扫描要扫**内容**,不能只看文件名。
- `AIza[0-9A-Za-z_-]{30,}` 这种松正则会在 base64 数据流里撞出一堆假警报
  (匹配长度 82,真 key 是 39)。用精确长度。

**并发**

- 退避必须加抖动。没有抖动时并发的 worker 会齐步退避、齐步重来,继续撞在一起。
  实测 20 并发下累计空等 84 分钟,相当一部分是这么来的。
- 判断"是不是并发开太大了"之前先量:有一轮 19/53 个间隔超过 60 秒,总计 84 分钟,
  根因是上游端点,不是并发策略。**改 harness 之前先有判断依据。**

## 什么时候可以改 harness

**有测量结果的时候。** 没有测量就不要改。

一个从严谨测量得出的架构,被一次凭感觉的改动污染之后,你就失去了"它为什么是对的"
这个知识 —— 而这比那次改动本身带来的任何收益都贵。

想改的时候先问:这条改动指向轨迹里的哪个观测?指不出来,就先去跑一轮把它量出来。
