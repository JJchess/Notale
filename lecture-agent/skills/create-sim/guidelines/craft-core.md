# widget craft 通则（主题无关，每个 widget 都适用）

> 移植裁剪自 GenUI 的 core craft，去掉了聊天应用专属项（CDN/host 变量/sendPrompt）。
> lecture-agent 的 widget 跑在 null-origin sandbox iframe 里，**颜色全部来自注入的主题 token**，见 interactive.md。

## 层级与节奏
- **单一主元素**：每个 widget 恰有一个主导元素（那块舞台 / 那条活迹 / 那个大数字）。其余一切明显从属——更小、更暗、或挪到一边。两样东西抢焦点时，压低其中一个。
- **间距节奏**：所有 gap/padding 取 4px 阶梯（8/12/16/20/24/32）。空白用来分组，忽大忽小的间距一眼就显得潦草。
- **交互状态**：每个可点/可拖元素都要有 hover + active + `transition`（~150ms）。死板没反馈的按钮最廉价。滑块实时更新读数，变化的值 flash 或缓动到新状态，让人看见 因→果。
- **动效纪律**：只动 `transform` 和 `opacity`（加 canvas 重绘）。循环动画放进 `@media (prefers-reduced-motion: no-preference)`。动效表现的是行为（流动、增长、响应），不是为动而动。
- **数字**：凡是显示到屏幕上的数字都过 `Math.round()`/`.toFixed(n)`——浮点毛刺（`0.30000000000000004`）毁掉可信度。会更新的数字加 `font-variant-numeric: tabular-nums`（用 `.mono` class 即可，srcdoc 已定义）。
- **首帧即 mid-action**：初始渲染就展示系统**已经走了一步**的样子——算法已应用第一次迭代、仿真已启动片刻。绝不是清零的仪表盘、绝不是「点击开始」的空舞台。让人先看见一个活的东西，再上手接管。

## machine tells——见到就杀
这些是一眼认出「AI 生成」的破绽，评审一律不放过：
- **自我介绍标题**：一个复述需求的 `<h1>`/大标题 + 灰色副标（「XX 交互式演示 / 直观感受……」）。这一页的讲义标题已经介绍过它了，widget 内部**禁止**出现 chrome 标题。内容性标题（图注「图 1」、一首诗的名字）可以：小号、贴风格、无副标解说。
- **双语标签**：「畸变程度 (DISTORTION)」。只用讲义语言那一种。（领域记号如「氯化钠 (NaCl)」是内容不是标签，保留。）
- **提示胶囊**：「提示：在画布上点击可…」。可操作性靠设计表达——`cursor: pointer/crosshair/grab`、hover 预览、首次使用的脉冲高亮——不靠一张贴纸解说 UI。
- **状态当指标**：把「当前步骤：分配点」塞进一个和真实数字并排的指标卡。相位/状态写在**舞台上**（角标、进度点），绝不进 KPI 卡。
- **同质卡片行**：3+ 个同尺寸同样式的盒子装异质内容（一个状态、一个计数、一个值）。指标卡行只在 3+ 个**真正可比、持续变化**的数字时才合法；否则做层级——一个主读数，其余用安静的行内小字。
- **emoji 小标题**：「💡 原理」「🎯 目标」。用一条 hairline + 小标签，或什么都不用。
- **氛围霓虹 / 发光节点胶囊**：每个盒子在暗底上戴一圈发光边——机器生成「科技 demo」的招牌样子。发光是数据不是装饰：至多一类活元素发光，结构和 chrome 都是扁平填色 + hairline 边。

## 可视化即界面
到处套盒子是机器味；融合是人味：
- **在舞台上标注，别围着它盖柜子**：簇计数就写在质心旁；当前步在舞台一角小号 mono 读出；一个值的历史是舞台内一条小 sparkline——不是下方三个卡片房子。
- **chrome 预算**：数一数非内容元素（面板、边框、标题、提示）。每一个都要自证其存在；「这条信息放哪」的默认答案是「放进舞台」。

## 出片前的 beauty check
1. 是否只有一个元素主导？
2. 有没有一个让人记住的 signature 细节？
3. 每个交互元素都对 hover/press 有反应？
4. 所有数字都四舍五入且等宽？
5. 切换深/浅主题，文字都还清晰？（颜色走 token 就自动满足）
6. 零 machine tells——无自我标题、无双语标签、无提示胶囊、无状态当指标、无同质卡片行？
