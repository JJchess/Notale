# ImageSearch 修正方案：通用检索、真实反馈、按需决策

2026-09-08 · 最新实现已改为 Gemini 3.8 Flash Google Search，支持单条／批量；旧 nokey／Serper 实现与脚本归档到 [legacy/image-search](../image-search/README.md)，不自动回退。最新独立工具对照见 [测试报告](../../../notale-v2/experiments/image-search-20260908/REPORT.md)。下文保留早期 Serper 方案，**不代表当前默认实现**；此前 nokey Planner 结果见 [历史报告](../../../notale-v2/experiments/media-search-20260908/REPORT.md)。

## 0. 结论与范围

保留 `ImageSearch(query, count)`，增加一个通用图片检索后端，完整返回检索与下载失败；Planner 仍自行决定采用、改词、补搜或无图完成。

推荐先用 **Serper Images** 做小样验证，通过后作为新默认。旧 `nokey` 实现只作为显式对照／回退选项，不自动兜底，不继续向它叠加来源。首轮不同时实现 Serper、Brave、SerpApi 三个适配器。

这是接入方案，不是新检索效果已经验证的声明：当前工作区未发现候选服务的常用凭据；尚未调用它们的认证 API。供应商账户、实际权限、返回样本和相关性需要在实施前的小样中确认。本文给出确认方法与不满足时的处理，不把它们藏成默认假设。

不新增角色、工具、页表字段、搜索次数门禁、素材预算、自动相关性打分、查询改写 agent、爬虫平台、全局素材库或缓存服务。ImageGen、Style Director、代码页风格不借此改造。

## 1. 依据：哪些问题已经证实

### 1.1 修改前代码

| 事实 | 位置 | 含义 |
| --- | --- | --- |
| 搜索固定传 `--source nokey` | [core/media.py](../../../notale-v2/core/media.py) 的 `fetch` | 不是通用互联网搜图；只查询六个素材库 |
| 来源异常收进 `errs`；下载模式只打印错误，仍正常退出 | [归档 webmedia.py](../image-search/web-media-getter/webmedia.py) 的 `run/main` | 进程成功不等于各来源搜索成功 |
| 成功分支只读 `attribution.json`，忽略 stdout 中的来源错误 | `core/media.py:fetch` | 空结果和来源失败被混淆 |
| 六源结果按完成顺序拼接，无跨源相关性排序 | `webmedia.py:run` | 不是全网相关性最高的若干图片；不能推断它丢弃了已经找到的好图 |
| 结果图片与文字一起返回模型 | [core/tools.py](../../../notale-v2/core/tools.py) 的 `media_call`、[core/planner.py](../../../notale-v2/core/planner.py) 的 `deck_call` | 本次不是缺少“查看图片”工具 |
| Planner 直接把工具文本当 JSON 数组解析 | `core/planner.py:deck_call` | 改结果结构必须同时改解析，不能只改工具描述 |

另一个接口事实：现有 `count=3` 是传给每个来源的数量，合并结果可能超过 3；工具描述的“候选数”没有说明这一点。新单后端按总候选数处理；对照实验必须记录实际返回数，不能假定旧新两臂都有 3 张。

## 3. 职责与边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| Planner／Builder | 表达检索用途、写 query、看候选、选择或放弃 | 选择供应商、读取密钥、判断 HTTP 错误是否发生 |
| `core/media.py` | 后端调用、结果归一、下载到私有目录、来源记录、错误事实 | 内容相关性裁判、页表分配、强制换词／重搜 |
| `core/tools.py:media_call` | 图像可解码检查、图片回灌、最终工具报告 | 课程是否必须配图 |
| `core/planner.py` | 从结果登记可用路径，沿用定稿校验和分发 | 检索和下载的供应商细节 |

首版在现有 `core/media.py` 内用普通函数实现两个明确分支：`nokey` 与 `serper`。不建 provider 基类、插件注册表或另起服务。

部署配置新增一项 `media.image_search_backend`，不进入模型参数。实施初期默认仍是 `nokey`，新后端验证后显式切为 `serper`；密钥只取 `SERPER_API_KEY`，加载现有 `.env.local` 机制。后端选择在一次运行内保持不变，日志注明实际值。缺少密钥不自动切回旧源，也不阻断完全不需要搜图的课程。

## 4. 调用兼容与结果契约

### 4.1 保留什么、改变什么

- 工具名和入参保持 `ImageSearch(query: string, count?: positive integer)`，默认 3。
- `FinalizePlan`、`pages_md`、`media_by_page`、相对路径语义和“结果返回后才能采用”保持不变。
- **ImageSearch 结果文本从数组改为 `{results, errors}` 对象。** 明确承认这是返回格式变更，同次修改 Planner 解析与测试，不声称完全零变更兼容。
- ImageGen 的模型可见数组返回保持原样；不为了统一外观顺带改生图协议。
- 内部 `fetch` 返回 `(out_dir, rows, errors)`，ImageGen 的 rows 不变、errors 为空；`media_call` 按工具名序列化。显式返回目录使零结果／全失败时也能记录，不能从第一张图片路径反推目录。只需简单函数契约，不另建框架。
- `attribution.json` 保持旧数组格式，`illustrations.json` 不动；旧 run、`sources()` 和来源汇总继续可读。旧 run 不原地重写，不要求恢复旧的活跃模型会话。

### 4.2 模型看到的内容

示意数据，不是真实检索结果：

```json
{
  "results": [
    {
      "title": "目标人物照片",
      "source": "serper",
      "page_url": "https://example.org/person",
      "url": "https://example.org/person.jpg",
      "path": "assets/img/planner-abc/00.jpg",
      "w": 800,
      "h": 1000
    }
  ],
  "errors": []
}
```

`source` 是检索后端，不伪装成作者；`page_url` 是来源网页，`url` 是原图片地址。author／license 仅在有实际信息时保留，缺失不填成 public domain。`media.describe` 应优先展示来源网页，兼容旧记录只有图片 URL 的情况。

下载或解码失败：保留该候选的标题与来源，带 `error`，不带可采用的 `path`。搜索／认证／来源级失败放在 `errors`，最少记录 `source`、`code`、简短 `message`；有真实重试等待信息时才附 `retry_after_seconds`。

只回传与选择有关的候选信息和实际错误，不发送每家来源的长报告、堆栈、成功宣言、计费说明、重复行为指南或原始 HTTP 响应。

### 4.3 状态语义，不额外增加 status 状态机

| 实际情况 | 报告形式 | 模型可作的判断 |
| --- | --- | --- |
| 搜索正常、没有候选 | `results=[]; errors=[]` | 本次词没有命中，可以改词或结束 |
| 来源／服务失败 | `errors` 含实际错误；正常来源候选仍保留 | 搜索不完整／没完成，不能解释成网上没有图片 |
| 找到了但下载失败 | 有候选、候选含 `error`，无 `path` | 目标可能存在，只是当前不能作为本地素材交付 |
| 部分下载成功 | 成功项有路径与对应图片，失败项无路径 | 可以采用成功项，不必整批失败 |
| HTTP 200 但 JSON／响应结构错误 | 明确响应解析错误 | 不能伪装成正常零结果 |
| 无密钥／401／403 | 明确配置或访问错误 | 改搜索词不能修复认证，不暗示反复尝试 |
| 429／网络超时 | 如实说明限流／超时及已有等待信息 | 不改词伪装网络恢复；不自动强迫下一轮再搜 |

## 5. 检索与下载的最小实现

### 5.1 先修旧链的错误通道

拟让 vendor 支持 `--download --json` 组合输出单份机器可读 `{results, errors}`，`attribution.json` 仍照旧写数组。原不带 `--json` 的 CLI 行为保留。`core/media.py` 解析结构化输出，不用正则从日志里抠 403；子进程异常／超时单独报告。内部辅助下载函数原来吞掉的异常至少转成该候选的实际失败说明，未知原因不得冒充“没有图片”。

合法搜索调用先建立私有目录，随后在 `fetch` 内将预期的配置／网络／供应商异常转为 errors，并返回目录；不能直接抛出使日志和结果结构都绕过去。无法创建目录等文件系统异常仍回传简短错误，并明确此次无法落盘，不承诺磁盘故障时也必有记录。

该阶段只修反馈，不改来源、排序或旧 `count` 行为，便于确认改善来自哪里。不能把“错误现在可见”当作检索能力已经升级。

### 5.2 通用后端不再六源拼接

Serper 返回结果按供应商顺序选取最多 `count` 个候选，必要时仅做同一原图 URL 的精确去重；不做模型二次重排、相似图聚类或过量检索。数量是一次请求所需候选数，不是每页／每套课的使用配额。

API 不支持请求数量或返回不足时，回传实际候选数；遵守官方参数限制，不自动分页到凑足、不偷偷发第二次付费查询。实施前的小样确定数量参数，不能用猜测的上限作为产品规则。

中文 query 原样保留，不强制译成英文，也不自动添加人物／算法关键词；语言参数仅按已核实 API 契约设置。人物补词和消歧由模型根据用途判断，不能由工具偷偷改成另一个检索任务。

### 5.3 找到、下载、能显示是三件事

沿用一调用一私有目录和本地文件交付。下载原图地址，保持来源网页；不要把网页 HTML 当图片，不把搜索缩略图静默当原图。

首版不增加网页爬取、登录、PDF 内图提取、去水印或缩略图自动兜底。原图失败如实返回候选错误；PDF／非 HTTP 地址不得声称已经取得图片。通用搜图可能找到论文配图，不等于获得论文全文研究能力。

沿用现有超时，不加跨来源自动重试链。API 429／网络错误先作为结果返回；不在供应商 SDK、media 和 Planner 三层叠加重试。30 路 Builder 并发不等于 API 配额保证；实施小样要确认账户吞吐，首版不建立全局调度器。持续限流时报告实际服务容量问题，不伪装成相关性差。

下载完成后验证为可解码图片再发布可采用路径；内部临时文件不进素材映射。首版交付现有浏览器支持的图片格式；遇到不支持的格式返回实际错误，不先造一套转换管线。记录实际文件尺寸，不将供应商宣称的原图尺寸用于缩略图。

### 5.4 通用 URL 带来的安全边界

只请求公开 HTTP(S) 资源，不向图片站携带搜索 API key、登录 Cookie 或其他服务凭据；不为 403 绕登录、挑战或访问限制。

外部地址及重定向不得访问本机、内网、链路本地或云元数据地址。实施时同时核对解析后的目的地址及重定向；不能只做 URL 字符串检查后宣称已经防住 DNS 重绑定。用下载器／部署出网约束落实公开目标边界，并以本地 fixture 验证。保留现有图片解码安全限制，流式下载避免一次无界读入；这是网络／文件安全，不是内容或取图预算门禁。

首版若无法证明公开出网边界，不将任意外网 URL 下载器直接作为面向不可信用户的服务上线；不因此扩展成独立安全平台。

## 6. 回灌、审计与提示词

### 6.1 短反馈进入 context，事实落盘

每次搜索目录增加一份小型 `search.json`：query、实际后端、请求数量、耗时、最终返回的 `{results, errors}`。候选来源仍归 `attribution.json`；`search.json` 是调用事实，不是第二个素材注册表，Planner 不从它重新加载输入。

由 `media_call` 完成解码、构造最终结果后，调用 media 层的记录函数在返回的 `out_dir` 写入，确保报告与模型实际看到的路径／错误一致。该函数同时将最终成功项的相对文件名写入数组形态的 attribution，失败项移除可用 `file` 标记并保留错误；不让已被解码拒绝的文件再次经 `sources()` 成为素材。只改本次私有目录，不扫描改写历史 run。

必须覆盖“零结果”和“整次失败”，不能只记录有图调用。日志脱敏复用 `core.redact`；不保存密钥、请求认证头或整张图片 base64。只有最终有可用文件的条目进入可采用路径集合。

不新建第二套轮数或成本预算；供应商实际费用与候选／回灌字节数只在实验中记录。错误直接回给 Planner 即可，不能因为 `search.json` 落盘失败就丢掉模型应收到的错误；记录失败单独说明。

### 6.2 模型提示词的最小变化

将 ImageSearch description 替换为：

> 搜索并下载图片候选，返回来源、可用路径、图片及实际错误；查看后按内容需要选用。

已接入的 `deck.md` 内容原则及“查看后可补搜，也可无图完成”保留，不新增人物名单、搜索模板和必须重搜次数。不把 401／403 解释规则分别复制到每个 skill；真实错误消息本身说明问题即可。

工具命中不证明人物身份、年代、原始出处或图片是否 AI 生成；模型仍需按图片和来源判断。保留真实材料优先的原则，但不让工具名字或 description 承诺“搜索到的一定是真实证据”。

## 7. Critic：两轮审查后保留的取舍

### 第一轮：为什么更简单的候选不够

| 初始想法 | 反驳 | 最终处理 |
| --- | --- | --- |
| 只让 Planner 换词／多搜 | portrait 复测仍然失败，无法修复 403 与覆盖面 | 修工具，再保留模型自主改词 |
| 加 Brave 就完了 | API 可用不等于账户允许长期保存与评估；未实测质量 | Serper 先做小样，Brave 保留为有条件备选 |
| 把错误日志直接附到旧数组后面 | 会破坏 JSON 解析，或把错误伪装成图片条目 | ImageSearch 明确改为 `{results, errors}`，同次迁移消费端 |
| 所有 media 返回统一大结构 | 会无必要地改 ImageGen 的模型接口 | 内部可共享 rows/errors，外部 ImageGen 不变 |
| 主服务失败就自动跑六源兜底 | 隐藏能力降级，多花调用仍可能只有无关馆藏 | 只显式选后端；无静默兜底 |
| 给候选加相关性分数与硬阈值 | 又造一层未验证裁判；同一图用途不同 | 保留供应商顺序，模型看图决定 |

### 第二轮：接上以后仍可能失败的地方

| 质疑 | 方案回应／剩余边界 |
| --- | --- |
| 搜到了，原图却 403／返回 HTML | 候选与下载状态分开；无可用 path，不能进最终映射。小样必须测试实际下载，不能只展示搜索标题 |
| 零结果与全部失败仍混淆 | 看 `errors`，候选下载错误保留在条目；计划用 mock 覆盖整次与局部失败 |
| 零结果没有图片路径，日志写哪？ | `fetch` 显式返回调用目录，预期错误也走结构化返回；不能依赖第一张图定位目录 |
| 回灌拒绝了坏图，attribution 却还标记成功 | 在回灌前完成本次来源记录归一，失败项无可用 file／path；旧 run 不动 |
| 供应商 200 但返回结构变化 | 报解析失败，不用 `.get(..., [])` 把结构错误吞成空结果 |
| 报告加长又翻倍输入 | 只投喂必要字段与实际异常，不加成功状态表、来源长日志或原始 JSON；量模型实际收到的文本与图数 |
| 反复失败仍可能无限搜 | 不承诺消除模型循环；不借修图工具新增门禁。原样记录，若真实实验出现无进展循环，另作可复现问题处理 |
| 有来源链接就能公开使用？ | 不能。保留作者、许可和来源，未知不冒充授权；部署前明确使用条件，不制造“教学用途必然可用”的结论 |
| 单测绿就算改善？ | 单测只证明协议；后端真实下载、人工相关性检查及整套页面实际加载分开验证 |
| 首轮就接三家是否更稳？ | 同时引入三组凭据、配额和失败差异不利于归因；一次只验证一家，不做供应商平台 |

没有采用的设计：强制补搜、人物照片配额、工具自行改 query、下载失败自动改用生图、低清缩略图冒充原图、全局缓存、分布式限流器、图库管理服务、新增图片选择工具、页表增列。

## 9. 验证设计：防止假通过

### 9.1 协议与故障测试

1. 正常候选、正常零结果、来源部分失败、来源全部失败分别可区分。
2. 成功退出但带来源错误不再被吞；认证缺失、401／403／429、超时、HTTP 200 非法 JSON／缺结构分别如实返回；错误经过脱敏。
3. 原图下载失败、HTML 伪图片、解码失败、非支持格式均不产生可采用路径；成功同伴仍能用。
4. `ImageSearch(query,count)` schema 不增参；新后端实际候选数不超过请求数，不暗中重搜／分页。ImageGen 可见返回仍是旧数组。
5. 正常文字与图片对应同一条候选；失败条目不挤乱图文对应；记录与回灌一致。
6. 错误后 Planner 可以换词再搜，也可以直接无图定稿；都不被新策略阻挡。不把 fixture 中模型被预设会换词当作真实模型能力证明。
7. 同响应刚搜到的图仍不能提前选用；此前可用路径仍可采用；失败／跨目录路径被现有规则拒绝。
8. Planner 与 Builder 都使用同一 media 执行路径，代码页仍不获得主题访问或共享写权限；并发私有目录不互相覆盖。
9. 旧 attribution／credits 读取正常；零结果和整次失败都有调用事实；失败图片不被 `sources()` 重新登记成可用。
10. 公网 URL／重定向校验、密钥不随下载请求传出、日志无密钥；针对本地／内网跳转做 fixture 检查。

执行现有 `python3 -B -m unittest core.test_media core.test_prompts core.test_builder`，随后 `python3 -B -m unittest discover -s core -p 'test_*.py'`。更新：新增测试已实施，全 core 103 项通过，详见实施报告；Serper 分支目前是 mock 协议测试，不能拿它代替认证检索与相关性验证。

### 9.2 小样集合与人工判读

同一机器、相近时间、原始 query 原样对照旧后端与新后端，记录来源、实际候选数、可下载数、耗时、错误与回灌字节数。相关性人工记录，不是运行时门禁。

| query／对照 | 看什么 |
| --- | --- |
| `Leo Breiman Random Forest` 与 `Leo Breiman portrait` | 算法结构图和人物照片是否被明确区分，人物／来源是否可核对 |
| `Perceptron Frank Rosenblatt 1958 Mark I` 与 `Frank Rosenblatt` | 长词与短词表现，感知机史料与同名／无关作品 |
| `LeNet-5 Yann LeCun 1998 architecture paper` | 论文相关结构图，不把任意神经网络示意图当作原文证据 |
| `MNIST handwritten digits grid sample` | 真正手写数字样本，不是文字海报或数字插画 |
| `叶绿体 显微照片` | 中文科学对象、照片与示意图的区别 |
| `史记 宋刻本` | 中文原始材料，版本信息可核对程度 |

对照应分别回答：有没有候选、有没有用途匹配候选、有没有能下载并显示的匹配候选。不能只统计图片数量，也不能只挑一个人名宣布全面成功。模型改词属于后续 Planner 测试，不混入后端原词检索对照。

### 9.3 Planner 与完整课件

- 首先用相同 query `集成学习--机器学习概论第八讲` 做 Planner 两后端对照；两臂都使用当前已接入的 guidelines，避免把新内容规划收益归给搜索后端。
- 之后用原神经网络 [query](../../../notale-v2/experiments/neural-networks-20260908/query.md) 做完整实验；Gemini 3.8 Flash、Style Director 开启、Builder 并发上限 30，其他设置沿用其历史实验。该运行只在用户批准实施与实验后启动。
- 为准确比较完整课件采用率，优先在同一版本分别跑两后端；历史 run 只作参考，不能当严格控制组。
- 分开记录“返回／可下载／Planner 选中／Builder 实际显示”。用已有浏览器审计检查本地图片请求、有效尺寸与实际可见状态，再人工看用途是否匹配。
- 不手工补素材使实验过关，不强制结果一定含人物照。若检索已有合适图片却未采用，继续定位 Planner 选择或 Builder 交接，不能再归因于检索源。
- 若一个样本存在关键回退／不稳定现象，针对该样本复测，不设无依据的总体通过率或固定重复次数。没有全量显著改善的证据时，只报告已证明的改善范围。

## 10. 尚需用户提供／确认的实施条件

推荐批准的下一步是 **Serper 试用小样**，不是直接全量替换：需要可用账户／`SERPER_API_KEY`、对该外部服务接收搜索词的认可，并确认使用场景下的素材许可与结果保存要求。不要把 key 发进聊天或提交到仓库。

本轮只检查了进程环境与 `.env.local` 中 Brave／Serper／SerpApi／Tavily 等常用凭据名是否存在，没有显示值；未发现这些配置，不等于用户其他账户中没有服务。

这不阻止完成方案设计，但阻止声称新供应商已通过认证、质量和下载验证。账户／权限或小样不满足时，保持旧默认，先交付阶段 A 的真实反馈；不能将阶段 A 冒充整个目标完成。
