# 媒体与视觉主题包 · 历史计划与 A 阶段记录

2026-09-07 原计划；2026-09-08 归档。A 阶段功能链路已验证，验证范围与内容质量问题见[实验报告](../../../notale-v2/experiments/media-a-20260907/VALIDATION.md)。**后续唯一实施依据为[风格控制升级方案](../../../notale-v2/PLAN-style-control.md)**，已取代本文 B/C 及相关主题、调度、验收建议；本文不再作为后续实施指令。第 3 节保留媒体 A 的交付契约，其余内容留作历史依据。本文当时替代了[更早计划](PLAN-media-template.md)；[v3 图](../architecture/ARCHITECTURE-v3.html)现在以新方案为准。

## 1. 目标与取舍

先让相关图片可靠地进入页面，再让用户提供的风格参考可靠地影响全套外观。保留 Planner、Style Director、Builder 三个职责，继续使用确定性编排与 run 目录交接。减少特殊回合、互相抵消的图像处理和与用户要求冲突的审美门槛。

| 旧设计 | 本次决定 | 原因 |
|---|---|---|
| Planner 固定两回合，第二回合补搜后直接结束 | 按需取图—查看—定稿；无图可一次结束 | 最终采用的图必须已有结果可看 |
| 按取图调用的 `pages` 参数送达 | 只按最终确认的页→素材映射送达 | 请求意图不等于最终选择，删除与换图必须生效 |
| 模板沿用全部审美闸 | 技术契约保持硬检查；审美偏好服从用户参考 | 米色、灰阶或品牌色不应触发重写 |
| 先压暗，再按 p95 求蒙版 | 保留原图，主题确定后只做一次合成 | 避免重复处理，不把统计估计当逐字对比保证 |
| 同级 agent 必须独立进程、互不知情 | 编排层负责调度；默认并行、只交换必要产物 | 职责独立不要求部署隔离，也不禁止必要内容约束 |
| 通用“模板” | 首版明确为“视觉主题包” | 复用颜色、字体、底图、角标与风格说明，不承诺版式复刻 |

不新增角色、工作流引擎、消息总线、素材服务、全局去重平台或自动审美修复循环。图片相关性与模板质量属于需要验证的判断，不宣称 schema 校验即可保证。

## 2. 原主干与职责（后续调度已被新方案取代）

编排层先完成 seed 与输入校验，随后并行运行 Planner 和 Director；两者成功完成后，生成并冻结 Builder 输入，再按现有页标签启动 N 路 Builder。首版复用现有线程和执行方式，只把调度职责从 `plan_run` 上移；若模型配置存在共享可变状态，显式传入各自配置，不为“同级”单独引入进程管理。

| 部分 | 负责 | 交付 |
|---|---|---|
| Planner | 页序、内容任务、证据需求；查看候选并确认采用 | `pages.md`、最终页→素材映射 |
| Style Director | 颜色、字体、风格说明；可选装饰底图与品牌元素 | `theme.css`、主题接口、引用的资源 |
| harness | 工具执行、输入输出校验、分发与汇总 | `plan/pNN.md`、`briefs.json`、来源记录 |
| Builder | 本页构图、实现、局部补图、Check 与页内修订 | `page-NN.html`、本页素材及运行记录 |

证据与装饰按用途划分，不按图片面积划分。整页历史地图或文献扫描件仍是 Planner 的内容证据，由 Builder 决定如何展示。Director 提供的装饰底图只是默认外观；内容页可以遮住它，保留独立的 logo 层与品牌约束。首版不要求 Director 等待 Planner，也不禁止 Builder 同时理解双方输出。

共享媒体能力只有一份：`core/media.py` 封装已有取图脚本，`core/tools.py` 复用执行函数与图片回灌。工具不感知页表；harness 分配私有输出目录，不覆盖共享素材。A 阶段不增加抠图、供应商适配层或 Director 取底图流程。

## 3. 图片流程：候选与采用分开

### 3.1 最小契约

每次取图返回相对 `pages/` 的路径、可查看的图片与供应商已有来源信息；失败返回原因。路径直接作为素材标识，不另建 ID、注册服务或必填元数据表。成功下载只代表候选可用，不代表已被采用。

取图工具没有 `pages` 参数。Planner 定稿时用一个薄的 `FinalizePlan` 入口提交：

```json
{
  "pages_md": "# page-01 ...\n# page-02 ...",
  "media_by_page": {
    "page-02": ["assets/img/planner-xxx/photo.jpg"]
  }
}
```

这是唯一新增的定稿入口，替代最终页表 Write；不负责取图或调度。页表仍是每页标签加一句主题，映射只列有图的页，无图可省略。不增加用途、重要性、布局、选用理由等字段。草稿留在对话与 trace；映射是完整快照，不合并旧候选。Planner 的选用不等于 Builder 最终使用。

harness 在发布前一并校验：

- 页号、页标签和内容满足已有页表契约，所有映射页号确实存在。
- 路径来自本次运行此前返回的可用图片结果，文件存在且可读；路径不能越界。
- 新取图片结果回到模型后才能选用；不增加查看确认工具或“已阅读／已批准”状态系统。
- 失败、未返回或已替换的素材不会进入最终映射。

校验成功后由现有编排函数写 `pages.md`、切分页文件并生成 `briefs.json`；函数成功返回后才启动 Builder，写入失败则不启动。不新增发布协议、事务层或文件监听。

`briefs.json` 保持 `description/prompt` 两个字段；将本页选中的路径与来源附到 prompt，不解析图池表或往主题句塞图片路径。Builder 可自行补图，不回写 Planner。来源复用每次取图脚本已有记录，批次结束单点汇总 `CREDITS.md`；明确包含未采用候选，不把它当作实际加载证明，也不建立实时采用追踪系统。来源汇总失败不阻断页面交付。

### 3.2 按需取图与完成

Planner 先按内容与讲述顺序拟定页表草稿，再按各页需要取图并查看，调整页表与素材选择，最后用 `FinalizePlan` 定稿。草稿不另行交付，不新增文件、工具或阶段；这是模型的工作顺序，不由 harness 校验或强制分回合。可以补搜，也可以无图一次完成；找不到合适图片时保留必要讲解。

不新增按角色、按页或按工具的响应次数、取图次数与张数配额，也不按轮次切换为只允许定稿。调用量、费用和耗时只作记录；沿用现有超时与有限的外部请求重试保护。

无图不是失败，也不强制“出现人物就必须配照片”。定稿不得包含悬空素材引用；运行结束仍无有效定稿则报告失败，不把草稿交给 Builder。

Builder 复用自己的现有工具循环：优先使用 brief 中已确认素材，有实际局部需求再取图，看结果后采用，不新增另一套规划流程。Planner / Director 与各页命名空间分开；Builder 只能写本页私有素材，不覆盖共享文件。Director 的新装饰图也必须在其写主题之前返回并被查看；失败即可省略装饰图。

## 4. 原 B：用户参考（已由新方案取代）

继续接受 `--template <dir>`，在说明与界面里称为“视觉主题包”。目录复用旧约定：必需至少一张 `shots/` 截图，可选 `backdrop`、`logo`、`fonts/` 与 `TEMPLATE.md`。首版不解析 PPTX，不增加模板 DSL 或版式组件系统。

有包时直接使用截图，跳过画廊选样；无包时保留现有“选少量参照→看图写主题”路径。画廊数量、选样数量及截图分辨率不进入架构契约。

约束分两种：

| 硬检查 | 可调整的设计偏好 |
|---|---|
| 路径与文件有效、CSS/接口契约有效、字体资源可加载、产物完整 | 米色禁令、灰阶禁令、语义色极差、跨明度档选样、卡片或材质偏好 |

用户主题包的明确要求优先于默认审美偏好。首版模板路径移除这些偏好的阻断与重试；无模板路径先保留现有基线，随后以独立实验决定哪些偏好降级为提示或记录，不将其继续扩散成通用硬门槛。

共享主题只管 token 和整体接口、页内组件由 Builder 实现，这个职责边界保留；它不等价于“某种颜色名或卡片形态永远不合法”。必要的 token 可以存在，不以命名黑名单替代职责约束。

包内说明中可表达留白、品牌元素位置等要求，Director 将可支持的要求写入主题接口供 Builder 使用。固定标题带、精确版式或逐像素复刻属于首版能力范围之外，需在输入检查/运行结果中明确说明，不静默忽略并宣称“忠实还原”。以后是否增加版式能力，由实际需求决定。

## 5. 原 C：底图合成（已由新方案取代）

下载或导入时保留原图；可制作缩略图，不预先统一压暗。Director 看原图与参考写出主题后，harness 才追加一次底图、可选蒙版、字体与 logo 的实现。这个小渲染辅助函数可先放在 Director 相邻代码中，出现独立复用需求再拆模块，不预设行数或新模块数量。

蒙版首版采用少量可解释的配置值与主题背景色，允许主题包明确指定；不建设自动 p95 透明度求解器。底图与 logo 分层，内容页铺证据图时不应同时消除角标。共用层的布局要求必须进入 Builder 接口，最终组合后的 CSS 仍要检查资源与语法有效性；不能因为是 harness 写的就跳过技术检查。

Builder 继续通过 Check 查看实际合成页面和修订文字/图片布局。对比检查能准确覆盖的纯色文字与背景可报告数值；复杂图片背景、混合或无法解析的文字区域报告“未覆盖，需看图”，不输出全页达标结论。p95 如保留，只作诊断信息。局部测量能力不作为首版新建复杂像素审计器的前置条件。

## 6. 失败与交付

- Planner 无有效定稿，或 Director 无有效主题：不启动 Builder，报告失败阶段与原因。可选装饰图失败则省略，不阻断主题产出。
- Builder 页内 Check 与修订沿用现有流程；自然结束不等于验收通过。
- 终止后独立审计保留，不回喂新一轮模型。致命错误与视觉警告分别记录；汇总结果明确指出失败页，不把部分成功标成整套通过。
- 来源由各次取图记录汇总，harness 单点生成 CREDITS；其中包含候选，不声明等同于已采用或实际渲染。实际加载另由实验浏览器检查。

## 7. 原分阶段计划（B/C 与后续验收已被取代）

每阶段独立验证，先冻结输入与基线再改动；不同时修改取图、主题策略和 Builder 提示词来解释同一个质量收益。

| 阶段 | 改动范围 | 必须验证的行为 |
|---|---|---|
| A. 修通图片交付 | 恢复共享取图工具；Planner 定稿契约；删除 IMG.md-as-data 正则链路；来源汇总 | 成功候选可送达；删除/替换不残留；失败或未查看候选不能采用；无图正常完成 |
| B. 接入用户参考 | Director 模板入口；可加载字体；模板路径取消审美阻断；调度上移 | 米色、灰阶和品牌色均能保留；缺文件可诊断；不支持的版式要求明确报告 |
| C. 底图统一合成 | 原图保留；单一合成辅助函数；Builder 主题接口 | 浅底深字与深底浅字均可呈现；全页证据可覆盖装饰底；logo 独立；复杂背景不虚报对比通过 |

A 阶段的回归必须验证具体页与具体素材的对应关系，不接受“至少一页包含 assets/img/”作为唯一判据。补搜→查看→确认、非法页号、写入中断和并发来源汇总都需要覆盖。

对完整产物沿用既有多学科基准与盲评方法，旧文档的历史结果只作动机，实施前重新冻结基线。分别记录内容/证据相关性、实际加载图片、模板颜色与字体忠实度、整页工艺、费用和耗时。已发现的某个 deck 内容错误或明显质量退步必须定位，不能由平均分掩盖；主观分数接近时复核，不将单次 judge 波动当成架构结论。模板比较使用米色、灰阶、品牌色、明暗底等不同参考，避免只验证默认审美喜欢的模板。

## 8. 后续门槛

只有观测到对应问题才追加机制：重复下载成本显著再加去重；进程内隔离确实不足再拆进程；局部对比失败频繁再评估像素测量或自动蒙版；用户需要固定版式再扩展模板能力。

A 阶段验证记录见 `experiments/media-a-20260907/`；原 B/C 未按本文实施，其能力已纳入[新的唯一实施方案](../../../notale-v2/PLAN-style-control.md)。新方案仍待实施。
