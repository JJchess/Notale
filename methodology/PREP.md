# 备课资料（PREP）——正确性的中枢

> 回答 owner 的第一优先问题："我们怎么保证生成的所有的都是对的？代码有编译器，数理化仿真需要仿真环境，
> 更抽象的——画面讲一个故事（曹冲称象），你怎么保证他是对的？"以及："交互设计也必须是合理的、对的。
> 有点世界模型的味道，但又不太像；它需要联网搜索等外部输入。"

---

## 0. 三句核心

整套设计只有三句话。后面所有内容都是这三句在不同知识类型上的**推论**，不是需要另外记住的条款。

> **一、先查资料，再生成页面。**
> 生成任何一页之前，先把这一课的备课资料查清楚。讲义只能讲资料里有的东西——页面上每个数字、
> 每行代码、每根水位线，都要能在资料里找到出处，找不到就是编的。
>
> **二、每条资料带着"怎么查它"一起存。**
> 能算的算、能跑的跑、有出处的查出处、画出来的比对条件；查不动的如实标注，不冒充已核实。
>
> **三、谁也不许自己给自己打分。**
> 写页面的不定自己的验收标准，判官要被抽查，返工只听外部信号。

拿曹冲称象过一遍就够了：先查资料（人物、船、石头，还有"水位一样高 ⇔ 一样重"这条能查的条件）；
画面照着资料生成——水位线是**用浮力公式算出来的**，不是美术摆的（第一句）；每条资料带着查法一起存——
"五六岁"带着史书原句，公式带着可以拿 sympy 复算的形式（第二句）；验收时判官只看图回答问卷、
答案由机器跟资料比对（第三句）。

## 1. 唯一的分叉：这条内容能不能被"造"出来

**正确性不能靠"写完再审"兜底。** 审查只能拒绝烂东西，不能生出对的东西；而且审查者（LLM/VLM 判官）
自己会说谎（该跑没跑、空转打分、定向扰动下超过一半漏检）。

把"看着对"和"是对的"分开，只有两条路：**事后检查**（自由生成再验）或**构造保证**（约束输入，
使错的东西根本生不出来）。选哪条**不是偏好，取决于一件事**：

> **这类内容有没有一个机械构造器？**

公式有（KaTeX）、方程有（积分器）、算法有（执行 + 录像回放）、数据图有；一句关于世界的散文断言
**没有**——没有任何程序能"从真相构造出一句正确的历史陈述"。于是全部内容按一个分叉走：

| 分支 | 什么内容 | 怎么做 | 保证强度 | 成本 |
|---|---|---|---|---|
| **① 可构造** | 方程、算法、数据、公式、状态机、参数化场景 | 模型只写**规格**，固定程序据此生成；验的对象缩成"规格这一条对不对"（单点，有 oracle）。**怎么验见 [`VERIFY-EXEC.md`](./VERIFY-EXEC.md)——一句话：找一个外生参照物比对** | **所有情况**（页面不是被查对的，是造得不可能错） | 低 |
| **② 不可构造、但可核** | 关于世界的事实断言 | 自由生成 + **独立核对**（出处、复算） | 抽查级 | 高 |
| **③ 两者皆无** | 类比恰不恰当、讲得清不清楚、文化语感 | 生成 + **如实标注"未核实"** + 人/趋势 | 无保证——但不许伪装成有 | 人力 |

**由此得到全系统唯一的战略命题：把内容尽量从右往左推。** 每造一个新的构造器，就把一整类内容从
"祈祷 + 抽查"搬进"不可能错"。组件库因此不是"复用省事"，而是**扩大①的覆盖面**，是杠杆最高的一笔投资。
曹冲称象用参数化场景而不是文生图，理由也在这：那一步把叙事画面从②搬进了①。

**①的两件套，缺一不可：**

| | 做什么 | 少了会怎样 |
|---|---|---|
| **页面由固定的程序从资料生成** | 模型只负责查资料、写下方程/故事/交互规则；**画页面的活交给固定程序**（已验证的引擎、编译器、录像回放器）——把模型赶出画页面这条路 | 如果画页面的代码是模型每次现写的，"生成得不可能错"立刻失效，只是把"生成页面"改名叫"生成" |
| **组件出厂自带运行时自检** | 自检条件（跑的时候必须一直成立的条件）嵌在组件内部，**在实际走到的每一个状态上**连续检查。⚠️ 条件必须**按系统类别挂**——"能量守恒"不是通用条件（辛积分器是有界振荡、耗散系统本应下降、RK4 本就漂移），详见 [`VERIFY-EXEC.md`](./VERIFY-EXEC.md) | 资料对、接线也对，数值还是会跑飞——这条缝没人守 |

**"固定的程序"不等于模板。** 三档：参数化组件（成品区）→ **通用生成器**（方程→仿真、算法+输入→录像动画、
交互规则→控件外壳；吃资料吐组件，输入空间无限，这是主力）→ 长尾现造（新生成器要走重验证，验完**入库
变成程序**）。类比 KaTeX：没人让模型逐像素画公式，模型写 LaTeX（规格）、KaTeX 排版（构造）——排版完全
是死的，公式的花样却是无限的，因为花样来自**规格**，不来自画法的自由。固定下来的是"怎么画"，不是"画什么"。

**为什么①比"给每个组件写测试"强**（写测试的方案已于 2026-08-08 否决，理由见 §6）：**测试只保证你抽查过的
那几种情况，其余靠祈祷**——交互组件的状态空间是组合爆炸的；**照着规格构造保证所有情况**。排序动画不可能
对算法撒谎——它就是算法跑一遍的录像回放。

**红线（两支通用）**：页面上出现的一切——一个数字、一行代码、一根水位线、一个滑块拖动后的反应——
都必须能在备课资料里找到出处；**同一个知识点只存一份**；找不到出处 = 编的。

**跟哪条技术路线无关**：备课资料是一份纯数据，不绑定 Track 1 或 v2。无论主干 ADR（`ROADMAP.md` §5）
判给谁，它都是那条路线的输入。

## 2. 分类不是挑标签，是回答两个结构问题

HTML 能嵌入的东西没有边界——今天想到物理仿真、代码、测验、叙事场景，明天可能冒出分子查看器、
交互地图、音频合成、协同白板。**任何按"内容域"枚举的分类表，永远追不上生成式内容能造出来的新花样**。

所以分类**不是**"从一张清单里挑一个类型标签"，是对任意一条内容回答两个跟内容域无关的结构问题：

> **一、这条内容有没有一个机械构造器？**（§1 的分叉——决定走①②③哪支）
> **二、它的可信度来自哪个参照物？**（[`VERIFY-EXEC.md`](./VERIFY-EXEC.md) 的参照物来源表——
> 闭式解 / 独立参考实现 / 声明的规格 / 学科定律 / 变换不变性 / 自身对拍 / 通用页面性质）

这两个问题对任何未来才会出现的内容类型都能问，**不需要为新类型开新桶**：一个全新的"化学滴定曲线
模拟器"不必现造一个"化学"类，直接问——有没有构造器（反应速率方程 + 曲线引擎）？有 → 走①，
参照物用闭式解或独立参考实现。一个纯审美的抽象数据艺术生成器——没有构造器、没有参照物 → 走③，
如实标注未核实。**分类接口因此是封闭的（两个问题），内容域是开放的（无限），封闭接口套开放内容域，
不会因为内容变多而膨胀。**

一条内容可以对这两个问题给出**多个**答案（一个统计数字既属①又要走事实检索），重叠时
**多一条查法是好事，不是毛病**（两条独立的查法，出错方式不一样，互相兜底）。

**这也部分回答"谁来分类"**：把"挑一个内容域标签"换成"回答两个结构问题"之后，分类的一大半可以做成
**结构检查**而不是创建者的自由裁量——"这条记录里有没有符号形式/参考算法字段"是能自动判定的，
比"这算不算叙事类"客观得多。真正留给自由裁量的只剩"有没有构造器"这个判断本身，这块仍然可能被
创建者敷衍，属于未解决的残余风险，不假装已经堵上。

> **一个结构性提醒**：备课资料里其实躺着两种生命周期不同的东西——**规格**（排大纲的人写、构造器消费、
> 属①）和**已核事实**（研究阶段查回来、散文消费、属②）。目前它们放在同一份资料里，接口层面应当分开。

### 示例（不是穷举）：目前想到的内容在这套接口下长什么样

下表是两个结构问题在我们已知内容上的**投影**，不是分类的终点。遇到表里没有的新内容，
去问上面两个问题，不要来这张表加行。

| 内容 | 分支 | 资料里存什么 | 外部输入 | 怎么查 |
|---|---|---|---|---|
| **事实** | ② | 断言 + 拆开的原子说法 + 出处（URL / 原文片段 / 抓取时间，**由工具记录自动带上**，见 §2.1） | **联网检索（强制）**、用户材料 | 引文是抓回文档的字面子串（机器查）+ 引文是否支持这句话（分级，见 §2.1） |
| **可跑的** | ① | 方程的符号形式 / 参考算法 / 数据，加自检条件，**加至少一个外生参照物**（闭式解优先） | 浏览器沙箱 + 成熟引擎 | 组件确实是由资料生成的 + 与参照物比对通过（[`VERIFY-EXEC.md`](./VERIFY-EXEC.md)） |
| **数量** | ① | 能复算的形式（sympy 表达式 / 算式 / 数据来源） | Pyodide + sympy | 独立复算一遍、单位与求和自洽（机器查） |
| **故事** | ①+② | 人物 / 时间顺序 / **必须成立的条件**（引用"可跑的"那条记录，不复制）/ 硬事实（走事实那一行）/ **不许出现清单** | 事实字段走检索 | 跨页是否自洽（机器查）+ **蒙着眼问判官**（见 §3） |
| **交互** | ① | 领域输入 / 动作 / 真实算法或方程 / 语义 trace / 初始状态 + 想让学生看见什么 | 浏览器内领域引擎 | 检查实现是否确实执行领域模型并投影 trace/result；教学价值由用户监督实验评估 |

交互的核心约束是：**教学状态必须由真实计算产生；界面只是计算结果的投影。** 浏览器随机点击只能证明
控件改变了 DOM，不能证明算法、方程或判定逻辑真实执行，因此不作为语义正确性的代理。

### 2.1 出处怎么来的：提取时确定性绑定（不是事后核查）

②支最大的失败模式**不是**"忘了标出处"，是**事后补出处**——断言其实来自模型记忆，写完再找一个看着
相关的来源贴上。数据很难看：前沿模型的链接有效率 >94%、内容相关性 >80%，**事实准确率只有 39–77%**；
换句话说"链接能打开""看着相关"这两个指标几乎不携带信息。

**做法不是检测它，是让它无法发生**——把出处从"模型填的字段"变成"工具记录带出来的事实"
（这就是①的思路用在②上）：

1. **提取即绑定**：research agent 调用一次检索/抓取工具后，harness **自动**把该次调用的 URL 与抓取时间
   写进产出记录。模型没有"贴出处"这个动作，也就没有可滥用的环节。→ 伪造 URL、引用从没抓过的页面、
   "链接通 + 看着相关"的表演，**全部结构性消失**。
2. **引文必须是字面子串**：记录里除 URL 外必须带**原文片段**，并由机器校验它是抓回文档的字面子串
   （substring 检查，零成本）。→ 伪造引文、张冠李戴消失。**没有这一条就别删事后核查**——只记 URL 的话，
   模型仍可以写一句错的概括然后诚实地标上"来自 URL X"：出处真、话不对。
3. **剩下的残差不是一个 agent，是一个函数**：字面子串管不住的只剩"引文是真的，但我这句话是对它的错误
   概括或过度推断"。这是蕴含判断，机器判不了，但它**不需要 agent**——不用重抓原文（引文在手）、不用
   研究上下文、天然干净（输入只有两个字符串，没地方藏记忆）。而且可分级：

   | 情形 | 处理 |
   |---|---|
   | 断言是引文的字面子集 | 机器判定通过，**零成本** |
   | 断言是概括 / 推断 | 一次两串文本的蕴含判断（小模型足够） |

4. **传递不许走样**（删了事后核查之后**更重要**的一条）：出处在提取时绑定，但页面上的句子离引文有两三跳
   （`引文 → 资料记录 → 页面句子`）。页面层要有一道**机器检查**：这句事实是否仍带着同一个绑定、有没有
   在改写中丢了或串了。它查的**不是真假**（真假在提取时就定了），是**有没有在传递中走样**。
5. **来源质量是另一根轴**：确定性绑定只保证"我忠实转述了它"，不保证"它对"。内容农场、以讹传讹的二手
   文章要靠检索时的**来源偏好**（一手史料 / 教材 / 课程主页 > 博客）来挡。曹冲称象的"七岁 vs 五六岁"
   就属此类——网上写七岁的一大片，只有回《三国志》原文（"生五六岁"）才对。

> **已删除的设计**：原方案有一个 **CitationPass**（独立 agent + 干净上下文 + 回抓原文逐句核对）。
> 它存在的唯一理由就是防事后补出处；上面第 1 条让事后补出处**在结构上不可能**，理由消失，遂删。
> 残留的蕴含判断退化为第 3 条那个无状态函数。**检测一个失败模式，不如让它无法发生。**

### 2.2 姊妹通道：教法笔记

研究阶段查回来的东西有**两个**去处，对称的一句话是全部道理：

> **页面照着备课资料生成；大纲照着教法笔记生成。**

- **课题知识 → 备课资料**（上表五类），给写页面的用，生成出来的是**页面**；
- **教法知识 → 教法笔记**（主流教材的讲授顺序、"先给反例再给定义"这类能搬走的教法、金样本注解卡里
  "好在哪的三个机制"、常见误解库），给排大纲的用，生成出来的是**大纲本身**。

它不进备课资料，因为它不出现在任何一页上、也没法用机器判对错；但它必须有个地方放，否则大纲的顺序
就成了排大纲那个 agent 的临场偏好。对应红线：**大纲上任何结构性决定（为什么这个顺序、为什么这里放
一个仿真）说不出依据 = 临场偏好**。它本身也常常是有出处的（教材目录就是出处），复用同一套"绑出处"的
规矩；但它生成出来的大纲只有**弱验收**（计划覆盖、DeckQuiz、人确认一轮）——跟"教学效果永不做硬门"
一致，不假装能强验。

**总原则（防信息悄悄蒸发）**：研究阶段并行查回来的每一份东西，要么进一条**明确说得出谁要用**的记录，
要么明确丢弃并写下原因。压缩造成的细节损失不算丢——原始笔记落盘、记录里留指针，随时能回溯。

## 3. 查法分六层（T0–T5）

以下是实验评估的能力分层，不是当前生成 workflow 内的第二套 Verifier。生成期只有 Builder 自己调用的
`check_page` 交付门；语义与教学质量在用户监督的实验中按需启用对应 oracle。

| 层 | 查什么 | 怎么查 | 硬门 / 趋势 |
|---|---|---|---|
| **T0 结构** | schema、引用、离线依赖、素材、inline JS 语法 | Builder 的 `check_page` | **生成期交付门** |
| **T1 能跑的** | "可跑的"那类 + 能求值的公式 | 组件确由资料生成 + 沙箱执行零报错 + 自检零违例 + 页面上写的输出 == 真跑出来的输出 | **硬门** (G2) |
| **T2 数量** | "数量"那类 | 能推的→复算/单位/求和自洽；推不出的→抽样查出处 | 能推的=**硬门**；抽查=趋势 |
| **T3 出处** | "事实"那类 | 引文是抓回文档的字面子串 + 页面仍带着同一个绑定（都是机器查）；断言是概括时补一次蕴含判断（§2.1） | 绑定在位且未走样=**硬门** (G4)；蕴含通过率=趋势 |
| **T4 故事与画面** | "故事"那类 + 图文是否一致 | (a) 跨页自洽（机器查）(b) **蒙着眼问判官**：判官只看截图、看不到答案，回答由资料自动出的问卷，答案由机器跟资料比对 (c) 文化语感人评 | (a)=**硬门**；(b)=趋势；(c)=里程碑 |
| **T5 教学效果** | 学生学会了吗 | DeckQuiz（只看讲义的 agent 答题）+ 真人试读 | 全部趋势，**永不做硬门**（防 Goodhart 效应：指标一旦成为目标就会被刷） |

蒙眼是 T4 的关键：判官"看着答案打勾"就是自己证明自己。

## 4. 实验判官的抽查五条

教训：现有两个判官都是"没跑也当过了"（语义质量门在默认路径下被过滤、视觉修复降级成只看不管）。

这些约束仅在用户决定启用相应实验评估时生效，不会自动重开已提交页面或生成经验 delta。

1. **没跑就没有该项结论**：不把未执行写成通过，并明确记录本轮覆盖率。
2. **掺沙抽查**（canary，掺进去的坏样本）：每批随机混入 `eval/sabotage/` 里的坏页；放过任何一个 →
   **这批分数全部作废**，降级人工验收。
3. **判分必须指出处**：每个判分要附页面上的原句或坐标，核不到就作废——杜绝空转打分。
4. **优先两两比而不是打分**：乱序匿名 A/B 择优；绝对分只在配了参照样例时用。
5. **拿人当尺子校准**：每 ~8 轮 owner 盲测抽样，判官跟人的一致率 <75% 则分数标"未校准"，不许用于发布决策。

## 5. 说清楚的边界

- **两条红线**：①**"好不好查"不许影响选题**——先按教学价值定讲什么，查法随后适配；查不动 → 降级 +
  人工排队，而不是干脆不讲（否则课程表会退化成"好查的那一小块"，是 iter1–54 教训的新形态）。
  ②**交付检查通过不等于语义或教学质量通过**——当前质量报告只陈述交付状态，不伪造后两者的结论。
- **长尾**：库里没有的生成器 = 缺口，验证升档（两套独立实现互相比对 + 有参考必比 + 人审后入库）；
  **实在查不动就降级**成静态示意图并标注。宁可这页少一个交互，不能多一个错的交互。
- **后端仿真环境：现在不需要**（浏览器里的 matter.js/Pyodide 够教学级用；重 PDE 是内容上限问题，先搁置）。
- **多幕动画的时序验证、会主动找茬的判官**：研究级，不挡主线。
- **最弱的一环，如实记下**：故事自洽没有机器能判的办法（人物-事件图还得靠 LLM 抽）；VLM 视觉判官不可靠
  （定向扰动下超过一半漏检、中国古代题材最好的模型也只有 58.7% 准确）。对策是**能构造就别靠事后检查 +
  判官自己也要被抽查 + 实在绕不开的显式降级给人看**，不是假装能全自动验证。

## 6. 已否决：给每个组件写测试（verificationCases）

> 记录在案防翻案（BACKLOG §C 的规矩；详见 `eval/LEDGER.md` R-004）。原方案要求每个 runnable/sim 携带
> verificationCases（输入→期望输出的测试集），2026-08-08 经对抗审计否决，六条理由：
> ①**盖不住**（抽查≠证明，"已验证"图章制造虚假信心）；②**问题只是搬了个家**（测试本身对不对 = 原问题）；
> ③**好查的内容占便宜**（奖励好查 → 课程漂向好写测试的内容）；④查的是机器不是课；
> ⑤静态抽查跟开放交互的形态对不上；⑥机器太重。替代做法就是 §1 的那两条。

## 7. 实现期备忘（**未立法**——不是规则，别当条款执行）

以下是设计讨论中长出来的做法。按宪章"渐进法制"，它们**还没在真实产出里翻过车**，所以不立法：
**等同类问题在真实运行中出现 ≥2 次，再走六维规约 + ADR 收紧**。记在这里只为不丢思路。

- **一个知识点只存一份**：其余地方引用它的 id（防副本各自漂移）。重叠只允许发生在"怎么查"上，不允许发生在记录上。
- **按知识类型定查法**：内容里有数字/公式→要能复算；断言涉及世界→要有出处；东西能跑→要能执行；有人物时序→要查自洽；有控件→要查交互。分不清时几条一起挂 + 明确豁免（豁免要留痕，不能悄悄漏掉）。
- **冲突时谁说了算（固定优先级）**：能推算的，算的赢检索的（教科书会有排版错，sympy 不会）；推不出的，出处赢模型记忆；真冲突 → 标"存疑"给人看，绝不悄悄挑一边。固定优先级保证同一个冲突永远同样处理。
- **Builder 内修复不另起状态机**：`page_write → check_page → page_patch → check_page → submit_page` 都在同一持久会话内完成；提交后不由外层 verifier 重新打开 task。持续失败由 stall/紧急预算触发降级或续跑。
- **组件对不对分四层**：选的模型对不对 / 动力学实现对不对 / 控件接线对不对 / 画面画得对不对——后端只是第二层，"后端写好=全对"不成立。构造原则"画面完全由状态驱动、前端不许自己模仿"把后两层的风险压到最小。
- **往下追不会没完**（"怎么写好小后端"终止于三处）：学科本身的解析真值 / 成熟的现成引擎（我们不写积分器）/ 组件库（验一次，永久复用）。
