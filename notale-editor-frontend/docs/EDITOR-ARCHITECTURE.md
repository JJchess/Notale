# 编辑器架构整理

目标：React 管理编辑器界面；独立状态层管理文档和编辑会话；画布控制层管理页面实例、局部更新及缓存。保留已有功能和保存语义，不以扩展名、文件数量或局部测试通过作为完成标准。

## 当前缓存边界（editor-polish）

- 编辑画布仍使用最多 3 个页面运行时；当前页加载后延迟预热下一页，预热任务捕获文档与版本，过期任务不执行。后台页面不可交互，其 ready 消息只用于暂停媒体和动画，不进入当前选区或就绪状态。页面激活后重新请求运行时状态。版本变化仍使运行时缓存失效。
- `canvas/author-objects.ts` 按文档、页面和 HTML 内容缓存对象解析，最多保留 3 页。几何、动画或保存版本变化无需重复解析相同 HTML；锁定状态和对象类型每次从当前输入合并。向使用者返回独立属性与样式记录，防止表单草稿污染缓存。控制器关闭时清理缓存。
- 放映运行时缓存独立管理，最多保留 5 页，并预热相邻页面。不要将两类运行时与对象解析缓存混为同一个版本策略。

## 当前所有权

| 层 | 当前实现 | 边界 |

## 当前复核结论与后续边界（Batch137）

重新读取 `components/editor.tsx`、`editor-shell.ts`、`canvas/author-controller.ts`、`canvas/controller.ts` 和 workbench 的翻页/提交边界后，确认以下区分：

- 应用界面已经使用 React/TSX：Editor 挂载 EditorChrome，并为每次挂载装配和释放 workbench。shell 只绑定画布视口与侧栏动作。把这些文件再次“迁移为 TSX”不是下一阶段任务。
- 组件目录的 HTML 注入包括素材预览、静态图表 SVG、公式、代码高亮以及富文本 contenteditable 初始化。最后一项由编辑会话 ID 控制初始化，不能被误改为每次 render 重置内容。注入点检索只证明这些命中的用途，不构成全部安全或生命周期审计。
- 当前页的普通编辑通过 AuthorController 发送 author-update / author-state 局部投影；资源地址按资产变化更新。它与 CanvasController 按文档/版本管理的页面实例缓存是两个边界，不能用“版本变化清缓存”推断每次改颜色都会重建当前页。
- 切换已有页先等待本地编辑落盘，不等待无关网络确认；新插入页面需要确认服务器资源存在。放映、工程导出、PDF 准备和显式历史恢复另外使用 flushDocument，将备注与正文提交完整后继续。

仍有明确后续范围：workbench 业务协调较集中，应结合真实功能修改提取职责；复杂任意 CSS 的准确属性编辑、备注连续自动保存和完整多窗口并发体验尚不能据现有定向用例宣称完成。近期动画字段合并、读数刷新及路径取消/同值提交的证据见工作记录 Batch133–136。当前这次源码复核没有运行新浏览器检查，也不将历史定向通过扩大为整体验收。

## 编辑会话与保存基线（2026-09-13）

### 内容变化与界面刷新分开判断

React 模型对象重新创建不代表用户正在编辑的数据变化。动画时间条使用文档、页面和动画数据组成的 `AnimationListModel.scope` 隔离手势；相同作用域刷新保留指针捕获和预览，实际动画变化或切页才取消旧手势。不要把每次 render 新建的 row/model 对象直接用作手势重置依赖。

富文本弹窗分别检查文档/页面/选区身份和打开时的对象 HTML。无关的讲义名称修改不阻止提交；目标文字或格式发生变化则保留草稿并提示冲突。对象名称编辑同样检查名称基线。不能用“当前仍选中同一个 ID”替代内容冲突检查，也不要用整个文档版本代替所有字段的基线。

### 文字序列化不应产生虚假编辑

画布 ProseMirror 会规范化样式和属性顺序；服务器还会补全节点 ID。`browser/text-editor.ts` 在初始化及接收确认后，用编辑器自身的 `html()` 结果建立 `lastHtml` 基线。原始 HTML 与规范化 HTML 的字符串差异本身不应生成新保存或撤销记录。

文本框级下划线/删除线不能靠给子文字设置 `text-decoration:none` 取消。画布编辑器先将根装饰转换为文字 marks，富文本弹窗转换为文字 spans，保留未选中部分，再将根样式覆盖与修改后的文字作为同一次 `element.patch` 提交。该实现覆盖编辑对象自身的装饰线；对象外部祖先或已有内联包装节点的装饰线仍需独立处理，不能据此声称任意 HTML 格式都已归一化。

输入法组合期间不处理编辑器的退出和格式快捷键。组合结束只有存在实际组合草稿时才发送收尾信号；空组合取消与未修改的文字会话不产生保存。表格文字也在 UI 和命令生成层跳过同值提交，状态绑定器不向命令队列提交空批次。

### 专用编辑入口与备用入口

普通文字支持富文本编辑时，不再显示重复的纯文本输入框；表格单元格使用表格专用输入与冲突保护。备用纯文本入口仍服务于不被专用编辑器覆盖的对象。隐藏入口必须按当前对象实际覆盖情况判断，不能因为存在某个面板就隐藏其内部所有不同类型对象的编辑能力。

### 验证证据与范围

对应定向用例包括 `rich-editor-react.spec.ts`、`rich-decoration-react.spec.ts`、`canvas-decoration.spec.ts`、`text-session-boundaries.spec.ts`、`animation-drag-refresh.spec.ts` 和 `table-editor-react.spec.ts`。它们覆盖冲突保留、装饰线局部修改与撤销、模拟输入法边界、无关刷新中的拖动及表格空保存，不代表所有原生输入法或任意复杂富文本已验收。

缩放 iframe 的点击验证需要将内部坐标按屏幕矩形换算。当前浏览器工具组合曾返回未包含 iframe CSS scale 的子对象坐标，造成虚假的 body 遮挡失败；应核对实际命中位置，不能通过强制点击或刷新绕过问题。

### 响应式资源与发布边界（2026-09-13）

同级后端的 `domain/srcset.ts` 提供纯字符串候选 URL 遍历，供 `domain/resources.ts`、`domain/layouts.ts` 和 `browser/author-runtime.ts` 共用。不能对整个 srcset 直接按逗号拆分，也不能因为首项是 data URL 就忽略后面的文件候选。转换保留密度/宽度描述符、空白及 data URL 中的逗号。

保留 iframe 的局部更新必须同时转换 img.src 与 img/source.srcset。新图片只存在于新文档版本时，遗漏 source.srcset 会让浏览器按旧 iframe 地址访问新文件，出现“保存成功但图片加载失败”。验证应读取浏览器的 currentSrc、complete 和 naturalWidth，不能只断言保存后的 src 字符串。已有资源内容发生变化时，也要按 changedPaths 更新 srcset 中的候选地址。

`?mode=review#note` 这类查询参数链接指向原页面文件，不是其所在目录。资源收集与跨目录布局转换都按原文件解析，并保留查询参数和片段；纯片段链接仍保留本页锚点语义。

以上域模块由在线后端执行，画布地址转换由动态加载的 bridge 执行；它们未由 `browser-api.ts` 向前端导出。因此可以独立发布后端模块或内容运行时，不必重新构建 Next.js 或更新前端 tarball。发布仍需核对实际进程启动路径、EDITOR_RUNTIME_DIR 和编译产物差异，而不是只看源码或发布记录。与此不同，修改前端实际导入的 author-dom 等共享模块仍必须更新前端依赖包。

### 媒体草稿与独立内容基线（2026-09-13）

媒体属性和裁剪弹窗共用 `state/media-settings.ts` 读取可由当前协议准确表达的百分比定位、方向关键字与 inset 裁切。实际样式优先于可能陈旧的媒体元数据。提交只包含用户修改的设置；修改焦点时成对提交两个轴，避免首次写入元数据重置未编辑轴。未修改的裁剪保存不创建命令。

裁剪会话以文档、页面、对象及资源/取景基线判断有效性，不用整个文档版本阻止无关更新。无法准确表达的像素偏移、calc、polygon 等 CSS 尚未完成属性编辑支持。对应控件显示“自定义”并禁用，矩形裁剪入口也禁用；其他媒体字段仍可编辑，提交不触碰这些自定义样式。不能将内部模型默认值当作原始效果。

高级 HTML 替换必须捕获对象内容基线，样式/属性基线不能代替内容冲突检测。多个独立草稿共存时，保存其中一个不能更新另一个草稿的冲突基线。未编辑的替换输入框不能提交空值清空内容；有意输入的空值仍属于用户编辑，应走正常验证。

### 打包前的定向类型检查

`npm run typecheck:files -- src/state/chart-table-paste.ts tests/chart-table-paste.test.ts` 复用根 tsconfig 的选项，对指定入口、传递导入和项目声明运行 TypeScript 检查；不生成代码、不改动 tsconfig、不复用旧类型缓存。它适合在新增测试或类型边界改动后提前定位错误，避免先完成 webpack 打包才发现可快速修正的类型问题。

这不是完整验收：反向调用方、未导入模块和 Next 路由生成校验仍由最终构建负责。一次本地实测，包含工具脚本编译的上述两文件检查耗时3.40秒；独立无效类型样本1.35秒返回非零退出码。纯视觉/文案改动不默认增加这一检查。

### React effect 重放与第三方实例

图表表格实例交给控制器后，不能在 StrictMode 的临时 effect 清理中销毁并创建另一实例，否则控制器仍持有已经脱离 DOM 的旧表格。`ChartGridView` 按组件实例保留适配器，使用 generation 区分临时重放和真实卸载；清理延迟到一个 microtask，若没有新的 setup 接管才释放资源。真实卸载仍销毁表格并结束未完成的挂载请求。

独立 React 开发模式环境曾复现“两个实例、已交付实例 disconnected”；修复后一个实例保持 connected，真正卸载后无存活适配器。这个检查隔离了第三方表格实现，生产表格打开、编辑与恢复另由既有浏览器流程覆盖。

### 放映前备注提交边界（2026-09-13）

放映入口先同步创建窗口以保留浏览器用户激活，再调用备注状态绑定器的 `flush()`，随后进入既有正文保存与服务端同步边界，最后打开指定版本。备注提交覆盖当前讲义各页的内存和本机草稿，批量提交前检查所有基准；冲突不覆盖，错误保留草稿。提交中的页面集合独立于当前侧栏页面，切页继续输入仍受保护；完成时仅清理匹配的草稿，更新期间的新输入会阻止本次放映启动并提示重试。备注编辑仍保留显式保存，此契约不代表已经实现连续自动保存。

工程导出、PDF 准备、放映及显式历史版本恢复共用 `flushDocument()`：备注草稿提交后完成正文同步，并复核会话和讲义身份。图表内部的正文刷新及普通撤销仍使用原有边界，避免把独立备注提交混入对象编辑操作。工程导出回导已验证未手动保存的备注得以保留；PDF 仍只输出页面，备注提交不意味着 PDF 中新增备注版式。

### 多选外观属性的读写边界（2026-09-13）

外观捕获保存每个对象的字段值及混合字段集合。面板中的混合标记不能作为提交值；命令创建必须携带实际修改的控件 ID，将该值与每个目标自身的字段合并，再生成各自的补丁。颜色、粗细、渐变参数等关联字段因此不会从第一个目标复制到其他目标。显式选择颜色/粗细时启用对应填充/描边是有意的关联行为。运行时提供独立 border-width、border-style、background-image；现有复杂 CSS 解析能力没有因此被扩大为完整通用样式编辑器。

### 讲稿停笔自动保存（2026-09-13，后续更新）

备注绑定器在最后一次输入后 650 ms 调用共享 flush 边界，批量提交当前讲义各页草稿；本机草稿仍在每次编辑时立即记录。中文 composition 期间暂停计时，结束后重新安排；卸载会话取消计时，不向已关闭会话提交。已有草稿在绑定时安排恢复保存。显式保存、放映和导出继续复用既有基准检查。

提交中产生的新输入不会被清除，自动流程会另安排一次提交；网络或基准冲突失败保留草稿并显示错误，不进行无限后台重试。用户新输入或明确解决冲突后可再次保存。重新进入存在远端差异的页面时恢复冲突选择。自动提交进入原有命令/同步队列，最终网络状态仍以编辑器的保存状态为准；不能将本机草稿存储成功等同于服务端确认。

后台备注提交还检查宿主的 `canAutosave`：画布文字会话存在时延后，避免通用命令提交中的文字结束操作打断用户输入；手动保存及放映/导出边界不受该后台延后策略影响。
