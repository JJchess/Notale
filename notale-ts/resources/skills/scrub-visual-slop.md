# 视觉禁用清单

按具体组合与作用判断，尊重明确风格和主题接口，不禁止孤立元素。
具体分工和主题承接见技术契约；以下禁的是失效做法，不是风格本身。
规则作用于新创作的内容与主题组件；用户模板的固定品牌、背景和原有装饰保留，不因本清单删除或遮盖。
1. 新增的说明、内容图示和控件组直接排在可用画布上，用邻近、留白和对齐组织，不在外围再加底板、圆角边框或阴影外壳，不为凑等高撑空操作区。
   线描、粗野、纸张等风格应落实到文字、图形笔触与真实对象上，不能成为给普通内容套框的理由。容器轮廓只用于表达真实对象或内容关系，或用户明确要求的容器设计。
   不给普通说明或结论添加装饰性左侧色条，包括 border-left、伪元素和 SVG 的同类画法。
   不给每个事实、步骤或对比对象套卡片，不在卡片内再套装饰性绘图区；说明贴近对象，以留白、对齐和直接标注建立关系。
   Director 不默认供应通用卡片、强化卡片和徽章套件；Builder 不为填满版式而调用这些外壳。真实容器、坐标轴、输入控件、选中和键盘焦点的必要边界保留。
2. 几何、点阵、渐变、斜体、霓虹、纹理可以是风格装饰，不必冒充科学含义；
   它们不能遮挡内容或替代数据、地图、真实对象和证据。
3. 不照搬参考的文案、品牌、营销导航或假数据。界面证据用真实截图，不造假 IDE / 浏览器内容。
4. sparkline、进度环和指标必须有真实数据或计算结果，不作装饰性“内容”。
5. 不默认添加同义英文眉题、页型名、版本、制作说明或宿主页码；
   真正有额外分类/状态意义的信息可以显示，不自动套徽章。
6. 功能图标风格一致、含义明确，不用无意义 emoji 占位。
7. 动效服务阅读和操作，不无限闪烁或劫持注意力；真实状态变化可反馈，尊重 reduced-motion。
