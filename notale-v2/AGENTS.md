# 协作偏好

## TS 重写前的整理约束

用户明确要求只做文件与代码归属整理，harness 行为不变。不得借整理改变模型输入、工具 schema、角色语义、调用顺序、并行关系、权限、重试或产物格式；路径迁移要保留现有 CLI 参数语义。迁移后用定向离线等价检查验证，不默认跑模型实验。

每轮开始先执行父目录 [AGENTS.md](../AGENTS.md) 中的开工自检和按风险分级验证规则；以下细则作为补充。

## 测试效率（用户于 2026-09-09 明确要求记住）

- 按改动范围和风险选择测试，不为每次小改动默认跑全套回归。
- 开发过程中优先跑直接相关用例；已通过且相关代码、依赖、配置未变化的测试，不重复跑。
- 涉及共享底盘、运行时或跨模块契约时才扩大回归范围；同一有效代码状态收尾最多跑一遍组合回归。用户明确要求全量测试时照做。
- 相互独立且不存在共享状态冲突的测试分组可以并行执行，不因此启动额外模型 agent。
- 范围外失败单独报告，不擅自修改无关代码，也不反复重跑拖延本次交付；不能将部分通过说成全绿。
- 测试提速优先减少重复启动、复用浏览器进程但保持用例上下文隔离，并在适用处以明确状态等待替代固定延时。不删除真实超时保护或动画验证所需的等待，不降低正确性检查。
- 纯文档或偏好记录只做必要的文本核对，不启动浏览器测试或模型端到端实验。
