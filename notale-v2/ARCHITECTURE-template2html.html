角色分工、源码归属与尚未完成的边界

角色分工：1 个 code agent，外部固定 workflow 加固

分析、实现、视觉自检和修正由同一个 Gemini 3.8 Flash agent 完成。图中的工具、判断和记录节点都不是额外的智能角色。

类别谁决定下一步执行职责源码与当前边界
Code agent · 唯一Gemini 3.8 Flash理解 PPTX、查继承、选素材表示、编写 HTML/CSS/JS、看图、定位问题与修正。model.py + loop.py 的模型循环；policy.md 提供领域规则。
固定 workflow · 领域层预置触发条件准备输入与参照、装配任务；agent 声称完成后独立验收；失败回传，通过后交付待审阅。environment.py / audit.py；run.py 与 loop.py 负责触发。不调用独立 reviewer 模型。
通用运行时与工具协议驱动；agent 选择工具动作历史与调用配对、JS/RPC、shell、图像回传、快照、日志、预算、checkpoint 与恢复。protocol.py / tools.py / code_worker.mjs / artifacts.py。执行代码本身不构成 agent。
人工审阅 · 边界人判断自动闸尚不能裁决的视觉保真与已披露限制。当前仅记录 delivered_needs_manual_review；没有自动人工审批流程。

实现边界：loop.py 仍混合通用循环和领域验收，尚未完成模块拆分。Gemini 接入及唯一模型约束仍待落实；旧图片桥不能用于绕过这一约束。
