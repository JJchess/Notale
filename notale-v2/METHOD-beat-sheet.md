# 方法论：一页是一段有时长的过程，不是一组属性

## 现在的失效方式

`ape-g8` 通过了全部闸：叠压 0、侵入 0、JS 报错 0、越界被裁 0、空页 0、
占用比中位 47%、四行反馈标签在 35 个交互页上 100% 命中。

**而它看起来仍然不好。** 这件事本身就是最强的证据：
问题所在的那个维度，**我现有的每一件仪器都测不到**。

原因是同一个盲区在两处重复出现：

| | 它描述的是 |
|---|---|
| `selfcheck` 量的 | 画面占用比、文本块数、字号、叠压 —— 一张**静止画面**的属性 |
| `pNN.md` 写的 | 知识结构、表征形式、场景构图、动效、四行反馈 —— 一台**静止机器**的属性 |

十节规格里**没有一节是时间轴**。最直接的证据：`停留 145 秒` 在整份规格里
只出现一次 —— 在标题行，之后再也没被用到。**每页有一笔 145 秒的预算，
却没有任何一处交代这 145 秒怎么花。**

于是每一页都是「一台装好的机器」交给建页 agent，由它自己去想这台机器
在课堂上那 145 秒里到底怎么运转。44 页各想一遍，就有 44 种运转方式 ——
这解释了几个一直治不好的数：

- **占用比 47% 对 Opus 的 63%** —— 没有人问过「第 60 秒时屏幕上有什么」，
  所以画面按"放得下"来排，而不是按"这一刻要撑住什么"来排
- **建页 agent 每页调用中位 25、`selfcheck` 跑了 373 次** —— 它在替规划补那段缺失的过程
- **`page-43` 打到 100 步上限没交付** —— 同一件事的极端形态

## 模型：四轨分镜

一页不是一组属性，是**一段 N 秒的过程**，同时有四条轨在走。这四条轨是
课堂现场真实存在的四件事，不是我发明的分类：

```
时间轴 ─────────────────────────────────────────► 合计 = 这一页的停留秒数

画面   这一刻屏幕上有什么、什么在动
操作   这一刻学习者可以做什么（不可做也是一种状态）
讲解   这一刻教师在说什么          ← SCENARIO 写的是「教师带着讲」
吸收   这一刻之后，学习者知道了什么他 5 秒前还不知道的
```

**一页切成 3–5 拍**，每拍四轨齐全。拍是过程的最小单位：一拍之内四轨不变，
换拍就是四轨里至少一条变了。

一个例子（那条太阳系 widget query 折成分镜的样子）：

```
拍1  25s  画面 深蓝星空亮起，八个空轨道位由内向外依次浮现
          操作 还不能动（只看）
          讲解 「轨道不是画上去的线，是行星实际走的路」
          吸收 意识到「位置有先后」这件事本身是可问的

拍2  20s  画面 底部托盘落下八颗打乱的行星
          操作 可以拿起任意一颗
          讲解 「按离太阳由近到远，把它们放回去」
          吸收 知道任务是什么、判据是什么

拍3  60s  画面 放对吸附发光，放错回弹并提示更靠近的那颗还没放
          操作 反复试放，进度显示 8 个位填了几个
          讲解 沉默（让学习者试）；卡住时点一句「想想温度」
          吸收 从「背顺序」转成「有个规律在决定顺序」

拍4  25s  画面 全部就位，轨道整圈亮起，四颗岩石行星与四颗气态行星分色
          操作 可一键重置
          讲解 「靠内的小而硬，靠外的大而轻——这不是巧合」
          吸收 拿到下一页要用的那个结论
```

### 为什么这个模型会起作用

因为它给出一个**可算的约束**，而这条项目七轮实测下来只有一件事成立：

> **有可算的数的约束起作用，没数的不起作用。**
> 字号地板给了数 → 不达标率 66% → 20%。
> 「不要太满」写在四处 → 七轮零改变。
> 而**唯一控制住页数的东西**，是「逐页停留加总 = 5400 秒」这一条。

四轨分镜的可算约束和那条**同构，只是下降了一层**：

```
deck 层   逐页停留加总 = 课时秒数     ← 已经在用，是唯一奏效的页数约束
页 层     逐拍秒数加总 = 这一页的停留  ← 新增，同一个杠杆
```

这不是又加一条要求，而是把已经验证过的那个杠杆用到下一层。
一旦每拍要报秒数、且必须加总对上，模型就**不得不**在脑子里把这一页放一遍 ——
因为凑不出 145 秒就意味着它没想清楚这 145 秒里发生了什么。

### 它吸收掉现有的哪几节（不是加第十一节）

这一点要紧：规格已经十节了，再加一节只会更像清单。四轨分镜**替换**其中三节，
因为那三节本来就是分镜的切片：

| 现有的节 | 在分镜里的位置 |
|---|---|
| `## 动效` 的「入场」 | 拍 1 的**画面**轨 |
| `## 动效` 的「反馈」 | 有操作那一拍的**画面**轨 |
| `## 交互` 的四行（做对/做错/做到哪儿了/做完了） | 分布在**操作**轨与**画面**轨上 |
| `## 必须点出来的一到三句` | **讲解**轨 |
| `## 场景构图` | **保留** —— 它是舞台，不是剧本 |
| `## 知识结构` / `## 不许碰` / `## 必用skill` / `## 媒体` | **保留** —— 都不是过程 |

所以规格从「十节属性」变成「六节属性 + 一张分镜」，长度基本不变，
但多了一根时间轴。

## 落地

- **`prompts/spec.md`** —— 删 `## 动效`、`## 必须点出来的一到三句`，
  把 `## 交互` 的四行并入分镜；新增 `## 分镜`，要求 3–5 拍、每拍
  `秒数 / 画面 / 操作 / 讲解 / 吸收` 五项齐全，**秒数加总 = {stay}**。
- **`core/planner.py: _valid_spec`** —— 加三条可算的判据：
  拍数在 3–5；每拍四轨都非空；**秒数加总等于该页停留（容差 ±10%）**。
  交互页另查：至少有一拍的**操作**轨非「不能动」。
- **`core/planner.py: _repair_spec`** —— 秒数加总差一点就按比例缩放补齐，
  不要为这个退回重写（那是算术，不是判断；harness 自己算）。

## 事前写死的判据，以及我不能声称的东西

**能声称的**：这个模型给出的是可算的约束，而可算的约束在这条项目上一贯奏效。

**不能声称的**：我没有任何证据表明分镜会把占用比从 47% 抬到 63%。
我有的只是三条：(a) 可算的加总约束控制住过页数和停留；
(b) 属性式规格产出的页面偏空；(c) Opus 那条线的规格更接近「预先放过一遍」
（它把 `Chrome.mount({...})` 连字号轴名数据表一起逐字写进 brief）。
**这是一个带机制的假设，不是已验证的修复。**

跑一轮要对的数（和 `ape-g8` 同模型同路由，只改规格层）：

| 数 | ape-g8 | 这一轮要看 |
|---|---|---|
| 分镜拍数合规率 | 不存在 | 100%（闸拦） |
| 逐拍秒数加总 = 停留 | 不存在 | 100%（可修补） |
| 占用比中位 | 47% | **是否 → 55%+**（这是假设的直接检验） |
| 建页 agent 每页调用中位 | 25 | 是否下降（规划替它做完了预演） |
| spec 中位字符 | 1,303 | ≤1,600（分镜换掉三节，不该涨） |
| 叠压 / 侵入 / 空页 | 0 / 0 / 0 | 不退 |

**若占用比不动**，那就说明「页面偏空」的成因不在规格缺时间轴，
而在别处（比如内容量本身不够、或版式类的默认排法就撑不满）——
那时该去量的是内容量，不是继续加规格字段。
