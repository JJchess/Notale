我们没有任何一页做过这个算术。

### 2.2 `## 场景构图` 是第二套独立的画面描述（成立）

我们每份规格用**两节各自描述一遍画面**，而两节互不引用：

> `## 场景构图` split-tb：上半部是一条悬浮在深暗空间中的长年代尺，四条青绿色证据带像不同时间
> 启动的轨道；下半部是低矮操作台，四枚标记依次为脚印、牙齿、手掌、颅骨线性图标。 —— `g11/p07`

`p41`（mm）更明显：`知识结构` 说"左侧照片 + 右侧三行表"，`场景构图` 又加"底缘地球弧面从照片下方

**两处都是提示词逼出来的，不是模型能力：**

`prompts/plan.md` 对视觉世界的要求是对的（"给具体取值，不要形容词"、母题 3–5 条），
但加了一句可算的约束：**"要写的六项，一行一项"**。模型贴边满足，347 字符封顶。
Opus 那 15% 是一张带「为什么」列的表 **加上三个被否决的调性方案**——
"浅色学术纸：14 张真实照片贴在白底上像剪贴画"、"饱和科幻蓝：它在开讲第一秒就替这堂课下了结论"。
它的两个色相是**两个变量**（赭石=基因/慢通道，青=文化/快通道），并写明目的：
"读者看 44 页下来，会在不被告知的情况下学会「赭色的东西慢，青色的东西快」"。
我们的主色相一句话背三件事（"生命、协作与从远古延续至今的文化链"）。

`数字口径` 那 22% 是一个提示词自相矛盾：

    ## 3. 数字口径
    全套统一的**关键数值列表**，逐条写明。页面一律从 `Lec.K` / `Lec.P` 取，**不要写死**。

既要数值列表、又在同一行禁止写死。模型的解法是列 60 多个函数名、**一个数都没有**。
同一个禁忌大概也压掉了页表「一句话」里的数字。

### 3.2 页表「一句话」带不带数（成立，22% → 0%/2%）

Opus：`2% 的重量，20% 的能量`、`4.7% vs 37–48%`、`1.4 km/s vs 7.7 km/s`、
`2970 吨换 48.6 吨`、`13 个里程碑，间隔从 84 万年缩到 57 年`、`从 1 个人到 115 个人`、`每月 1–1.5%`。

因果链是通的：页表那一句带数 → 规格必须承载它 → 页面必须显示它。
量到的下游就是每页真内容 47.2 对 33.0。

### 3.3 Opus 有三节我们完全没有

## 5. 底盘（同一份 base 之上的 deck 层）

### 5.1 供给-需求脱节（成立，45% → 3%/9%）

| | 类数 | 被规格点名过 | 被页面用过 | 死类 | 带几何 |
|---|---|---|---|---|---|
| Opus `deck.css` | 74 | **33 (45%)** | 54 | 14 | 49 |
| g11 `theme.css` | 118 | **4 (3%)** | 93 | 25 | 75 |
| mm `theme.css` | 90 | **8 (9%)** | 69 | 21 | 62 |

Opus 被点名最多的类：`.mount` 44 份、`.sub` 43、`.hint` 31、`.claim` 7、`.big` 5、`.flow`/`.hier` 各 3。
我们被页面用得最多的类：`.min0` 152 次（规格点名 **0**）、`.row` 115（**0**）、`.cell` 107（**0**）、
`.muted` 78（**0**）、`.between` 65（**0**）。

**不是我们缺语义词汇** —— `theme.css` 里 `.panel .dim .arw .support .legend .step` 和 Opus 同名都在。
是**规格不点名**，于是每页现场决定用哪个类。

### 5.2 根因是流水线顺序（成立，且是三秒能改的）

`core/planner.py: plan_run()` 的真实执行顺序：

    800  seed()          base.css / base.js / CHASSIS.md 就位
    803  lec.js
    828  PLAN.md
    854  expand()        ← 48/50 份规格在这里写   ★ 此时 theme.css 还不存在
    856  theme.css       ← 版面层在规格之后才写
    884  CONTRACT.md     ← 契约最后写,规格也看不见
    891  skeletons()

**规格点名版面类在因果上不可能。** 第 806 行的注释写着「PLAN 必须在 theme 之前」——
那次调序是有意的（为了让 theme 拿到版式清单），但没人注意到 `expand()` 也留在了 theme 前面。
`prompts/spec.md` 收到的注入里有 `lec_api`、`lec_values`，**没有任何 CSS 类名**。

Opus 是单一上下文：`deck.css` 是它自己写的，写 44 份规格时全程在手。

### 5.3 JS 层不是同一种东西

- Opus `deck.js` **109 行**：`ACTS` / `el()` / `mount(cfg)`。**纯 chrome，没有计算层。**
  它的数据和计算在规格里（13 行真实数据表 + "照抄这些值" + 当场算的公式 + 核对值）。
- 我们 `lec.js` **653 行**（mm 1076 行）：`K`（常量与数据）+ `P`（对数时间尺、单位换算、脑重异速生长…）。
  规格去指它，于是画面上的数变成了指针。

两种架构都自洽。但我们这一种有一个额外条件：**规格必须拿得到值**。
`expand()` 已经注入 `lec_values`（第 845–853 行的注释记着这次修复的收益：Edit 6.5→1.1、
画布占满 24/48→44/44），可是**表格里仍然写指针**——注入了值，规格却没有把值搬进画面清单。

### 5.4 自文档这一层谁来写

Opus 自己生成 12,013 B 的 `CHASSIS.md` 描述接口；我们的 `CHASSIS.md`(6,891 B) 是**我们手写的
harness 输入**，模型不写接口文档。这两份不能比质量，只能比"有没有这一层、谁来写"。

`planner.py` 已经有一个补偿机制：把 `theme.css` 自报的 `INTERFACE` 块追加进 `CHASSIS.md`
（第 860 行起的注释说明这是抄 nn-11 协调者的行为）。**但 `CHASSIS.md` 只发给建页（`brief.md` 的
`{assets}`），不发给写规格那一步** —— 所以接口词汇到达了 build，没到达 plan。

## 6. 不能下的结论（混淆项）

1. **「模型」和「harness」分不开。** 没法把 Opus 放进 notale-v2，也没法让 GPT 自己搭 harness。
   上面所有结论都可能含模型能力成分。但其中五条有**明确的 harness 侧成因**，与模型无关：
   `Lec.mount` 断链、`expand()` 在 theme.css 之前、`CONTRACT.md` 在规格之后、
   「一行一项」把视觉世界锁在 347 字符、「不要写死」压掉数值。
2. **`CHASSIS.md` 两边性质不同**（它的是产物，我们的是输入），只比了"有没有这一层"。
3. **A2 的原始形式不成立。** 我读了十几份就下的判断（"Opus 的知识结构是几何承诺，我们的是标签"）
   被全量统计推翻：提到几何对象的比例 72% 对 60%/66%。真正分开的是我们**多**一节 `场景构图`。
4. **页面/规格比不是 plan 阶段的结论。** Opus 每个规格表格数值渲染出 3.5 个屏上信息项，
   我们 1.65 个 —— 这一半在 build 阶段，本报告没有隔离它。

## 7. 改动清单（按代价排序）

实测：规格返工 3 秒 / 份（32 份 98 秒，20 路并行）；建页磨一页 21.4 分钟。**差 400 倍。**
所以能在规格层解决的一律不要留到建页层。

### 甲 · 断链，必须先修（判据 0 节）

1. **`prompts/spec.md`：删掉 `Lec.mount(...)` 或把它换成真实存在的接口。**
   现在 48/48 份规格命令建页调用一个不存在的函数，`take` 因此 43/48 页丢失。
   两个选项：(a) 把 `kicker/title/take` 改成"写成页面上的三个真实元素，各自给字号和落位"；
   (b) 在 `base.js` 或 `theme.css` 的 INTERFACE 里恢复一个最小的 `mount`。
   **(a) 更符合"chrome 由每页自己排"这个已经做出的决定。**
2. **顺带恢复讲解轨。** `foot:` 那句"交给下一页的问题"是 Opus 100% 落实、我们 0% 的东西，
   它原来就寄生在 mount 上。改 (a) 时把它写成规格的一节：`## 交给下一页的问题`。

### 乙 · 流水线顺序（改 4 行，判据 5.2）

3. **把 `expand()` 挪到 `theme.css` 之后**，并给 `prompts/spec.md` 注入 theme 的 INTERFACE 块
   （类名 + 各自的几何 + 许用场合）。这一条直接对着 45% vs 3% 那个差距。
4. **`CONTRACT.md` 也挪到 `expand()` 之前**，或至少把契约里与规格有关的几节前置。

### 丙 · 提示词的两处自相矛盾（改两行，判据 3.1）

5. **`prompts/plan.md` 的 `数字口径`**：把"不要写死"限定为"页面不要写死"，并明确要求
   **这一节必须列出真实数值**（每条一个数 + 出处）。现在这一节 60 多个函数名、0 个数。
6. **删掉「六项，一行一项」**，改成 Opus 那个形状：一张带「为什么」列的表，
   外加"**写出至少两个被你否决的调性方案和否决理由**"。后者是让配色变成系统而不是清单的关键。

### 丁 · 规格模板（判据 2.1、2.2、2.3、2.5）

7. **合并 `场景构图` 进 `知识结构`**，只留一节描述画面。这是浮动组 2.0→4.0 的来源。
8. **`## 照这个写` 从 401 字符压到接口引用**（点名类和函数，不复述配置字面量），
   把省下的篇幅给 `知识结构`。
9. **数据表必须填真值**：`lec_values` 已经注入了，加一条闸——表格单元格里不许出现
   `Lec.K` / `Lec.P` / "对应条目"。这是一条可算的判据，可以直接进 `_valid_spec`。
10. **加 `## 核对`**：凡是有当场计算的页，规格给出 2–3 个期望值。Opus 47% 的页有，我们 0–8%。
11. **让规格的形状随页面变化**：无交互的页不写「交互」节，不挤的页不写「版面」节，
    没有照片的页不写「媒体」节。现在 8 节每页强制，产出的是模板而不是规格。

### 戊 · 不要做

- **不要在页表「一句话」上加"必须带数字"这条闸。** 它会被贴边满足（今天量到 `OCC_FLOOR=45`
  导致四页停在 45–48%）。数字应该来自 `数字口径` 那一节真的有数（改动 5），
  页表自然会引用它。
- **不要改时长分配**（判据 3.4：我们比它好）。
- **不要动共享契约**（第 4 节：不是差距所在，而且我们的鬼引用更少）。

### 顺带查出的两件事

- **`MAX_CHARS["spec"]` 从来没生效**：它只在 `cached()` 里被检查，而规格走 `expand()`。

  而 API 注释没说它带符号。于是 `g14/p07` 的年代印成"约 +366 万年前"。
  影响面 2/8 页（g11 0/48、sol47 0/31、Opus 0/44）。**没动它** —— 它在两条线逐字节
  同一份的冻结层里，改了就失去"同一个 base"这个单变量前提。

# 附：skill 那一层的账（2026-08-23 量的）

## 一个页面加载几个

中位 2、众数 2、平均 1.9。sol48 的 34 页：0×1、1×6、**2×22**、3×4、4×1。
已建 12 页 **指派 24 / 实读 24 / 自选 0 / 漏读 0**。

（`planner.py:826` 注入全 49 条）→ `_skill_list_row()` 转成 `  - name` 行（`planner.py:594`）
