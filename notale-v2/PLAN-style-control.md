## 1. 为什么改，改到哪里

目标是让用户要求或视觉参考真正影响字体、形状材质、图片处理与背景，而不只是换颜色；同时修复现有 Director 的输出和修订漏洞。范围包括封面、内容和交互页；代码页继续独立，不优化外观。

| 当前证据 | 本次处理 | 不因此增加什么 |
| --- | --- | --- |
| Director 的选样/主题闸按明度档、奶油色、纯灰、极差等拒绝；与提示词例外不一致 | 配色统计回到参考/诊断；具体技术错误才触发修订 | 自动审美裁判、更多配色阈值 |
| SHAPE 全局拒绝形状，SURFACE 全局误伤局部变量 | 允许具名局部样式；公共承载面许可仍收紧 | 组件库、版式 recipe、继承层 |
| 实测缺 `--text/--font-sans`、损坏 CSS 可过；空 Write 与多个 Write 未拒绝 | 补输出契约与浏览器有效性检查 | 全面 CSS 安全分析器 |
| 每次重试新建 history，只带错误不带失败 CSS；trace 漏 Write 内容 | 同一修订上下文回传候选和错误；补现有记录 | critic、修复 agent、日志服务 |
| 模板与装饰图尚未接入；代码外壳仍链接共享主题 | 主题输入、共享媒体工具、原生背景与品牌层；保护代码隔离 | 第二套搜索、背景渲染器、代码皮肤 |

证据来自 [director.py](core/director.py)、[gallery.py](core/gallery.py)、[style-theme](prompts/style-theme.md)、[builder.py](core/builder.py)、[code_runtime.py](core/code_runtime.py)。审计中的确定性反例须转为回归测试，不能用现有六个 SURFACE 测试的通过来覆盖它们。

以下旧设计撤回：`style.json`与编译器、独立风格说明文件、主题继承、Planner→Director 页表依赖、全局概念绑定与未绑定概念强制中性化、默认给 Builder 全量 CSS、独立背景关闭开关、旧提案目录兼容层、代码页换肤。不给 Planner 增加概念表来替代已撤掉的通信。

## 2. 保留并行与两步选样，不重建编排

编排仍先 seed，再并行运行 Planner 与 Director；两者成功后启动 Builder。Director 读取已有题目、读者、场合及用户风格要求，不读页表、不等 Planner、不回写内容。跨页数据含义与图例由 Builder 按内容表达，不新增统一概念配色保证。

自动生成保留两个有实际作用的步骤：

1. `pick()`根据现有文本索引选少量参照。保留目前 5 张的载荷设置，不把 5 或跨明度档当质量定律；不足 5 张时使用可用数量，无可用参照则明确报错。验证 ID 真实、唯一、图片可读，不因都属同一明暗风格而重选。去掉未交给下游的逐项理由要求；`style-picks.tsv`仍按首列 ID 读取，旧记录可读。
2. `theme()`同时接收配色参考图、风格表及风格视觉参考、ban list 和用户要求，在本次响应里完成风格选择、配色协调与主题创作，不另设“选风格”或“加和”阶段。可以按需调用现有图片工具，收到并看到结果后再使用。无取图、无错误、无需另取细节图时仍是选样一次、写主题一次；工具结果后的继续创作或修订会增加响应，不承诺所有运行固定两次调用。

用户提供参考时跳过画廊选样；有效成品主题无修改要求时跳过模型创作和风格库加载。无需为了角色对称而执行空调用。画廊缓存保持现有简单形式；索引里的最大面积色改称“主色”，不声称它一定是背景或次色一定有语义。不重新标注整个既有画廊；本次风格表来自用户明确指定的 40 项，不扩成风格分类服务。

Director 自己的选样、看图与修订使用连续 history，工具返回图片后继续原对话；这与 Planner 保持独立是两回事。ban list 在看图写主题前明确进入上下文，约束创作而不按配色统计触发输出重试。它必须允许用户要求的风格特征，例如霓虹、渐变、粗边框或密集构成；不能换一个位置继续全盘禁止它们。明确风格要求优先于通用审美禁令，技术与可读性底线保留。

保留当前线程、run 目录与错误上报方式；两边无数据依赖，不能把旧方案引入的“等待页表互锁”算作当前系统需要修复的故障。在途外部请求沿用已有超时，不新增取消协议。

### 写主题时的风格表与图片

一份 `references/styles/INDEX.md`登记全部 40 项，包含稳定 ID、名称、可见视觉做法、配色结合/讲义落点与源行。它是给模型读的短表，不是 CSS schema、40 套成品主题或组件库。名称不限定系统能创作的风格。

8 张海报各有 5 个右侧网页示例：逐条裁为 40 张独立参考，去掉海报标题、左侧说明、统一灰色圆角包装和浏览器地址栏，不按整图平均五等分。保留原图及来源对应关系，不改色、不补画，也不把截图直接当最终页面资产。具体源文件映射、条目与裁图要求都只在参考表维护。

默认输入设计：40 条短表＋八组带 ID 的风格概览（每组五项），与本次配色参考图分别标注用途，共同进入“看图写主题”。概览由已裁图片离线缩放排布，不调用模型。运行时只取表格和使用说明，不把裁图操作说明与来源目录灌进创作上下文。

用户明确指定单一条目时，可直接提供该项原裁图与说明；自由描述或自动选择仍使用全表/概览，不用另一个模型做分类。需要辨认字体、纹理等细节时，沿用图片读取能力一次取回所需裁图，下一次响应继续创作；这会增加一次模型调用，不能藏在“固定两次”里。概览是否足够清楚、图片输入成本多少，须按实际模型测量；拼成八组只减少消息碎片，不自动保证更省 token。

40 项并非互斥流派：排版、材质、插画、构图和交互方向有重叠。Director 负责可共享视觉语言，Bento/分屏只给构图倾向，动效/叙事滚动/3D 的实际行为由 Builder 决定。静态图不能证明动画、视差或可操作 3D；固定舞台不能冒充原生长页滚动。完整长页滚动若被明确要求，需要另行改变底盘，不算本次已支持。

配色与风格可以协调，不是任意换色都保留原身份：黑白摄影要保留黑白关系，新拟态依赖同色底的光暗差，霓虹和金属有各自的对比/材质关系。冲突时说明取舍，不机械套一个色板。字体、布局、图表和控件仍需适配正文，不能把这些首页示例当作每页固定模板。

## 3. 输入与交付：一个文件入口，一份最终主题

新增两个可选输入：`--template <path>`接收单张参考图或主题/参考目录，`--style <要求>`明确指定风格或对成品主题的修改。题目/读者/场合仍是内容语境。保留独立风格输入的具体理由是：成品主题能否直接复用必须由显式输入决定，不能暗中新增模型调用或关键词分类器来猜“是否要求重写”。两个 CLI 共用导入逻辑与参数含义。

| 输入 | 行为 |
| --- | --- |
| 未提供文件 | 按题目语境与可选 `--style`选参照、看图生成 |
| 单张截图，或包含 `shots/` 的参考目录 | 看用户参考及可选 `--style`生成；不要求先写 CSS |
| 有 `theme.css`，未传 `--style` | 校验并复用，除本地资源 URL 重定位外不改样式 |
| 有 `theme.css`，传了非空 `--style` | Director 按明确修改要求读取原主题与参考，生成本次完整版本，不保存基础层＋补丁层 |

主题目录只要求有效的 `theme.css`；它引用的资源必须存在，`assets/`存图片/字体/logo，`shots/`可选。资源用途通过用户原要求和 CSS 表达，不增加资源 manifest。截图参考不是可执行主题；目录缺 CSS 又缺参考图则说明缺什么。PPTX 解析、任意母版精确复刻不在范围；旧 B/C 未实施，不为其草拟目录额外造兼容适配。

明确要求优先于包默认值，包优先于自动偏好。CLI 说明和运行摘要须写清：修改成品主题请用 `--style`，不能以题目内容不同就自动改主题。空白 `--style`报参数错误。互相冲突的明确要求需澄清，不按默认审美替用户选择。修改主题只在新 run 内进行，来源包和旧 run 不改；原样复用校验失败时报告错误，不擅自让模型重写用户主题。

交付仍为 `pages/assets/theme.css`。导入资源保留目录层级落在 `pages/assets/style/`，避免同名文件覆盖；CSS URL 按源 CSS 所在目录解析，再重定位为相对最终 CSS 的路径，保留必要 fragment。只复制本次输入中需要的资源与参考，不复制包内脚本并执行。路径解析后的越界与外部软链接拒绝；缺文件报具体路径。

用户图片默认是参考，只有被明确要求或选定作装饰才进入 CSS。用户指定 logo/字体/背景不能被随机搜索替换。Director 的新增装饰图复用 `core/tools.py::media_call()`与 `core/media.py`，owner 使用 Director 自己的命名空间；保留原图与已有来源记录，不另造素材 ID。整幅地图、扫描件等内容证据仍归 Planner/Builder，不因铺满画面而变成装饰。

本次保留显式关闭能力，不擅自废弃 `--no-style-director`。关闭时沿用 Planner 写主题；新的 `--template/--style`入口要求 Director 开启，冲突参数在调用模型前报错。旧路径不复制模板/取图逻辑，只复用适用的主题基础校验与统一规则。

## 4. 主题接口：实现留在 CSS，Builder 只用公开能力

主题可控制字体、字阶、间距、边框、阴影、材质、图注、控件状态和动效参数；Builder 决定内容、几何、拓扑、布局与交互步骤。保留现有基础 token，不把目前固定 padding、字阶数值或“只准一条线”继续当作唯一风格。

使用说明仍放在 `INTERFACE` 注释里，供 `_theme_interface()`读取。列出实际公开 token 的名称与用途、具名样式、变体及必要净空；实现值以 CSS 为准，Builder 用 CSS 变量或 `Deck.token()`取值，不抄写一份 hex。删除强制“论点/材质/签名/禁令/修订”全套自述，允许短的风格与构图说明。

示意接口：

```css
/* ==== INTERFACE ====
方向：摄影纪录；正文开放排版，标题避开右侧照片主体。
token --accent：品牌强调，不代表正确性或数据类别。
class .nt-title：页标题。
class .nt-controls：需要操作时使用的局部控件面，不用于包住所有内容。
variant opening：照片开篇；配套浅字，标题放在左侧。
默认：不设置 data-variant，使用无图正文外观。
品牌：右上角 logo；按实际尺寸在内容中留出净空。
==== /INTERFACE ==== */
```

主题样式显式挂在 `.nt-*`及其子元素/状态上，不全局重写每个 div、button 或第三方组件。私有子类无需全部列入接口；公开名称必须存在，不能把现有“漏列私有类”的提示重新升级成硬闸。

根与公开接口不发布裸 `--surface/--panel/--card`等任意容器垫底槽位。局部 `.nt-controls { --surface: …; background: var(--surface); }`合法；改名但继续承诺“任何区块底色”仍违背边界。声明作用域可检查，语义是否过泛需读说明与看实际页面；不声称正则或 CSS 解析器理解全部用途。`.nt-card`有前缀也不自动证明卡片墙合理。

Builder 默认仍只接收接口，不全量注入 CSS，不复制主题私有实现。视觉参考沿用现有图片消息通道：用户/主题包的代表样张复制进 run 并随视觉页输入提供；不要求每包必有样张，也不为每套自动生成演示页面。代码页不接收。

必须同步修正 `REF_SHOTS_NOTE`：用户参考可以要求沿用颜色与材质，不能再统一说“不抄配色”。画廊候选只是启发，不等于最终主题；现有 `--ref-shots`候选图实验不自动升成默认，更不能覆盖用户样张或主题接口。修改过的主题以新接口和明确修改要求为准，原样张不冒充修改后的效果。仅有封面图时明确正文是推导；无视觉能力的模型不能声称看过参考，需报告限制或更换适用模型。

## 5. 背景与品牌：只用浏览器已有机制

一个 `html[data-variant]`同时改变背景与前景；未设置属性就是默认外观。名称属于主题并在接口说明，不增加系统级 `reading`别名或背景关闭开关。Builder 在图表初始化前选择变体，不做运行时换肤。

背景在实际缩放的 `#stage`上，以多重 `background-image`合成图片与蒙版。以下只是机制示例，不是完整主题：

```css
:root {
  --bg: #f3f0e8;
  --text: #202722;
  --muted: #505b53;
  --font-sans: sans-serif;
  --backdrop: none;
}
html[data-variant="opening"] {
  --bg: #14221a;
  --text: #ffffff;
  --muted: #e1e9e3;
  --backdrop:
    linear-gradient(90deg, rgba(16,27,19,.82), rgba(16,27,19,.12)),
    url("style/assets/forest.jpg");
}
#stage {
  background-color: var(--bg);
  background-image: var(--backdrop);
  background-size: cover;
  background-position: 72% 45%;
  background-repeat: no-repeat;
}
```

根属性与现有 `Deck.token()`读取位置一致；SVG 用 CSS，Canvas/图表明确读取主题 token。局部反色区域需读取对应局部值，不假设根 token 自动反映局部样式；不新增通用图表 adapter。

图片主题须有可读的无图状态；需要保留深底浅字时可另提供无图深色变体，不机械退回浅底。图片加载失败仍有相容底色。Builder 不得用 stage 的 background 简写无意清空主题合成；全幅证据可以覆盖装饰，不替换共享 CSS。

为独立品牌层保留 `#stage::after`，主题定义 logo 外观，底盘约定层级与 `pointer-events:none`，跟随舞台缩放。内容须留净空且不得盖住品牌层；其他元素的伪元素仍自由使用，无 logo 时不生成可见品牌。实际有正文含义的标识用可访问的内容元素，不靠伪元素传达。

不添加第二套压暗 CSS、不预先烘焙蒙版、不做自动透明度求解。照片主体裁切、文字与 logo 可读性由实际截图检查；修复可改裁切、移动文字、调整蒙版或选变体。

代码页沿用[独立风格契约](runs/ens-code-stylefix-0907/VALIDATION.md)。其外壳当前仍加载 `theme.css`，需解除这条共享链接并由宿主保有必要底色/文字/字体值，防止新增品牌层泄漏。只保持原外观与执行，不改 Monaco、iframe 内样式或工作台布局；不承诺代码页继承讲义 logo/背景。

## 6. 校验只检查可证明的事

生成、修改和直接导入共用同一主题检查，显式关闭 Director 的旧路径也使用适用的基础检查。不要将现有正则扩成另一种 CSS 语言。

| 层次 | 检查与处置 |
| --- | --- |
| 输出契约 | 每次提交恰好一个目标 Write；JSON 对象、路径与字符串类型正确；内容非空。不默默取多次 Write 的最后一个，也不把错误类型转成字符串 |
| 必需运行接口 | 完整 INTERFACE；默认及声明变体中 `--bg/--text/--font-sans`可解析、可用于对应属性；公开类、token、变体确实存在。颜色不限定六位 hex；字体通用族合法 |
| 文件与字体 | CSS 引用可解析且不越界，图片可加载，本地字体文件可加载。已安装字体表只供创作参考，不能阻断有效 `@font-face`或通用 fallback；指定字体缺失/缺字需报告，不能靠“发生了 fallback”声称还原 |
| 主题边界 | 公共 surface 与具名局部实现分开；保留 stage 缩放、指针、hidden、焦点与 reduced-motion 的底盘行为。用明确声明检查和固定页运行回归，不承诺静态穷尽所有层叠组合 |
| 实际页面 | 页面声明的变体有效；背景与品牌实际加载、可见；纯色可测对比与复杂背景未覆盖区域分开。关键文字未经看图，不给可读性通过结论 |

用成熟 CSS 解析能力读取声明、作用域和 URL，不自写语法编译器。浏览器负责值解析、资源加载和实际呈现；不能因浏览器容错忽略了损坏片段就算语法合格，也不要求解析器对全部新 CSS 特性做语义证明。未知/不支持项应给具体诊断，不能默默丢弃。主题预检只用已有底盘与基础探针，不根据开放接口自动搭建组件展示页；它不是完整视觉预览。上表“实际页面”由 Builder 的 Check 与交付验收覆盖。

不允许包脚本、联网样式或 `@import`；图片/字体以本地文件引用，现有纯 fragment 引用保留。不为外部 URL 或嵌入式资源另建下载/解包协议；不支持的来源表达需报清楚，不靠漏查放行。检查页禁用外部请求，不把导入主题当可信可执行代码。

奶油色、纯灰、语义色极差、参照明度距离和跨明度档不再触发拒绝。删除 SHAPE 全局形状禁令；相同规则同步到 `style-pick/style-theme/direction`、主题 scrub、视觉页 tech/visual scrub，不能只改 gates。保留真实性、数据准确、操作与可读性要求；装饰不再必须伪装成科学含义。

可复用文件在 run 内自包含；如选择系统通用字体，报告跨机器字形可能不同，不承诺像素一致。缺失用户指定素材则该要求未满足；自动装饰失败可放弃并记录，但最终 CSS 不留悬空 URL。无有效主题不启动 Builder，不以降级掩盖失败。

## 7. 修订与记录：修原稿，不重新抽样

沿用有上限的技术修订，不用审美分数触发重写。保留已有 3 次主题提交上限，选样错误沿用自身有限重试；合法的媒体调用不算主题失败，不为本次另设取图配额。

主题阶段接入现有媒体 schema 与执行体，history 保留工具调用、结果及返回图片。Write 是主题候选提交，不新增 FinalizeTheme：

- 路径只能是本次主题目标；候选先校验，失败返回具体错误，后续响应能看到上一份候选。
- 新取图片先返回模型才能用于主题；同一响应不能提交引用尚未回灌图片的最终主题。规则只检查数据可用顺序，不声称证明模型“认真看过”。
- 校验成功结束主题阶段，再发布到最终路径。主题阶段没有有效 Write 就不能按“自然结束”报成功；发布失败报告 I/O 错误，不让模型反复改 CSS。
- 输入包缺文件等源输入错误直接报告；生成的错误引用可在现有修订里修正。一次技术修订不重新选画廊，也不更换用户原要求。

候选可使用本 run 的临时文件做加载检查，成功后写入正式主题；共享主题在 Builder 期间只读。页内布局由 Builder 的现有 Check 修；终止后的独立审计仍只报告、不回喂。修改已交付风格时生成新 run，并重建受影响页；不承诺任意页面只换 CSS 就完成结构换肤。

沿用 `trace.jsonl`与现有失败文件，记录步骤、候选 Write、错误和实际修订次数、费用/耗时。图片只记录路径或必要引用，不把 base64 重复灌入日志；脱敏沿用已有记录层。删除未使用的 `dist`参数、重复读取和失效说明，不为辅助函数拆新平台。

## 8. 实施顺序与完成证据

以下是一次完整升级的依赖顺序，不将“能显示背景”当最终完成：

| 顺序 | 修改位置 | 完成证据 |
| --- | --- | --- |
| ① 修正现有 Director | `core/director.py`、相关 prompts/scrub、`core/test_director.py` | 输出漏洞反例被拒，合法颜色/字体/局部样式通过；重试带原稿、记录可追查 |
| ② 接入主题与资源 | 两个 CLI、Director 导入辅助逻辑、现有 media/tools、chassis 与代码外壳 | 输入路由明确；同一 CSS 原生合成；资源离线可用；Planner 仍并行、代码仍隔离 |
| ③ 验证 Builder 应用 | Builder 接口/参考图说明与加载、主题样例、已有 Check | 不全量注入 CSS 也能实际使用类/变体，风格与内容/交互同时成立 |

测试按风险分层，固定页和模型生成各回答自己的问题：

- **确定性回归**：默认开启与显式关闭；四类输入路由及冲突参数；非法/重复/空 Write；缺必需值、损坏 CSS、合法短 hex/颜色函数与通用字体；公开 surface 拒绝、局部 surface 允许；修订含候选、无效主题不建页、资源/发布失败。使用 mock，不调用模型。
- **40 项参考覆盖**：核对八张原图各五项全部有表项、源行、独立裁图与概览 ID；逐图检查边界与辨识度。确认自动输入能看到全部条目，指定条目能读到对应图，ban list 不会整体排除其中某类。资源接入不等于 40 种最终生成效果都已通过；未实跑的方向明确标记为生成待验证。
- **固定浏览器诊断页**：同页包含标题/正文/图注、具名控件、SVG/Canvas、背景与品牌。用普通排版、局部玻璃、照片背景三个主题检查能力；切浅/深/无图状态，查裁切与全幅证据、缩放点击、键盘与 reduced-motion。注入同名资源、嵌套路径、fragment、缺图/缺字体、离线场景；同时复用一个代码页隔离样本。它不是主题美感评分器。
- **真实生成应用**：上述三个方向分别覆盖自动生成、用户截图、已有主题修改，再各建开篇、正文/图表、交互页，共 9 页；事实与数据冻结，逐页操作并对照参考。同主题无需预配每页布局；检查是否有实际非颜色差异、是否滥用承载面、是否遵守用户要求。直接复用路线由固定主题回归另测，必须不调用模型改样式。
- **已有回归**：运行 `python3 -B -m unittest core.test_director core.test_prompts core.test_media core.test_builder`，补相应资源与浏览器测试。既有媒体 A 的 FinalizePlan、采用映射、来源记录和代码隔离不能退化。

九页来自三个关键风格机制与三个页型的交叉覆盖，是初始工程样本，不是统计显著性、泛化或全部 40 项生成质量的保证。本次参考范围以用户提供的 40 项为准；代表实跑之外的风格不能直接宣称生成已验证，需要逐项补齐相应证据后才给出该结论。不要求先手写 40 套生产主题模板，也不以少数代表样本替代完整参考收录。

配色分布仅诊断收敛，黑白主题不因色相极差小失败；同时看字体层级、形状材质与图像处理的实际变化，不强迫每套在每个维度都不同。历史约 12pp 是占用比波动，不是所有视觉判断的噪声。记录失败、未满足要求、未验证区域、费用和耗时；不以平均分掩盖严重不可读、数据错误或交互失效。
