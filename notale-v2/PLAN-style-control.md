# Style Director 升级与整改计划

> 2026-09-10 综合方案（待实施）：以下「当前方案」是本轮风格多样性与可解释性升级的唯一方案入口，取代 auto-only 草案及此前未实施的冲突建议。下方历史记录保留，不代表当前待办。此次仅整合文档，尚未修改运行代码或验证新效果。

## 当前方案：看图选方向，按需读详情，把风格交到页面主体

### 1. 目标与边界

让自动模式能选择并落实不同的视觉语言；选择能追溯到实际看到的参考，最终结果能对照 CSS 和页面解释。不是增加一套审美评分器，也不是保证每次重新生成都随机换皮。

- **套内一致**：题名、正文、图解、控件属于同一视觉语言，构图随内容变化。
- **套间多样**：不同要求可以产生形状、排版、材质、图像处理都不同的结果，不只是换背景色和字体。没有“每个学科只能对应一个流派”的映射。
- **可解释**：保留参考 ID、简短的可观察依据、采用/放弃的处理及最终实现。理由是可审计的设计说明，不是模型内部思考的证明。
- **继续做减法**：原生 CSS + `html[data-variant]` + `#stage` 背景合成不变；不加 schema、编译器、adapter、评审 agent、强制预览选择回合、跨页概念色协调或审美重试。
- Planner 只规划内容，Director 定主题方向并实现共享外观，Builder 设计具体 slides。Planner∥Director 不交换页表，仍并行；Builder 等主题完成的既有依赖不变。代码页保持独立，不参与这轮风格优化。

### 2. 事实校正：吸收 critic，但不按过时前提删功能

证据来自当前代码及 `style-e2e-0909a-*`、`four-topics-0909-171933-*`、`neural-check-trim-0909-193805-neural` 的记录。

| 建议或判断 | 取舍与理由 |
| --- | --- |
| 当前 pick 看不到布局、笔触和材质 | 接受。`gallery.index_text()` 只有标题及配色，真实图在 theme 阶段才进入。颜色是视觉信号，但不足以判断完整风格；关键词匹配是风险，不是已证明的唯一决策原因。 |
| 五个 ID 应附理由 | 接受，但不是只改一句提示。`pick()` 当前把返回内容拆成 ID，再只保存 ID，第二列会丢失；须同步保存。`_one_write()` 只检查文件提交，不是解析 ID 的函数。 |
| 理由完全无法进入下游 | 校正。pick/theme 共用 history，Write 参数已随 replay 保留；加理由后 theme 可看到。需要修的是持久化及明确交接，不另造通信层。 |
| 按明度分层随机抽样可解释性 100% | 不采用生产默认。它解释了抽样规则，没解释视觉适合性，并把多样性缩成明暗分布。随机臂只在需要检验选择器价值时作为研究对照，不恢复跨明度闸。 |
| 204 张合成一张图就能解决 | 吸收“看图选择”，不照搬巨型联络表。小格、标签、服务端缩放会损失信息；一张图也不必然比文本便宜。优先复用已有 40 项、8 张带 ID 概览。 |
| 删除 reference/modify/reuse、`--style/--template` | 不采用。用户指定风格、图像参考、只修改已有主题都是不同的实际意图；保留显式方向也是验证风格承接的控制变量。不能为清理分支而移除控制能力。 |
| Director 失败后发三个 token 的兜底主题 | 不纳入本轮。与风格多样性不是同一问题；三个 token 不能代表完整字体和标题角色契约。保留明确失败，不把无风格交付算升级成功。产品可用性降级另议。 |
| 加 `style.json`、改 Future/线程、删 vision 守卫 | 本轮不做。状态复用现有 trace/实验报告；线程调整不改善风格。请求携带图片却配置非视觉模型仍应明确报错。 |
| 0909 auto 0/3，所以现在没有 auto 基线 | 已过时。后续四套交付了 19/11/11/16 页，最新神经网络交付 15 页；它们是历史事实，不是当前方案的单变量质量对照。不能再用早期已删门禁解释今日结果。 |

另一个必须补入的差异：旧 reference 的 `builder.log` 第 9 行明确记录 **1 张参照图随视觉页输入**。当前 `user_ref_images()` 默认传用户图；auto 的 `ref_images()` 却受默认关闭的 `--ref-shots` 控制。之前只比较 Director 输出，漏掉了 Builder 图像输入不对称。这支持补齐交接，但不能单凭这一点证明它是全部原因。

旧 reference 的便签、不规则边缘、荧光强调值得保留；`.compound/.fixed`、`#amount` 等题目专用协议不恢复。当前主题 ban list 与旧 reference 注入文本相同，不能把退化归因于最近“禁掉了一切装饰”。Director 和 style_catalog 实现哈希也相同，重点是选择输入、创作说明和消费端。

### 3. 主流程：从选五份配色，改为选一个视觉方向

**自动模式：看 40 项视觉索引 → 选主方向并解释 → 宿主加载该方向详情、原图、字体 → 同一 Director 对话写 CSS → 技术校验 → Builder。**

这是本方案唯一有意调整的选样职责：不再让 204 张作品的标题和色值先决定基调，再让风格表替它配字体。

#### 第一次模型调用：视觉选择

输入：query、audience、scenario、用户明确要求（如有）、现有 `references/styles/INDEX.md` 轻索引和 `overviews/01..08.png`。这八张图来自已有 40 张裁图，不新造图、不新增每次运行的截图任务。

- 40 项全部可见，不先按学科过滤成几个“安全选项”。名称仅辅助检索，取舍依据包含图中真实的形状、排版、材质或图像关系。
- 用户明确指定风格时直接尊重；没有指定时根据交流目的与场合判断，学术题材不自动等于低饱和、细线和瑞士风。
- 默认选一个主方向。只有明确组合要求或确有互补作用时才加辅助方向；辅助不能变成第二套页面皮肤。不强制凑五张，也不为“多样”强迫每次混搭。
- 40 项是参考入口，不是风格枚举上限。自定义方向选最相关资料作依据，并在理由中说明偏离；不发明不存在的资源 ID。
- 继续用 `style-picks.tsv`，每行 `风格ID\t简短依据`；首行为主方向，其余为辅助。依据说明图中可见特征及本次采用目的，不写隐藏推理过程、题材联想套话或虚构细节。
- 宿主检查 ID 存在、去重、文件可读，保留完整第二列；不按理由字数、色相、风格流派或多样性分数触发重试。日志保留原始交换。

示例（说明输出形状，不作为所有任务的固定答案）：

```tsv
19-hand-drawn	采用不规则墨线和荧光批注，让推导像现场演算；数据坐标保持准确，不借用参考里的卡通人物。
```

图像输入用保留标签可读性的尺寸，不把长条概览走默认 900×900 的缩图后就假定可辨。先复用现有 720px 宽概览，显式控制发送尺寸；选中项在下一步用单张原裁图确认。记录实际请求图尺寸与 usage，不承诺八张图免费或一定省 token。

204 项作品画廊、现有测色缓存和来源资料不删除，但退出默认 Director 必选流程，保留既有人工/实验用途。本轮不再新造画廊检索工具。用户给的配色、参考图仍可与所选方向组合；没有外部配色要求时直接从选中视觉参考与内容需要协调颜色。

#### 第二次模型调用：看原图写主题

宿主按已选 ID 调用现有 `style_catalog.detail()`，把详情、单图及字体声明作为下一条输入送回同一 history，无需让模型先再发一次 Read 才取得已确定的资料。

- ban list 在创作阶段加载，仍区分“无语义容器许可”和“具名局部风格材质”。
- 第一轮的依据是创作起点，不是不能修正的命令。原图与详情发现冲突时，在最终接口说明采用/放弃了什么；不机械混色，不抄导航、logo 或原图文案。
- 必要时仍可 Read 补充风格详情或取素材，因此两次是**正常直通调用数，不是硬轮数上限**；工具结果必须回到模型后才能完成 Write。
- 字体物化、技术校验、原子发布继续沿用当前实现和顺序；技术修复在同一对话，不另选模型或重启 agent。

### 4. 主题资料和 CSS：方向要能实施，但不规定页面

保留轻索引 → Markdown 详情的形状，不增加另一份 JSON 设计系统。40 项中英标题/正文/数字字体、真实字重、图像来源继续有效；逐项核对资料是否提供了颜色和字体以外的落点，缺的补，已有的不用重写。

每项资料需能回答：哪些视觉关系让它可辨识；如何用于标题、图解、批注/操作；哪些只是参考中的内容，不应照搬。不是每种都必须有纹理或阴影，也不建立特征数量闸。

| 方向示例 | 可迁移到页面主体的依据 | 不能冒充的效果 |
| --- | --- | --- |
| 手绘 | 不规则边缘、圆头笔触、手写批注与荧光强调 | 只换楷体；或把科学曲线坐标抖乱 |
| 包豪斯 | 几何体块、非对称重量、尺度与色块关系 | 只用红黄蓝；或每页贴三个装饰圆 |
| 新粗野 | 强轮廓、硬偏移阴影、直接的按压状态 | 给所有段落套粗框卡片 |
| 瑞士 | 明确阅读轴、强字阶反差、字图和色块关系 | 把淡灰底、细网格当作全部身份 |
| 拼贴 | 裁切、叠压、纸边和图文层次 | 随机倾斜一切，或伪造历史照片 |

动态/3D/滚动方向的静态图只能提供外观线索；行为仍由 Builder 按固定舞台与 reduced-motion 契约实现，不因为选了名字就宣称拥有动态能力。

`theme.css` 顶部仍只保留一个 INTERFACE，承担：

1. 来源与方向：最终采用的参考 ID，以及简短的形体、排版、材质依据；取舍说明不重复第一次选样全文。需要向 Builder 传图时，沿用接口的逐行写法增加 `reference style:19-hand-drawn` 或 `reference user:<已导入相对路径>`，第一项为主参考；只允许本次已加载/已导入的来源。它只指认输入图片，不定义主题数据模型或页面结构。
2. 字体/标题角色与必要语义色：可用值和实际字重，不只写“高级/清晰”。
3. 实际可用的前景样式：如笔触、批注、按钮、节点、图像边缘；公开使用它们必需的类、局部变量、宿主关系和一个必要例子。
4. 变体/背景/品牌净空：只说明确实实现的内容。

短接口不等于只列字体。也不要求穷举私有子类。凡作者必须知道才能使用的入口都应公开；私有实现细节不抄。主题类不控制页面坐标、宽度、列数、图表数据和对象拓扑。

共享 CSS 实现可保留局部边框、阴影、玻璃、笔触和按钮状态。Canvas/ECharts 需要的少量视觉值公开使用，不增加逐图表 adapter、固定 token 表或领域数据系列协议。没有共享需求就不造新变量。

### 5. Builder 交接：统一 auto/reference 的信息质量

视觉 Builder 默认得到：**最终 CSS 的简短接口 + 最终采用的一个主视觉参考**。不是初选候选集合，不是额外生成的一张风格示范页。

- auto 使用最终主方向对应的原裁图；用户参考路线使用承担主视觉依据的用户图。明确组合时只追加确需承接的辅助图，不默认灌入全部候选。
- 继续在现有首条输入附图，不增加模型响应、Read 或协调步骤。同套复用同一图与说明；实际图片 token、缓存和轮次成本仍须记录，不把“调用次数不变”说成“成本不变”。
- 图是形状、材质、字图关系的依据，不是要照抄的页面，也不冒充最终主题截图；颜色和实际字体以最终 CSS 为准。
- modify 的旧图不能冒充改后的方向。若换风格，交接新采用的主参考；只改配色则可保留原图并明确仅参考其不变的形体/材质。reuse 无参考图时用现有接口，不自动补图或重写 CSS。
- Builder 从最终 INTERFACE 的 reference 行解析已授权的图片，不从自由措辞猜路径，也不把第一轮被放弃的候选误当最终方向。引用不存在或未加载的来源是输入契约错误，不静默猜图。旧主题没有 reference 行时，沿用包内明确用户参考；无图则仅使用接口，不强制重写旧主题。来源文件仍按现有导入边界处理，不通过一句自然语言无限授权目录文件。
- `ref_images()` 要能解析新风格 ID；旧 run 的裸画廊 ID 仍按既有画廊路径解析，不把两者混成错误图片。历史 run 不回写。删除已被默认主参考交接取代的生产 `--ref-shots` 开关，避免一个状态有两套约定；单变量无图对照由实验 runner 向现有 build_one 输入传空 refs 实现，不新增生产开关。manifest 的 `refShots` 按实际是否传入参考填写，并记录实际参考来源，不能继续记录旧开关值。
- 有图且模型不支持 vision 继续报配置错误；代码页仍不接主题图/CSS。不能以吞图来假装实验条件一致。

Builder 提示不是再追加一串“必须有风格”，而是替换重复段落为一个清楚原则：

> 你决定本页主体、布局和交互。沿用主题的字体、颜色，也把其形状、笔触、材质或图像处理落实到适用的主体、图解、批注或操作元素中；可用共享类，也可自行实现。不必添加所有装饰，不另造一套皮肤，不照抄参考网页布局。

reference/Main 样例教内容关系与实现方法；其默认色、字体、控件皮肤不覆盖最终主题。无需删除样例，也不把完整 CSS 或风格卡反复注入各轮。第一版之后有具体问题才定点读实现的效率规则保留。

### 6. 调用数、失败和可解释性落盘

| 输入 | 正常 Director 调用 | 说明 |
| --- | --- | --- |
| auto | 2 | 看视觉索引选择；详情由宿主加载后写主题 |
| 明确库内风格 | 1 | 已知 ID 直接加载详情，不先跑一次无意义选样 |
| 用户参考图 | 1 起 | 直接看图创作；需要 Read 风格详情则多一次响应 |
| 有效主题，无修改要求 | 0 | 原样验证与复用 |
| 主题明确修改 | 1 起 | 旧 CSS 与明确要求一起进入；补读或素材操作增加响应 |

调用数不含 Builder，也不掩盖 Read、素材工具后续响应及技术修复。用户明确风格与输入校验仍保留；这不是恢复四套不同的创作器，而是沿用当前入口，收敛到同一个 theme 创作过程。

`style-picks.tsv` 保存选择与依据；最终 INTERFACE 解释实际实现；现有 trace 保存请求、图片身份/哈希、工具结果、模型/profile/effort 和技术失败，实验 manifest 引用这些信息。成功/失败状态使用现有报告，不新增 `style.json` 设计或状态平面。不在 slides 可见内容里显示内部理由。

发现颜色变了但没有保住形体/排版，应归为风格落实问题；模型调用失败、资源缺失和 CSS 技术失败分开报告。没有“闸过了所以多样性好了”的结论。

| 文件 | 改动 |

顺序：先固定现状证据 → 完成选择/交接整个改动批次 → 快速定向检查 → 分层实测。选择器和 Builder 的效果分开归因，不能把一揽子改善冒充某一句提示的因果证明。

`core/planner.py` 的并行编排、`core/theme.py` 的导入沙箱/技术闸、本地字体准备顺序不为本方案顺手重构。`gallery.py` 保留供旧实验及其他消费者使用，别误删同名模板功能。

### 8. 验证：少量可回答问题的对照，不拿测试规模代替结论

本次仅写方案，没有授权新付费实验。实施后的模型实验须先告知预算与范围，不自动启动四套完整生成。

**离线检查，默认总预算 60 秒：**

- 40 个 ID、详情、裁图、概览覆盖及字体路径完整；按既有缓存复用，不重新截图 40 个主题。
- mock 首次输入确有视觉概览；选择顺序/依据保存；已选详情进入下一响应，正常两调用，技术修复沿用原 history。
- visual Builder 默认拿最终主图且不重复；修改不误用旧图，代码页隔离，非 vision 配置明确失败；显式风格与 reuse 保持预期调用数。

详情给出首选搭配和必要回退条件，相关 `@font-face` 原生声明随详情加载。Director 仅将选用声明写入 CSS；宿主在技术检查前按 CSS 引用复制白名单中的字体及授权到 `pages/assets/fonts/library/`。不添加字体下载工具，不在请求中联网取字体，不按 Planner 页面文字裁字。主要字体使用独立 CSS 别名和随包资源，不用 `local()` 掩盖缺文件；用户字体继续按已有导入机制处理，复用主题连同授权自包含迁移。

Canvas 在加载实际字体后测量并绘制；检查实际渲染的中英字形，不把 CSS family 字符串、字体请求成功或 `document.fonts.ready` 当作无缺字证据。字体样张与模型生成作品分开验收：已做的 40 项固定中英样张只检查引用/覆盖，之前有限真实主题和单页尝试不替代本轮 §8 的 auto 应用验收。新规则不回写旧 run，代码页继续独立。

40 项并非互斥流派：排版、材质、插画、构图和交互方向有重叠。Director 将主题方向落实为共享基础，Bento/分屏只给构图倾向，具体页面的视觉表达与动效/叙事/3D 行为由 Builder 结合内容设计。静态图不能证明动画、视差或可操作 3D；固定舞台不能冒充原生长页滚动。完整长页滚动若被明确要求，需要另行改变底盘，不算本次已支持。

配色与风格可以协调，不是任意换色都保留原身份：黑白摄影要保留黑白关系，新拟态依赖同色底的光暗差，霓虹和金属有各自的对比/材质关系。冲突时说明取舍，不机械套一个色板。字体、布局、图表和控件仍需适配正文，不能把这些首页示例当作每页固定模板。

## 3. 输入与交付：一个文件入口，一份最终主题

新增两个可选输入：`--template <path>`接收单张参考图或主题/参考目录，`--style <要求>`明确指定风格或对成品主题的修改。题目/读者/场合仍是内容语境。保留独立风格输入的具体理由是：成品主题能否直接复用必须由显式输入决定，不能暗中新增模型调用或关键词分类器来猜“是否要求重写”。两个 CLI 共用导入逻辑与参数含义。

| 输入 | 行为 |
| --- | --- |
| 未提供文件 | 按题目语境与可选 `--style`选参照、看图生成 |
| 单张截图，或包含 `shots/` 的参考目录 | 看用户参考及可选 `--style`生成；不要求先写 CSS |
| 有 `theme.css`，未传 `--style` | 校验并复用，除本地资源 URL 重定位外不改样式 |
| 有 `theme.css`，传了非空 `--style` | Director 按明确修改要求读取原主题与参考，生成本次完整版本，不保存基础层＋补丁层 |

主题目录只要求有效的 `theme.css`；它引用的资源必须存在，`assets/`存图片/字体/logo，`shots/`可选。资源用途通过用户原要求和 CSS 表达，不增加资源 manifest。截图参考不是可执行主题；目录缺 CSS 又缺参考图则说明缺什么。PPTX 解析、任意母版精确复刻不在范围；旧 B/C 未实施，不为其草拟目录额外造兼容适配。

明确要求优先于包默认值，包优先于自动偏好。CLI 说明和运行摘要须写清：修改成品主题请用 `--style`，不能以题目内容不同就自动改主题。空白 `--style`报参数错误。互相冲突的明确要求需澄清，不按默认审美替用户选择。修改主题只在新 run 内进行，来源包和旧 run 不改；原样复用校验失败时报告错误，不擅自让模型重写用户主题。

交付仍为 `pages/assets/theme.css`。导入资源保留目录层级落在 `pages/assets/style/`，避免同名文件覆盖；CSS URL 按源 CSS 所在目录解析，再重定位为相对最终 CSS 的路径，保留必要 fragment。只复制本次输入中需要的资源与参考，不复制包内脚本并执行。路径解析后的越界与外部软链接拒绝；缺文件报具体路径。

用户图片默认是参考，只有被明确要求或选定作装饰才进入 CSS。用户指定 logo/字体/背景不能被随机搜索替换。Director 的新增装饰图复用 `core/tools.py::media_call()`与 `core/media.py`，owner 使用 Director 自己的命名空间；保留原图与已有来源记录，不另造素材 ID。整幅地图、扫描件等内容证据仍归 Planner/Builder，不因铺满画面而变成装饰。

本次保留显式关闭能力，不擅自废弃 `--no-style-director`。关闭时沿用 Planner 写主题；新的 `--template/--style`入口要求 Director 开启，冲突参数在调用模型前报错。旧路径不复制模板/取图逻辑，只复用适用的主题基础校验与统一规则。

## 4. 职责与主题接口：方向约束创作，不替页面做设计

Director 定主题方向，并把其中可共享的视觉选择落实成 CSS 与用法；Builder 决定每页如何表达内容。**共享的是设计语言，不是页面几何；类名可以不用，同一角色的视觉依据不能随页换一套。** 不覆盖共享资产、不重置整套主题、不改底盘机制。

| 整套共用的依据，由 Director 提供 | 内容驱动的变化，由 Builder 决定 |
| --- | --- |
| 标题/正文/数字的字体角色、双语主次和层级关系 | 题名长度、换行、位置、列数、图文比例；选用适合本页职责的标题角色 |
| 线条、形体、边界与材质的处理方式，强调色用途 | 用柱、曲线、照片或实物表达哪个关系；数据、坐标、拓扑、交互与必要状态区分 |
| 背景变体的共同特征、用途与阅读净空 | 选默认或适用变体，安排主对象避让；不必每页都有相同装饰 |

这不是三组新 schema 字段。Director 在已有“方向”和 class/token/variant 说明中写清本套实际选择即可。组合多个风格时，先协调成一套可贯穿全篇的表达，例如瑞士排版为主、几何形体为辅；不要把一种参考分给封面、另一种分给交互。不强制主辅比例，不要求每套都有阴影、几何或变体，不将这次 Swiss 的克制推广成全部 40 种风格的规范。用户明确要求章节对比或多风格时，以该要求为准。

reference 保留从题材推导本页视觉主体与表达的要求；将可能被理解为“另起一套视觉语言”的措辞改清楚，不把主题缩减为颜色/字体，也不把数据规则扩大到所有外观。数据渐变必须对应连续量、类别与状态须有真实含义；主题装饰渐变、纸纹、霓虹、手绘笔触可以纯粹表达风格，不需要伪装科学含义。Check 不因具名便签/玻璃等具有分组作用就要求清除，也不因 `.nt-*` 前缀就批准卡片墙；判断其是否服务本页构图与阅读。统计容器数量/填充率不能自动导出删除指令。

在原来源直接修订 `prompts/style-theme.md`、`prompts/tech.md`、适用的 workflow references、visual scrub 与 `core/tools.py` 的 Check 提示；检查三个视觉 workflow 的实际拼装输入，避免原文正确而路由后的提示仍矛盾。不增加一个新的“总优先级提示”覆盖未删除的旧规则。样例已有“迁移构图/机制、替换题材/配色/底盘”的说明，样例带原字体或颜色本身不是冲突，不因此重做样例库或改变 Main/aux 路由。

使用说明仍放在 `INTERFACE` 注释里，供 `_theme_interface()`读取。说明实际公开 token 的用途、具名样式、变体及必要净空；明确普通页题名、区块标题、封面强调的默认字号/字重/行高与中英主次，写出实际依赖的少量排版值并与 CSS 保持一致，不抄全量 token 或实现。没有新增解析字段、独立风格文档或每页自述。

示意接口：

```css
/* ==== INTERFACE ====
方向：摄影纪录；正文开放排版，标题避开右侧照片主体。
token --accent：品牌强调，不代表正确性或数据类别。
class .nt-title：正文页题名，主标题为中文；内部 .nt-title-en 放辅助英文。封面可强化尺度，但保留这套双语主次。
class .nt-controls：需要操作时使用的局部控件面，不用于包住所有内容。
variant opening：照片开篇；配套浅字，标题放在左侧。
默认：不设置 data-variant，使用无图正文外观。
品牌：右上角 logo；按实际尺寸在内容中留出净空。
==== /INTERFACE ==== */
```

主题样式显式挂在 `.nt-*`及其子元素/状态上，不全局重写每个 div、button 或第三方组件。必要的类名、宿主关系属于公开用法；复杂样式给一个最小 HTML/SVG 使用例子即可，不要求列出所有实现选择器。公开名称必须存在，不能把“漏列私有类”的提示重新升级成硬闸。按钮、节点、线条及 hover/focus/aria-pressed 等通用状态外观保留；不预设训练集/验证集、已读词等领域语义、数据结构、隐藏 DOM 协议或“唯一允许的操作台”。

图表样式须明确区分线、点、文字；曲线的 `fill:none`、粗 `stroke` 等规则不得无差别命中文字。通用样式以 currentColor 或公开局部变量承接系列颜色，Builder 决定数据意义、对象关系和状态切换；CSS 已设 stroke 时不误以为 SVG presentation attribute 能覆盖它。不规定全项目统一图表类名，不引入 adapter，不让主题负责坐标、数据或拓扑。

若主题定义了需要 HTML/SVG 与 ECharts/Canvas 共用的线宽、点样式或标签层级，这些就是公开用法，不能只藏在 SVG 私有选择器里。相关值用本套实际需要的少量 CSS 变量共享；JS 消费项说明单位和用途，直接数值可读取，复杂 CSS 值通过适用元素的 computed style 解析，不用 `parseFloat()` 冒充表达式求值。形状/虚实等选择用已有类说明表达，不建立跨库枚举或 adapter。Builder 在现有库配置中承接这些值与关系，而不是沿用库的默认皮肤；也不必换库。

这不要求每个主题发布同一套图表 token，更不要求无图表需求也造控件系统。同类图形沿用线条气质与主次关系，数据可区分性优先；不额外建立逐线像素对齐或渲染器补偿流程。局部图形几何仍由 Builder 负责，不把它与底盘二次缩放混为一谈。

根与公开接口不发布裸 `--surface/--panel/--card`等任意容器垫底槽位。局部 `.nt-controls { --surface: …; background: var(--surface); }`合法；改名但继续承诺“任何区块底色”仍违背边界。声明作用域可检查，语义是否过泛需读说明与看实际页面；不声称正则或 CSS 解析器理解全部用途。`.nt-card`有前缀也不自动证明卡片墙合理。

Builder 默认仍只接收接口，不全量注入 CSS，不复制主题私有实现。`CHASSIS.md` 等位置的“只读 INTERFACE”改为“默认预置公开用法，必要时可按需读取 theme.css 实现，不能修改共享主题”。不强制新增一次 Read 或测量回合，也不把必要查阅自动算成失败。视觉参考沿用现有图片消息通道：用户/主题包的代表样张复制进 run 并随视觉页输入提供；不要求每包必有样张，也不为每套自动生成演示页面。代码页不接收。

### 字体与固定画布

- 字体角色以主题实际实现为准，公开标题/正文/数字的必要使用方式。数字字体不等于完整标签字体：含中文的图注、图例、数值说明必须有对应中文承接字体；纯数字不强制额外加载 CJK。混排规则放在共享创作约定和实际输入来源，不给 40 张卡各复制一套新规则。
- 明确用户字体优先；指定新风格时，按该风格的首选搭配或有说明的替代落实被改变的角色，旧主题相应默认值不能压过新要求。只改配色则保留未要求改动的字体，不把 modify 一律解释为全套重设计。资源不可用或缺字须记录实际回退，不用字体分类器或审美阈值触发重试。
- Builder 使用主题字号 token **或具名排版类**均合法，允许主题类内部的 `em`、`calc()`、`clamp()` 等原生实现；不强迫每个文字元素的最终像素值等于某个根 token。布局仍须保证必要内容、真实字形和可读性，不以任意缩小文字消除溢出。
- 同套同角色保持同一默认排版。新创主题沿用 h1 为普通页题名、h2 为区块标题的惯例，封面强调明确说明；不按 token 名称重解释导入主题，不因名称不同将旧主题判为无效。Builder 优先安排标题区域、换行与图文关系，为实际标题高度留空间，不每页重新选字阶或随意缩标题。允许封面反差与单语页，不恢复 offScale 或硬像素门禁。上面示例的中文主标题不是全项目语言政策。
- 舞台内尺寸按固定逻辑画布设计，整体适配只由底盘缩放。字号及影响排版的尺寸不再随外部视口单位/断点二次缩放；可用逻辑 px 或以稳定逻辑尺寸为基准的相对单位。不是禁用 CSS 函数，也不新增响应式排版引擎。1600×900 与 800×450 对照应保持逻辑字号、换行和几何关系，显示尺寸按底盘比例变化。
- Canvas 使用实际元素解析后的字体尺寸与字体栈，再加载、测量、绘制；`Deck.token()` 返回原始字符串，不声称把 `clamp(...)` 拼入 `ctx.font` 就完成了解析。不新增每主题字体 adapter。

必须同步修正 `REF_SHOTS_NOTE`：用户参考可以要求沿用颜色与材质，不能再统一说“不抄配色”。画廊候选只是启发，不等于最终主题；现有 `--ref-shots`候选图实验不自动升成默认，更不能覆盖用户样张或主题接口。修改过的主题以新接口和明确修改要求为准，原样张不冒充修改后的效果。仅有封面图时明确正文是推导；无视觉能力的模型不能声称看过参考，需报告限制或更换适用模型。

## 5. 背景与品牌：只用浏览器已有机制

一个 `html[data-variant]`同时改变背景与前景；未设置属性就是默认外观。名称属于主题并在接口说明，不增加系统级 `reading`别名或背景关闭开关。Builder 在图表初始化前选择变体，不做运行时换肤。

变体是同一套设计的用途变化，不是按封面/正文/交互各造一套皮肤；只生成确有用途的变体，不要求 opening/compare/lab 三件套。默认可以安静、开篇可以强化、深浅底可以切换，但字体角色、形体处理与层级关系应能对应。

**背景图层改变时，一起检查 size、position、repeat 等受影响的配套属性。** 整幅形体通常用整幅尺寸与不重复；网格/纹理需要平铺时明确对应尺寸和重复。多图层列表长度不同时浏览器会循环匹配，不能误用基础网格的尺寸去画整幅圆弧。需要重置时在该主题变体里明确声明；共用值适合放基础规则则继续共用，不要求机械重复每条 CSS，不在底盘添加全局 no-repeat 或自动修补器。默认与变体都按真实渲染描述，不能用“近白底”掩盖满屏装饰。

背景在实际缩放的 `#stage`上，以多重 `background-image`合成图片与蒙版。以下只是机制示例，不是完整主题：

```css
:root {
  --bg: #f3f0e8;
  --text: #202722;
  --muted: #505b53;
  --font-sans: sans-serif;
  --backdrop: none;
}
html[data-variant="opening"] {
  --bg: #14221a;
  --text: #ffffff;
  --muted: #e1e9e3;
  --backdrop:
    linear-gradient(90deg, rgba(16,27,19,.82), rgba(16,27,19,.12)),
    url("style/assets/forest.jpg");
}
#stage {
  background-color: var(--bg);
  background-image: var(--backdrop);
  background-size: cover;
  background-position: 72% 45%;
  background-repeat: no-repeat;
}
```

根属性与现有 `Deck.token()`读取位置一致；SVG 用 CSS，Canvas/图表明确读取主题 token。局部反色区域需读取对应局部值，不假设根 token 自动反映局部样式；不新增通用图表 adapter。

图片主题须有可读的无图状态；需要保留深底浅字时可另提供无图深色变体，不机械退回浅底。图片加载失败仍有相容底色。Builder 不得用 stage 的 background 简写无意清空主题合成；全幅证据可以覆盖装饰，不替换共享 CSS。

局部净空或确有构图用途的遮罩仍允许。若必须用全屏白层抹掉大部分主题才可读，优先选择已提供的安静状态或调整内容布局，并记录主题缺陷；不将这种盖白处理作为成功承接主题的证据。没有可读状态时如实未通过，不给 Builder 临时改共享主题的权限，也不增加 Builder→Director 回修回合。

为独立品牌层保留 `#stage::after`，主题定义 logo 外观，底盘约定层级与 `pointer-events:none`，跟随舞台缩放。内容须留净空且不得盖住品牌层；其他元素的伪元素仍自由使用，无 logo 时不生成可见品牌。实际有正文含义的标识用可访问的内容元素，不靠伪元素传达。

不添加第二套压暗 CSS、不预先烘焙蒙版、不做自动透明度求解。照片主体裁切、文字与 logo 可读性由实际截图检查；修复可改裁切、移动文字、调整蒙版或选变体。

代码页沿用[独立风格契约](runs/ens-code-stylefix-0907/VALIDATION.md)。首轮已解除代码外壳的共享主题链接，由宿主保有必要底色/文字/字体值，防止品牌层泄漏；本轮只回归这一隔离，不再把它列为待实施升级。保持原外观与执行，不改 Monaco、iframe 内样式或工作台布局；不承诺代码页继承讲义 logo/背景。

## 6. 校验只检查可证明的事

生成、修改和直接导入共用同一主题检查，显式关闭 Director 的旧路径也使用适用的基础检查。不要将现有正则扩成另一种 CSS 语言。

| 层次 | 检查与处置 |
| --- | --- |

### 消费者整改：删错误推断，保留实际测量

1. **主题生效**：删除 `--pad-x` 存在性及非零 padding 的主题有效性判据，不给新主题补假 token。用已经约定的必需 token、样式资源加载和适用元素的 computed style 报告具体事实；缺 token 不等于已证明语法损坏，不让无权改主题的 Builder 反复修共享资产。生成前的主题校验与页面阶段的加载检查分别负责自己的范围。
2. **字阶**：删除 `parseFloat(--fs-*)` 与离散字号集合比较的 `offScale` 判据、工具说明及报告压缩中的相关分支；不另造 CSS 表达式求值器来维持这条检查。保留实际字号分布、裁切、溢出、文字重叠和交互状态检查。测试不能继续用手工构造的 `padX/scale/offScale` 正例证明新主题兼容。
3. **颜色**：保持 `Deck.token/rgb/rgba` 接口，颜色解析与转换交给浏览器原生能力；需要数字 RGB 时得到明确的 sRGB 值，不能用正则拆 `oklch()` 或 `color(display-p3 ...)`。同时检查 selfcheck 的亮度/对比度计算，不能继续假定 computed color 总为旧式 `rgb()`。透明叠色与复杂背景无法准确测量时明确未覆盖，不输出伪精确结论；覆盖旧 hex/rgb、现代颜色、透明和连续调用，避免探针残留状态。
4. **审美提示**：修改 Check 的强制删面/边框/阴影措辞和半空容器的自动整改结论；保留测量与内容关系判断，不增设颜色、材质、卡片数或字体家族闸。数据真实性、缺资源、JS 错误、不可操作和底盘损坏仍须检查。

这些修复放回现有 chassis、selfcheck 和 tools，不新增诊断服务、通用主题解释器或第二套 Check。只影响新生成/明确重建的 run；旧 run 是失败证据，不批量替换其 theme.css、底盘或 HTML。

本轮 1/2/3 追加：Check 保留前进、回退、末态检查和截图，但删除 PNG 字节完全相等判据及“只向前追加”的推断；有无截图都执行相同分步序列，真实运行错误仍报告。删除最低步数限制；`onStep` 第二参数明确为最大下标，0/1/2 三个状态传 2。主题选择器用已有 CSS token 的顶层逗号拆分，保留原作用域、公共 SURFACE 与底盘边界；删除无法理解否定句的中文语义关键词闸。不改 Builder 停止条件、CLI 退出或选样流程。

7. 逐页记录自然终止/失败、响应数、Read/Check/Look/Patch、请求等待与工具耗时、token/可得费用，不承诺固定时限或强行封顶。所有原始失败保留，必要重跑另建 run；不能换模型、补页或手改后报模型通过。完整交付也不证明空交付概率为零或全部 40 种风格均可靠。

## 9. 保留的不确定性与禁止扩张

### 对方案的反向审查

| 质疑 | 收敛后的处理 |
