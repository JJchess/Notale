## 1. 结论：哪里改错了

内核不用推倒：原生 CSS、一个 `html[data-variant]` 联动前景背景、`#stage` 多重背景，仍然成立。真正需要纠正的是：**共享主题承担了越来越多页面组件职责，而 Builder 得到的关键排版约定反而变得含糊；旧 harness 的错误判据又把部分页面拖入反复修改。**

三个问题不是同一条因果链：

| 用户看到的问题 | 已证实的原因或缺陷 | 不能据此声称 |
| --- | --- | --- |
| 13、22 空交付 | Read 后第二次响应变成问候语，没有 Write；Builder 按无工具调用结束。缺产物已记录，但 CLI 仍退出 0 | 已定位模型为何忽略任务；是主题门禁拒绝；加一句“必须交付”就能治好 |
| 34 分 34 秒才结束 | 旧新实验模型、页数等不一致；新实验请求耗时明显更高。06 误解分步参数，15 遇到回退截图误报，均反复改查 | 全部是 Director 拖慢；旧版没有长尾；删一条闸就一定恢复 6 分钟 |
| 标题忽大忽小、局部排版及系列颜色错误 | 页标题/区块标题角色约定被放松；复杂主题引入私有 SVG 系列状态，消费端不知道且被 CSS 覆盖 | 所有字号都应一样；所有布局及数学错误都由共享 CSS 导致 |

前两次整改的失误，是把“补齐接口”主要写成“说明更多东西”，没有先压缩主题的职责；把“允许内容适配”写成多处宽泛豁免，没有保住同一角色的默认约定。153 项离线测试验证了手写夹具能正确使用能力，**没有证明真实 Director 输出能让独立 Builder 自然一致**。不能用这些绿灯替代整套效果验收。

没有写文件、没有进入页面 Check，也没有主题技术校验拒绝。这是“未开始制作就结束”，不是生成了空白 HTML。

旧版单页已有 47 次响应，只因多数请求更快，墙钟没有暴露到这次程度。新 CSS 体积变大也是复杂度线索，不是延迟因果证明；Builder 默认只预置 INTERFACE，不是把 558 行全部直接灌给每页。

**15 页的 Check 缺陷已按生产路径复现：**同一产物、实际 `selfcheck.run`、默认等待、真实 800×450 缩图，三次都只有 4 个像素不同，却报“onStep 没完整重绘，只是向前追加”。此前 1600×900 诊断显示 DOM/文字相同，仅一个像素不同，文件哈希与本次一致。关闭截图输出后，同页不再报告这项问题。截图字节差既不能证明这种代码错误，也不应因是否保存截图改变正确性结论。

### 2.3 排版：旧约定被稀释，新接口没有接住

旧 `style-theme.md` 明确：`--fs-h1` 页标题，`--fs-h2` 区块标题，提供值和使用位置。新版只要求提供 h1/h2 等字阶，并允许封面/正文角色变化、必要时局部调尺度，且明确不复制 CSS 值到接口。

新主题实际把 `.nt-title` 设为 `--fs-h2 = 54px`，另有未公开的 hero 组合使用 `--fs-h1 = 76px`。接口没有解释这两个 token 的角色差异。于是同为正文页，14/36 自行采用 h1 的 76px，32 采用 h2 的 54px，33 又写死 42px。这里不是某个尺寸天生错误，而是**类与 token 含义不一致、每个 Builder 都在重新判断哪个才是页标题**。长句标题再叠加绝对定位，出现换行后压住导语、图形或控件。

主题同时生成 `nt-pixel-grid/data-level`、`nt-sequence/data-seen`、图表 `data-series="validation"` 等内容组件约定。14/32 给 SVG 写了不同 `stroke` 属性，却被 `.nt-data-line` 的固定 CSS 描边覆盖，两条线同色；接口未说明的 validation 属性才是主题预设的分色入口。这是可以删除的耦合，不值得再补一套更长组件说明。

页 07 的 XOR 条件、21 的公式漏 floor、33 的 tanh 值越界等另有内容实现错误；19 的键盘翻页冲突、44 的点击遮挡也不能用调主题一并解释。保留这些失败记录，不为了论证 CSS 整改而隐藏它们。

## 3. 建议批准的最小整改

### A. 主题缩回共享视觉基础，不生成内容组件协议

保留 Director 的风格选择、中英字体、颜色用途、背景合成和变体、局部材质 CSS。它可以表达玻璃、粗边框、纸纹、包豪斯等，不退回“只能换颜色”。

删除要求 Director 为图表、序列、离散数据预建 DOM/SVG 组件及状态入口的暗示；不再由主题定义 `validation`、`data-level`、`data-seen` 等内容语义。这里是收窄创作职责，不是新增按类名封禁的正则。

Builder 自己定义数据系列、图形元素和交互状态，使用主题颜色、字体和确有需要的少量笔触变量。主题可提供视觉用途明确的局部类，但不拥有数据映射、坐标、组件结构或“唯一允许的操作台”。图表层直接在页面自己的 CSS/库配置中设置系列样式，不同时接受主题私有状态和 SVG presentation attribute 两套控制。

同时删除“为跨 SVG/Canvas/ECharts 的所有同类细节证明最终比例一致”的泛化要求。保留同一套线条气质、主次关系和字体，不要求额外建立渲染器适配、像素补偿或逐线测量流程。数据可区分性优先于装饰一致性。

### B. 恢复稳定的排版角色，停止让每页重新选择字阶

沿用已有命名，不发明 typography schema：`--fs-h1` 表示普通内容/交互页题名，`--fs-h2` 表示区块标题，body/lead/label/tick 按已有用途。若提供 `.nt-title`，它必须与页题名 token 表达同一角色；不能一边叫 h1 一边默认读 h2。

每套主题确定自己的字体、字号、字重、行高和双语主次，不恢复全项目固定 34px。封面可有明确的一种强调用法；用户要求章节对比时尊重要求。不要求每页双语，也不把封面差异扩大为所有正文页自由改标题大小。

**撤回“不在接口写任何 CSS 值”的一刀切。** 在同一个 INTERFACE 中，写出 Builder 实际依赖的少量排版角色及值、必要类和变体用法；不列全量 token，更不复制实现。少量值与角色同处一份 CSS 文件，维护成本比每页猜测或读取整个实现低。它仍是自然语言注释，不新增解析字段或编译器。

例如下述仅示意普通页标题的一条说明，不规定所有风格都用这个数值：

```css
/* ==== INTERFACE ====
token --fs-h1：48px，普通内容/交互页题名；.nt-title 使用同一值。
token --fs-h2：28px，页内区块标题，不用来替换页题名。
class .nt-title：本套题名字体与行高；可换行，不规定位置、宽度或列数。
==== /INTERFACE ==== */
```

Builder 的正文页标题沿用该角色；优先安排标题区域、换行及图文关系，不再从多个字阶任取或任意缩标题“消除溢出”。题名过长时保留短论点，将完整限定或解释放入导语，而非丢内容。标题与导语通常采用正常流；必须绝对定位时，按实际换行后的高度留空间，不能拿单行假设给下面内容写死 top。

这是输入契约修复，不新增字号白名单、标题字符上限、自动缩字或固定页面模板。旧有效主题仍可零模型调用复用，不因为没有新版推荐说明就自动判无效或擅自重写。

### C. 删除错误门禁，保留真实边界

| 删除/纠正 | 保留 |
| --- | --- |
| PNG 字节相等的回退门禁及其“只会向前追加”的武断诊断，不另换感知阈值或 AI 裁判 | 分步前进、回退、末态截图；真实 JS/资源错误。具体状态正确性用针对页面的输入输出断言验证 |
| “用了分步就至少 2 步”的门禁和提示 | 静态页、只推进一次及多步均合法；声明了中间步却既无元素也无回调的空步错误仍可报 |
| 用接口中文关键词判断任意容器许可的硬闸；“页面底色，不用于任意区块底色”反而会命中禁词 | 公共作用域裸 `--surface/--panel/--card` 等命名槽限制；具名局部私有实现允许。别名语义由创作约定约束，不声称关键词能理解否定句 |
| 用 `selector.split(',')` 推断每个选择器归属的通用硬闸；`.nt-button:is(:hover, :focus-visible)` 被错误拆开后拒绝 | 在创作提示中保留具名局部作用域；底盘定位/缩放、hidden、品牌指针等实际行为边界仍检查。SURFACE 的作用域识别只处理 CSS token 顶层逗号，不做完整选择器分析器 |

后两处本轮离线反例已复现，但**这次 Director 首稿通过，不能把它们算作本次长尾的原因**。删它们是减少已证实的未来误拒绝，不是虚报提速收益。

修正 `Deck.onStep(fn, n)` 文档：第二参数是**最大 step 下标**；状态 0/1/2 应传 2，不是 3。API 和调度实现不改，只修参数说明、例子和相应测试。

主题必需值、实际资源存在/解码、导入路径边界、底盘机制仍保留校验。一次最终产物审计不是冗余门禁：它确认交付事实，不能因为 Builder 自称检查过就删除。主体占比、区块数量、字号统计等观察项不得成为“全部清零才结束”的义务。

### D. 交付以产物为准，不新增完成工具或补催回合

保留现有 Write → Check → 必要修改 → 正常结束。无工具响应仍结束这次生成，**但不等于交付成功**：使用现有 `artifact_present`、`audit.fatal_errors` 等结果，缺页或致命失败必须令 CLI 非零退出；主实验入口不得把进程自然结束写成整套成功。保留终止原因与失败页，不新增并列状态 schema。

不加 Finish 工具、不要求最后再读一次自己的文件、不强制模型提交完成宣言。宿主已经能检查目标产物，重复让模型证明没有收益。也不预加问候检测后的补催、重启、切模型、自动补页；这些都会污染原始失败率而不能解释空交付。

空交付根因单独定位：实施时给一次单页探针临时启用请求证据捕获，保存首轮和 Read 后实际发送的任务/工具结果/匹配 ID，以及原生响应的普通内容块和 `stop_reason`。在现有请求边界做 opt-in 记录，不做日志平台；凭据剔除，图片记哈希，不落隐含推理文本，签名/不透明块只记类型及哈希。未再现就明确写未再现，不能把一次成功当根因修复。

根据实际交换，只修证据指向的本地拼装或适配错误；若任务在原始交换中完整，不能继续凭问候语推断“任务丢了”。模型服务行为待定位，不用重写所有协议来赌。

### E. 提示词减法：每项规则只有一个消费侧来源

这次不在五个文件后面再各补一段“注意”。直接替换冲突原文：

- `style-theme.md`：保留创作职责、稳定角色、短接口；删内容组件/跨渲染器协议暗示。`direction.md` 仅保留风格判断，不重复技术契约。
- `tech.md`：作为 Builder 的主题消费和页面布局边界唯一来源。删“必要时按比例调整”这类没有角色边界的豁免，改成 B 的明确分工。
- `CHASSIS.md`：保留实际运行 API、缩放、字体解析和参数含义；删重复的风格宣言、图表审美要求。
- 三类视觉 workflow 的 SKILL/reference：保留内容证据、构图、交互真实性指导；删除重新选择整套材质/字阶的歧义和重复消费规则。删“首轮必须写一句选择理由”的形式要求，不新增构图报告。
- `core/skills.py` 的运行时改写同步调整，否则改了 SKILL 仍会被宿主重新注入。保留现有 Main/aux 路由和需要的并行 Read，不把早已存在的读样流程未经对照就当成空交付原因。
- ban list 仍在看图写主题前加载，用户明确风格要求优先；不把审美阈值移到另一个工具继续重试。

代码页继续独立，不借本轮重做皮肤、字体或执行协议。这里的 SKILL 指项目给 Builder 的工作流文件，不是新增 Codex 技能。

## 4. 保留与不做

保留：默认打开 Director；Planner 与 Director 并行；40 项轻索引→按需读详情、参考图、中英字体；用户给图/已有主题/修改入口；连续修订上下文；本地资源、背景、品牌；字体承接、现代颜色解析、固定逻辑画布；背景各变体 size/position/repeat 配套。

## 5. 实施顺序与验收：少做实验，不降低验收范围

1. **先减协议和错判。** 改 `selfcheck.py`、分步文档、主题误拒绝、CLI 退出语义；补相应离线反例。空交付探针只定位，不补催。此阶段不碰模型默认配置、并发、样例路由或生成页。
2. **再替换主题/消费提示原文。** 落实 A/B/E；检查最终 `instruction_blocks()`，覆盖封面/内容/交互三种真实输入，而不是只搜源文件中有没有一句话。旧主题原样复用、显式关闭、代码隔离仍走既有离线回归。
3. **先过确定性回归，再进行一次完整 auto 验收。** 不恢复 reference/modify 全量矩阵，不用三页代替整套，不以 30 页盲评排名决定修复成败。付费验证待方案获批后执行，本轮不运行。

最低离线验收集直接来自本次反例：

- 无 Write 的结束必须报告缺页并非零退出；真实产物正常结束仍成功。带致命错误的产物不得因文件存在被当成功。
- Read 后序列化保留任务与工具结果，ID 一一对应；缺结果或 ID 错配的负例能被测试识别。当前正常重建结果不能充当历史根因证明。
- 回退微小像素差不再报虚构代码原因；开/关截图的错误语义一致。三状态传 maxStep=2，单次推进合法，确实越界仍暴露 JS 错误。
- 原生函数选择器、接口否定句不过度拒绝；公共 SURFACE 仍拒绝、局部实现仍允许。没有新增色相、字号或排版审美阈值。
- 用本次标题/SVG 失败形状构造最小夹具：页标题类与 token 同角色、长题名不压住导语/可点区域、两个数据系列不被共享样式改成同色；中英主字体真实命中，1600→800 缩放关系不变，变体背景不误平铺。

随后原样运行原神经网络 120 分钟 query，Planner 自主决定页数，全部进入 Builder。冻结并公布代码/主题哈希及完整配置，不通过删页、缩短 query、手改、提前停慢页或换模型补跑来过关。生成期间观察不回灌；独立浏览器全量验收放在生成结束后，减少同机资源干扰。

全量验收必须分别报告：规划/交付/失败页、标题及图表实际一致性、逐页布局和交互问题、总墙钟与 Planner/Director/Builder 分段、每页响应数和请求耗时。42/44 不是成功；没有资源报错也不是排版通过；仍存在遮挡或内容错误就保留失败，不用“风格基本一致”替代。

**性能约束：**继续把用户期望的约 6 分钟作为要核对的目标，但当前新旧记录不是同条件对照，不能承诺提示词整改必然达成。若要量化升级的时间影响，另做固定页表、同模型/路由/notes/并发/资源的一组窄 A/B；未经这样的证据，不报提升百分比。不能把 Gemini 的 6.7 分钟与 Sonnet 的 31.5 分钟当作纯风格回归，也不能为了达标静默更换生产模型。

## 6. 请 critic 裁决的核心取舍

建议接受的是一组减法：**恢复少量稳定的排版语义，删除主题对内容组件的控制，删错误判据，修交付结果的诚实性。** 不建议接受的是“再加更多接口说明、更多审美校验、更多自动重试”。

在故障归因上，空交付上游起因和同条件性能差异仍未确定；两者在本稿中明确保留为验证任务，不伪装成已找到并修好的问题。本稿尚未实施，标题一致性等真实生成效果也须经过上述验收，不能由方案本身证明。评论这份方案时，重点检查：删减后是否仍涵盖用户的全部 40 种风格、是否保住同角色一致性、是否把未知问题又偷渡成了新机制。
