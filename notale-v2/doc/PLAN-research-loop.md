# notale-v2 长期自主优化计划（研究循环版）

2026-09-05 · 只读调研 + 4 套新题实跑，未改任何代码 · 供审核

---

## 0. 一句话结论

这套系统的**工程可靠性已经够了**（5 套 102 页 102/102 交付、0 JS 报错、0 越界），
但**教学与设计层面的失败是系统性的、跨学科同形的**，而且现有的全部仪器（selfcheck）都测不到它们：
五套完全不同学科的讲义，79 个非封面页 **79/79** 长成同一个版式指纹「标题条 + 一个装着 7–20 个小块的容器」，65 个内容页 64 个带控件，
文科页退化成引文卡片墙并给文学判断编分数，理科页把同一张曲线重复画 10 次，
交互页里每个滑块都真地改变了状态，但几乎没有一页的交互是从知识结构长出来的。

过去三周 210 次提交的绝大部分改的是 harness 可靠性、token 成本和提示词字数，
评价的数是占用比 / 步数 / 缓存命中率，**从未有一项实验以"教学价值"或"跨学科泛化"为判据**，
而且全部 36 轮带规划的实验里 31 轮跑的是同一个学科（机器学习）。
所以第一优先级不是再改 prompt，而是**先造出能看见这些失败的仪器和基准**，否则任何改动都是盲改。

## 0′. 目标（2026-09-05 用户简化版，覆盖下文 §4.3 的五判项）

用户把目标收成三条，代码页不优化：

| # | 目标 | 量法（每个数都是"和参照比"，参照见 `refs/quality/`） |
|---|---|---|
| G1 | **风格自适应**：不同题目要长得不一样（现在配色一族、版式一个指纹） | (a) 跨 deck 版式指纹重合率（现 79/79）；(b) theme.css 底色/强调色/字体族的跨 deck 距离；(c) 盲评"把 5 套各抽 3 页混起来按学科归类"的准确率。目标：指纹不重合、归类准确率 ≥ 80% |
| G2 | **设计与交互质量对齐 Pudding，页面模板对齐高级 PPT 模板** | 成对盲评：生成页 vs 参照页（金样本 / Pudding / Codrops），问"哪一页更像专业作品"。内容页配 Pudding 段落与金样本，交互页配 Codrops 交互 demo 与金样本交互页。分数 = 胜率；现在预计接近 0 |
| G3 | **去 AI 味**（文案语域 + 视觉套路） | 盲评"这页是人做的还是 AI 做的"，生成页与参照页混合投喂；分数 = 被认成 AI 的比例。再跑一次只给可见文案的版本，把文案与视觉分开 |

参照体系：`refs/quality/`（README 写了采集口径）——A 金样本 22 份、B Pudding 2023 起 52 篇活页截图 + 46 个仓库（含预构建 docs/）、C Codrops 2020 起 demo 98 个仓库 + 2025–26 教程 demo 78 个。画廊 `http://127.0.0.1:4190/refs/quality/index.html`。
judge 用非 gemini-3.8-flash 的看图模型（GPT-5.6-Sol 或 Sonnet 5）；builder 自述不进统计；每周人工抽检 judge 与人的一致率。

### 0′.1 基线（2026-09-05 晚，judge = GPT-5.6-Sol/low，100 张生成页 = 5 套 deck 去掉代码页）

| 目标 | 基线数 | 读法 |
|---|---|---|
| G1 风格自适应 | 压糊缩略图配对：同 deck 判"同" 26/27，**跨 deck 判"异" 5/33**。theme.css 五套里四套底色色相 190–204°、明度 93–96；语义色五套全是红 7–11° / 蓝 189–209° / 绿 126–151° 三件套 | 85% 的跨学科页对被认成同一套视觉身份。目标：跨 deck 判异 ≥ 80% |
| G2 对齐金样本 | 成对盲评（只比工艺、不比信息量）生成页 vs 金样本：**41/100**；封面 13/21、内容页 **18/65**、交互页 10/14；分 deck：ML 13/25、史记 5/15、化学 7/17、热岛 10/19、经济 6/24 | 内容页是主战场。输的理由高度一致："卡片切割过多、字号偏小、没有视觉主体、像后台界面"。目标：内容页 ≥ 50% |
| G3 去 AI 味 | 单页判别：生成页被判 AI **64/100**（内容页 49/65、交互页 12/14、封面 3/21）；参照页误判 1/71 | judge 校准良好（假阳性 1.4%）。目标：≤ 20%，且封面以外的页型都要降 |

judge 的两条方法教训（都已修正）：
- **跨用途的成对比较无效。** 第一版拿 Pudding 滚动段落和 Codrops demo 当对照，生成页"胜" 83/100，理由全是"信息更完整、结构更系统"——judge 把信息量当成了工艺。改成只比工艺后，vs 金样本 41/100。Pudding/Codrops 留作 G1/G3 的参照与人的灵感库，G2 只跟同用途的金样本比。
- **AI 判别的提示要排除图像伪影线索。** 第一版 judge 拿"文字不畸变"当"人做的"证据；改成按设计习惯判（模板化卡片、默认主题感、AI 腔文案、有没有视觉主体）后才有区分度。

人工校准页：`refs/quality/calibrate-ai.html`（12 张生成页，judge 判 AI/人各 6，请你盲判后展开对照）。
原始记录：scratchpad `judge-ai.jsonl` / `judge-pair.jsonl`（跨用途，作废）/ `judge-pair-sample.jsonl` / `judge-style.jsonl`；脚本 `judge.py`。

## 1. 当前系统实际上怎么工作（以代码为准）

用户设想的链条是「内容理解 → 规划 → 结构设计 → 交互选择 → 视觉 → 代码 → 浏览器 → 评价/修订」。
实际代码里的链条是这样的：

```
planner (1 次模型调用, GPT-5.6-Sol/medium)
  输入: query + audience + minutes + scenario + deck.md 模板 + direction.md + scrub-theme-slop.md
  输出: 同一响应两次 Write → theme.css (含 INTERFACE 注释块) + pages.md (每页一个 [标签] + 一句主题)
  harness 校验(标签集/连续页号/#stage flex/INTERFACE 定界) → 最多重试 3 次
  ↓ 确定性: 按 # page-NN 切 pNN.md · 图池表→取图/生图/抠图→IMG.md · 填 brief 模板→briefs.json
builder (每页一个独立自由循环, ThreadPool 并发, gemini-3.8-flash/low)
  system = IDENTITY + philosophy(page) + 两份反套路清单 + CHASSIS.md + theme INTERFACE + 标题页大纲 + tech.md + 路由到的 SKILL.md
  user   = environment_context + brief + <chapter_context>(本章各页的一句话主题)
  典型轨迹: Read(reference) Read(Main sample) Write Check Patch Check  → 无工具调用即停 (中位 6–8 次)
  工具: Read/Write/Patch/Check(=selfcheck 渲染+截图+--after)/Look/Bash ; 代码页 CodeScaffold/Edit
  ↓
audit_delivery: 停止后跑一次无截图 Check(+代码页浏览器自检) → 只记录, 不回喂
输出: page-NN.html · trace.jsonl · builder-results.json · builder-manifest.json
```

对照用户设想，缺的环节是：

| 设想的环节 | 实际情况 |
|---|---|
| 内容理解 | 没有独立步骤。planner 一次调用里顺手完成；产物只有"一句主题"，没有知识结构、前置、误解、证据 |
| 页面/体验结构设计 | 没有。页与页之间的关系只靠标题页分章 + 邻页一句话；无节奏、无时长、无"这页先立什么" |
| interaction 选择 | 只剩标签（内容/交互/代码），且标签→workflow 一对一映射；交互形式完全由 builder 在读一份 sample 后临场决定 |
| 视觉/构图 | theme.css 管 token 与组件；构图靠 reference 里的散文规则（"one dominant evidence field"）+ 一份 Main sample |
| 评价 / 修订 | 只有 selfcheck 的几何量（越界/被裁/字号/占用比/次级文字/主体比）；**没有任何判断教学价值、交互意义、重复、假数的仪器**；无 critic；`check-page` workflow 存在但代码里零调用；模型自己写的收尾自述被当作"完成" |

两条要点：
- **确定性的部分做得很扎实**：越界拦截、Patch 原子性、缓存前缀共享、代码页沙盒、图池取图/压暗/抠图、fail-visible 的一贯原则。这是可以依赖的底座。
- **所有"判断"都塞在两次模型调用里**（planner 一次、builder 每页一个自由循环），而这两次调用拿到的输入里没有任何一处描述"这套讲义的知识结构是什么、哪一页要建立什么、什么时候该动手"。

### 2.1 观察到的失败模式（每条都有页面可指）

**F1 版式同形（跨学科模板化）** —— 5 套讲义、79 个非封面/非代码页，**79/79** 是同一指纹。看缩略图分不出这是化学还是史学。
Main sample 本身（escapement / rain-paths / neuron-to-formula）都是"一个大主体 + 少量文字"，但迁移到产物里全部变成"左图右卡片堆"。
selfcheck 报的"主体比"（最大内容块 / 第二大）在内容页中位只有 1.2–1.9，说明没有主体。

**F2 文科退化 + 假量化** —— 《史记》15 页全部是引文卡片 + 标签切换。两个交互页把文学判断做成分数：
page-07「战勇 −15 治军 −20，与本传偏离度 0%→92%」，page-13「事实链证据充分率 100%，论赞价值介入强度」。
这些数字没有任何来源，而 builder 的收尾自述把它们当作"已验证的核心交互事实"。
根因不在 builder 的品味，在 `build-interaction/references/general.md` 的合同：它要求 canonical model / measurement / rule-based consequence，
对没有数值模型的学科，满足合同的唯一办法就是编一个。

**F3 同一证据反复画** —— 缓冲溶液 17 页里滴定 S 曲线出现 10 次（01/07/09/10/11/12/13/14/15/16/17）；
集成学习里 solar-storage 那种"双曲线 + 右侧读数卡"被 7 页复用。planner 只给一句主题，各页并发独立构建，没有任何机制知道邻页画了什么。
现有仪器测不到：整页感知哈希两两相似度 ≥0.85 的对数为 0/136（版式不同、曲线相同）。

**F4 为交互而交互 / 内容页交互化** —— 65 个「内容页」里 64 个带控件（tab 切换 / 预设按钮 / 滑块），交互页与内容页在产物上已无法区分。
探针显示每个控件都真的改状态（像素变化 1–30%，0 JS 错），所以**机械判据通不过去**——问题是这些切换替代了原本该一屏讲清的对照。
反过来，真需要动手的地方（史记：把散见材料拼成人物；化学：预测再验证）没有一页做了预测-验证式的交互。

**F5 节奏与密度失控** —— 30 分钟被规划成 15–24 页（经济学研讨课 24 页 = 每页 75 秒）；
内容页文本块中位 55–90 个、次级小字承载 20–60% 字符、正文字号中位 15px。密度是"报告式"不是"课堂式"。
没有任何输入告诉 planner 一页该停多久，也没有仪器量"一页有几个主张"。

**F6 planner 例子泄漏与标签僵化** —— deck.md 里的 AdaBoost 示例带「（模拟训练）」，历史上 140 个交互页 52% 原样带这个括注（提示词明写"只有用户要求才注明"）。
标签集只有 4 种，交互页的形式选择被压缩成"是否要交互"一个比特。

**F7 图片链路断裂（确凿 bug）** —— 城市热岛规划了 7 张图、取到 6 张，**0 张送达 builder、0 张渲染**。
`plan_run` 把 `assets()` 返回的 IMG.md 文本当作 `pool` 传给 `briefs()`，而 `img_plan()` 的正则只认原始图池表的裸文件名，匹配 0 行。
2026-08-28 塌缩后这是第一轮真有图池的 run，所以此前不可见。另：off-topic 守卫放过了一张 Holbein 肖像（检索词 "infrared urban surfaces FLIR"）。

**F8 自我宣布成功** —— builder 最后一条无工具消息是"已构建完成并通过双态检验……"，其中列举的"验证事实"包括 F2 的假分数。
`check_use` 要求"说出一条你真核验过的证据"，Gemini/low 在 27 页中只有 5 页首轮写了任何文字（要求的"先陈述迁移模式"多数被跳过），
说明**面向模型的文字要求在这个模型档位上大多不执行**，而 harness 并不检查。

**F9 文案 AI 味未被清单捕获** —— 禁用短语表在 27 页只命中 1 次，但正文满是「群智涌现的前提」「集成质跃」「工程启示：…系统工程」「严禁使用激进的指数损失 Boosting」「英雄本人的天命遮羞布」。
清单是词表，问题是语域（评论体/营销体替代教学体）。

**F10 优化历史的选择偏差** —— 36 轮带规划的实验中 31 轮是 ML 题；样本库 22 份里 4 份承担了 62% 的读取；
过去 3 周所有 A/B 的判据是占用比、步数、token、缓存。系统被优化成"在 ML 题上便宜地填满画布"。

### 2.2 哪些是好的（不要误伤）

- 理工数值正确率高：缓冲溶液的 pKa、半当量点、β_max、体积换算全部核对无误；热岛的能量收支数量级对。
- 城市热岛 04/05/06/16 页有真正的机制图（能量通量、峡谷剖面、树冠）；经济学 page-10 是真模拟（DGP + OLS 偏误）；page-15 的"主张装配器"是少见的文科式交互雏形。
- 封面页普遍成立；主题色板逃出了 cream/dark-tech 两套默认（check_palette 全部"其他"）。
- 工程稳定：102/102 交付、0 致命、每页 6–8 次调用、缓存命中 72%。

## 3. 能力边界（问题 1）

| 维度 | 现在能稳定做到 | 现在做不到 / 靠运气 |
|---|---|---|
| 内容正确性 | 理工数值、公式、经典引文（《项羽本纪》论赞原文准确） | 区分"教材事实"与"自己编的量化"（F2）；不知道自己不知道 |
| 该讲什么 | 覆盖面完整、术语准确、按 minutes 给页数 | 取舍与节奏：每页一个主张、该停多久、什么该删（F5） |
| 何时交互 | 标签 = 交互就一定有控件 | 判断"这页不需要动手"或"这页需要预测再看" |
| 交互形式 | 参数滑块→曲线/读数；情景按钮→切换状态 | 构造/排序/拼装/预测-验证/诊断类；文科证据组织类（F4） |
| 页面组织 | 一屏装下、不溢出、字阶合规 | 一个主体（主体比中位 1.3–1.8）；把关系画成几何而不是卡片（F1） |
| 视觉+动效+交互合一 | 主题一致、色板不俗 | 动效几乎没有；交互与视觉分离成"面板 + 图" |
| 自我判断 | 越界/报错/被裁 | 教学价值、重复、假数、AI 味、跨页一致（F3/F8/F9） |
| 跨学科 | 理工机制类最好，环境/工程次之 | 文本解释类最差；程序/技能类变成流程卡片 |

## 4. 持续优化机制设计

### 4.1 基准题集（问题 2）

现状：31/36 轮是 ML。要泛化就必须先有"从未见过"的题，并且题的两个维度要交叉：**学科**（数学/CS、自然科学、工程、人文、社科、艺术语言）×**内容结构**（机制/过程 M、量化关系 Q、文本/证据解释 T、程序/技能 P）。
24 题草案在 `scratchpad/bench-briefs.md`（本轮跑的 4 题已在其中）。规则：

- **冻结**：query/audience/minutes 逐字不变；每题存一份冻结的 planner 产物，builder 层实验统一在冻结规划上跑（历史例子见 [run-focus.sh](../../legacy/notale-v2/experiments/run-focus.sh) 的 `freeze()`；脚本含删除重建操作，不直接重跑）。planner 层实验才重新规划。
- **开发集 / 盲测集**：16 + 8，盲测集每域至少 1 题、每结构 2 题；接受一项改动前只跑一次盲测集，迭代过程中不看它。
- **轮换防过拟合**：一项改动被接受后，把它优化过程中看过最多的 2 题移入"已过拟合"名单，从题库外补 2 题。
- **抽样跑法**：日常实验不必 24 题全跑。builder 层一轮抽 6 题（每域 1，结构轮换）≈ 100 页 ≈ 6.5 分钟墙钟、$12；planner 层一轮 6 题 ≈ 6 次调用、$1。

### 4.2 什么归确定性代码，什么归模型（问题 3）

原则沿用这个仓库已经验证的两条经验："**有可算的数的约束起作用，没数的不起作用**"、"**一条只有某个模型能过的闸是模型指纹不是质量判据**"。

| 归确定性代码（harness / 仪器） | 归 prompt / skill / sample / 模型判断 |
|---|---|
| 所有**测量**：版式指纹、主体比、控件数与控件后状态变化、跨页证据重复、量化词密度、每页主张数、字阶、渲染错误 | 所有**选择**：这页讲什么、要不要动手、用哪种交互、构图是什么 |
| 所有**送达**：图池→brief（F7）、邻页已用证据场→本页 context、planner 决定→builder 可见 | 内容深浅、术语、例子 |
| **协议闸**（fail-visible）：文件存在、标签合法、JSON 合法、越界拦截 | 风格、语域（但由仪器**报数**给它看） |
| **重复与一致**的检测（deck 级，构建后） | 重复的**消解**（builder 改页 / planner 换主题） |
| 假数探测（"分/%/指数/强度"出现在无数值模型的页）→ 报给模型和 critic | 判断这个数该不该存在 |
| 实验编排：冻结、分臂、盲评页生成、指标汇总、回归对照 | — |

明确**不做**的确定性闸：占用比下限、文本块区间、主体比阈值——仓库已经为这三条付过学费（Sonnet 打满 100 步）。它们只能是**报数**。

### 4.3 评价体系：三层，谁都不能给自己盖章（问题 5、7）

> 2026-09-05 后改按 §0′ 的三个数；下面的五判项只保留作为 judge 提问时的参考维度，不再单独计分。

**第一层 · 浏览器仪器（每页、每轮、零成本）** —— 全部在真实 Chromium 里对渲染后的 DOM/像素量，不看源码：
1. 现有 selfcheck 全部指标（保留）。
2. **版式指纹**（本轮已原型 `layout_sig.py`）：顶层区块几何 → 签名字串；deck 级报"同指纹页数 / 总页数"。
3. **交互探针**（本轮已原型 `explore.py`）：枚举控件 → 逐个操作 → 记录像素变化%、文本变化、JS 错误、控件在重绘后是否消失。deck 级报"有控件的页 / 内容页有控件的页 / 无效控件数"。
4. **证据场重复**：不是整页哈希（已证明无效），而是取每页"最大媒体块"（svg/canvas）的内容签名：坐标轴标签文本 + 系列数 + 图形类型（ECharts option 类型 / SVG path 数量级）；两页签名同 → 记一对重复。
5. **量化词探测**：`\d+%`、`\d+ 分`、"指数/强度/充分率/偏离度" 在页面可见文本中的出现数，配合该页是否引用了任何数据源；在文本解释类(T)题上非零即标红。
6. **每页主张数**：h1/h2 + 加粗短句的计数；密度的直接替身。
7. 图片送达与渲染（现有 `scripts/inspect_run.py images`）。

**第二层 · 盲评 judge（每轮、约 $1–2）** —— 独立于 builder 的模型（不能是 gemini-3.8-flash 自己评自己；用 GPT-5.6-Sol 或 Claude Sonnet 5，二者当前路由都可用且都能看图），输入只有：**截图（初态 + 探针操作后 1–2 态）+ 页面可见文本 + 该页一句主题 + 邻页主题**。
不给它 builder 的自述、不给它 reference。输出结构化 5 项，每项 0/1/2 且必须引用截图里可见的东西：
`claim_clear`（这页要读者相信的一个判断能否 10 秒内说出）、`evidence_geometry`（关系是否画成了几何而非卡片）、`interaction_earned`（若有控件：动手是否比不动手多学到东西；无控件：是否本该动手）、`fabrication`（有没有无来源的数）、`register`（教学体还是评论/营销体）。
成对盲评优先于打分：A/B 两臂同一页并排、随机左右、只问"哪一页教得更好，为什么"。仓库里 `experiments/codex-workflow-skills-next/lab.py` 的 `make_review` 已有盲化页生成器，可直接复用。

**第三层 · 人（每周一次，10–20 页）** —— 只看 judge 与人的分歧样本和 taste 问题（§4.11）。人不打分，人裁决"judge 判对了吗"，用来校准 judge，而不是替代它。

**防"自己宣布成功"的具体机制**：
- builder 的收尾自述**不进任何统计**，只存档。
- `check_use` 那句"说出一条你核验过的证据"改成可校验的形式：Check 报告要求模型回写一条 `--after` 断言（例如"点 #btn 后 #readout 文本变为 4.76"），harness 真跑并记录通过与否——把"我验证了"变成"harness 验证了"。这是一个候选实验，不是定论。
- judge 与仪器不同源：仪器是几何，judge 是语义，人校准 judge。三者一致才算"变好"。

### 4.4 从一页坏产物追到系统根因（问题 4）

固定一套"五问"追溯，每问对应一个可以拿出来看的文件：

1. **planner 给了什么？** `pages.md` 那一行 + `theme.css` 接口 → 主题句是否已经把这页推向错误形式（如"（模拟训练）"）。
2. **builder 第一轮读了什么、说了什么？** `trace.jsonl` 首轮 + `reference_reads` → 选的 Main 是否按机制选（还是按题目名）；有没有陈述迁移模式。
3. **第一次 Write 长什么样？** 首版 HTML（可从 trace 的 Write 参数重建）→ 失败在首版就有，还是 Patch 循环引入的。
4. **Check 之后它改了什么？** Patch 参数 + Check 报告 → 它对着报告里的哪个数在改；有没有被参考项牵着走。
5. **邻页在做什么？** 同 deck 其他页 → 是这一页的问题还是 deck 级结构问题（F3 一定是 deck 级）。

追到层之后用**反事实臂**定位而不是靠推理：同一冻结规划，只换一个变量（换 Main sample / 去掉一句 reference / 改主题句 / 给邻页信息），跑同一页 3 次。一页 $0.12，一次定位实验 ≈ 6 页 × 3 臂 × 3 重复 ≈ $7。
规则："**没有反事实臂就不许写 root cause**"。本轮 F7 就是这样确认的（`img_plan(IMG.md)` = 0 行 vs `img_plan(pages.md 表)` = 7 行）。

### 4.5 要不要多 sub-agent（问题 6）

**不要在 builder 循环里再加 agent 层**。理由：每页已经是独立 agent，成本/延迟最敏感；仓库过去为 lec.js、CONTRACT、逐页规格、分镜等中间层付过学费，最后都塌缩掉了。

但要补两个**不在循环里**的角色，实现为 harness 步骤 + 一次模型调用，而不是对话式子 agent：

| 角色 | 何时跑 | 做什么 | 结果去哪 |
|---|---|---|---|
| **deck 级审读**（planner 之后、builder 之前，一次调用） | 每轮 | 看整份页表：每页一个主张？相邻页是否要画同一证据？哪些页不需要动手？给每页补一行"主证据场 / 是否动手 / 动手形式"——这正是已实现但未验证的 `--visual-focus` 开关的位置 | 写回 `pNN.md`，builder 可见 |
| **critic**（builder 之后，不回喂） | 每轮 | 第二层盲评 | `critic.json`，进指标，不进模型 |

planner 与 builder 之间是否再加"页面合同"步骤，取决于 D2 实验（§6）；不预设。

### 4.6 多少跨学科测试才算泛化（问题 8）

噪声底已知：同条件两轮逐页占用比差中位 6pp、均值 12pp（`occupancy-noise-floor`）。所以：
- **连续量指标**（占用比、主体比、小字比）：每臂至少 2 次重复，只报中位差且差 ≥ 10pp 才算效应。
- **计数/比例指标**（版式同形页比例、有控件的内容页比例、假数页数、重复对数）：deck 级二项计数，两臂差 ≥ 3 页/deck 且方向在 ≥ 5/6 个 deck 上一致。
- **盲评成对胜率**：60 对以上，胜率 ≥ 67% 才接受（二项检验 p<0.01 约在 65%）。
- **泛化的最低要求**：一项改动至少在 **6 个学科 × 2 种内容结构 = 6 个 deck** 上不劣化任何一个 deck 的第一层指标，且盲评胜率在文科与理科两个子集上都 ≥ 50%。"平均变好、某域变差"= 拒绝。

### 4.7 记忆：失败、知识、模式、回归（问题 9）

全部放仓库里、机器可读、能被检查：

- `eval/FAILURES.md` —— 每条失败模式一节：症状、可指的页、探测器（哪个仪器哪个字段）、当前状态（open / mitigated by <commit> / regressed on <date>）。**没有探测器的失败不许登记为"已修"**。
- `eval/KNOWLEDGE.md` —— 设计知识，只收"有对照证据"的条目，每条附实验 label（例如 `#stage flex column` 那条）。禁止收"感觉"。
- 样本库治理（`skills/*/samples/catalog.json` 加字段）：每份样本的读取次数、被读后产物的盲评均分；**一个类别 ≥ 40% 读取集中在一份样本上就触发"补样本或删样本"**；新样本必须来自盲评最差的那类失败。
- `eval/regression/` —— 金样本：每个失败模式一个"曾经坏过、现在好"的 (冻结规划页, 探测器期望值) 对；每次接受改动后全跑。现有 `experiments/workflow-skills-next/fixtures/adaboost-cold-gray` 就是第一份。
- 实验记录沿用 `../runs/notale-v2/*-experiment.json` 的形状，但补齐固定字段（§4.8）。

### 4.8 一次实验失败时记什么、何时 revert（问题 10）

每次实验一份 json，字段固定：`hypothesis`（一句机制假设）、`layer`（planner/builder-prompt/sample/reference/harness/instrument）、`change`（diff 摘要 + commit）、`arms`、`decks`、`repeats`、`pre_registered_metric`（跑之前写死的判据与阈值）、`result`、`verdict ∈ {accept, reject_no_effect, reject_regression, inconclusive}`、`side_findings`、`cost_usd`。
Revert 规则：
- `reject_regression`：立刻 revert（任何一个 deck 的第一层指标恶化 ≥ 阈值）。
- `reject_no_effect`：revert，但把假设与"为什么没效"写进 FAILURES（仓库已有先例：floors-ab）。
- `inconclusive`：不合并、不 revert，标记需要更多重复；一周内没补齐则按 reject 处理。
- 不允许"改动留下、判据事后改"——`pre_registered_metric` 是跑之前写的。

### 4.9 没有人工任务时怎么找下一个问题（问题 11）

每周一个固定周期：
1. 跑开发集 6 deck 基线（约 $12），刷新仪器与盲评。
2. 生成失败直方图：按 (失败模式 × 学科) 计数，乘以严重度权重（假数 > 教学失效 > 重复 > 版式 > 文案）。
3. 取**频率 × 严重度 × 可定位性**最高的一条；可定位性 = 能否在一天内用反事实臂定到层。
4. 必须写出**机制假设**（"因为 X 层里的 Y 导致模型只能 Z"），没有机制的假设不立项。
5. 排除已在 FAILURES 里标 `regressed` 的旧问题优先复查。

### 4.10 限制自己（问题 12）

- **prompt 字节预算**：builder system 块 ≤ 20,000 字符、planner ≤ 12,000（当前 19.5k / 12.4k）。加一条必须删一条。
- **规则须有探测器**：任何新增的散文规则如果没有对应仪器字段，先做仪器，再决定是否还需要那条话（仓库的实证：同一句话发 73 遍无效）。
- **样本数上限**：每类 ≤ 5 份 Main；新增必须替换掉读取最少或盲评最差的一份。
- **不加 agent 层**：任何新的模型调用必须证明 (a) 它替代的是确定性代码做不了的判断，(b) 在 6 deck 盲评胜率 ≥ 67%。
- **一次一变量**、**冻结规划优先**、**判据预注册**。
- **不动模型与 effort**（用户已锁定）；成本优化只在样本预算、步数、缓存维度做。
- 每周回顾一次"过去 7 天新增了多少规则 / 删了多少"，净增 > 0 需要在周报里解释。

### 4.11 什么时候必须停下来找你（问题 13）

- **taste 分歧**：judge 与我对同一页的判断相反，且涉及"好看 vs 教得好"的取舍。
- **产品边界**：例如"文科交互页该不该存在"、"30 分钟到底几页"、"讲义是课堂投影还是自学"——这些改变基准题的 audience/scenario 定义。
- **要改 planner 标签集或页型协议**（影响所有下游）。
- **要动样本库中人挑过的样本**（future-climate-analogy 的 mini 曾被你否决）。
- **任何会改变模型/effort/路由的建议**。
- **连续两周盲评没有任何一项改动被接受**——说明方向错了，不是要更努力。

## 5. 研究循环（对用户版本的修正）

用户给的环是：observe → recurring failure → hypothesis → locate layer → smallest change → unseen examples → browser test → compare → accept/reject → capability/regression → repeat。
按这个仓库的实际情况改三处：

1. **在 hypothesis 之前插入"造仪器"**：这套系统里每个已被治好的问题（越界、字号、#stage flex）都是先有了数才治好的；每个治不好的（不要太满、一个主体、不要卡片）都只有话没有数。所以"identify recurring failure"必须产出一个可算的探测器，否则不进入下一步。
2. **locate layer 用反事实臂而不是推理**（§4.4）。这一点是仓库自己的教训（"17 vs 49 是假的"、"两份不同 planner 产物做因果推断"）。
3. **区分 page 级与 deck 级环**：F3/F5/F6 只能在 deck 级看见和修，page 级实验永远测不到它们。所以循环有两个尺度：deck 级（planner + deck 审读）与 page 级（builder），各自有冻结物与指标。

修正后的环：

```
跑基准 → 看产物(缩略图+探针) → 命名失败并造探测器 → 在 6 deck 上量出频率
→ 机制假设 → 反事实臂定层 → 最小改动(一次一变量, 预注册判据)
→ 冻结规划上跑开发集 → 仪器 + 盲评 + 回归 → accept/reject(按 §4.6/4.8)
→ 写 FAILURES/KNOWLEDGE/回归金样本 → 盲测集验一次 → 轮换题 → 重复
```

## 6. 若从今天起自主跑 7 天

预算按 gemini-3.8-flash 实测 ≈ $0.12/页、$1/次盲评 deck 估。全周约 $150。每一天都写清"怎样算成功、怎样算失败"。

**D1 · 只造仪器，不碰模型。** 把本轮的三个原型（版式指纹、交互探针、量化词探测）加证据场重复、每页主张数、图片送达，接进一个 `eval/` 入口，对 5 套已有 deck 出一张表；写 24 题基准与冻结脚本；把 lab.py 的盲化页接到新 run 结构上，用 GPT-5.6-Sol 跑一次 judge 并对 20 页人工抽检 judge 的一致性。
成功：judge 与我的 20 页抽检一致率 ≥ 75%；探测器在已知坏页（史记 07/13、缓冲 10 次曲线、热岛 0 图）上全部报红。失败：一致率 < 60% → D2 前先修 judge 提示，不进模型实验。

**D2 · 基线 + 噪声。** 6 题开发集（每域 1 题，结构 M/Q/T/P 各至少 1）各规划一次并冻结；builder 每题跑 2 次重复。
成功：拿到每个指标的重复间噪声，确定 §4.6 阈值；失败模式直方图出来。这天没有假设要证。

**D3 · F1 定层实验（版式同形）。** 三个互斥机制假设，各一臂，同冻结规划：
A. 主题接口里那份"共享组件表"（`.panel .big .quiz .tag …`）把页面推向面板堆 → 臂 A：planner 不写组件表、只写 token。
B. Main sample 迁移失效是因为 mini 样本丢了构图 → 臂 B：full 样本（已有 --samples full）。

**D4 · F2 文科假量化。** 假设：交互合同要求 measurement，文科无数值模型就编数。两臂：

在 T 结构 4 题（史记、达尔文第四章、挑战者号报告、图灵论文）各 2 个交互页上跑。
判据：假数页 8 → ≤ 2；盲评 `interaction_earned` 不降。两臂都成 → 取 B（更便宜、无 prompt 增长）；都不成 → 记 FAILURES，把"文科交互页"列为 §4.11 的 taste 问题。

**D5 · F3/F5 deck 级：审读一步值不值。** 用现成的 `--visual-focus`（planner 每页多一行主证据场）为臂 A；臂 B 在此之上加一行"是否动手 / 动手形式"；基线为当前。6 deck 各一次。
