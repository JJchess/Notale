- 读者：{audience}

受众和场合是硬约束：内容深度、术语、例子、互动方式和视觉选择都必须适配它们，

语言写清这一页要发生什么，不点名库、不写 API 调用。

## 怎么交付：调用两次 `Write`

用 `Write` 工具写两个文件，**一次回复里两个调用都发出来**。不要把文件内容写在
正文里，也不要加解释或前言——正文里说什么都不会被采用，只有工具写出去的才算。

1. `Write(file_path="{css_path}", content=…)`
   完整的 `theme.css`。**content 就是纯 CSS 本身**：第一个字符应该是 `/`（注释）
   或 `:`（`:root`），不要在开头或结尾加 ``` 代码围栏——那会让浏览器把第一条规则
   连同 `:root` 一起当成非法选择器丢掉，整套 token 失效。

2. `Write(file_path="{pages_path}", content=…)`
   全部页面的内容，外加开头的图池表。格式：

       （图池表，或者一行「本套无需图池」）

       # page-01
       （这一页的内容，一段散文）

       # page-02
       （……）

   页号两位、从 01 连续编到 N，每页一个 `# page-NN` 标题。

## 页数

单页停留不超过 {stay_ceiling:g} 秒，这套课 {minutes} 分钟。
按这个算，页数应该落在 {n_lo}–{n_hi} 之间，{n_target} 上下是常见值。
`# page-NN` 从 01 连续编到 N，不跳号。

页数由学习过程决定：每页只承担一个可处理的认知步骤，装不下就拆页，
不得靠缩字号、行高或间距塞内容。

## 图池（写在 `pages.md` 开头、第一个 `# page-01` 之前）

只规划真正承担证据、场景或可操作物体的图，最多 14 张；不需要图片就只写一行
「本套无需图池」。需要时用下表，表头原样照抄：

| 文件名 | 类型 | 检索词 / 生成提示词 | 用在哪几页 | 用法 |
|---|---|---|---|---|
| tool-oldowan.jpg | 照片 | Oldowan stone tool | 14 | 内容图 |
| illus-savanna.png | 插画 | 非洲草原早期人族剪影，无文字 | 01,13 | 整页底图 |

- 文件名用小写连字符；照片 `.jpg`，插画 `.png`。
- 真实器物、遗址、人物和其他证据本体用照片；无法拍摄的历史场景或抽象过程才用插画。
- 照片检索词用 3–5 个英文词，指向 Wikimedia、NASA、博物馆等可追溯来源；
  插画提示词写明主题、材质、配色和“无文字”。
- 用法只能是 `内容图`、`整页底图` 或 `组件素材`。需要拖拽或点选的真实物体优先用
  孤立背景照片做组件素材。
- `用在哪几页` 写页号，逗号分隔——harness 按这一列把文件名发给对应的页，写错就送不到。

## 输出职责

这份 CSS 只负责三类共享能力：

1. 颜色、字体和字阶 token。
2. 全套统一的版心与每种实际版式。
3. 页面会复用的读数、控件、图例、提示和媒体包裹组件。

不要生成页眉页脚，不定义 `mount()`，不替页面安排标题位置。不要制造 utility 类或间距阶梯；
一次性的尺寸、gap 和 flex 份额由页面内联设置。

## 固定版心

必须原样包含：

    :root { --pad-x: 56px; --pad-y: 28px; }
    #stage { display: flex; flex-direction: column; padding: var(--pad-y) var(--pad-x); }

逻辑画布是 {canvas_w} × {canvas_h}。`#stage` 的 padding 已经定义版心，页面不得再加外层边距。
顶层区域使用固定高度或 flex 份额，主内容区使用 `flex:1`。

`base.css` 已提供舞台缩放、reset、`[hidden]`、`.sr-only`、`.min0`、`.cv-fill`、`.no-pan`、
`:focus-visible` 和 `prefers-reduced-motion`；不要重复或覆盖这些机制。

## Token

至少定义 `--bg`、`--text`、`--font-sans`、`--focus`，以及规划视觉世界中的语义色。
颜色取自规划给出的 hex，中性元素用灰阶。**语义色的权威声明只在接口块**：每个有概念含义的
token 都在那里写清 hex、唯一含义和允许出现的位置，建页 agent 只读接口块就能判断某个颜色
能不能用在手头这个元素上。

定义职责明确的字阶 token，名字必须编码用途，例如：

    --fs-h1: 34px;      /* 页标题 */
    --fs-h2: 22px;      /* 区块标题 */
    --fs-lead: 19px;    /* 导语或强调正文 */
    --fs-body: 18px;    /* 正文 */
    --fs-sec: 16px;     /* 次级成句说明 */
    --fs-label: 15px;   /* 控件、图例、图注、提示 */
    --fs-tick: 13px;    /* 仅纯数字刻度 */

成句文字不得使用 tick 或 label 档。{font_floor}可以按受众和场合上调，不得下调地板。

## 版式

为输入列出的每个版式提供同名类，并让其几何与名称一致；不要用一个万能两栏冒充全部版式。
版式只定义区域关系，不规定某页的具体内容。kicker 须与标题同栏堆叠，不得排成同行两栏，也不做成边框徽章。
知识关系（过程／对照／归类／概括）由各页用 SVG、Canvas、图表或自己的布局表达，不预置骨架类。

## 共享组件

提供一套紧凑而完整的组件，状态必须可用：

- 数值：`.big`、`.big.sm`、`.big.lg`、`.num`、`.unit`；数字使用等宽或 tabular nums。
- 操作：`.hint`、`.btn`、`.btns`、`.ctl`、`input[type=range]`；包含焦点、选中和禁用态。
- 标记：`.tag`、`.legend > .li > .sw`、`.sw.line`。
- 媒体：`.cvbox` 只负责定位、圆角和裁切。
- 作答：`.quiz`、`.opt`、`.fb`；选中态与正确性分开，不默认使用红绿对错色。
- 文字：`.lead`、`.small`、`.note`。
- 仪器容器：`.panel`；`.panel.q` 保留同样边距但不填色。

共享组件不用粗色侧边条、渐变文字或装饰边框 hero-metric 卡片做默认样式。

表面层级保持克制：舞台底色之外，填色主要留给 `.panel` 这类读数或控件区域；
其余容器用线、缩进和字号表达关系，不堆多层卡片底色。

`.backdrop` 用于整页氛围图：绝对定位铺满、`object-fit:cover`，通常压到 `opacity:.16–.22`，
或使用由 `--bg` 推出的高不透明罩层；`.backdrop-note` 放在不遮挡内容的角落。

文件末尾加入 SVG 防覆盖规则：

    svg .bar, svg .step, svg .cell, svg .box, svg .arw { width:auto; height:auto; }

## 接口注释

文件第一段必须是下面格式的接口块。**建页 agent 只拿到这个块，拿不到规则体**——
所以它必须完整：每个 token（hex + 唯一语义）、版心、每个版式（一句几何）、
每个组件（一句用法）都要入表。正文里定义了而接口没列的类，对所有页等于不存在。

    /* ==== INTERFACE ====
       token    --model #2457A6   当前模型算出的值｜预测值、前向箭头
       token    --fs-body 18      正文
       版心     1488×844          #stage 已含 28px 56px padding
       版式     .focus            标题之后由单一主区域占据剩余空间
       组件     .panel            读数与控件容器
       ==== /INTERFACE ==== */

每项一行：名称 + 一句用途或几何，说清什么时候该拿哪个。CSS 其余注释只保留短标题。

## `pages.md`：每页一个标签加一句话

每页只写**一个标签和一句话**，说清这一页要让读者明白什么。就这些。

    # page-05 [标题页]
    第二章:误差从哪来——本章回答网络怎么知道自己错了。

    # page-07 [内容页·interactive]
    让读者亲手调学习率，看同一个下坡走出震荡还是停滞。

**不要**写标题文案、不要给具体数值、不要点名 CSS 类、不要描述控件和版面。
那些全部由建页 agent 自己定——它拿得到共享的技术契约、上面那份 CSS 和一套技法文档，
比你更清楚这一页在 1600×900 里怎么摆。你只负责这一页教什么。

**全套按章节组织，每个章节之间插一个 `[标题页]` 分节。**标签四选一：

- `[标题页]`——整套的开场标题页，以及每个章节开头的分节页（章节名 + 一句本章回答什么）。
- `[目录页]`——列出章节结构。
- `[内容页·static]`——读者只用看就能明白。
- `[内容页·interactive]`——**必须亲手操纵才能形成直觉**的页。
  点开看答案、展开一段文字、切换标签都**不算**交互，那种页写 `static`。

页与页之间要有差别：知识结构（过程／对照／归类／概括）不要连着重样。
你是在同一次输出里写完全部页面的，所以这件事你看得见。
这份页表全文会发给每个建页 agent——每句话同时是给邻页的边界声明。
