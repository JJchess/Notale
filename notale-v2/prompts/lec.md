写一个全套页面共用的计算模块 `assets/lec.js`,挂到全局 `Lec`。

它只承担两件事,**不管版面**:

1. `Lec.K` —— 这个主题里所有的常量。物理常量、单位换算、关键数值。
2. `Lec.P` —— 这个主题里所有的算法与公式,以函数形式提供。页面调用它拿数,
   **页面自己不许写死任何数字**。凡是能算的都在这里算。

**不要写 `mount()`,不要生成页眉页脚,不要碰版面。** 骨架只有这些:

    <div id="stage">
      …这一页的内容,由建页的 agent 自己决定怎么排…
    </div>
    <script src="assets/base.js"></script>
    <script src="assets/lec.js"></script>

标题写在哪、有没有页眉、组件怎么摆 —— 全部由建页的那个 agent 决定,
它比你更清楚这一页要呈现什么。你只负责让它算数的时候有现成的函数可调。

有一条仍然是硬的:**页码和总页数一概不显示。** 不要 `50/50`、`Page 38`、
`第 38 / 48 页`。`<body>` 上的 `data-page` / `data-total` 只用来算进度
(比如进度条百分比)和键盘翻页,**不许拼成字符串印出来**。
这条是量出来的:一轮里写了 `ui: { pageLabel: 'Page' }`,于是每页都印着「Page 38」;
改成从 `data-*` 读之后又写了 `page + '/' + total`,于是每页印着「50/50」。
总页数对读者没有意义,而「还剩多少」该由图形表达,不是数字。

这是全套数值一致性的唯一来源:各页各自独立构建、互相看不见,只有共用同一份计算才可能算出
一样的数。所以 `Lec.P` 要覆盖到每一页会用到的量,宁可多几个函数,不要让页面自己算。

题目:{query}

规划还没写,你先根据题目判断需要哪些常量和算法。写成纯 ES5 兼容的 IIFE,
不依赖任何库,`file://` 下直接可用。

输出格式:**把整个文件包在一个 ```js 围栏里**,围栏之外不要有别的代码块。

这条是为了给 harness 一个能算出来的边界。你在围栏前面想怎么斟酌都行 ——
harness 只取那个围栏里的内容,前面的思考会被丢掉,不会进到页面里。
反过来,如果不给围栏、把代码和思考混在一起,harness 只能去猜代码从哪一行开始,
而实测猜错的代价是整轮作废(有个模型连续三次把六万字符的推理稿当文件交出来)。

围栏里必须是可以直接 `node --check` 通过的完整文件。
