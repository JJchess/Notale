## 输出长度与原则

**每一页**的规格必须在 400–2,000 个 Unicode 字符之间。简单转场页应明显短于复杂交互页。
只写规划阶段才能决定的内容：准确文字、关系几何、真实数据、接口选择、交互行为、核对值和边界。
不要解释这些规则的历史，不要重复共享契约，不要为填模板制造无用小节。

## 固定输出结构

按页号升序，为上面每一页各输出一份完整规格，每一份都以自己的这一行开头：

`NN` 和秒数取自该页页表行。页之间不写过渡语、小结或分隔线，后一页直接从 `# page-NN` 开始。

### `## 照这个写`

### `## 知识结构：<该页页表行里的知识结构>`

用两段短句说明：

1. **关系不变量**：哪些对象必须同行、同尺度、同基线、相连或嵌套；这是本页唯一的版面底线。
2. **共享原语**：点名 1–3 个主题接口中的类，并说明各自承担哪层关系。必须包含对应的 `.k-*` 骨架；

知识结构只定义一套主几何。不要另写一套与它平行的“场景构图”。按该页页表行里的版式，
说明骨架如何落入该版式即可。

### `## 表征形式`

- 使用哪个已安装库，或说明原生 DOM/SVG/Canvas 更合适的原因。
- 渲染器配置、尺度与轴的设定、状态变化走哪个接口，都留给建页阶段按 workflow 决定，这里不写。

常规图表优先用 ECharts；关系网络可用 D3；命中检测场景可用 Konva；3D、物理或粒子场景按库清单选择。

## 按需小节

### 内容填充表

除纯标题或转场页外，增加一个按实际内容命名的小节，例如 `## 六个事件`、`## 物种对照`、
`## 四条支撑`，不要笼统叫“数据”。把画面真正需要的行、列、文字、值和单位写成 Markdown 表格。

- 显示常量：从上面的 `Lec.K` 实际值抄入表中。
- 计算结果：写公式入口和 2–3 个代表参数；另在“核对”节给期望值。
- 明确哪些值写入内容、哪些只用于核对，避免把测试答案误印到页面。
- 有来源时同时给完整来源和页面短标法，例如“页面只写 `Organ 等，2011`”。
- 只写本页会出现的行，不复制整个 `lec.js`。

### `## 交互`

仅当页表交互不是“无”时出现。写清：学习者操纵什么、范围和默认值；哪些数值或图形立即变化；
应形成什么直觉；如何重新开始。滑块、游标、缩放和切换是观察仪器，没有目标态时不要编造“正确位置”；
只有分拣、配对、拼装等有目标态的任务才写成功和失败反馈。复位不是每个交互都必需，状态可逆且清楚即可。

### `## 动效`

只有动效承担过程或反馈时出现。给出对象、方向、位移、时长和错开量；入场总时长宜短，
不得用动效重复已经清楚的静态关系。

### `## 核对`

本页有公式、模拟、积分或单位换算时出现。给 2–3 组参数和期望结果，让实现者能发现符号、单位或数量级错误。

### `## 画面`

只用于整页底图或四种骨架都不适合的自由构图。按背景到前景写区域、对齐、关键数值及其原因，
并明确必须留空的位置；普通骨架页不要出现这一节。

### `## 媒体`

需要图片时出现。优先点名图池中的 `assets/img/...`，写用途、裁切方式和需要照抄的 `title`。
整页底图使用主题 `.backdrop`，保持弱对比。只有图池没有所需素材时才给简短检索词或生成提示词，
如果取得或生成素材就是本页的主要难点，分别选 `get-photo-ref` 或
`get-illustration`；否则不要为了媒体再增加第二个 workflow。出处和许可只进 `title` 或低干扰层。

只输出这几页的规格正文，不写解释，不加 Markdown 围栏，不重复页表。
