## 照这个结构写

归类之后是八类,零项落在类外。**五类必填,三类看这一页需不需要。**

    # page-{nn} · 短标题 · **{stay} 秒**

    ## 照这个写
    **这一节给的是可以直接落进代码的字面量,不是描述。**

    这一页要用到库的话,把关键配置写成字面量 ——
    比如 `echarts.init(el, null, {{renderer:'svg'}})`、`textStyle.fontSize: 16`、
    `轴标签 14`、`inverse: true`。写清楚一行,胜过让建页 agent 试三次。

    可以调的计算接口就是下面这些(常量和函数,**不含版面**——版面全由建页 agent 定):

{lec_api}

    常量的**实际内容**(照着抄进你的数据表,不要只写键名):

{lec_values}

    这一条是量出来的,而且量的是**返工**:规格里带字面量的那一轮,
    页面占用比从 47% 升到 51%(GPT 七轮里最高);而规格只给散文描述的轮次,
    建页 agent 平均 17 次 Edit/页、16 次自检 —— 那些步数就是在把描述翻译成代码。
    **规格里省下的一行,构建时要花十几步换回来。**

    ## 知识结构：{structure}
    这个骨架要把哪一层关系显式化,以及这一页具体靠什么显式化它
    (箭头 / 对齐的行列 / 嵌套 / 主干分支 / 前后态)。

    ## 表征形式
    静态、动态还是交互,具体是什么。按学习者需要建立的心理表征选,
    不按视觉多样性选。

    ## <骨架的填充物 —— 标题按骨架取名,不要笼统叫「数据」>
    这一节装的是骨架里那些格子要填的东西,**标题就叫它实际是什么**:

        process         → 「六个 step」「六个事件」「箭头上的连接问题」
        comparison      → 「维度表」「四行 × 两列」
        classification  → 「层级里的各项」
        generalization  → 「四条支撑」「五条支撑」
        enumeration     → 「并列的各项」

    **画面上真正要出现的那几行,写成一张 markdown 表。** 不是描述有哪几列,
    是把行列和值都写出来 —— 建页 agent 照着渲染,不用自己编也不用去猜。

    **画面上要出现的值,一律直接写在表里。** 常量的实际内容就在下面
    「可以调的计算接口」那一节里,照着抄过来 —— 不要写「去 `Lec.K.xxx` 里取对应的」,
    那句话对建页 agent 等于什么都没说,它得自己去翻、去猜哪一条对应哪一行。

    这一条是量出来的,而且量的是**成品**:上一版要求「跨页共用的写键名不要抄值」,
    结果一页的规格写成「年代来源:`Lec.K.timeline` 中对应两足行走事件」,
    画面上就只出现了 4 条泳道十几个信息项;而 Opus 那条线的同一页规格里
    直接摆着 13 行 `| 距今 Ma | cc | 名 |`(从乍得沙赫人到智人),
    画面上是 40 多个带名字的数据点。**消融验过:只换规划、不换建页模型,
    Edit 6.5→1.1、画布占满 24/48→44/44、占用比 51%→63%。**

    `Lec.P` 留给**要算的**量(速度、能量、比值、坐标换算)—— 那些页面调函数;
    而**要显示的**常量,值写在这张表里。

    表的标题按内容命名,不要笼统叫「数据」:`尺上的事件`、`物种数据`、`八颗行星的距离`
    —— 建页 agent 一眼知道那是什么,而「数据」两个字它得读完才知道。

    **只写这一页画面上真的出现的那几行。** 上一版要求「画面上每一个数值连单位和
    出处都写进来」,规格中位涨到 3,116 字符,大半是把 lec.js 整个抄了一遍;
    我因此改成「只点名不给值」,结果数据表的覆盖率从 Opus 那条线的 52% 掉到 15% ——
    **省过头了**,建页 agent 又得自己去凑那张表。要的是这一页的那几行,
    不是整份 lec.js,也不是一个键名列表。

    ## 必须点出来的一到三句
    读者离开这一页时应该带走的话。表里「一句话」那一列是核心,可以润色。
    **几句由这一页真正需要几句来定** —— 实测承担收束的页往往两三句,
    聚焦一个现象的页一句就够。承担收束时可以把标题写成「收束主张」「收尾一句」。

    ## 交互（只有这一个）
    表里给的那个交互。先写:读者动什么、看到什么变、从中该形成什么直觉。
    **然后这四件必须都写到**,一件一行,写具体的表现而不是「给出反馈」:

        做对了立刻看到什么   吸附归位 / 描边发光 / 连线接通 —— 具体那一下是什么
        做错了立刻看到什么   回弹 / 抖动 / 提示的原话是什么（提示要指出错在哪，不是「再试试」）
        做到哪儿了怎么知道   进度的形式：8 个位填了 3 个 / 第 2 轮 / 剩 4 个
        做完了怎么收         全部就位之后画面怎么变，以及能不能一键重置重来

    这四件是量出来必须加的:上一轮 45 页里，**成功判据只有 17% 写了、
    进度 11%、收尾 2%** —— 也就是「做对了会发生什么、做到哪儿了、做完怎么收」
    大面积留给建页 agent 自己发明,而那正是学习者最能感知的部分,
    45 页各自发明就会各不相同。

    **表里写 `无` 的话,这一节就写「无 —— 这一页只承担<开场/推进/过渡/收束>」**,
    上面四件不用写。

    ## 场景构图
    **这一页是那个视觉世界的哪一角。** 先引用 `视觉世界` 里的母题（写出用了哪几条），
    再写元素怎么摆。

    上一轮 91% 的页有这一节,但写的是「左侧是装配架,右侧是仪表」——
    那是**槽位**,不是场景。槽位任何题目都能填,所以填出来的 45 页长得都像。
    要写的是这一页画面属于哪个世界:那条太阳系的例子里,
    「深蓝星空 + 发光轨道环 + 底部行星托盘」是场景,「左侧列表右侧详情」是槽位。

    ## 动效
    两项,一项一行。交互页两项都要,静态页只要「入场」:

        入场   页面刚出现时什么动（谁先出现、往哪个方向进来）
        反馈   学习者做对/做错的那一下什么动

    实测上一轮点名动效的页只有 37%、指了动效 skill 的 6%、
    `animation-systems` 全程实调 2 次 —— 不写就等于没有。

    ## 不许碰
    表里那一列,展开成具体的边界。

    ## 必用skill
    这一页**真正需要**哪些技法文档,写名字,逗号分隔。两类都要考虑:

      - 交互要做出来缺哪一块知识(动画、图表、物理、三维之类)
      - **这一页要不要图。** 要真实照片就写 `web-media-getter`,
        要生成插画就写 `make-illustration` —— 写了下面的 `## 媒体` 节,
        这里就必须把对应的 skill 写上,否则构建这一页的 agent 不会去取图,
        那一节等于白写。

    不要为了填满而硬凑;确实没有贴合的就写「无」。
    构建这一页的 agent 会被要求先读完你指定的这些。可选的清单:

    {skills}

下面这一节**只在这一页真的需要时才写**,不需要就整节不要出现
(原来这里还有一节「版面提示」,已经并进上面的必填 `## 场景构图` 了):

    ## 媒体
    用到真实照片或生成插画时才写。

    **要生成插画的话,把可以直接交给 `gen.py` 的那句提示词写出来** ——
    含视觉世界里的母题和材质语言,不要只写「一张示意图」。
    这一条是量出来的:上一轮 `gen.py` **实际调用 0 次**,而取现成照片的
    `webmedia.py` 跑了 30 次 —— 因为取图只要一个搜索词,生成图却要建页 agent
    自己想一整句提示词。提示词由你在这里写好,它就只需要执行。

    要真实照片的话写要什么图、为什么照片比示意图更能说明问题。
    出处与许可**不上主画面**,只进 `<img title="…">` 或页脚极小字。
    **这一节写了图,上面的 `## 必用skill` 里就得有对应的那个 skill** ——
    真实照片 `web-media-getter`,生成插画 `make-illustration`。
    这里说要一张 Laetoli 足迹的照片、而 `必用skill` 里没写取图的 skill,
    构建这一页的 agent 就不会去取,这一节等于没写。实测一轮 48 页 0 张图就是这么来的。

## 几条硬约束

- 停留 {stay} 秒是定好的，内容量要对得上：**这一页只做一件事**。
- 这一页的 kicker（`SHORT-CAPS` 形式的短标签）和主标题也在这里定下来。
- 只输出这一份规格的正文，不要解释、不要 markdown 围栏、不要重复页表。
