## 第一条,必须写:`#stage` 是 flex 列

theme.css 里**必须有这一条**,一个字不能少:

    #stage { display: flex; flex-direction: column; }

**这是全套里最要紧的一行 CSS。** 理由是量出来的,而且是个干净的二分:

    Opus 那条线  44 页   #stage 是 flex   子元素高度之和 = 900px 的 **100%**(44/44 页)
    我们           52 页   #stage 是 block  子元素高度之和 中位只有 **89%**(0/52 页达 95%)

`#stage` 是 block 的时候,子元素各自按「我的内容需要多高」取高 —— 写完三块加起来
800px,**剩下 100px 就空着,没有任何东西要求填它**。而 `#stage` 是 flex 列的时候,
子元素**必须把 900px 分完**:谁写了 `flex: 1`,剩余空间全归它。

所以这一行把「填满版心」从**判断**变成**几何后果** —— 页面想留空都留不下来。
对照:占用比我们中位 51%,Opus 63%,那 12 点里的一大块就是这 11% 的死空间。
而且 block 布局下「填满」得靠人去量(写完看看剩多少、改个高度、再看看),
实测建页 agent 平均 **17 次 Edit/页**;flex 列下这件事不用调。

两边的 `assets/base.css` 完全相同、都没设这个属性 —— 这不是底盘的差别,
是主题里加没加这一行的差别。

配套要写清楚给每一页的规矩:

- 顶层区域**要么给固定高度,要么给 `flex` 份额**,主内容区一律 `flex: 1`
- 一次性的尺寸和份额**写内联** `style="flex:2"`,不要为每个一次性的东西发明类名
  (实测 Opus 每页 36 处内联、我们 5 处,而我们的页内 CSS 反而是它的 3.3 倍 ——
  那些字符就是花在造一次性类名上)

## 版面由每一页自己定,你只给可复用的类

**这一版没有页眉页脚,也没有 `mount()`。** 骨架里只有一个空的 `<div id="stage">`,
标题写在哪、有没有页眉、组件怎么摆,全由建页的那个 agent 按这一页要呈现什么来定。

所以你要给的不是一套固定框架,是**可拼装的原子和骨架类**:
配色 token、字阶 token、间距阶梯、五种知识结构各自的骨架类、控件与读数面板的外观。
各页自己组合。

这条是量出来的:一轮里样式表只定义了一个左右两栏,结果 20 页全部套进去、一页不差;
而同类任务里给出的是 `row` / `col` / `grow` 这样可拼装的原子,各页自己组合,
没有任何一个布局类过半。**框架给死会让 44 页长成一个样。**

硬约束:

- 逻辑画布 {canvas_w} × {canvas_h},所有页尺寸一致,铺满显示不出现滚动条。
- 铺满时整体缩放,1366 宽的屏上系数约 0.85。**字号必须做成一套 token,而且 token 的名字
  要编码它属于哪一档** —— 页面只许用这些 token,不许写裸 px 字号。照这个形状:

      --fs-h1     34   页标题
      --fs-h2     22   区块小标题
      --fs-lead   19   导语 / 强调正文
      --fs-body   18   正文(默认)
      --fs-sec    16   次级说明、表格正文、图注正文
      --fs-label  15   控件标签、图例、操作提示
      --fs-tick   13   **纯数字刻度(只有数字和单位时才可以用)**

  地板是三档:成句的正文 ≥16px、控件标签/图例/图注 ≥14px、纯数字刻度 ≥12px。
  上面每个 token 都在自己那一档之上留了余量;取值你可以改,但**名字必须说清档位**,
  并在注释里写明每个 token 允许用在什么元素上。折行文本行高不小于字号的 1.35 倍。

  **这一条是量出来的。** 上一轮把刻度档的 token(`--fs-tick: 15px`)用在了成句的 take 上,
  而 take 属于正文档、地板 16px —— **一次命中 18/18 页**,因为它在样式表这一层、
  不在某一页里。而 selfcheck 只报「最小字号 15px」,报不出它属于哪一档,
  所以这个违规在闸上是隐形的。档名编码档位之后,「刻度档的 token 不能用在句子上」
  才成为一句能自查的话。另一轮把档位写清之后,正文档不达标率从 48% 降到 23%。

  同类的坑:名字里带 small / sm / caption 的那档,如果会被用在成句的说明文字上,
  它就属于正文档、地板 16px 而不是 14px。要么提到 16,要么只用在标签类元素上,
  在注释里写明选了哪个。

- 底盘 `assets/base.css` 已经处理了固定画布的整体缩放和可访问性基线,
  这里不要重复,也不要覆盖它。


## 必须定义的 token(base.css 的硬依赖,它刻意不给默认值)

    --bg          页面底色
    --text        默认文字色
    --font-sans   默认字体族
    --focus       焦点描边色(:focus-visible 用它,缺省会退化成 currentColor)

base.css 已经提供了这些,**不要重复实现、也不要覆盖**:

- 舞台:`--stage-w/--stage-h`(默认 1600×900)、`--s` 当前缩放比、`#stage` 的定位与缩放
- reset、`[hidden]`、`.sr-only`
- `.min0`(flex/grid 子项允许收缩 —— 不加的话内容会被静默裁掉)

- `:focus-visible` 描边、`prefers-reduced-motion` 分支

你要写的是这套骨架**之上**的视觉:配色、字族字阶、间距、

## 五种知识骨架:每一种要给出排版原语,不只是一个类名

页面结构必须由**知识关系**决定,不是由容器决定。所以这五个骨架类不能只是
「一个居中的框」——每一种都要给出**子元素原语**,并写明它把哪层关系显式化、
不这么做错在哪。照这个形状:

    结构              原语                                    硬要求
    process           .k-process > .step,中间插 .arw(自动     **必须有可见的箭头或
                      画出 → / ↓);.axis 是一条贯穿的主轴      进度轴**,不能只是并排的块
    comparison        .k-comparison 是 grid:第一列 .dim 是    **同一维度必须在同一行
                      维度名(右对齐),其后每列一个被比较对象;   上**,两侧不能各排各的
                      .hdr 做列头,.rowline 通栏分隔,.diff 高亮差异
    classification    .k-classification > .lv(左竖线+缩进);   **下位项必须在上位项的
                      .box > .bt 是带标题的包含框              框内或缩进下**
    generalization    .claim 是左粗竖线的主张句,.supports >    **主张要在视觉上比支撑
                      .support 挂在 .trunk 那条竖干上          重一档**
    enumeration       .k-enumeration > .it,统一项模板          这是最弱的结构,
                                                              不该成为默认选择

原语只是起点:能用 canvas / SVG 把同一层关系画得更清楚就画。
**唯一硬要求是那层关系必须在画面上看得见,不能让读者自己在脑子里拼。**

这一节是这份文件里最要紧的部分。上一轮我只给了五个类名、没给原语和硬要求,
结果 **48 页里 `k-` 开头的类一次都没被用上** —— 页面拿到「知识结构:comparison」
和一个空壳类名,不知道该用「对齐的行列 + 共同基准轴」,于是各自退回左右两栏或 grid,
文字叠压 29 处。

## 文件开头必须有一段接口块

`theme.css` 的第一段注释要按下面这个格式列出**你提供了什么** —— 构建单页的 agent
看不到这份指令,只能看到 harness 转达给它的东西,所以这段是它唯一的接口来源:

    /* ==== INTERFACE ====
       token   --fs-body 18      正文(默认);成句文字只许用 body / lead / sec
       token   --fs-label 15     控件标签、图例、操作提示
       token   --fs-tick 13      纯数字刻度,只有数字和单位时才可以用

       版心     可用画布 1600×900 整块 —— 没有页眉页脚占位,
                各页自己决定留多少边距

       骨架     .k-process        把「先后 / 因果」显式化:横向分段 + 段间箭头,
                                  当前段高亮,已过的段降饱和
       骨架     .k-comparison     把「同一维度上的差异」显式化:对齐的行列 +
                                  共同基准轴,差异列加底色
       骨架     .k-classification 把「归属」显式化:嵌套包含框,层级靠缩进和边框粗细
       骨架     .k-generalization 把「主张—支撑」显式化:主干居中,分支向外,
                                  支撑在视觉上从属于主张
       骨架     .k-enumeration    把「同级并列」显式化:统一的项模板,不暗示顺序

       组件     .panel            读数面板    .ctl 控件行    .note 图注
       ==== /INTERFACE ==== */

**「骨架」那几行是这一整块里最要紧的部分。** 只列类名不够 —— 必须写明
**这个骨架把哪一层关系显式化、靠什么原语显式化**(箭头 / 对齐的行列 / 嵌套 /
主干分支 / 前后态)。构建单页的 agent 拿到 `.k-comparison` 这个名字,
如果不知道它该用「对齐的行列 + 共同基准轴」,就会退回自己拼一个左右两栏。

实测参照:同类任务里协调者自发写的交接文档有九节,其中它自己标注
**「这是这一层最重要的部分」**的那一节,正是五种骨架的排版原语。
另外它还写了「版心尺寸(照这个排,不要自己量)」和「现成组件(class 直接用,
不要重写一套)」—— 这两样也一并列进来。

同一个道理和上面那条 92 次调用一样:你现在写这十几行,省的是下游几十页各自去猜。
