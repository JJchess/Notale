# 风格创作、字体与来源约定

资料基于用户给定 8 张海报的 40 个视觉条目；稳定 ID 与裁图保留，不把布局、材质、历史运动和交互方向误当成互斥分类。2026-09-10 全部 40 项完成 description、定义边界与配色关系审校。

## description 编辑约定

- 轻索引只写可辨识的组织方式与视觉特征，不写题材/受众分配、不用“高级、专业、最佳”等价值判断替某种风格拉票。相近信息密度是一项编辑要求，不是字数门禁。
- 区分风格核心、单张图的观察和本项目的应用建议。示例颜色、唯一字体、胶带或窗口等偶然做法不升格为必要条件；真实的像素格、玻璃透叠、暗底关系等也不因“无偏”而抹掉。
- 风格与配色可以组合，字体是有条件的设计建议，不按学科自动选择。只换色保留未要求改变的字体、形体和材质；说明必要的明暗关系，不新增拒绝阈值。
- 历史与设计系统依据见相关详情的外部来源。现代视觉标签没有统一依据时明示为项目工作描述，不编造流派历史或官方标准；原裁图仍是具体视觉实例，不证明整个类别。
- 研究来源不放进轻索引，也不为调用模型新增研究步骤。全部详情均审校；有外部资料支持的定义/机制与仅按项目参考整理的方向分别注明，不能把后者称为已获外部验证。
- 审校逐项确认：无学科预设、无偶然色板/字体绑定、无价值排序；相邻方向仍可区分；索引与详情一致；应用约束未伪装为历史事实。重点比较 Editorial/Fashion、Bento/Dashboard/Split、Collage/Hand-drawn/Monoline、Brutalism/Neo-Brutalism、3D/Clay/Low-poly 和 Motion/Scrollytelling。
- 不用 40 项等概率选中或四套必须不同风格作为验收。描述中立不保证模型无偏；资料审校与实际生成质量分开报告。

## 一次创作的职责

- 自动模式先看完整小概览与轻索引选择主方向，保留可观察的依据；宿主随后加载选中详情、原裁图与中英字体，Director 协调后写原生 CSS。用户配色仍可与风格组合，不强制先凑五份作品色板。
- 默认选择一个主要方向，按用户要求组合。风格并非枚举上限；自定义方向可借用相关资料后创作，不能冒称完全复刻。
- 用户明确要求优先；参考图提供视觉依据，不要求照搬其中的默认 UI 皮肤。黑白摄影、新拟态、金属和霓虹各有身份关系；冲突须说明，不保证任意色板都能无损替换。
- Director 定主题方向，Builder 结合内容完成具体页面的视觉设计、版式几何和交互；共享样式不是必用组件。风格卡不定义每页布局、不读 Planner 页表、不新增协调回合。
- 组合参考形成贯穿整套的排版、形体与材质语言，不按页型分配不同皮肤；Builder 可变构图，同类角色沿用主题的默认排版，封面强调按接口使用。用户明确要求多风格时例外。
- 共享按钮、节点、线条与通用选中外观属于主题；具体数据系列、对象关系和状态切换属于 Builder，不在风格卡里预设领域协议。
- 风格卡属于共享创作资料，不是被撤回的“每个 run 再输出一份风格说明/配置”。最终主题仍只有 CSS 与被引用的本地资源。
- CSS 的 INTERFACE 同时说明适用的前景处理与真实用法，不只列字体；reference 行指认最终主图，供视觉 Builder 随初始输入查看，颜色和具体字体仍以最终 CSS 为准。不把候选图或旧主题样张冒充修改后的结果。
- 不复制截图的网站导航、营销文本、假数据、品牌或原海报包装；裁图不是背景素材。
- 公开层不发放无语义 surface/panel/card 槽位，避免把默认通用 Paper 反复供应为内容底板。与整套字体、轮廓和材质一致的风格化容器可以承载整幅图表、数值或操作区；不以白底、有框或面积大单独判错。
- 3D、动效和叙事方向的静态图只证明视觉线索。真实行为由 Builder 实现，固定舞台不冒充长页滚动；代码页独立。

## 字体落实

详情中推荐的中英字体是项目设计判断，不声称认出了原图字体。相近风格可以共用字体；差异还来自尺度、字距、对齐、材料和图片。数字字体不替代数学排版引擎。

第一组是推荐而非强制。条件备选说明何时采用编辑式、几何式或书写式字形，中文标题也必须作出选择，不仅替换拉丁字。只加载已选详情链接的字体声明，按最终 CSS 复制实际资源；不将全部字体表灌入每次上下文。

字体资源库只维护可分发文件、上游版本/授权和真实字重。Director 选择片段写入 CSS，宿主按引用复制资源，不构造字体分类模型或样式编译器。正文与标题分别指定栈，通常英文先、中文后；中文标点保持正常节奏。字体缺字须记录实际回退；CSS 中写了名字不能证明字体生效。

数字字体不等于完整标签字体：含中文的图例、图注和数值说明要有中文承接，纯数字无需额外 CJK。修改时只覆盖用户要求改变的角色；指定新风格须落实新搭配或说明替代原因，只改配色不擅自换字体。运行时规则进入 `prompts/style-theme.md`，不向 40 张卡重复附加同一套规则。

[得意黑作者](https://github.com/atelier-anchor/smiley-sans)明确其窄斜和标题用途，不能当通用直立正文。像素风使用真实中文像素字体；[Fusion Pixel 作者](https://github.com/TakWolf/fusion-pixel-font)说明了比例与等宽模式差异。

Canvas 需明确加载将使用的字体再测量/绘制；仅读取 font-family 字符串不等于已加载。[浏览器字体加载接口](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Font_Loading_API)

## 补充实现资料

- 玻璃：透明/半透明区域才能看到背后过滤结果；这是实现机制，不是蓝紫配色规定。[backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter)
- 动效/叙事：减少动态偏好下保留可读状态和真实操作。[prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)
- 风格卡不宣称实现某版完整 Material 系统，也不从截图推断站点行为或历史流派定义。
