# page-38 · 力绕过你 · **140 秒**

**kicker:** `FORCE PATH`

**主标题:** 你的肌肉是旁观者

## 知识结构：process
这一页显式化的是**力传递路径的转移**——从「体内路径」到「体外路径」。
骨架是**前后态的对比**，由一条箭头串联：

**体内路径（无外骨骼）** → 肩关节 → 脊柱 → 髋关节 → 膝关节 → 踝关节 → 地面
**体外路径（有外骨骼）** → 背架 → 髋部铰链 → 大腿支杆 → 小腿支杆 → 鞋底 → 地面

学习者拖拽同一个重物，观察两条路径上力的分配变化。

## 表征形式
动态交互 —— 一个侧视人体轮廓，叠加两条发光的力传递路径。拖拽重物时，体内路径的节点逐渐变暗，体外路径的节点逐渐变亮。不是示意图，是**可操作的实物隐喻**。

## 六个节点（体内路径）
| 节点 | 位置 | 初始状态 |
|---|---|---|
| 肩关节 | 肩部 | 亮（承受力） |
| 脊柱 | 背部中线 | 亮 |
| 髋关节 | 骨盆 | 亮 |
| 膝关节 | 膝部 | 亮 |
| 踝关节 | 踝部 | 亮 |
| 地面 | 脚底 | 亮 |

## 六个节点（体外路径）
| 节点 | 位置 | 初始状态 |
|---|---|---|
| 背架 | 背部外侧 | 暗（不承受力） |
| 髋部铰链 | 髋部外侧 | 暗 |
| 大腿支杆 | 大腿外侧 | 暗 |
| 小腿支杆 | 小腿外侧 | 暗 |
| 鞋底 | 脚底外侧 | 暗 |
| 地面 | 鞋底下方 | 暗 |

## 力分配算法
当拖拽重物质量 `m` 增加时（从 0 到 `Lec.K.EXO_MAX_LOAD`，默认 50 kg）：

- 体内路径每个节点的力 = `m × Lec.P.G × (1 - r)`，其中 `r` = 外骨骼承担比例
- 体外路径每个节点的力 = `m × Lec.P.G × r`
- `r` 从 0 线性增长到 1，当 `m` = 0 时 `r = 0`，当 `m` = `Lec.K.EXO_MAX_LOAD` 时 `r = 1`

节点亮度映射：力 = 0 时亮度 10%，力 = 最大值时亮度 100%，线性插值。

**常量：**
- `Lec.P.G`：9.81 m/s²
- `Lec.K.EXO_MAX_LOAD`：50 kg（外骨骼额定负重，此页面定义）

## 必须点出来的两句
1. 外骨骼把力绕过你的身体，直接传到地面。你的肌肉是旁观者，不是参与者。
2. 负载越重，体内路径越暗——这不是辅助，这是替代。

## 交互（只有这一个）
**可拖拽的实物隐喻：** 读者拖动一个标有「重物」的方块，沿垂直方向上下移动。方块越往下（代表负载越重），体内路径的六节点逐渐变暗，体外路径的六节点逐渐变亮。屏幕上同时显示一个实时数字：**「外骨骼承担：X%」**，X = `r × 100` 取整。

**直觉目标：** 让读者感受到「力不从我身上走」——身体还在动，但力已经不再经过关节和肌肉。

## 不许碰
不讲神经接口（p39 讲）。不讲外骨骼的控制信号、肌电传感器、脑机接口。不讲外骨骼的材料、电池、驱动方式。只讲力传递路径的转移。

## 必用skill
threejs-webgl, konva-js

## 存疑
表里知识结构是 `process`，交互是「可拖拽的实物隐喻」。这两个对得上——拖拽本身就是过程的外化，学习者通过操作来体验「力路径转移」。但表里版式是 `canvas-full`，而 `process` 的默认版式是 `stage-cards`。这里用了 `canvas-full` 是因为需要一个大画布来放置人体轮廓和两条力路径，`stage-cards` 装不下。不算冲突，是合理的例外。
