# 页面构建契约

这份文档是 60 页互动讲义的共同建造标准。每一页由独立的 agent 构建，它们只看得到这份契约、`PLAN.md`（本页专属的页面规划）、`assets/theme.css` 和 `assets/lec.js`。凡是“每页都一样”的东西，全部写在这里，不允许各页自行决定。

---

## 一、构建范围

你只碰一个文件：只写自己那一页的 HTML（`page-NN.html`），放在 `pages/` 目录下。绝不读、不改、不依赖任何其他 `page-*.html`。页面之间通过契约和共享资源保持统一，而不是互相窥探。

---

## 二、HTML 骨架

每页使用完全相同的骨架，只改 `data-page`、`data-total` 和 `<title>` 里的页号，以及 `#stage` 内的内容。骨架如下：

```html
<!doctype html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <title>第 NN 页 · 互动讲义</title>
  <link rel="stylesheet" href="assets/base.css">
  <link rel="stylesheet" href="assets/theme.css">
  <!-- 页面专属的样式可以写在这里，或单独一个 <style> 块 -->
</head>
<body data-page="NN" data-total="TT">
  <div id="stage"></div>
  <script src="assets/base.js"></script>
  <script src="assets/lec.js"></script>
  <!-- 页面专属的脚本、库引用写在这里 -->
</body>
</html>
```

- `data-page` 填当前页码（两位数，如 `"03"`）。
- `data-total` 填总页数（两位数，如 `"60"`）。
- `<title>` 改为 `第 NN 页 · 互动讲义`。
- 你只往 `#stage` 里加内容。页眉、页脚、进度条由 `Lec.mount()` 生成，由 `theme.css` 负责外观，不许重复生成、不许修改它们的类名、不许覆盖它们的样式。

## 三、版面预算

每页的整体内容区是 `#stage` 内部扣除页眉（96px 高）和页脚（88px 高）后剩下的 1408×620 像素。所有视觉元素必须放在这个范围内。

**硬上限**：
- 每页文本元素总数（包括坐标刻度、图例标签、控件标签、读数、提示文字，但不包括 `#stage` 外的页眉页脚）**不得超过 80 个**。超过 80 个时，必须通过简化信息、合并读数、减少冗余图例来缩减，**绝对不允许缩小字号塞进去**。
- 画面占用比（`selfcheck` 报告的“元素面积 / 画布面积”）**不得超过 0.70**。超了意味着太满，需要拆页或精简，不允许缩小元素。

**字数预算**：正文句子不超过 200 字（含标点），句子以外的标签、注记、刻度等尽量简短，每个标签不超过 15 个汉字。解释性文字如果需要写长，拆成两页，或改用交互式逐步展示。

---

## 四、字号下限

字号是硬约束，不可为了多塞内容而缩小。所有尺寸基于 1366px 宽屏幕（缩放系数约 0.853）计算，实际渲染字号的物理大小必须满足：

- 纯数字刻度（如坐标轴上的数值）≥ 12px
- 含词句的标签、图注、控件标签 ≥ 14px
- 正文句子 ≥ 16px
- 行高 ≥ 1.35

`theme.css` 已经提供了三个 token：`--fs-body` (18px)、`--fs-label` (15px)、`--fs-tick` (13px)。你只能使用这三个 token 或更大的值，不允许自己定义更小的字号。KaTeX 公式的基准字号必须 ≥ 20px（见后文）。

**为什么是 0.853？** 当屏幕宽度为 1366px 时，底盘将 1600px 的逻辑画布缩放到 1366px，缩放比 = 1366/1600 ≈ 0.853。所有 CSS 字号乘以这个系数后就是屏幕上实际看到的像素大小。因此 16px 的正文在屏幕上是 13.6px，12px 的刻度是 10.2px——已经很小，不能再降。

---

## 五、数字一律从 `Lec` 取

页面不允许写死任何物理常量、函数参数或计算结果。所有数据必须通过 `Lec.K`（常量）或 `Lec.P`（函数）动态获取。讲解中提到的数字必须与 `Lec` 返回的值一致，不允许用假数据。

例如，行星重力用 `Lec.K.MARS_GRAVITY`，跳跃高度计算用 `Lec.P.jumpHeightFromVelocity(v0, gravity)`。连简单的单位换算（如 `Lec.P.clamp`）也要走 `Lec`，不要自己写表达式。

## 六、底盘机制

底盘（`base.css` 和 `base.js`）提供了画布缩放、高分屏适配、指针换算、动画循环等基础能力。**所有页面必须使用底盘提供的接口，不允许自己重写。**

### 6.1 缩放与布局
- 页面必须包含 `<div id="stage">`，底盘自动处理缩放。
- 内容区宽 1408px、高 620px，由 `theme.css` 定义。不要用 `position: fixed`，因为缩放会使 `fixed` 脱离逻辑画布。绝对定位如果需要，应相对于 `#stage` 内的容器。
- 默认用 `flex` 布局，需要二维表格式对齐时才用 `grid`。禁止通过计算坐标（`left`/`top`）来对齐元素，改用正常流和 `transform` 偏移。

### 6.2 canvas 与指针
- 所有 `<canvas>` 必须使用 `Deck.fit(cv)` 获得 2D 上下文，或对需要自动重绘的用 `Deck.autofit(cv, draw)`。**绝对不要自己写 `devicePixelRatio` 缩放。**
- 所有指针事件（鼠标、触摸）必须通过 `Deck.pt(el, e)` 换算为逻辑坐标，**不要用 `e.offsetX` 或 `getBoundingClientRect` 自己算。**
- canvas 内取色使用 `Deck.rgb(name)` 或 `Deck.rgba(name, alpha)`，不要写死颜色值。

### 6.3 动画
- 所有连续动画必须通过 `Deck.loop(fn)` 驱动，**不要自己写 `requestAnimationFrame` 循环。**
- 动画中必须处理 `reduced-motion`：如果 `Deck.reduced()` 为 `true`，动画应停在关键帧（第一帧或由 `opt.still` 指定的帧），不要播放连续运动。

### 6.4 其他
- `Deck.init({ index: NN, total: 60 })` 在页面脚本开头调用，提供键盘翻页和标题设置。
- 底盘提供的工具函数（`Deck.clamp`、`Deck.lerp`、`Deck.fmt` 等）可以直接用，不必重复实现。

## 七、主题与样式

`theme.css` 提供了全部颜色、字体、间距 token，以及四个骨架类（`.k-process`、`.k-comparison`、`.k-classification`、`.k-generalization`、`.k-enumeration`）和组件类（`.panel`、`.ctl`、`.note`）。**所有页面必须使用这些 token 和类，不允许自创颜色、字体或间距。**

- 颜色：背景 `var(--bg)`，文字 `var(--text)`，需要强调的用 `var(--focus)`。
- 字体：`var(--font-sans)`，不要替换。
- 骨架类：用来组织内容的逻辑关系，页面上如果有先后因果、维度对比、归属分类、主张支撑或同级并列，必须使用对应的骨架类，不要自己写一堆 `div` 去模拟。
- 组件类：读数面板用 `.panel`，控件行用 `.ctl`，图注用 `.note`。

**禁止删除或覆盖 `theme.css` 和 `base.css` 提供的任何类**，尤其是 `lec-root`、`lec-page`、`min0`、`cv-fill` 等。这些类是画布定位和缩放的基础，删掉会导致内容溢出或遮挡页眉页脚。

## 八、库的使用

`assets/lib/` 下预置了 18 个库，覆盖了大部分常见交互需求。**凡是已有库能完成的工作，不允许自己从底层重写。** 对照表如下：

| 需求 | 必须用 | 全局对象 |
|------|--------|----------|
| 坐标轴、刻度、图例、折线柱状散点等常规图表 | echarts | `echarts` |
| 可拖拽、需命中检测的二维场景 | konva | `Konva` |
| 三维场景 | three.js | `THREE` |
| 物理模拟（下落、碰撞、堆叠） | matter.js | `Matter` |
| 节点连线、数据驱动的矢量图形 | d3 | `d3` |
| 大量元素同时运动 | pixi.js | `PIXI` |
| 分步动画 | anime.js | `anime` |
| 时间线编排动画 | gsap | `gsap` |
| 数学公式 | katex | `katex` |
| 矩阵运算 | ml-matrix | `mlMatrix` |
| 可复现随机 | seedrandom | `Math.seedrandom` |
| 小神经网络实时训练 | mlp.js | `MLP` |
| 大规模神经网络/加载模型 | tf.js | `tf` |

引用方式：直接在 HTML 中写 `<script src="assets/lib/xxx.min.js"></script>` （相对路径）。不需要下载、检查，文件已存在。版本号见 `assets/lib/LIBS.md`，代码按这个版本 API 编写，不要去压缩文件里查版本。

### 几条硬性附加规则
- **echarts 必须用 `renderer: 'svg'`**。默认的 canvas 渲染器会让文字脱离 DOM，自检工具看不见，等于没做字号检查。同时必须显式设置全局 `textStyle: { fontSize: 16 }` 和轴标签、图例等字体 ≥14px。
- **konva 里的文字标签不要用 `Konva.Text`**，而是用绝对定位的 DOM 元素叠在上面，以保证字号自检能抓到。只有图形内部离不开变换的短标注才用 `Konva.Text`，并显式设置 `fontSize` ≥14px。
- **katex 公式基准字号必须 ≥20px**。嵌套缩放（分式内的上下标）会使字号按 0.847 和 0.605 倍递减，20px 基准下最深处仍 ≥12px。引用时同时加载 CSS 和 JS：`<link rel="stylesheet" href="assets/lib/katex.min.css">` 和 `<script src="assets/lib/katex.min.js"></script>`。
- **随机生成的数据必须用 `seedrandom`** 给定种子（如 `new Math.seedrandom('page-07')`），确保每次打开结果一致，否则讲解中的数字会变成假话。
- **小网络训练用 `mlp.js`，不要用 tf.js**。`mlp.js` 极快且无 GPU 开销，`tf.js` 只用于加载预训练模型或大矩阵场景。

## 九、交互定义

**真交互**：用户操作（点击、拖拽、滑块、输入）会改变页面上的至少一个计算结果或可视化状态，且这个变化是实时计算得出的，不是预录动画或切换静态图片。

**装饰**：纯视觉动画（如背景粒子、自动循环的图形）不算交互，但必须遵循 `reduced-motion` 规则：检测到 `Deck.reduced()` 为真时，应停止或切换为静态。

所有交互控件必须满足：
- 键盘可达：`Tab` 键能聚焦，`Enter` 或空格能操作。滑块、按钮等使用原生 HTML 元素，不要用纯 `div` 模拟。
- 提供清晰的视觉反馈：焦点时有轮廓，操作时有即时视觉变化。
- 触摸设备上可用，且不依赖 `hover` 效果。

## 十一、完工前自检

在 `pages/` 目录下运行：

```bash
python3 assets/selfcheck.py page-NN.html
```

它会用 1600×900 视口加载页面，报告：
- JS 错误
- 加载失败的资源
- 超出画布或被裁剪的元素
- 字号最小值、中位数（是否违反下限）
- 密度指标：文本块数、元素面积占比、文字叠压、小容器

**必须改到所有指标通过为止**，不允许以“看起来没问题”为由跳过。如果因为交互导致状态变化，可用 `--after "<JS>"` 测试交互后的状态，多次使用可多存截图。

重点检查：
- 文本块数 ≤ 80
- 画面占比 ≤ 0.70
- 最小字号 ≥ 12px（刻度）且 ≥ 14px（标签）且 ≥ 16px（正文）
- 没有文字叠压
- 没有 `position: fixed`
- 所有资源加载成功
- 没有 JS 错误

## 十三、语言与受众约定

本讲义面向大学一年级通识课学生，文理兼有，不假定具备微积分或生物学基础。所有页面中的文字必须：
- 用口语化、平实的汉语，句子长度不超过 30 字。
- 专业术语首次出现时，用括号或一句话解释，例如：“加速度（速度变化的快慢）”。
- 提示语用友善、鼓励的口吻，如“试试拖动这个滑块，看看形状怎么变化”而不是“用户应调节参数以观察形态变化”。
- 避免长段论述，关键概念用短句配合交互呈现。
