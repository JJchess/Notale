# page-25 · 力量/体重比 · **130 秒**

## 知识结构：process
这一页把「力量/体重比决定跳跃高度」这条因果链显式化为一个**输入→处理→输出**的流程：

- **输入**：体重（kg）与腿部力量（N），两个独立滑块
- **处理**：实时计算力量/体重比（N/kg）
- **输出**：跳跃高度（m），由 `Lec.P.jumpHeightFromVelocity()` 反推——先通过力量/体重比和有效加速距离估算初速度，再代入重力场

学习者拖拽两个滑块，同时看到三个数值的变化：力量/体重比、对应的初速度、最终跳跃高度。右侧用 echarts 散点图实时标出当前组合在群体分布中的位置。

## 表征形式
动态交互：左侧双滑块控制两个连续变量，右侧散点图给出参照系。学习者通过拖动滑块建立「推力/体重」这个抽象比值的直觉——不是背公式，而是感受到「同样力量下，体重每增加10kg，跳跃高度掉多少」。

## 输入变量与计算链

### 滑块参数
| 滑块 | 范围 | 默认值 | 来源 |
|---|---|---|---|
| 体重（kg） | 50–120 | 70 | 允许输入任意值 |
| 腿部最大推力（N） | 200–3000 | 700 | 允许输入任意值 |

### 实时计算链
1. **力量/体重比** = 腿部推力 ÷ 体重（单位：N/kg）
2. **初速度估算**：假设加速距离为0.6 m（从蹲踞到离地，大腿长度量级），
   ```
   a = 腿部推力 / 体重 - g
   v0 = sqrt(2 × a × 0.6)
   ```
   其中 g 取 `Lec.K.EARTH_GRAVITY`（9.8 m/s²）。若 a ≤ 0，则 v0 = 0，跳不起来。
3. **跳跃高度** = `Lec.P.jumpHeightFromVelocity(v0, Lec.K.EARTH_GRAVITY)`

### 散点图参照数据
通过 `Lec.P.getHominidData(key)` 获取四种猿人数据，若该函数返回对象包含 `bodyMass` 和 `legForce` 估算字段，则标出；若无，则使用以下算法生成参照点：

- **南方古猿**：体重 35 kg，腿部推力 500 N
- **能人**：体重 45 kg，腿部推力 600 N
- **直立人**：体重 55 kg，腿部推力 750 N
- **智人**：体重 70 kg，腿部推力 900 N

每个参照点按同样计算链算出跳跃高度，在散点图上以灰点标出，当前学习者拖出的组合以高亮色点标出。

## 必须点出来的两句
1. 跳跃高度不取决于体重，也不取决于绝对力量——它取决于**力量/体重比**。大象力量巨大，但体重更大，所以跳不起来。
2. 大体型动物跳跃难，根本原因就在这里：力量增长赶不上体重增长，比值下降，离地初速度就掉下来了。

## 交互（只有这一个）
拖拽「体重」和「腿部推力」两个滑块，左侧实时更新力量/体重比、初速度、跳跃高度三个数值，右侧散点图实时移动当前标记点，反映该组合在猿人参照系中的位置。学习者从中该形成的直觉：**增加力量或减少体重都能提高比值，但体重增长对跳跃的惩罚比力量增长对跳跃的奖励更陡**（因为体重同时出现在加速度公式的分母和净力的减项中）。

- 不讲恐龙或其他已灭绝巨型动物
- 不讨论肌肉生理横截面积与力量的精细关系（那是 p19 的事）
- 不引入宇航服或外星球重力（那是 p34 及以后的事）
