# page-56 · 外骨骼助力 · **90 秒**

## 知识结构：process
骨架要显式化的关系：**外骨骼施加的额外初速度增量 → 跳跃高度提升**，同时**外骨骼自身质量 → 初速度损耗**，这两条路径反向拉扯，最终落在一个可拖拽的权衡点上。

具体通过两个并列的 process 实现：
- 主路径：外骨骼助力等级 → 有效初速度增加值 → 跳跃高度（地球 1g 下）
- 制约路径：外骨骼质量 → 总质量增加 → 初速度折扣 → 实际跳跃高度

两条路径在同一个拖拽滑块上同时生效，读者拖拽时看到两条曲线在 echarts 里交叉，matterjs 里的人形跳起高度实时变化。

## 表征形式
动态交互：左侧 split 面板是 matterjs 的侧视跳跃模拟（一个人形 + 外骨骼轮廓，从蹲姿起跳，到达最高点后回落）；右侧 split 面板是 echarts 双 Y 轴折线图，X 轴为外骨骼助力等级，蓝色线为“净跳跃高度”，红色虚线为“仅考虑初速度增益的跳跃高度”，灰色虚线为“仅考虑质量惩罚的跳跃高度”，让读者看到两条相反力量在哪个点交汇。

## 外骨骼参数与跳跃高度对照表

**外骨骼助力等级范围**：0 到 1，步长 0.05，共 21 档。
- 0 档：外骨骼无助力，质量增量 0 kg，初速度增量 0 m/s
- 1 档：外骨骼最大助力，质量增量 20 kg，初速度增量 1.2 m/s

**中间档位线性插值**：
- 质量增量 = `grade * 20` kg
- 初速度增量 = `grade * 1.2` m/s

**计算逻辑**（所有数值从 `Lec` 取，不得硬编码）：
- 基础人体质量：`Lec.K.ASTRONAUT_MASS`（70 kg）
- 基础初速度：`Lec.K.HUMAN_JUMP_INITIAL_VELOCITY`（≈2.5 m/s）
- 地球重力加速度：`Lec.K.EARTH_GRAVITY`（9.8 m/s²）
- 总质量 = `Lec.K.ASTRONAUT_MASS + 质量增量`
- 有效初速度 = `基础初速度 + 初速度增量`（此为理想值，未考虑质量惩罚）
- 质量惩罚后的实际初速度 = `基础初速度 × (Lec.K.ASTRONAUT_MASS / 总质量) + 初速度增量`
- 跳跃高度 = `Lec.P.jumpHeightFromVelocity(实际初速度, Lec.K.EARTH_GRAVITY)`

**三条曲线**（echarts 绘制）：
- 蓝色实线：净跳跃高度（使用质量惩罚后的实际初速度）
- 红色虚线：仅初速度增益（使用有效初速度，忽略质量惩罚）
- 灰色虚线：仅质量惩罚（初速度增量 = 0，仅质量增加）

**matterjs 模拟**：
- 左侧画面始终显示当前档位的人形跳跃
- 外骨骼以半透明轮廓叠加在人形上，轮廓厚度随质量增量变化
- 起跳点、最高点用水平虚线标出，旁边显示数值

**默认档位**：0.5（即质量增量 10 kg，初速度增量 0.6 m/s）

## 必须点出来的三句
1. 外骨骼通过增加有效初速度来提升跳跃高度，但自身质量也会抵消部分收益——存在一个最优助力点。
2. 在地球 1g 下，外骨骼质量惩罚显著；但在低重力环境中，质量惩罚减弱，助力收益更突出。
3. 本章后续会看到，演化、训练、装备三者结合，才是跳跃能力的完整图景。

## 交互（只有这一个）
读者拖拽滑块（外骨骼助力等级 0→1）。

**看到什么变**：
- matterjs：人形起跳高度实时变化，外骨骼轮廓厚度同步变化
- echarts：三条曲线上出现一个跟随滑块移动的垂直标线，标线与三条线交点处的数值实时显示在右侧图例区
- 滑块上方显示三个数字：当前助力等级、外骨骼质量增量、净跳跃高度

**从中该形成什么直觉**：
- 外骨骼不是“越强越好”——质量惩罚会吃掉一部分收益
- 存在一个“甜点”档位，净跳跃高度最高
- 这个甜点位置取决于重力和基础初速度，不同星球不同

## 存疑
表里「知识结构」为 `process`，这一页确实符合（拖拽一个连续变量看系统响应），但「交互」列写的是“拖拽外骨骼助力，看跳跃高度提升”——这个表述只强调了正向增益，没有提到质量惩罚的权衡。如果严格按照这个表述做，页面上只展示一条单调上升的曲线，那就不是一个完整的 process，而是一个简单的 causation。当前规格把“权衡”作为核心，是更诚实的 process 写法，但可能与表里那句话的乐观语调有落差。建议在最终审稿时确认：这一页到底要传达“外骨骼有用”还是“外骨骼有用但有代价”。
