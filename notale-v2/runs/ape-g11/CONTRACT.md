# 页面构建契约

## 1. 工作边界

- 只创建或修改分配给你的 `pages/page-NN.html`。
- 不读取、搜索、复制、比较或修改任何其他 `page-*.html`。
- 可读取且应按需读取：`PLAN.md`、本契约、`assets/theme.css`、`assets/lec.js`、`assets/CHASSIS.md`、`assets/lib/LIBS.md`、对应技法文档。
- 底盘接口只查 `assets/CHASSIS.md`，不得把它转抄进页面或其他文件。
- 页面必须自包含；用 `file://` 直接打开即可显示和交互。所有资源用相对路径，禁止 CDN、网络请求和运行时下载。
- 除这一页 HTML 外，不新建或修改 CSS、JS、图片、文档、测试及其他文件。

## 2. HTML 骨架

严格保留以下骨架，只改 `NN`、`TT`，只向 `#stage` 添加本页内容；标题也是本页内容，不存在统一页眉页脚，不调用 `Lec.mount()`。

    <!doctype html>
    <html lang="zh">
    <head>
      <meta charset="utf-8">
      <link rel="stylesheet" href="assets/base.css">
      <link rel="stylesheet" href="assets/theme.css">
    </head>
    <body data-page="NN" data-total="TT">
      <div id="stage"></div>
      <script src="assets/base.js"></script>
      <script src="assets/lec.js"></script>
    </body>
    </html>

需要库时：

- 库 CSS 放在 `theme.css` 之后。
- 库脚本放在 `lec.js` 之后、本页内联脚本之前。
- 依赖先于调用方：`three` 先于 `globe.gl`/`vanta`，`gsap` 先于 `ScrollTrigger`。
- 不移动、删除或替换 `base.css`、`theme.css`、`base.js`、`lec.js`。
- 不给页面另造全局框架；`#stage` 必须保留且仍为主题定义的 flex 列。

## 3. 版面硬预算

画布逻辑尺寸固定为 1600×900。

- 画面占用比必须 ≥45%。
- 页面文本块总数必须为 20–70 个，包含标题、正文、按钮、标签、图注、刻度、图例、读数、提示和动态文字。
- 连贯说明正文为 100–320 个汉字；标题、标签、公式、刻度和控件文字不计入。超过 320 字必须删减或拆页，不得缩字。
- 可操作控件总数 ≤6；同组单选项、按钮、滑块、输入框分别逐个计数。
- 同时展示的独立读数 ≤8；能合并就合并。
- 超过任一上限，直接判定“本页超预算”，删内容或拆页；禁止通过缩字号、压行高、负间距、裁切、滚动区或隐藏文字塞入。
- 低于占用比或文本块下限时，应增加有教学意义的结构、比较维度或过程展开；禁止靠放大字号、空装饰、拉大间距填空。
- `#stage` 的顶层区域必须给固定高度或 `flex` 份额，主内容区用 `flex:1`；禁止所有顶层区域都按内容自然取高。
- 默认用 flex。只有矩阵、维度表等真正二维对齐才用 grid。
- 需要算坐标才能对齐时应改结构。拖拽用 `transform` 偏移并保留正常流位置，不用修改 `left/top` 凑布局。
- 禁止 `position:fixed`；需覆盖时用相对内容容器的 `position:absolute`。
- 一次性尺寸可写内联样式，不为单个元素发明类名。

## 4. 字号与可读性

以下均指浏览器最终计算字号：

- 纯数字或短单位刻度：≥12px。
- 标签、图注、轴名、图例、控件文字、带词句的刻度：≥14px。
- 标题、正文、提示、按钮、tooltip、动态说明：≥16px。
- 正文行高：≥1.35。
- KaTeX 基准字号统一 ≥20px。
- 不得用 transform 缩小文字规避字号下限。
- 1366×768 显示时，1600×900 舞台按 `min(1366/1600,768/900)` 缩放，约为 0.853；上述字号是缩放前逻辑字号，已为该课堂屏幕留出实际可读底线。
- canvas/Konva 中能改用 DOM 的文字必须用 DOM。必须画入 canvas 的短标注也要显式满足相应字号。

## 5. 受众与语言

- 面向大学一年级通识课学生，文理混合；不得假定微积分、生物学或专业工程背景。
- 首次出现的专业术语必须在同页用一句通俗中文解释；必要英文放在中文后括注，不得只给英文缩写。
- 先讲现象或问题，再给机制、关系或公式；公式中的每个符号必须就近说明。
- 一句只承担一个主要意思，单句原则上 ≤35 个汉字。
- 不堆术语、定义或公式；不用“显然”“不难看出”“大家都知道”等预设口吻。
- 提示语使用直接、平和、可执行的课堂口气，如“拖动观察”“比较两边”；不用命令、责备、卖萌或游戏化夸奖。
- 页面应支持教师带讲，也应让学生课后仅凭本页标题、说明、图注和反馈重建主要结论。
- 交互结果的解释必须就近出现，不能只靠教师口头补充。

## 6. 主题、类与数字

- 所有颜色、字体、圆角、阴影、边框和间距从 `theme.css` 的 token 或已有骨架类取；不得自创另一套配色、字体或间距体系。
- 可组合主题类，但不得删除或用 `classList.remove()` 移除底盘/主题类，包括 `lec-root`、`lec-page`、`min0`、`cv-fill`。
- 不得覆盖这些类的关键定位、尺寸、溢出和布局属性。
- 页面展示的事实数字、常量、单位换算、计算结果和读数一律来自 `Lec.K(...)` 或 `Lec.P(...)`；不得在 HTML、CSS、JS、SVG、图表配置或 canvas 文案中写死。
- 页码、总页数、数组索引、循环计数、像素尺寸、字号、时长和库配置等非教学事实参数除外。
- 派生量必须由 `Lec.P` 实算；不得把预先算好的结果写成常量。
- 随机样本一律引入 `seedrandom`，使用稳定种子（建议 `page-NN`）；禁止 `Math.random()`。
- 交互改变参数后，读数、图形与结论必须由当前状态重新计算，禁止假数据、预录轨迹或只换文案。

## 7. 库与技法

动手前先按任务查 `assets/lib/LIBS.md`；版本以该文件为准，不去压缩库中查。已有库能完成的呈现工作，禁止从底层重写：

- 常规坐标轴、刻度、图例、折线、柱、散点、面积、饼、热力：ECharts。
- 可拖拽、需命中检测的二维场景：Konva。
- 三维场景：Three.js。
- 下落、碰撞、摆动、堆叠、约束：Matter.js。
- 节点连线、数据驱动矢量图：D3。
- 成千上万元素同时运动：PixiJS。
- 多动画时间线：GSAP。
- 数学公式：KaTeX。
- 矩阵运算：ml-matrix。
- 页面实时训练小型二分类网络：`mlp.js`；不得用 tf.js 或另写同类训练器。
- tf.js 仅用于预训练模型、真实图像卷积或确需 GPU 的大矩阵；每步用 `tf.tidy()` 或显式 `dispose()`，并确认 `tf.memory().numTensors` 不持续增长。

强制细则：

- ECharts 必须 `echarts.init(el,null,{renderer:'svg'})`，并显式设置各类文字字号；不得使用默认 canvas renderer。
- Konva 负责图形、拖拽和命中；普通标签用绝对定位 DOM 叠加，不用默认 12px 的 `Konva.Text`。
- KaTeX 必须同时引用本地 `katex.min.css` 与 `katex.min.js`，基准字号 ≥20px。
- 页面计算可以自行实现，但不得重写已有呈现层，也不得用伪动画代替真实计算。
- 技法清单中有对应文档时，必须先用 `Skill` 读取再编码；没有对应项才自行实现。

## 8. Canvas、缩放与动画

- 所有 canvas 尺寸适配一律使用 `Deck.fit` 或 `Deck.autofit`。
- 所有手写 canvas 指针坐标一律使用 `Deck.pt`。
- 所有逐帧动画一律使用 `Deck.loop`。
- canvas 颜色一律使用 `Deck.rgb` 或 `Deck.rgba`。
- 禁止自行实现 `devicePixelRatio` 缩放、`getBoundingClientRect()` 指针换算或 `requestAnimationFrame` 循环。
- Konva 的指针坐标使用其自身 API，不再二次换算。
- canvas 的 CSS 尺寸与逻辑尺寸必须随容器变化同步适配；缩放舞台、高分屏和窗口变化后不得模糊、拉伸、错位或命中偏移。
- 必须处理 `prefers-reduced-motion: reduce`：停止持续运动和自动播放，直接显示稳定终态；用户主动操作仍可立即更新。
- 动画不得成为理解内容的唯一途径，暂停或 reduced-motion 下仍能读懂。
- 所有可点击、拖动或切换功能必须键盘可达：使用原生控件，或提供 `tabindex`、语义角色、可读名称及 Enter/Space/方向键操作。
- 焦点样式必须可见；不得只用 hover、颜色或指针位置传达状态。
- 拖拽交互必须提供键盘等价操作和明确的当前值。

## 9. 交互标准

真交互必须同时满足：

- 用户能改变至少一个有教学意义的变量、对象、步骤或视角。
- 变化会触发真实计算、约束或数据更新。
- 图形、读数或解释会立即给出可理解反馈。
- 用户能比较变化前后，或通过重置恢复稳定初态。
- 输入范围受约束，极值、快速操作和重复操作不会报错或产生不可信状态。

以下只算装饰，不得冒充交互：

- 仅悬停发光、倾斜、浮动、粒子跟随。
- 点击后只播放预录动画或切换无信息差的样式。
- 自动循环但用户不能改变变量。
- 控件变化与结果无计算关系。
- 只有鼠标可操作而无键盘路径。

若 `PLAN.md` 未要求交互，不得为凑数量加入装饰控件。

## 10. 完工自检

在 `pages/` 目录运行：

    python3 assets/selfcheck.py page-NN.html

有关键交互时，再用一个或多个：

    python3 assets/selfcheck.py page-NN.html --after "<触发交互的 JS>"

必须检查初态、主要交互态、极值态、重置态和 reduced-motion 分支。交付前必须全部满足：

- 无 JS 报错、控制台异常或资源加载失败。
- 无元素超出 1600×900、被意外裁切或脱离缩放舞台。
- 无文字叠压；无占比不足 1% 的无意义小容器。
- 画面占用比 ≥45%。
- 文本块为 20–70 个。
- 最小字号、分类字号和正文行高全部达标。
- 1366×768 缩放下布局、hover、tooltip、拖拽和指针命中正确。
- 键盘可完成全部核心操作，焦点清晰。
- reduced-motion 下无持续自动运动且信息完整。
- 随机结果可复现；动态数字与图形一致；ECharts 使用 SVG。
- 视觉、读数和说明在所有允许状态下恒真。

任何一项不干净就修改本页并重跑，直到所有检查通过；不得带已知问题交付。
