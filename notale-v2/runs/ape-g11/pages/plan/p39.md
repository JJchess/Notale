# page-39 · 月球任务总账 · **140 秒**

## 照这个写
`Lec.mount({index:39,kicker:"MISSION LEDGER",title:"五本账，必须同时闭合",take:"一次任务必须同时闭合速度增量、质量、时间、通信与生命保障预算"})`

```js
const profile = Lec.K.missions;
const checks = ["deltaV","mass","time","communication","lifeSupport"];
const pass = checks.every(key => state[key].used <= state[key].limit);
```

速度增量调用 `Lec.P.rocketDeltaV(exhaustVelocity,initialMass,finalMass)`；质量占比调用 `Lec.P.ratio`、`Lec.P.formatPercent`；时间调用 `Lec.P.formatDuration`；地月延迟调用 `Lec.P.moonSignalDelay()`、`Lec.P.moonRoundTripSignalDelay()`；进度调用 `Lec.P.progressPercent(passed,5)`。所有任务基准只读 `Lec.K.missions`、火箭参数只读 `Lec.K.rocket`，不另建同名常量。

## 知识结构：process
把任务设计显式化为一条反复回算的闭环：选择任务方案 → 分配质量 → 校验速度增量 → 校验时间与生命保障 → 接受通信约束 → 五账同时通过。五行总账上下对齐；任何控制变化都沿细线回流到受影响行，而不是按顺序点完即过。

## 表征形式
交互式工程总账。读者配置载荷、乘员、任务时长、推进剂与通信自主度；右侧五行实时显示“需求／可用／状态”，底部只在五项同时通过时开放“批准任务”。

## 五项预算检查
| 账目 | 读者配置 | 实时计算与显示 | 通过条件 |
|---|---|---|---|
| 速度增量 | 推进剂、有效载荷 | `Lec.P.rocketDeltaV(...)`；需求取 `Lec.K.missions` | 可用速度增量 ≥ 任务需求 |
| 质量 | 载荷、推进剂、乘员与保障 | 各项相加；占比 `Lec.P.formatPercent(Lec.P.ratio(part,total),0)` | 总质量 ≤ 运载上限 |
| 时间 | 任务时长：短／标准／延长 | 时长取 `Lec.K.missions`，用 `Lec.P.formatDuration` | 计划时长覆盖全部阶段 |
| 通信 | 地面依赖：高／中／低 | 单程、往返分别调用月球延迟接口 | 关键操作不要求即时地面响应 |
| 生命保障 | 乘员 × 任务日；冗余 0／1／2 天 | 需求按“乘员日”显示 | 储备 ≥ 任务需求且含 1 天冗余 |

## 必须点出来的一到三句
月球任务不是把某一项调到最大，而是让五项约束同时成立。增加载荷、乘员或停留时间，会把压力传到不止一本账上。

## 交互（只有这一个）
读者调整五个配置控件，观察五本预算如何联动，从中形成“局部改善可能破坏整体闭合”的直觉。

- 做对了立刻看到什么：对应行由灰转青绿，状态变为“已闭合”，细线接通至“任务批准”印章。
- 做错了立刻看到什么：超限行橙色抖动一次，并显示具体提示，如“质量超限：减少载荷或增加推进剂会继续挤压其他项目”“通信：月球往返延迟不允许实时遥控关键操作”。
- 做到哪儿了怎么知道：顶部固定显示“预算闭合 3 / 5”及五格进度灯。
- 做完了怎么收：五行同时通过后，橙色轨道从地球接通月球，“批准任务”盖章；保留“一键重置”，重置回初始未闭合方案。

## 场景构图
使用母题“脚印逐渐变成发光轨道点的路径”“地平线弧线”“航天手套的手掌尺度标记”。深蓝技术台像任务控制中心的纸质总账：顶部地球弧面与月球由一条断开的橙色轨道连接；中央五条横向账目如飞行检查单；底部航天手套按住待批准任务卡。青绿表示闭合，橙色只标当前超限项与最终接通瞬间。

## 动效
- 入场：五行账目从上到下依次滑入，地球到月球的轨道只绘制到三分之一处。
- 反馈：通过时连线沿该行向右点亮；失败时仅超限数字横向抖动；全通过时轨道在 700ms 内补全并落下批准印章。
