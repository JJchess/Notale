# 1. 这堂课在讲什么（你那一页必须服务于这个主张）

全课主张：人类并不是先拥有“适应一切的身体”才走出森林、迈向星空，而是不断把生存能力从身体扩展到工具、文化与维持微环境的技术系统中。

| 章 | 页 | 这一章要让读者信什么 |
|---|---|---|
| I 从一口空气开始 | 01–05 | 猿人与太空人面对的是同一个问题：怎样让脆弱生命跨过环境门槛 |
| II 身体走出森林 | 06–17 | 早期人族的身体变化不是笔直升级，而是在波动环境中形成的拼接式适应 |
| III 石头成为体外器官 | 18–27 | 工具、火、协作与文化传递，把个体无法积累的能力保存到群体之外 |
| IV 用技术随身携带地球 | 28–39 | 太空人的身体没有适应真空；航天技术把可居住环境包在身体周围 |
| V 两条进化通道 | 40–50 | 生物进化改变身体，文化技术改变选择压力；走向星空需要两者共同受约束 |

E1 远古环境不是稳定背景；气候、资源与地形的波动筛选了能移动、散热、取食并调整行为的身体组合。  
E2 石器、火、协作和教学把生存能力移到身体之外，使文化积累成为比个体学习更快的适应通道。  
E3 真空、微重力和辐射并未使太空人迅速“进化”；现代航天依靠压力边界与生命保障系统暂时替身体适应。  
E4 太空生存不是某件装备的胜利，而是资源闭环、冗余、维护和风险权衡组成的系统工程。  
E5 从走出森林到迈向星空，人类持续改变环境与选择压力；未来的“进化”会是身体、文化和技术的共同反馈。

无交互页：01、03、06、18、28、40、48、50；它们只承担开场、推进、过渡或收束。

你的页面只讲自己 `pNN.md` 写明的内容；其中“不许碰”的内容属于别页。越界或重复会让整堂 90 分钟课程塌掉。

# 2. 颜色语义（全套 50 页统一，不得挪用）

读者会在 50 页中不经说明地学会以下对应。相关概念出现时必须用绑定色；无关元素只用主题的中性灰阶。

| CSS token／色相 | 唯一语义 |
|---|---|
| 主题深炭黑 token／`#0B0F12` | 全套底色与生命边界之外的未知；主画面保持低亮度 |
| 主题赭石 token／`#C56A32` | 身体、化石、地层、生物进化的慢通道 |
| 主题电青 token／`#45D6E8` | 当前操作对象、压力边界、流动方向、即时反馈 |
| 主题中性灰阶 token | 其余文字、容器、辅助线、未被强调的信息 |

字体：标题与正文用主题无衬线体；年代和工程读数用主题等宽体；化石学名才可局部使用衬线斜体。  
材质：证据优先用写实照片，关系优先用线性科学示意图；生成插画只用于无法拍摄的远古场景或抽象生理过程。

统一母题按 `pNN.md` 需要选用：发青光的闭合“压力边界”；赭色脚印转为青色轨道弧；身体／工具双秤；远古沉积层转为任务时间轴；水、氧、热、废物构成的生命保障环。

禁止浅色论文页、蓝紫高饱和科幻界面、全套羊皮纸或洞穴壁画风；不得把“太空”预设为更先进的文明等级。

# 3. 知识结构——骨架约定（最重要的一条）

不要用“左右两栏”“卡片网格”这类容器思路搭页面；容器不是关系。

| 骨架 | 必须让读者一眼看见的关系 | 硬要求 | 什么样就算失败 |
|---|---|---|---|
| `process` | 先后、变化、因果或流向 | 用连续路径、箭头、状态差或时间推进连接各步 | 只是把三个块并排放着，不算 process |
| `comparison` | 同一维度下的差异与代价 | 共用基线、尺度、单位和比较维度 | 两边各画各的图、各用各的比例尺 = 失败 |
| `classification` | 上位概念与分支归属 | 层级、包含关系和分类依据必须可见 | 平铺的同级项，不算 classification |
| `generalization` | 主张由哪些证据支撑 | 主张最显著，证据明确汇入主张 | 主张和支撑一样重，不算 generalization |

`theme.css` 已提供 `.k-*` 原语，接口见 `assets/CHASSIS.md`。原语只是起点；SVG、canvas 或 DOM 能把同层关系画得更清楚就使用。硬要求是关系直接可见，不能让读者自行脑补拼接。

# 4. 交互的规矩

- 同一个关系只用一种交互讲透；禁止为同一变量同时做滑块、滚轮、拖拽，或用图表和模拟重复同一结论。
- 背后必须真算：教学常量、初值、范围、比较值和显示结果都从 `Lec.K`／`Lec.P` 取得并现场计算，公式与常数以 `pNN.md` 为准。正文出现科学数值却未引用 `Lec`，或把结果数字写死，即为违反。
- 随机必须引 `assets/lib/seedrandom.min.js`，并使用 `new Math.seedrandom('page-NN')`；同页每次打开结果必须一致。
- 首屏静止状态必须已经能讲，不能以“—”“等待操作”占据主要区域。动画用 `Deck.loop(fn,{still:t})` 给出有信息的定格；交互只负责再进一步。
- 有交互必须放一句 `.hint`，直接说明动作，字号不低于 14px。未要求交互时不得硬加；不服务理解的效果删除。

# 5. 技术契约

harness 已建好每页骨架，只往 `#stage` 加内容，其他部分不得改：

    <!doctype html>
    <html lang="zh">
    <head>
      <meta charset="utf-8">
      <link rel="stylesheet" href="assets/base.css">
      <link rel="stylesheet" href="assets/theme.css">
    </head>
    <body data-page="NN" data-total="50">
      <div id="stage"></div>
      <script src="assets/base.js"></script>
      <script src="assets/lec.js"></script>
    </body>
    </html>

- `data-page` 已按两位补零，`data-total="50"`；不得修改。画布固定 1600×900，不得出现滚动条。
- `#stage` 是 flex 列。顶层区域必须给固定高度或 flex 份额，主内容区用 `flex:1`；禁止让顶层区域按内容取高。主区内部默认 flex，不写死 px 高度；确需定高的图片框除外。
- 装不下就删短内容；禁止靠缩字号、行高或间距塞入。字号只用主题 token，不写裸 px：正文 ≥16px，控件标签、图例、图注、提示 ≥14px，纯数字刻度 ≥12px，多行文本行高 ≥1.35。
- 颜色、字体、圆角、阴影、间距只取 `theme.css` 变量和已有类。canvas 取色用 `Deck.rgb()`／`Deck.rgba()`。一次性尺寸可内联，如 `style="flex:2"`，不要为单个元素造类。
- 不得删除 `min0`、`cv-fill`、`no-pan`，不得覆盖其定位属性。缩放画布内禁用 `position:fixed`；固定叠层放在相对容器内并用 `position:absolute`。
- 默认用 flex；只有矩阵、维度表等真正二维对齐才用 grid。
- 库能完成的呈现不得从底层重写：常规图表用 ECharts，且 `echarts.init(el,null,{renderer:'svg'})`，全局字号 16、轴标签 14、图例 14；拖拽命中二维场景用 Konva，文字标签用 DOM；节点连线与数据驱动矢量图用 d3；三维用 three；碰撞、摆动、堆叠用 matter；上万元素运动用 pixi；多动画时间线用 gsap；公式用 KaTeX 并同时引 CSS，基准 ≥20px；矩阵用 ml-matrix。实时小神经网络用 `mlp.js`，真实图像卷积或大型 GPU 矩阵才用 tf.js。
- 手写 canvas 仅用于库覆盖不到的自定义图形，并用 `Deck.fit()`／`Deck.autofit()`；动画用 `Deck.loop()`；指针坐标用 `Deck.pt(el,e)`，不得用 `offsetX`。拖动区域加 `.no-pan`。
- 库版本与引用路径只查 `assets/lib/LIBS.md`，不读库源码。页面必须在 `file://` 下直接运行，只引用 `pages/` 下相对路径，禁用 CDN。

# 7. 文字风格

- 面向大学通识课、文理混合读者，不预设古人类学、航天工程或编程基础。术语首次出现就用一句短白话展开；说明句只承担一个意思，提示语用直接、友善的动作口吻。
- 讲课口吻，短句。禁用“如图所示”“我们可以看到”“接下来我们将探讨”和 AI 式元评论。
- 每个数字都给可感换算；不确定结论标明“目前有争议”等限定，不能把假设讲成定论。
- 始终用“极端环境中的生存”连接猿人与太空人：上半场讲身体与石器在远古环境中的拼接式适应，下半场讲技术系统在真空中维持生命；不得写成从落后到先进的胜利史。
- 收束句只写读者应带走的判断；下一问只写交给下一页的钩子。两句都不得改写成本页摘要。

# 8. 自检

写完用 `Check`，`page` 指向 `page-NN.html`。必须达到：0 个 JS 报错、0 个资源加载失败、0 个超出画布、0 个被裁切，最小字号 ≥12px。

交互页必须在 `after` 中逐个执行触发交互的 JS；每增加一段就多测一个状态。所有交互状态仍须 0 溢出、0 被裁、字号不低于地板；只测初始状态等于未自检。报告问题时用 `Look`，`box` 原样抄报告的 `@x,y w×h`；看清后用 `Patch` 修改，直到干净。

只交付 `page-NN.html`；不写测试或报告，不修改 `assets/` 下任何文件。

# 9. 版面密度与常见坑

- `Check` 的画面占用低于 45% 表示排空：收紧错误的 flex 分配，或扩大真正承载信息的图框、行距；不得靠装饰、放大字号或拉大间距填空。高于 85% 表示过挤：删减或拆分内容，禁止缩字号。
- 一页不得出现两块以上大面积空白。主关系必须占据视觉中心，标题、提示、收束不得把主内容挤成附属物。
- 顶层区域必须共同用满 900px；禁止用按内容取高的块把未分配死空间留在底部。
- 照片不加白框；canvas、动画、拖动和坐标换算必须分别遵守 `Deck.fit()`／`Deck.autofit()`、`Deck.loop()`、`.no-pan`、`Deck.pt()`。
