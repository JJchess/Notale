# 《从猿人到太空人：身体、文化与技术的接力》 90 分钟互动讲义 · 总规划

## 0. 这套讲义的主线

人类并不是沿着“低等猿人 → 高等太空人”的阶梯前进，而是在演化形成的身体上，用累积文化和集体技术不断扩展行动范围；进入太空没有让我们摆脱生物约束，反而让这些约束更加清楚。

| 章 | 页 | 这一章要让读者信什么 |
|---|---:|---|
| Ⅰ · 拆掉进步阶梯 | 01–06 | “Apeman – Spaceman”不是一条注定向上的直线，而是一个需要解释的问题。 |
| Ⅱ · 一种灵长类如何成为人 | 07–15 | 人类来自分支式演化；直立、工具、火、社会学习共同塑造了我们。 |
| Ⅲ · 身体之外的第二套演化 | 16–22 | 语言、合作、能源与制度使文化变化远快于基因变化，任何太空成就都是集体系统的产物。 |
| Ⅳ · 把演化来的身体送入太空 | 23–32 | 轨道、火箭和生命保障不是“征服自然”，而是对引力、质量与人体需求的精确妥协。 |
| Ⅴ · Spaceman 之后仍然是什么 | 33–41 | 太空未来是生物、技术与伦理共同选择的分岔口，不是单纯的速度竞赛。 |

### page-01 · 两个剪影之间
**章**：Ⅰ　**kicker**：`APEMAN — SPACEMAN`  
**标题**：`同一种动物，怎样走到地球之外？`  
**take**：`这堂课研究的不是一条英雄式进步史，而是身体、文化与环境如何共同变化。`  
**停留**：`1.5 分钟`

**内容**
- 画面只保留一名早期人属剪影、一名舱外航天员剪影和中间的问号。
- 教师请学生先在心中补完两者之间“最重要的一步”，暂不公布答案。

**采用的形式**：一张跨越整页的双剪影主视觉，不设交互。  
理由：用视觉距离制造问题，避免开场就用术语和时间表占满工作记忆。

**版式**：focus  
**必用skill**：theme-factory, make-illustration

**采用的形式**：实时投票条带与班级分布图。

### page-03 · 那张熟悉的错误图
**章**：Ⅰ　**kicker**：`NOT A LADDER`  
**标题**：`“弯腰猿 → 直立人 → 航天员”哪里错了？`  
**take**：`演化没有预先瞄准现代人，更没有预先瞄准太空。`  
**停留**：`2.25 分钟`

**内容**
- 展示一条故意制作的“进步队列”，学生点击其中可疑之处。
- 依次揭示三项问题：现代猿不是祖先、演化会分支和灭绝、环境适应不等于普遍进步。
- 把线性队列折叠成分支树，现代人与其他现生灵长类落在不同末端。

**采用的形式**：可纠错的“错误图”转化为分支树。  
理由：从学生熟悉的图像出发重组概念，比直接给出正确树更容易发现旧模型的问题。

**版式**：canvas-full  
**必用skill**：d3-viz, gsap-timeline

### page-09 · 选择不是“努力升级”
**章**：Ⅱ　**kicker**：`SELECTION GAME`  
**标题**：`环境筛选差异，不替物种制定目标`  
**take**：`自然选择改变的是不同特征留下后代的相对机会，不是个体朝目标主动升级。`  
**停留**：`2.25 分钟`

**内容**
- 一群具有可遗传差异的虚拟觅食者生活在周期变化的环境中。
- 学生只能改变环境条件，不能直接给个体“升级”；算法按觅食成功、存活与繁殖生成下一代。
- 使用 `Math.seedrandom('page-09')` 保证初始种群和课堂复看一致。
- 胜利条件是准确预测下一代特征分布的移动方向。

**采用的形式**：三代自然选择预测小游戏。  
理由：把“环境—差异—繁殖”的因果链变成可操作过程，并阻止目的论式操作。

**版式**：split-tb  
**必用skill**：mini-game

### page-10 · 直立不是免费升级
**章**：Ⅱ　**kicker**：`BIPEDAL TRADE-OFF`  
**标题**：`两足行走同时带来机会与代价`  
**take**：`一种适应通常重新分配成本，而不是让生物在所有方面都更优。`  
**停留**：`2.25 分钟`

**内容**
- 对照四足与两足姿态在视野、双手释放、移动和稳定性上的差异。
- 学生拖动身体重心，观察支撑区域与倾倒风险；模型按重心投影是否落在支撑面内判定稳定。
- 只讨论基础力学直觉，不引入微积分或复杂骨盆生物力学。

**采用的形式**：可拖动重心的侧视平衡实验。  
理由：让“权衡”通过身体稳定性被直接感知，而不是变成优缺点清单。

**版式**：triptych  
**必用skill**：matterjs

### page-14 · 文化为什么跑得更快
**章**：Ⅱ　**kicker**：`CUMULATIVE CULTURE`  
**标题**：`不等基因改变，方法就能跨代传播`  
**take**：`文化可以通过模仿、语言和记录横向传播，并在同一代内反复改进。`  
**停留**：`2.25 分钟`

**内容**
- 左侧模型只能让信息从亲代传给子代；右侧模型允许同代交流与记录。
- 学生启动同样数量的迭代，比较一项技巧覆盖群体所需的代数。
- 代际跨度用 `Lec.P.generationsAcross` 现算；随机传播使用固定种子的 `Math.seedrandom`。

**采用的形式**：并行运行的两种传播网络。  
理由：传播路径和速度差异需要动态网络，而不是“文化更快”四个字。

**版式**：split-tb  
**必用skill**：d3-viz

### page-20 · 体外器官
**章**：Ⅲ　**kicker**：`EXOSOMATIC TOOLS`  
**标题**：`衣服、望远镜、计算机和火箭都在扩展身体`  
**take**：`工具分别扩展保温、感知、记忆、计算和移动，但仍需要身体提出目标并承受后果。`  
**停留**：`2.25 分钟`

**内容**
- 中央人体周围连接五类功能：保护、感知、记忆、计算、运动。
- 学生拖拽物件到其扩展的功能；允许一个物件连接多个功能。

## 3. 数字口径

| 关键数值或关系 | 统一来源与计算口径 |
|---|---|
| 演化事件年代 | 从 `Lec.K.EVOLUTION` 读取；通过 `Lec.P.eventYearsBP` 转换为距今年数。 |
| 演化时间轴位置 | 使用 `Lec.P.eventTimelinePosition`；不得在页面中手写百分比位置。 |
| 物种存在时长 | 从 `Lec.K.EVOLUTION` 读取物种记录，使用 `Lec.P.speciesDurationYears`。 |
| 两物种共存时长 | 使用 `Lec.P.speciesOverlapYears`，不凭时间轴像素估算。 |
| 跨越的世代数 | 使用 `Lec.P.generationsAcross(years, generationYears)`；代长参数必须在页面显示。 |
| 历史事件位置 | 使用 `Lec.P.timelinePosition` 或 `Lec.P.eventTimelinePosition`，线性与对数尺度必须明确标注。 |
| 人体静息能量 | 使用 `Lec.P.restingEnergy`。 |
| 多人多日代谢能量 | 使用 `Lec.P.metabolicEnergy`。 |
| 能量换算为功率 | 使用 `Lec.P.powerFromEnergy`，页面必须同时显示对应持续时间。 |
| 天体质量、半径及基础常量 | 从 `Lec.K.BODY`、`Lec.K.COSMOS`、`Lec.K.UNIT` 读取。 |
| 天体表面重力 | 使用 `Lec.P.bodySurfaceGravity` 或 `Lec.P.surfaceGravity`。 |
| 相对地球重力 | 使用 `Lec.P.gravityRelativeToEarth`。 |
| 指定质量在天体上的重量 | 使用 `Lec.P.weightOnBody`；质量输入不随天体变化。 |
| 圆轨道速度 | 已选天体时使用 `Lec.P.bodyOrbitVelocity`；自定义质量与半径时使用 `Lec.P.circularOrbitVelocity`。 |
| 圆轨道周期 | 已选天体时使用 `Lec.P.bodyOrbitalPeriod`；自定义中心天体时使用 `Lec.P.orbitalPeriod`。 |
| 每日绕行圈数 | 使用 `Lec.P.orbitsPerDay`。 |
| 逃逸速度 | 已选天体时使用 `Lec.P.bodyEscapeVelocity`；自定义参数时使用 `Lec.P.escapeVelocity`。 |
| 发动机排气速度 | 由比冲通过 `Lec.P.exhaustVelocity` 计算；比冲数据从 `Lec.K.ROCKETS` 读取。 |
| 比冲 | 需要从排气速度反算时使用 `Lec.P.specificImpulse`。 |
| 火箭速度增量 | 使用 `Lec.P.rocketDeltaV`，输入必须明确显示湿质量与干质量。 |
| 所需火箭质量比 | 使用 `Lec.P.rocketMassRatio`。 |
| 推进剂质量比例 | 使用 `Lec.P.rocketPropellantFraction`。 |
| 火箭推力加速度 | 如任务检查需要，使用 `Lec.P.thrustAcceleration`。 |
| 推重比 | 如任务检查需要，使用 `Lec.P.thrustToWeight`。 |
| 生命保障质量 | 使用 `Lec.P.lifeSupportMass`；乘员、天数与循环比例均由页面当前状态传入。 |
| 单程光行时间 | 使用 `Lec.P.lightTravelTime`。 |
| 往返通信时间 | 使用 `Lec.P.roundTripLightTime`。 |
| 航行距离 | 使用 `Lec.P.travelDistance`。 |
| 航行时间 | 使用 `Lec.P.travelTime`。 |
| 光年与米换算 | 使用 `Lec.P.lightYearsToMeters`、`Lec.P.metersToLightYears`。 |
| 天文单位与米换算 | 使用 `Lec.P.auToMeters`、`Lec.P.metersToAu`。 |
| 霍曼转移速度增量 | 使用 `Lec.P.hohmannDeltaV`。 |
| 霍曼转移时间 | 使用 `Lec.P.hohmannTransferTime`。 |
| 天体尺度比较 | 使用 `Lec.P.bodyComparison`，不得手写质量比、半径比或逃逸速度比。 |
| 百分比与比例 | 分别使用 `Lec.P.percent`、`Lec.P.ratio`；界面显示时再按统一格式化规则处理。 |
| 数值舍入 | 使用 `Lec.P.round`、`Lec.P.significant` 或 `Lec.P.formatCompact`；计算内部保留原始精度。 |
| 单位换算 | 使用 `Lec.P.kmToM`、`Lec.P.mToKm`、`Lec.P.daysToSeconds`、`Lec.P.secondsToDays`、`Lec.P.yearsToSeconds`、`Lec.P.secondsToYears`。 |
| 页面随机模拟 | 一律使用 `Math.seedrandom`，并以页码作为固定种子的一部分；不得直接使用不可复现的 `Math.random()`。 |
| 模型性参数 | 凡 `Lec.K` 未提供、只用于课堂模型的参数，必须在页面标为“模型参数”，允许学生查看和修改，不得冒充经验测量值。 |
