# page-30 · 推进剂也要被推进 · **130 秒**

**Kicker：** `MASS CARRIES MASS`

**主标题：** 火箭先得运走自己的推进剂

## 知识结构：comparison

把“推进剂占比较低”和“推进剂占比较高”的火箭并排比较，显式对齐四个维度：初始总质量、燃尽质量、质量比、理想速度增量。

两列始终使用相同的归一化初始总质量与有效排气速度，只改变燃尽后仍需保留的质量。每列用嵌套关系呈现“载荷与结构被推进剂包裹”，再用燃烧前后态显示推进剂虽然会被消耗，却必须从地面一起加速。

比较关系由对齐行列和前后态共同建立：

- 横向：较低推进剂占比 ↔ 较高推进剂占比。
- 纵向：燃烧前总质量 → 燃烧后保留质量 → 质量比 → 理想速度增量。
- 列内：推进剂质量嵌套在初始总质量中，不画成外部能源。

## 表征形式

动态交互式二维侧视物理模型。

主画面是三个依次展开的 stage card：

1. **装载**：两枚火箭由等质量块组成，结构与载荷块固定保留，推进剂块数量不同。
2. **燃烧**：推进剂块逐批脱离并落入回收区；火箭读数随剩余质量实时变化。
3. **比较**：两枚火箭停在同一标尺上，以对齐表格比较质量比与理想速度增量。

Matter.js 只负责质量块的拖动、脱离、碰撞与堆积，让“被消耗的推进剂起初也是负担”具有可感知的重量。速度增量不由 Matter.js 的像素运动推算，而由 `Lec.P.rocketDeltaV()` 独立计算。

## 四行 × 两列

| 对齐维度 | 较低推进剂占比 | 较高推进剂占比 |
|---|---|---|
| 初始总质量 | 归一化为同一湿质量 | 归一化为同一湿质量 |
| 燃尽质量 | 保留较多结构与载荷块 | 保留较少结构与载荷块 |
| 质量比 | 较小的湿质量／干质量 | 较大的湿质量／干质量 |
| 理想速度增量 | 较小 | 较大，但随质量比按对数增长 |

画面中的质量类别固定为：

- **载荷**：氧化橙实心块；始终保留。
- **结构与发动机**：骨白框线块；始终保留。
- **推进剂**：轨道蓝液舱块；燃烧时逐批脱离。
- **燃尽质量**：载荷、结构与发动机之和。
- **湿质量**：燃尽质量与推进剂质量之和。

两列不得通过改变火箭尺寸、排气速度或载荷任务来制造差异；唯一比较变量是推进剂占初始总质量的比例。

### 公式与运行时数值

页面不写死任何任务数值。所有读数由当前质量块状态实时计算。

- 初始湿质量：
  `mWet = payloadMass + structureMass + propellantMass`
- 燃尽质量：
  `mDry = payloadMass + structureMass`
- 推进剂质量：
  `mPropellant = mWet - mDry`
- 质量比：
  `massRatio = mWet / mDry`
- 推进剂占比：
  `Lec.P.percent(mPropellant / mWet)`
- 保留质量占比：
  `Lec.P.percent(mDry / mWet)`
- 理想速度增量：
  `deltaV = Lec.P.rocketDeltaV(effectiveExhaustVelocity, mWet, mDry)`
- 反向校验质量比：
  `Lec.P.rocketMassRatio(deltaV, effectiveExhaustVelocity)`
- 质量读数：
  `Lec.P.formatNumber(mass)`，单位显示为“相对质量单位”
- 速度增量读数：
  `Lec.P.formatNumber(deltaV)`，单位随函数计算层使用 `m/s`
- 必须同时显示无量纲读数：
  `deltaVOverVe = deltaV / effectiveExhaustVelocity`
  页面当场计算并以 `Lec.P.formatNumber(deltaVOverVe)` 显示为 `Δv / vₑ`
- 所有百分比均由 `Lec.P.percent()` 格式化，不在标记中预写百分数。
- 有效排气速度由页面共享的单一演示参数传给两列；两列必须读取同一个运行时值，不允许分别调整。
- 每个 Matter.js 质量块的演示质量由所属类别总质量除以该类别当前块数计算；物理引擎中的质量与公式中的质量保持同一比例。

公式标注：

`Δv = vₑ ln(m湿 / m干)`

公式中的自然对数由 `Lec.P.rocketDeltaV()` 内部处理，页面不要求学生计算。公式旁必须标明：

“理想模型：忽略空气阻力、重力损失与发动机工作细节。”

## 必须点出来的一到三句

火箭必须从起点开始加速自己的推进剂；推进剂越多，起初要推动的质量也越大。

决定理想速度增量的不是“装了多少吨推进剂”本身，而是湿质量与燃尽质量之比。

## 交互（只有这一个）

学生在两个火箭卡片之间拖动推进剂质量块，保持两列初始湿质量相同；放入一块推进剂时，必须从同列的燃尽质量中移走等质量的结构或载荷块，反向操作亦然。

按下“燃烧”后：

- 推进剂块按固定顺序从火箭脱离，在 Matter.js 场景中下落、碰撞并堆积。
- 湿质量、剩余推进剂和瞬时剩余质量同步更新。
- 燃烧结束时锁定燃尽质量、质量比与 `Δv / vₑ`。
- 两列结果在同一行列中亮起差值，不用火焰长度或火箭飞行高度代替计算结果。
- 若两列配置相同，比较区明确显示“质量比相同，理想速度增量相同”。
- 若燃尽质量为零或出现负质量，拒绝放置并把质量块弹回原位，不调用火箭方程。
- “重置”只恢复本页初始比较状态，不设置胜负、计时或评分。

学生应形成的直觉是：把更多初始质量分给推进剂通常能提高质量比，但推进剂本身也必须先被运走；收益由质量比控制，并非与推进剂吨数线性对应。

键盘操作必须与拖拽等价：质量块可聚焦，以方向键选择列，以空格确认移动。开启减少动态效果时，推进剂块直接进入回收区，所有读数与比较结果保持一致。

## 不许碰

- 不把质量块组织成一级、二级、三级，也不允许在飞行中抛弃发动机、贮箱或结构；多级火箭如何及时丢掉无用结构只在 p31 展开。
- 不比较级数，不提供“最佳分级”提示，不出现级间点火、分离时机或分级优化。
- 不把本页扩展成任务预算；载荷、安全、成本与时间的综合交换留给 p33。
- 不重新讲“跳得高不等于入轨”或轨道速度直觉；这些沿用 p26–p29。
- 不把理想速度增量称为实际入轨速度，不补入空气阻力、重力损失或发动机效率的精细模型。
- 不把推进剂质量等同于燃料质量；画面统一称“推进剂”，不另行展开燃料与氧化剂组成。
- 不用 Matter.js 中火箭的位移、弹跳高度或像素速度代表真实火箭性能。
