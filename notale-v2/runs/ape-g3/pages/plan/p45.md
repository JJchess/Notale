# page-45 · 谁被标准看见 · **145 秒**

**Kicker：ACCESS BY DESIGN**

# 改写标准，也在改写“谁能代表人类”

## 知识结构：comparison

把同一项航天任务的两套招募方案并排比较：左列是以履历代理任务能力的“门槛式标准”，右列是把任务拆成可验证能力的“任务式标准”。

四行严格对齐，使学习者逐行看见：

1. 标准怎样表述；
2. 标准与任务的联系是否可解释；
3. 候选人怎样证明能力；
4. 哪些人会在进入考核前被排除。

每次改写一行，左右两列保持同一任务目标，右侧候选池同步更新。比较的是标准设计及其准入后果，不是候选人的人格高低。

## 表征形式

交互式左右分栏筛选模拟。

左侧固定呈现“原招募简章”，右侧呈现可改写的“任务导向简章”。中央使用对齐连线标明每条标准服务的任务：操作复杂系统、处理突发故障、跨专业协作、向地面清楚报告。

底部是一排虚构候选人卡片。卡片只展示与任务相关的可公开履历和能力证据；入选、待验证、被门槛排除三种状态随标准变化即时更新。所有候选人使用同等视觉权重，不设置默认“理想航天员”形象。

## 四行 × 两列

| 比较维度 | 门槛式标准 | 任务式标准 |
|---|---|---|
| 标准表述 | 用特定职业头衔、单一路径或笼统的“优秀背景”代替能力说明 | 写明任务中必须完成的行为，以及成功条件 |
| 任务联系 | 读者难以判断门槛为什么必要 | 每条要求连接到一项明确任务，不相关的要求不得保留 |
| 证明方式 | 主要依赖既有头衔、机构经历或单一履历标签 | 允许用工作样本、情景测试、模拟操作或可核验经历证明 |
| 准入后果 | 在实际能力被观察前先缩小候选来源 | 扩大进入考核的路径，但不降低任务表现要求 |

模拟采用四项任务能力：

- **复杂系统操作**：按程序监控状态、识别异常并正确交接。
- **故障处置**：在信息不完整时排序问题、说明依据并修正方案。
- **跨专业协作**：理解角色边界、共享关键信息并接受纠错。
- **任务沟通**：把观察、判断与不确定性清楚传给队友和地面团队。

候选人卡片采用虚构、去身份化资料，只呈现不同的能力证明路径：

- 通过高风险设备运行经历证明系统操作；
- 通过现场维修与应急演练证明故障处置；
- 通过科研外业与数据记录证明观察和报告；
- 通过复杂项目协调证明跨专业协作；
- 通过模拟任务样本证明多项能力，但没有传统航天职业头衔；
- 具有传统航天相关履历，但仍需完成同一任务测试。

画面数值仅包括：

- **当前可进入考核人数**：运行时统计未被硬门槛排除的候选人卡片数，算法为 `candidates.filter(candidate => passesEntryRules(candidate, rules)).length`。
- **当前满足任务证据人数**：运行时统计四项任务能力均达到当前证据条件的候选人卡片数，算法为 `eligibleCandidates.filter(candidate => requiredCapabilities.every(capability => hasEvidence(candidate, capability))).length`。
- **被标准提前排除人数**：候选人总数减去当前可进入考核人数，运行时计算，不写死。
- **任务覆盖项数**：当前标准已明确连接的任务能力去重计数，运行时由 `new Set(activeRules.map(rule => rule.capabilityId)).size` 计算。
- **无任务依据的门槛数**：当前启用且没有 `capabilityId` 的规则数，运行时筛选计算。

所有计数使用 `Lec.P.formatNumber()` 显示；候选人总数、规则数和能力项数均从页面配置数组长度取得，不在显示层写死。页面不显示年龄、体检指标、疾病信息或任何个体医疗数值。

## 必须点出来的一到三句

招募标准既反映任务需求，也会决定谁有机会代表人类。

把履历门槛改成可验证的任务能力，可以扩大进入考核的路径；扩大路径不等于降低任务要求。

## 交互（只有这一个）

学生在右侧把左栏的门槛式条款改写为任务式条款：为每条要求选择它服务的任务能力，并把“限定某种背景”改为“允许多种证据路径”。

每次改写后：

- 中央任务连线即时建立或消失；
- 底部候选人卡片重新分为“可进入考核”“仍需补充证据”“被门槛提前排除”；
- 顶部计数同步更新；
- 系统突出显示“准入人数变化”和“任务能力覆盖是否变化”，不宣告唯一最优组合。

默认状态先呈现：传统履历门槛筛出较窄的候选池，但部分条款与任务能力没有清楚连线。学生完成全部改写后，应观察到候选来源可能扩大，而四项任务能力仍全部需要证据。

课堂节奏：

- 前 25 秒：教师让学生只看左右标准措辞，指出两列都声称在挑选“胜任者”。
- 中间 85 秒：学生改写条款，观察同一批候选人的准入状态怎样变化。
- 后 35 秒：教师锁定最终状态，对照“准入路径是否扩大”与“任务要求是否保留”两个结果收束。

交互只比较标准设计，不设置胜负、总分、人格评价或“最像航天员”排名。

## 不许碰

- 不讨论任何候选人的病史、体检结果、残障诊断、生殖信息、心理记录或其他个体医疗隐私；相关伦理冲突留给 p46。
- 不把某一国家、机构或年代的现行航天员标准写成自然、普遍或永久规则。
- 不声称所有传统资格都无效；每条资格是否保留，只看能否解释其与具体任务的联系。
- 不把扩大申请来源写成自动录取，也不把公平简化为降低安全要求。
- 不重复 p44 的出资者、受益者与风险承担者分布。
- 不进入 p46 的自主、救援义务、公共成本或医疗伦理审议。
- 不评价真实航天员或真实申请者，不使用真实个人作为“合格／不合格”案例。
- 不按性别、族群、国籍、社会阶层或专业背景给候选人打能力分；若身份差异出现在辅助说明中，只用于提示标准可能产生不同准入后果。
