# page-16 · 没有完美骨盆 · **140 秒**

**Kicker：** `BODY / TRADE-OFF`  
**主标题：** 骨盆要同时完成几种任务

## 知识结构：classification

把“骨盆折中”显式分成一个主类与三条并列约束分支：

- 主类：骨盆是同时响应多项目标的结构。
- 分支一：行走——连接躯干与下肢，并传递运动中的力。
- 分支二：支撑——承托躯干、连接肌肉与保护盆腔内结构。
- 分支三：分娩——产道需要允许胎儿通过。

画面以主干分支呈现：中央“骨盆结构”装配区连向三张目标卡。学生每替换一个结构模块，三张卡同步显示“受益 / 受限 / 基本不变”，让同一改变在不同类别中的归属与后果对齐出现。

分类目的不是寻找“最好骨盆”，而是识别：同一结构特征可能服务一个目标、限制另一个目标；最终形态属于多目标约束下的可行组合。

## 表征形式

交互式二维结构模型，用 Konva 绘制正面简化骨盆轮廓、模块插槽、三张目标卡与连接线。

骨盆不是写实解剖模型，不呈现可供医学判断的精细尺寸；只保留理解折中所需的结构关系：

- 躯干承重区
- 左右髋关节连接区
- 盆腔通道区
- 肌肉与软组织作用的简化边界

模块被放入后，轮廓以短暂形变动画过渡；三条分支分别亮起反馈。任何方案都不得显示为全项“最优”，成功状态定义为三个目标均达到“可行”，而非某一目标达到极端。

## 层级里的各项

### 主类：多目标骨盆

中央标签：

- **骨盆结构**
- 副标签：连接躯干、下肢与盆腔

中央结构只表达“一个结构同时被多个任务使用”，不把骨盆拆成互不相关的独立零件。

### 行走分支

目标卡标题：**传力与稳定**

卡内判据：

- 躯干的力能否传向左右下肢
- 髋关节连接是否保持在可用位置
- 单脚支撑时是否保留足够的肌肉作用条件

反馈词：

- 有利
- 可行
- 受限

不显示步态速度、能耗或跑步能力；这些属于 p14–15。

### 支撑分支

目标卡标题：**承托与连接**

卡内判据：

- 是否形成连接脊柱与下肢的稳定环
- 是否保留肌肉和韧带作用的附着边界
- 是否为盆腔内结构提供基本承托与保护

反馈词：

- 有利
- 可行
- 受限

“支撑”不等于骨盆越厚、越重越好；极端增大结构同样会给其他任务带来限制。

### 分娩分支

目标卡标题：**通过空间**

卡内判据：

- 盆腔通道是否连续
- 入口、中段与出口是否共同保持可通过性
- 扩大局部空间时，是否牵动行走与支撑条件

反馈词：

- 有利
- 可行
- 受限

只讲通道与结构约束，不呈现分娩过程，不给出临床阈值，不讨论医疗处置。

### 可装配模块

每个插槽提供成组的抽象方案，不标成“男性型”“女性型”，也不标成演化阶段：

- **髋关节连接位置：**更偏外 / 居中 / 更偏内
- **盆腔通道轮廓：**偏紧凑 / 居中 / 偏开阔
- **承重环形态：**偏轻窄 / 居中 / 偏厚宽

页面不显示角度、直径、面积、载荷或百分比分数。所有结果均以离散状态呈现，避免把教学模型误读成真实人体测量。

状态判定由 `Lec.K.p16PelvisTradeoffModel` 提供模块组合与三类目标的结果映射；页面组件不得自行写死判定表。输入组合先经 `Lec.P.finite(...)` 与 `Lec.P.clamp(...)` 校验索引，再读取对应结果。

若需要内部动画插值，使用归一化进度，由交互状态计算；该进度不出现在画面上。页面上没有需要展示的真实数值、单位或临床参考范围。

## 必须点出来的一到三句

骨盆同时承担行走、支撑与分娩，多目标不会产生完美结构。

一个改变可能改善某项目标，却限制另一个目标；“折中”不是缺陷，而是共享结构面对多重约束的结果。

## 交互（只有这一个）

**拼装骨盆折中**

学生把三类模块分别拖入中央骨盆的对应插槽，完成一个组合。

每次放置后：

- 骨盆轮廓立即更新。
- “行走、支撑、分娩”三张目标卡同步切换为“有利、可行、受限”。
- 从被替换模块到受影响目标卡出现短暂连线，明确“哪个结构变化影响了哪个目标”。
- 若某一目标受限，该卡只说明约束关系，不使用“畸形、退化、失败”等词。

游戏目标：拼出一个让三张目标卡都达到“可行”或更高状态的组合。

成功后不授予“完美骨盆”称号，而显示：

**可行组合：三个目标都能工作，但没有一个目标被无限最大化。**

若学生连续选择极端模块而使任一目标受限，显示针对性的因果提示，例如：

- “通道更开阔，同时改变了髋关节与承重环的关系。”
- “承重结构更厚，并不自动让所有任务都更好。”
- “先检查受限卡，再替换与它相连的模块。”

提供“重置”按钮，恢复为空插槽；提供“换一种可行组合”按钮，让学生验证可行解不止一个。成功条件、状态与重置结果通过小游戏统一接口上报，不设置积分榜、倒计时或速度奖励。

键盘操作支持在模块间移动焦点、选择模块、切换插槽与放置；状态变化同时用文字和图形表达，不只依赖颜色。拖放热区大于可见模块边界，错误放置自动返回原位。

学生应形成的直觉：骨盆不是分别为三个任务制造的三件东西，而是同一结构必须同时满足多个不能完全一致的要求。

## 不许碰

- 不讲现代产科，包括剖宫产、助产技术、临床风险评估、产程管理与医疗建议。
- 不展示或解释临床骨盆测量值，不让学生据此判断任何真实个体的分娩能力。
- 不把骨盆简单分成固定的“男性骨盆 / 女性骨盆”模板，不把个体差异写成二元本质。
- 不宣称存在一个单一、确定、已经解决全部争议的“产科困境”解释。
- 不把分娩约束归结为单一原因，也不提前展开脑扩张及其成本；脑的能力、能耗与分娩成本留给 p17–18。
- 不重复 p13 的骨盆—脊柱—下肢三维结构，不展开 p14 的步态动力学或 p15 的耐力与散热假说。
- 不把折中描述为设计失误、身体缺陷或演化朝某个目标做出的计划。
- 不使用“更先进”“更原始”“最优人类骨盆”等目的论或等级化表述。
