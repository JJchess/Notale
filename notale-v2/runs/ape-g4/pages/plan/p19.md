# page-19 · 手不是一把钳子 · **105 秒**

**Kicker：BODY / GRIP**

**主标题：一次抓握，怎样由整只手完成？**

## 知识结构：process

把抓握显式化为一条带反馈回路的过程，而不是“手指弯曲”这一单步动作：

**确定目标 → 手掌定位 → 拇指对向 → 手指包合 → 感觉校正 → 形成稳定抓握**

主画布中央是一只侧前方视角的简化手掌。六个 step 沿手的外缘依次点亮，以箭头连接；“感觉校正”另有一条回箭头指向“拇指对向”和“手指包合”，表示抓握会根据滑动、压力与物体位置持续调整。

学生完成一次力量握和一次精细握后，画布保留两个半透明前后态轮廓：两者都调用骨骼、肌肉与感觉反馈，但接触范围、用力分配和动作容错不同。

## 表征形式

交互式二维物理实验。

Matter.js负责物体的质量感、碰撞、摩擦、滑落和稳定状态；Konva负责手掌、指骨关节、肌腱牵引线、接触区域、六步流程标注及反馈覆盖层。

手不是写实解剖模型，而是教学用的功能模型：

- 手掌作为稳定基座。
- 四指各由可弯曲的简化指节链表示。
- 拇指具有“张开—对向”和“屈曲—压合”两个可控方向。
- 肌肉不画成独立可拖动物体，只以牵引线和张力变化表示。
- 触觉以接触点亮起、滑动警示和压力分布变化表示。
- 练习以第二次操作时保留上一次成功姿态的淡色轮廓表示，不宣称短时操作产生生物结构改变。

画布提供两种并列任务，但属于同一个实验流程：

- **力量握**：用手掌与多根手指包住较大的物体并将其提起。
- **精细握**：用拇指与一根手指夹住较小物体并移动到目标区。

## 六个 step

### 1. 确定目标

任务物体出现，目标区同时显现。物体的形状、尺寸、质量和表面摩擦共同决定后续抓握方式。

力量握使用可被手掌包合的圆柱体；精细握使用只能由指端稳定夹持的小片状物。两者不以“难度高低”排序。

### 2. 手掌定位

学生拖动腕掌基座，使手掌接近物体。

离物体过远时，手指即使完全弯曲也无法建立有效接触；位置合适时，可能接触的区域以低亮轮廓提示，但不自动吸附。

### 3. 拇指对向

学生拖动拇指控制柄，使拇指朝向其他手指形成夹持面。

若只弯曲四指而不让拇指参与，圆柱可能短暂被托住，小片状物则容易旋转或滑落。这里强调拇指与其他手指的空间配合，不把“拇指”单独写成人手能力的唯一来源。

### 4. 手指包合

学生拖动统一的“屈曲”控制柄；可再展开单指微调。

力量握中，多根手指与手掌扩大接触并共同抵抗物体滑动；精细握中，指端接触位置和方向比接触面积更关键。关节链受范围限制，不能穿过物体或向不可能的方向反折。

### 5. 感觉校正

接触后，学生看到三类即时反馈：

- 接触点稳定：柔和常亮。
- 接触点持续滑动：沿滑动方向闪动。
- 局部压力过度集中：颜色升温，但不显示为疼痛或损伤诊断。

学生根据反馈调整拇指位置、手指弯曲或整体握力。关闭“感觉反馈”后，物理结果不变，但接触与滑动提示消失，用来体验缺少反馈时为何更难及时校正。

### 6. 形成稳定抓握

物体被提离支撑面并保持稳定后，系统冻结一帧成功姿态，描出：

- 参与接触的手掌或指端区域；
- 各手指的相对位置；
- 物体的重心投影；
- 抵抗滑动的合成接触方向。

完成另一种抓握后，两种姿态并置短暂比较。结论落在协作过程，不评选“更高级”的抓握方式。

## 抓握模型与页面量

画面不展示真实人体的固定握力、关节角度或肌肉力量数值，避免把教学模型误写成生理测量。

如显示操作量，全部来自以下页面级参数与计算，不在组件中写死：

- 物体质量：从 `Lec.K.p19GripObjects[task].massKg` 读取；显示单位为 `kg`，经 `Lec.P.formatNumber(...)` 格式化。
- 物体重量：由 `Lec.P.weight(massKg, Lec.K.standardGravityMS2)` 计算；仅在教师展开“模型参数”时显示，单位为 `N`。
- 接触摩擦参数：从 `Lec.K.p19GripObjects[task].frictionScenario` 读取；主画面只显示“较滑 / 中等 / 较涩”的情景标签，不把简化系数称为人体皮肤实测值。
- 手指关节活动范围：从 `Lec.K.p19HandModel.jointLimits` 读取，仅用于约束模型，不在主画面显示角度。
- 拇指对向范围：从 `Lec.K.p19HandModel.thumbOppositionLimits` 读取，仅用于约束模型。
- 控制输入：先经 `Lec.P.finite(...)` 检查，再经 `Lec.P.clamp(...)` 限制到对应关节范围。
- 握力控制比例：由当前输入与允许输入的比值计算，经 `Lec.P.ratio(...)` 和 `Lec.P.percent(...)` 生成；若显示，单位为 `%`，明确标注“模型控制量”，不称真实握力。
- 接触稳定度：由观察窗口内物体位移、角速度和有效接触持续时间共同计算，阈值统一从 `Lec.K.p19GripStabilityThresholds` 读取；主画面只显示“滑动 / 调整中 / 稳定”。
- 练习对照：第一次成功姿态与第二次尝试姿态的关节位置差，由页面当场计算；只以轮廓重合程度表现，不显示“技能提升百分比”。
- 所有物理步长、约束刚度、阻尼、碰撞分组和判稳时长均从 `Lec.K.p19GripSimulation` 读取，不作为人体事实展示。
- 页面停留提示若出现，读取课程页表中的 `105 s`，经 `Lec.P.formatDuration(...)` 显示，不在组件内写死。

## 必须点出来的一到三句

人手的力量握与精细握，不是某一根手指单独完成的；它们来自骨骼约束、肌肉牵引、感觉反馈和练习的协作。

## 交互（只有这一个）

**抓握手指实验**

学生依次完成“握住圆柱”和“夹起薄片”两个动作：

1. 拖动手掌接近物体。
2. 调整拇指对向。
3. 弯曲四指，并按需微调单指。
4. 提起或移动物体。
5. 根据接触、滑动和压力反馈修正动作。
6. 切换感觉反馈，再尝试同一动作。

学生看到物体是否旋转、滑落或稳定，接触区域如何改变，以及力量握与精细握调用了哪些不同的接触配置。

交互要形成的直觉是：成功抓握不是“把力加大”就够了；手的结构提供可能范围，肌肉产生动作，感觉负责在线修正，练习帮助更快找到合适的协作方式。

提供“重置本次动作”，不设积分、排行榜或胜负。键盘操作可在手掌、拇指、四指屈曲和单指微调之间切换；关闭动态效果时，滑落与校正改用离散状态和轮廓变化表达。

- 不讲模仿、教学、知识保存和跨代文化累积；这些属于 p27。

- 不把二维物理参数当作真实握力、肌肉力量、皮肤摩擦或临床关节活动度。

## 版面提示

采用 `canvas-full`：手与任务物体占据画布中央约三分之二区域，六步流程沿外缘形成顺时针路径；控制器贴近对应部位，不另设远离手模型的仪表盘。

左上角仅保留 kicker、主标题和一句操作提示；右上角切换“力量握 / 精细握”；底部放置感觉反馈开关、重置和无障碍键盘提示。成功后的两种抓握轮廓在画布两侧短暂并置，不跳转到新面板。
