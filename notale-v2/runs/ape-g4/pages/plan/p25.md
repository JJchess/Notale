# page-25 · 先在体外处理食物 · **140 秒**

- kicker：`OUTSOURCED DIGESTION`
- 主标题：烹饪不只加热：它同时改写能量、咀嚼与风险

## 知识结构：comparison

把“同一份食物，生食与烹饪后有什么不同”显式化为对齐的两列比较。

- 左列固定为“未烹饪基线”，右列为“烹饪后”。
- 两列使用相同起始食物、质量和化学能，只改变加工状态。
- 四行依次对齐：食物结构、可获取能量、咀嚼成本、安全风险。
- 每行中央放方向标记：上升、下降或依食物与火候而变；不把所有效果合成一个“更先进”总分。
- 下方实验台用同步前后态补充表格：同一咬合压力作用于两组食物颗粒，直接比较破碎、吞咽所需次数与风险指标。

## 表征形式

交互式上下分屏比较。

上半屏是稳定的两列 × 四行比较板，保证学习者始终能逐维对齐“未烹饪／烹饪后”。下半屏是 Matter.js 侧视实验台：两只透明咀嚼槽接收相同质量的同类食物颗粒，左槽保持生食参数，右槽随加热程度改变颗粒连接强度、弹性和风险标记。

实验台不模拟真实口腔、消化道或微生物运动，只把三个难以同时观察的量转成可比较反馈：

- 颗粒破碎难度代表食物结构与咀嚼成本；
- 破碎后可释放区域代表模型中的可消化吸收比例；
- 残留风险标记代表简化安全风险指数。

## 四行 × 两列

### 共同输入

两列顶部始终显示相同输入，避免把“吃得更多”误认成“加工后更容易获取”。

- 食物类型：取自 `Lec.K.p25FoodScenarios`，页面至少提供块根、肉类、谷物三种教学情景；名称不带数值。
- 初始食物质量：显示 `Lec.P.formatNumber(foodMassKg * 1000)` g；`foodMassKg` 由 `Lec.P.clamp` 限制在 `Lec.K.p25FoodMassRangeKg`。
- 单位质量化学能：显示 `Lec.P.formatNumber(scenario.grossEnergyJPerKg / 1000)` kJ/kg，来自当前 `Lec.K.p25FoodScenarios` 条目。
- 初始化学能：显示 `Lec.P.formatNumber(foodMassKg * scenario.grossEnergyJPerKg / 1000)` kJ，由页面当场计算。
- 加热程度：左列固定取 `Lec.K.p25RawProcessingLevel`，右列由控件给出无量纲加工比例，并以 `Lec.P.percent(processingLevel)` 显示；输入先经 `Lec.P.finite` 与 `Lec.P.clamp`。
- 证据标签：各食物情景从 `Lec.K.evidenceLabels` 读取“较确定”或“有支持但仍争议”；模型输出统一标“模型推测”。

`Lec.K.p25FoodScenarios` 的每个条目必须分别存储生食基线、加热响应范围和适用说明，不得用一种食物的参数替代所有食物。页面不写死任何默认质量、能量密度或加工百分比。

### 第一行：食物结构

**未烹饪**

- 显示“结构完整度”及无量纲结构指数，格式为 `Lec.P.percent(rawStructureIndex)`。
- `rawStructureIndex` 来自当前食物情景的 `rawStructureIndex`，输入经 `Lec.P.clamp`。
- Matter.js 颗粒间约束强度由 `Lec.P.p25StructureStrength(rawStructureIndex, scenario.materialResponse)` 计算。

**烹饪后**

- 显示加工后的结构指数 `Lec.P.percent(cookedStructureIndex)`。
- `cookedStructureIndex = Lec.P.p25CookedStructureIndex(scenario, processingLevel)`。
- 对多数教学情景，颗粒连接会随加工减弱；若某情景存在干燥、结壳等非单调响应，函数按该情景曲线计算，页面不得强制显示“越热越软”。

中央标记显示 `Lec.P.p25Direction(rawStructureIndex, cookedStructureIndex)` 的结果，只允许“较高”“接近”“较低”，不显示无来源的效果倍数。

### 第二行：可获取能量

**未烹饪**

- 可消化吸收比例：`Lec.P.percent(rawDigestibleFraction)`，来自当前情景的 `rawDigestibleFraction`。
- 咀嚼能量成本：`Lec.P.formatNumber(rawChewingEnergyJ / 1000)` kJ。
- 净可获取能量：`Lec.P.formatNumber(rawNetAvailableEnergyJ / 1000)` kJ。

**烹饪后**

- 可消化吸收比例：`Lec.P.percent(cookedDigestibleFraction)`。
- 咀嚼能量成本：`Lec.P.formatNumber(cookedChewingEnergyJ / 1000)` kJ。
- 净可获取能量：`Lec.P.formatNumber(cookedNetAvailableEnergyJ / 1000)` kJ。

计算统一为：

- `rawDigestibleFraction = Lec.P.p25DigestibleFraction(scenario, Lec.K.p25RawProcessingLevel)`
- `cookedDigestibleFraction = Lec.P.p25DigestibleFraction(scenario, processingLevel)`
- `grossEnergyJ = foodMassKg * scenario.grossEnergyJPerKg`
- `absorbedEnergyJ = grossEnergyJ * digestibleFraction`
- `chewingEnergyJ = Lec.P.metabolicEnergy(chewingPowerW, chewingDurationSeconds)`
- `netAvailableEnergyJ = Lec.P.p25NetAvailableEnergy(absorbedEnergyJ, chewingEnergyJ)`

`Lec.P.p25NetAvailableEnergy` 必须阻止负值和非有限值；所有比例经 `Lec.P.clamp`。这里的“净”只扣除页面模型中的咀嚼代谢成本，不扣除烹饪燃料、采集、储存或全身消化代谢成本，标签旁明确写出该口径。

### 第三行：咀嚼成本

**未烹饪**

- 达到吞咽粒径所需咬合次数：显示 `Lec.P.formatNumber(rawBiteCount)` 次。
- 模型咀嚼时长：显示 `Lec.P.formatDuration(rawChewingDurationSeconds)`。
- 咀嚼功率：显示 `Lec.P.formatNumber(rawChewingPowerW)` W。

**烹饪后**

- 达到同一吞咽粒径所需咬合次数：显示 `Lec.P.formatNumber(cookedBiteCount)` 次。
- 模型咀嚼时长：显示 `Lec.P.formatDuration(cookedChewingDurationSeconds)`。
- 咀嚼功率：显示 `Lec.P.formatNumber(cookedChewingPowerW)` W。

计算统一为：

- 每次咬合的平均时长来自 `Lec.K.p25ChewingModel.biteDurationSeconds`。
- `chewingDurationSeconds = Lec.P.p25ChewingDuration(biteCount, biteDurationSeconds)`。
- `biteCount` 由实验台达到 `Lec.K.p25ChewingModel.swallowParticleSizeM` 所需的物理步数换算，不直接写死。
- `chewingPowerW` 来自 `Lec.P.p25ChewingPower(scenario, structureIndex)`。
- 两列使用相同的 `swallowParticleSizeM`、求解步长和咬合器运动幅度。

Matter.js 的碰撞次数不是现实中的咀嚼次数；显示值必须标为“教学模型”。

### 第四行：安全风险

**未烹饪**

- 显示风险指数 `Lec.P.formatNumber(rawRiskIndex)`，单位为“模型点”。
- 风险构成以三段细条显示：病原风险、食源性毒素风险、加工副产物风险；各段分别来自当前食物情景，不得合成后隐藏来源。

**烹饪后**

- 显示风险指数 `Lec.P.formatNumber(cookedRiskIndex)` 模型点。
- `cookedRiskIndex = Lec.P.p25SafetyRiskIndex(scenario, processingLevel)`。
- 风险变化显示为 `Lec.P.p25Direction(rawRiskIndex, cookedRiskIndex)`。
- 风险构成分别由：
  - `Lec.P.p25PathogenRisk(scenario, processingLevel)`
  - `Lec.P.p25ToxinRisk(scenario, processingLevel)`
  - `Lec.P.p25ProcessingByproductRisk(scenario, processingLevel)`
  计算，再由 `Lec.P.p25SafetyRiskIndex` 按 `Lec.K.p25SafetyRiskWeights` 汇总。

“模型点”是相对比较尺度，不是患病概率、病例数或医学安全阈值。加工不足时病原风险可能仍高；加工过度时副产物风险可以回升，因此不得把右列永久编码成绿色或“安全”。

## 必须点出来的一到三句

烹饪改变食物的可获取能量、咀嚼成本和安全风险；这三个维度必须分别比较。

它常能减少身体在进食前后要完成的一部分工作，但效果取决于食物种类与加工方式，并非“越熟越好”。

## 交互（只有这一个）

交互名：烹饪能量实验台。

读者只操作右侧的“加热程度”推杆，并可在每轮开始前切换食物类型；左侧未烹饪基线始终不动。推杆是同一个核心操作，不另设温度、时间、切碎程度或燃料控件。

一次操作流程：

1. 选择食物情景后，两只槽装入相同质量、相同初始化学能的颗粒。
2. 拖动加热推杆，右槽颗粒的约束强度、可释放区域和风险标记同步更新；上方右列四行数值实时重算。
3. 按“同时咀嚼”，两侧咬合器以相同运动幅度和频率压碎颗粒。
4. 任一侧达到同一吞咽粒径时停止该侧计数；另一侧继续，直到达到阈值或到达 `Lec.K.p25ChewingModel.maxBiteCount`。
5. 实验结束后，高亮三项差值：净可获取能量、咬合次数、风险指数；不生成综合分数，也不判定唯一最佳火候。
6. “重置”恢复当前食物的默认教学情景；不保留排行榜。

读者应形成的直觉：烹饪是在进食前把一部分结构破坏和风险控制移到身体之外；同一加工变化可能让一个指标改善、另一个指标变化较小或反向变化。

无障碍与降级：

- 所有拖动都提供键盘方向键操作和数值输入。
- 颜色之外同时使用箭头、纹理和文字标记升降。
- 开启减少动态效果时，不运行连续碰撞动画，改为按相同步骤显示初态、破碎态和结果态。
- Matter.js 求解结果必须固定初始颗粒布局与时间步长，保证同一输入可复现。
- 物理模拟只决定视觉破碎与模型咬合次数；能量和风险数值必须由 `Lec.P` 计算，不从像素位置反推。

## 不许碰

- 不宣称烹饪单独造就大脑，也不把净可获取能量的变化直接画成脑容量增长；脑的能耗与能力已由 p18 承担。
- 不提出“控制用火导致人类出现”的单因果链。
- 可以在角标调用 `Lec.K.controlledFireEvidenceYearsAgo`，显示“较稳妥证据量级约 `Lec.P.formatNumber(...)` 年前”，并附 `Lec.K.evidenceLabels`；不得把更早争议证据并入同一个确定年代。
- 不展开牙齿、磨耗或同位素如何重建古代食谱；这些属于 p20。
- 不讨论工具动作序列、文化跨代累积或语言教学；这些分别属于 p26–28。
- 不把教学情景中的吸收比例、风险指数或咬合次数称为所有人、所有食物的实测常数。
- 不把“熟食”统一标成安全，也不提供现实食品安全温度或医疗建议。
- 不讨论现代烹饪制度、农业起源、学校教育或大脑演化的完整假说。

## 版面提示

采用 `split-tb`。

- 上部约占页面高度的五分之二：左“未烹饪”、右“烹饪后”，四行严格共用水平基线；中央窄列只放方向标记。
- 下部约占五分之三：两只等尺寸咀嚼槽并排，唯一推杆固定在右槽下方，“同时咀嚼”按钮居中跨两槽。
- 净可获取能量是第二行的主读数，但不得放大到压过另外两项核心结果；咀嚼成本和安全风险必须无需滚动即可看见。
- 食物类型切换放在上下分屏交界处，明确它会同时重置两列，避免被误读为第二个实验变量。
