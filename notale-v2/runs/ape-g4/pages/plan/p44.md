# page-44 · 生存也有发射价 · **100 秒**

**Kicker：MASS LEDGER**

**主标题：每一份生存资源，都要推进能力买单**

## 知识结构：generalization

用一条主张和四条支撑，把“增加生存资源”推广为统一的质量约束：

**增加水、屏蔽或备件 → 末端质量增加 → 所需推进剂增加 → 初始质量增加或任务余量减少。**

四条支撑以对齐账本行显式化，共用“当前质量—调整量—推进代价”三列：

1. **任务目标规定门槛**：任务情景给出航程、乘员与所需 Δv；这些不是可随意挪用的质量。
2. **生存资源都进入末端质量**：水、屏蔽和备件用途不同，但装上火箭后都按质量进入账本。
3. **推进剂不是固定附加项**：末端质量增加后，推进剂需求按当前 Δv 与比冲重新计算。
4. **同一笔增加有两种结局**：若放大初始质量，则付出更多推进剂；若锁定初始质量，则挤占任务余量。

主干只回答一个问题：**为什么“多带一点”不能只在原总质量上简单加一点。**

## 表征形式

交互式质量账本，采用 `ledger` 版式。

左侧是可调整的生存资源账目；中部是由 `Lec.P` 实时结算的火箭质量账；右侧是一张 ECharts 主图，使用 **SVG renderer**，显示“末端质量—推进剂—总初始质量”的堆叠关系。

主图只保留一张：

- 横轴：基线方案与当前方案。
- 纵轴：质量，单位由 `Lec.P.formatNumber(...)` 自动选择 `kg` 或 `t`。
- 堆叠段：结构与固定设备、生存资源、其他任务载荷、推进剂。
- 一条预算上限标线：仅在所选任务情景提供初始质量上限时出现。
- 调整资源时，账本数字与堆叠条同步更新；不播放装饰性动画，只用短暂颜色过渡标出被改动的账目及其推进连带成本。

## 四条支撑

### 一、任务门槛

画面顶部固定显示当前任务情景：

- **任务时长**：单位自动显示为小时或天；来源为 `Lec.K.missionScenarios` 中的情景时长，经 `Lec.P.hoursToSeconds(...)` 或 `Lec.P.daysToSeconds(...)` 统一换算，再由 `Lec.P.formatDuration(...)` 显示。
- **乘员人数**：单位 `人`；来源为 `Lec.K.missionScenarios`。
- **任务所需 Δv**：单位 `m/s` 或 `km/s`；来源为 `Lec.K.missionScenarios` 当前情景，不允许页面自行写定。
- **推进系统比冲**：单位 `s`；来源为 `Lec.K.specificImpulseScenariosS` 当前选项。
- **标准重力加速度**：单位 `m/s²`；公式提示中引用 `Lec.K.standardGravityMS2`，不在页面另设常量。

任务情景切换只改变账本输入，不展开轨道计算、火箭级数或具体发射器设计。

### 二、生存资源质量

三项可调账目全部以 `kg` 或 `t` 显示，并用 `Lec.P.formatNumber(...)` 控制有效位数：

- **水**  
  来源为 `Lec.K.missionScenarios` 中的饮用、卫生、任务时长与乘员参数，以及 `Lec.K.lifeSupportRecoveryScenarios` 当前回收档。  
  页面按以下算法当场计算所需补给质量：先由任务时长、乘员数和各用途日需求得到总用水量，再按回收情景逐循环计算必须携带的初始库存与补充量。体积换算质量时使用 `Lec.K.waterDensityKgM3`。不得把某个“每人每天用水量”写成全任务通用事实。

- **屏蔽**  
  基线质量来自 p42 输出或 `Lec.K.missionScenarios` 当前任务的屏蔽配置；材料密度来自 `Lec.K.radiationShieldMaterials`。若由体积与质量互算，调用 `Lec.P.density(...)`。本页只把屏蔽作为质量账目，不重新模拟粒子穿透或比较材料防护效果。

- **备件**  
  基线质量与允许调整范围来自 `Lec.K.missionScenarios`。本页不估算具体故障率，只显示“多带备件会增加可用冗余，同时占用质量预算”。

另列但不可拖动的账目：

- **结构与固定设备质量**：单位 `kg` 或 `t`；来源为 `Lec.K.missionScenarios`。
- **其他任务载荷质量**：单位 `kg` 或 `t`；来源为 `Lec.K.missionScenarios`。
- **末端质量**：单位 `kg` 或 `t`；由所有非推进剂账目求和后，经 `Lec.P.finite(...)` 检查。

所有滑块输入先经 `Lec.P.finite(...)` 与 `Lec.P.clamp(...)`；不得出现负质量或超出情景允许范围的输入。

### 三、推进结算

页面只显示结算所需的三个结果：

- **质量比**：无单位；由  
  `Lec.P.rocketMassRatio(任务所需Δv, 当前比冲)`  
  计算，并由 `Lec.P.formatNumber(...)` 显示。

- **推进剂质量分数**：单位 `%`；由  
  `Lec.P.propellantFraction(任务所需Δv, 当前比冲)`  
  计算，再经 `Lec.P.percent(...)` 显示。

- **推进剂质量**：单位 `kg` 或 `t`；算法为  
  `推进剂质量 = 末端质量 × (质量比 − 1)`。  
  结果先经 `Lec.P.finite(...)` 检查，再由 `Lec.P.formatNumber(...)` 显示。

- **初始质量**：单位 `kg` 或 `t`；算法为  
  `初始质量 = 末端质量 + 推进剂质量`。  
  同时使用 `Lec.P.rocketDeltaV(初始质量, 末端质量, 当前比冲)` 反算校验；反算值与任务所需 Δv 不一致时，不显示“完成结算”，而显示输入错误状态。

火箭方程结果标注为**单级等效教学账本**，不冒充真实多级运载器的完整设计结果。

### 四、增加一项后的代价

学生调整任一资源后，账本即时显示相对基线的四个差值：

- **资源质量变化**：单位 `kg` 或 `t`；当前资源质量减基线资源质量。
- **推进剂质量变化**：单位 `kg` 或 `t`；当前推进剂质量减基线推进剂质量。
- **初始质量变化**：单位 `kg` 或 `t`；当前初始质量减基线初始质量。
- **预算余量**：单位 `kg`、`t` 或 `%`；若任务情景提供初始质量上限，则由上限减当前初始质量，并用 `Lec.P.ratio(...)`、`Lec.P.percent(...)` 生成比例。分母为零时不显示百分比。

差值不预设固定增量；学生实际拖动多少，就按当前 Δv 与比冲重新结算多少。

## 必须点出来的一到三句

每增加一份水、屏蔽或备件，都要由推进能力和任务目标买单。

生存资源增加的不只是自身质量：为了把它送到任务终点，通常还要同时增加推进剂；如果初始质量不能增加，它就会挤占别的任务余量。

## 交互（只有这一个）

**配平火箭生存账本。**

学生可做四类动作：

- 拖动“水”“屏蔽”“备件”三条账目；
- 切换 `Lec.K.lifeSupportRecoveryScenarios` 的低、中、高回收情景；
- 切换 `Lec.K.specificImpulseScenariosS` 中的推进情景；
- 切换 `Lec.K.missionScenarios` 中的任务目标。

每次操作后同步变化：

- 生存资源质量；
- 末端质量；
- 所需推进剂质量；
- 初始质量或预算余量；
- ECharts SVG 堆叠条及基线差值。

交互反馈分为三种，不设置积分或胜负：

- **账本可结算**：所有输入有限且处于情景范围内。
- **预算吃紧**：仍可结算，但剩余质量余量进入情景定义的警示区。
- **预算超出**：初始质量超过情景上限；明确指出超出的质量来自哪些账目及其推进连带量。

提供“恢复情景基线”按钮。学生应形成的直觉是：**任务载荷与推进剂不是两本分开的账；改变任何要带到终点的质量，都会重算整本账。**

## 版面提示

采用横向三栏账本：

- 左栏约占三成：任务情景与三项可调资源。
- 中栏约占三成：末端质量、质量比、推进剂、初始质量、余量五行结算。
- 右栏约占四成：唯一的 ECharts SVG 堆叠图。

所有账目行严格水平对齐；质量增加用同一强调色，推进连带增加用第二强调色，超预算只使用警示色。公式收在结算行的展开提示中，不与主账本争夺视觉层级。
