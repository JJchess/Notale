# page-19 · 没有人知道全部，群体仍能做出新东西 · **142 秒**

Kicker：`CULTURAL ACCUMULATION · GROUP`

主标题：没有人知道全部，群体仍能做出新东西

## 知识结构：generalization

这一页要把“群体创新来自局部知识的连接，而非某个全知个体”显式化。

骨架采用“中心问题—贡献者节点—知识连接—共同方案”的汇聚网络：

- 外围节点代表只掌握局部知识的贡献者。
- 节点被汇聚到中心协作区后，互补知识之间出现连线。
- 连线沿着“观察—材料—制作—检验—使用”的依赖关系接成可运行的知识路径。
- 中心方案由多条局部贡献共同点亮；任何单个节点都不能独自点亮完整方案。
- 把关键贡献者移出协作区时，相关连接断开，方案退回“不完整”，使“汇聚”和“断链”形成可比较的前后态。

这里的 generalization 不是宣称“人越多一定越聪明”，而是从一个具体网络归纳：当局部知识能够被表达、接触并组合时，群体可以形成超过任一个体知识范围的方案。

## 表征形式

交互式 D3 网络。

初始画面中，贡献者节点分散在中心协作区之外，每个节点只显示人物代号与一条局部知识。中心是尚未完成的任务：“做出一种可重复使用、便于携带且能安全取水的容器”。

学习者将贡献者拖入协作区后：

- 符合依赖关系的知识节点自动连线。
- 连线按知识流向显示箭头。
- 中心方案从“零散想法”依次变为“可以组合”“形成方案”。
- 方案旁同步生成一句自然语言解释，明确是哪几类局部知识刚刚接通。
- 将节点拖出协作区，相关连线立即消失，中心方案同步退回相应状态。

网络位置只表示当前是否进入共同讨论及其连接关系，不表示人物等级、知识多少或社会地位。节点大小固定，避免把中心性误读为“更聪明”。

## 四条支撑

### 1. 每个人只知道局部

贡献者节点及其局部知识：

- 观察者：宽口容器容易取水，也容易洒出。
- 材料熟手：柔韧薄片可以折叠，但接缝会漏水。
- 编结熟手：绳结可以固定提手与外框。
- 密封熟手：树脂类黏结材料可以封住接缝。
- 使用者：装满后必须能单手提起，放下时不能倾倒。
- 试验者：先装少量水检查接缝，再逐步增加负载。

这些内容以页面本地结构化条目提供，不显示人物能力总分，不给任何节点冠以“发明者”或“领导者”。

### 2. 互补知识连接后才形成部件

网络连接及箭头方向：

- “宽口容易洒出” → “需要可收束的开口”
- “薄片可以折叠” → “形成容器主体”
- “接缝会漏水” → “需要密封接缝”
- “绳结可以固定” → “形成提手与外框”
- “单手提起且放置稳定” → “约束提手位置与底部形状”
- “逐步增加负载” → “检验密封和承重是否同时成立”

只有连接两端都位于协作区时才绘制箭头；连线由页面依赖表实时计算，不因节点之间的屏幕距离自行生成。

### 3. 方案来自组合，不归属于单个节点

中心方案的状态文案：

- 零散想法：已有局部经验，但尚未形成可执行组合。
- 可以组合：部分知识已经接通，仍缺少制作、约束或检验环节。
- 形成方案：材料、结构、使用条件与检验方法已经接成一条可执行路径。

状态由当前激活的依赖类型实时计算，不显示百分比、分数或人数排名。完整状态必须同时满足：

- 有形成容器主体的知识；
- 有处理接缝的知识；
- 有携带或稳定性的使用约束；
- 有实际检验方法。

页面不把任一节点设为“掌握全部条件”的角色。

### 4. 汇聚依赖可交流的连接

当节点进入协作区但尚未接通依赖时，反馈为：

“人在一起不等于知识已经汇合；局部经验还需要找到能接续的问题。”

当一条依赖接通时，反馈按实际连接生成，例如：

“‘接缝会漏水’与‘封住接缝’接通：材料经验变成了可执行的制作步骤。”

当节点离开导致断链时，反馈为：

“方案仍有想法，但这一步失去了来源；群体成果依赖知识之间保持可见的连接。”

本页不显示任何数值、比例、排名或计时读数，因此没有需要从 `Lec.K` 或 `Lec.P` 读取的画面数值。网络节点、连接和完成条件均由页面本地语义数据与当前交互状态实时派生，不把节点坐标、力参数或数组长度呈现为教学数字。

## 必须点出来的一到三句

群体让不同人的局部知识汇合，创新不必来自一个全知个体。

关键不只是“有很多人”，而是不同经验能否被表达、接上并共同检验。

## 交互（只有这一个）

交互名：汇聚群体点子。

学习者唯一的核心动作是把贡献者节点拖入或拖出中心协作区。

拖入时，系统实时检查该节点与区内其他知识是否互补；能接续的节点之间立即出现带方向的连线，中心方案状态和解释文案同步更新。拖出时，相关连线断开，方案状态立即回退。

学习者应形成的直觉是：一个可执行方案可以由多个不完整知识片段共同生成；创新属于连接起来的网络，不要求网络中存在一个知道全部的人。

即时反馈包括：

- 节点尚无可接连接：提示“这条经验已进入讨论，但还没有找到接续点”。
- 新连接形成：高亮新增箭头，并用一句话说明两个局部知识如何互补。
- 完整方案形成：中心节点点亮，展示组合后的方案描述，不宣布某位贡献者获胜。
- 连接断开：对应箭头淡出，缺失的条件在中心方案旁明确标出。

重置入口恢复所有节点的初始分散位置和“零散想法”状态。

键盘操作：

- `Tab` 依次聚焦贡献者节点、协作区与重置按钮。
- `Enter` 或空格拾取当前节点。
- 方向键移动被拾取节点。
- 再次按 `Enter` 或空格放置。
- `Escape` 取消本次移动并返回原位。
- 状态变化通过 `aria-live="polite"` 播报；连线变化必须同时转述为文字，不能只依赖颜色和动画。

## 不许碰

- 不讨论谁有权决定采用哪套方案，不比较专家权威、投票、成员自治或命令体系；治理制度留给 p42–p43。
- 不讨论风险应由谁承担、谁同意、谁受益，也不把协作效率推导为决策正当性。
- 不把“更多人”直接等同于“更高创新能力”，不设置人数滑块或群体规模结论。
- 不展开示范、纠错与共享注意如何提高传递保真度；这是 p18 的职责。
- 不展开现代航天器的专业分工、接口标准与部件封装；这是 p20 的职责。
- 不展开记录、备份、冗余与训练如何防止知识遗忘；这是 p21 的职责。
- 不把网络中心节点解释为最聪明、最重要或拥有最多知识的人。
- 不使用从左到右的个人天才发明流程，也不设置单个“正确贡献者”作为答案。

## 版面提示

采用 `d3-network` 全幅主画面：

- 左上放 kicker 与主标题。
- 网络占据页面主体，中心协作区固定在视觉中心偏右。
- 贡献者节点初始分布在协作区外围，避免排成等级队列。
- 中心方案卡固定在网络右下侧，与中心节点用短引线关联；状态文案不随节点漂移。
- 页面底部设置一条常驻反馈带，容纳即时反馈、键盘提示与重置入口。
- 用节点填色区分“区外”“区内未连接”“区内已连接”，同时辅以边框样式和文字状态，不能只靠颜色。
- 连线动画只在新连接形成或断开时短暂出现；网络稳定后停止持续漂移，避免运动掩盖知识关系。
