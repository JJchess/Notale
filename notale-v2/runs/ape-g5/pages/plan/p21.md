# page-21 · 知识链也会断 · **137 秒**

**Kicker：KNOWLEDGE CHAIN**  
**主标题：知识不会自动留下来**

## 知识结构：process

把“解决方案如何跨越人员更替继续有效”显式化为一条从经验到接续的六步主链：

**形成做法 → 写成记录 → 保存记录 → 检验记录 → 训练执行 → 交给下一批人**

六步按从上到下的 ledger 行排列，行间用箭头连接。每个箭头都对应一个连接问题：

- 做法能否被准确描述？
- 记录能否在原件损坏后找回？
- 接手者能否确认记录仍然可用？
- 阅读者能否把文字变成正确操作？
- 熟练者离开后，下一批人能否继续执行？

交互前显示一条“看似完整、实则脆弱”的单链；加入记录、冗余、测试和训练后，同一条链转为带旁路、回路与接续节点的耐断裂状态。重点不是罗列保存手段，而是让学习者看到每种修补改变了哪一段传递过程。

## 表征形式

交互式 ledger。

中央主栏是一张纵向知识链账本，每行包含“当前状态—传递动作—可能断点—修补位”。右侧是四枚可拖动或键盘放置的修补签：

- 记录
- 冗余
- 测试
- 训练

学习者放置修补签后，对应箭头立即改变：

- 无保护的细线变为稳定实线；
- 冗余产生一条并行旁路；
- 测试产生返回上一环的校验箭头；
- 训练把“读懂”与“会做”之间的断口接合。

底部“运行交接检验”依次高亮知识链，不播放预录动画；状态完全由当前放置结果实时计算。检验结果只用“断裂 / 勉强接续 / 耐断裂”三级文字反馈，不显示数值评分。

## 六个 step

| step | 主链内容 | 未修补时的断点 | 对应修补后的变化 |
|---|---|---|---|
| 形成做法 | 某位成员通过尝试形成可工作的操作方法 | 方法只存在于个人记忆与熟练动作中 | 为“记录”提供待捕捉的过程信息 |
| 写成记录 | 把步骤、条件、异常情况与判断依据外化 | 只记结论或成品，接手者无法还原过程 | 放置“记录”后，经验变成可查阅的操作说明 |
| 保存记录 | 让记录在人员离开或单份载体损坏后仍可取得 | 唯一副本损坏、遗失或无法访问 | 放置“冗余”后出现独立副本与替代路径 |
| 检验记录 | 由未参与原过程的人照记录复现，并核对结果 | 错误、遗漏或过期内容长期潜伏 | 放置“测试”后出现“执行—核对—修订”的反馈回路 |
| 训练执行 | 通过示范、练习与纠错把说明转成可执行能力 | “读过”被误当成“会做” | 放置“训练”后，接手者经过练习与反馈再取得执行状态 |
| 交给下一批人 | 新成员在原熟练者缺席时继续使用并维护做法 | 知识随关键人员离开而中断 | 前述修补共同生效时，链条在人员更替后仍可接续 |

### 箭头上的连接问题

- **形成做法 → 写成记录：** 隐性的判断依据是否被写出来？
- **写成记录 → 保存记录：** 是否只有一个可失去的入口？
- **保存记录 → 检验记录：** 能找到记录，是否就代表记录正确且仍然适用？
- **检验记录 → 训练执行：** 能按说明复现，是否已经能处理偏差与异常？
- **训练执行 → 交给下一批人：** 能力是否只集中在当前熟练者身上？

页面不出现科学量、时间量、比例、评分或其他数值，因此不调用 `Lec.K` 常量或 `Lec.P` 数值函数。六个步骤和四类修补是本页固定的教学内容结构，不作为可计算读数显示。

## 必须点出来的一到三句

文化也会遗忘；记录、冗余、测试和训练让知识链更耐断裂。

保存一份说明并不等于保存了能力：记录还要能被找回、检验，并通过训练重新变成行动。

## 交互（只有这一个）

**修补知识链。**

学习者把“记录、冗余、测试、训练”四枚修补签放到知识链中最合适的断点，然后运行一次确定性的交接检验。

- 拖动“记录”到“形成做法—写成记录”之间，经验由个人记忆转为可查阅说明。
- 拖动“冗余”到“保存记录”行，主链旁生成独立副本路径。
- 拖动“测试”到“检验记录”行，增加执行后返回修订的校验回路。
- 拖动“训练”到“训练执行”行，接手者从“只读过”转为“经练习并获纠错”。

每次放置后立即反馈该修补解决了什么、仍留下什么断点；错误位置不吸附，并提示其机制与该断点不匹配。所有修补签放置完成后，“运行交接检验”按固定顺序模拟：

**原熟练者离开 → 单份记录不可用 → 文档含有遗漏 → 新成员首次执行**

情境固定，不使用随机生成。主链会在未被修补的首个断点停止，并用文字指出原因；修补充分时，流程到达“下一批人继续执行”，同时保留测试回路，避免把成功表现成永不出错。

重置入口恢复单链初始态。键盘操作支持 Tab 聚焦修补签、方向键选择断点、Enter 放置或取回、空格运行检验；焦点状态、放置结果和断裂原因均以可见文字及 `aria-live` 即时反馈。

学习者应形成的直觉是：可靠传承不是把同一份信息“存久一点”，而是在传递链上增加外化、旁路、校验与重新习得能力的机制。

## 不许碰

- 不讲封闭任务中的备份水、氧气、食物、零件或其他资源配置；这些属于 p36。
- 不计算备份份数、存储容量、故障概率、回收率或任务物资余量。
- 不把“冗余”扩展成航天器硬件冗余设计；本页只讨论知识与操作能力的传承。
- 不重复 p18 对示范、纠错和共享注意如何提高教学保真度的展开；本页只把训练作为知识链的耐断裂环节。
- 不重复 p19 的群体知识汇聚网络，也不讨论群体规模。
- 不重新拆解 p20 的航天专业分工与部件封装。
- 不声称记录可以消除遗忘或错误；测试与训练也只能提高耐断裂性，不能保证知识永久不失效。

## 版面提示

采用 ledger 的纵向账本结构：左侧约三分之二宽度放六行知识链，右侧约三分之一宽度放四枚修补签与即时反馈。主链始终保持从上到下的阅读顺序，旁路和反馈回路不得穿过正文。

修补前使用低对比细线和明显断口；修补后仅以单一强调色标记新增结构。底部固定放“运行交接检验”和“重置”，不另设第二组控制。窄屏时右侧修补签移到主链上方，六行顺序不变。
