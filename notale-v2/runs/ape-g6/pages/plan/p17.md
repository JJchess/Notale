# page-17 · 熟了，不等于一键变聪明 · **120 秒**

**Kicker：** `FOOD PROCESSING / COSTS & RETURNS`

**主标题：** 熟了，不等于一键变聪明

## 知识结构：comparison

把“加工前／加工后”在同一食物构成下沿两个维度对齐比较：

- 横向两列：**较少加工**、**较多加工**。
- 纵向两行：**可获得能量**、**咀嚼成本**。
- 上半屏用两列食谱盘显示前后态；下半屏用同一量纲的两组哑铃图连接两端，显式呈现“一个收益可能上升、一个成本可能下降”。
- 比较只表达食物加工改变收益与成本，不画“食物加工 → 大脑增大”的单向因果箭头。

## 表征形式

交互式比较图。

学生调整食谱中“较多加工食物”的比例；两个食谱盘同步改变，下方 ECharts 哑铃图实时显示：

1. 相对可获得能量指数；
2. 相对咀嚼成本指数。

图表必须使用 `echarts.init(element, null, { renderer: 'svg' })`。动画只用于数值位置平滑过渡，不播放自动演示，不引入第三个结果指标。

所有指数均标注“课堂比较模型”，不显示千卡、营养素或每日摄入量，避免伪装成现代营养计算器。

## 四行 × 两列

| 比较维度 | 较少加工食谱 | 较多加工食谱 |
|---|---|---|
| 食谱构成 | 食物更多保持原始结构 | 更多食物经过切碎、捣碎或加热 |
| 可获得能量 | 结构较难破坏，消化可及性相对较低 | 结构被部分破坏，可及性通常提高，但幅度依食物而异 |
| 咀嚼成本 | 通常需要更多咀嚼时间与用力 | 通常更软或更碎，咀嚼成本降低 |
| 可以推出什么 | 需要投入较多口腔处理 | 可能改变净收益与进食时间；不能单独推出脑增大、智力提升或某一演化结果 |

### 课堂比较模型

页面局部配置全部挂载到 `Lec.P17`，界面不得另写数字字面量：

- `Lec.P17.RAW_SHARE_MIN = 0`
- `Lec.P17.RAW_SHARE_MAX = 1`
- `Lec.P17.RAW_SHARE_DEFAULT = 0.5`
- `Lec.P17.RAW_SHARE_STEP = 0.05`
- `Lec.P17.INDEX_BASE = 100`
- `Lec.P17.ENERGY_PROCESSED_FACTOR = 1.2`
- `Lec.P17.CHEWING_PROCESSED_FACTOR = 0.55`
- `Lec.P17.DISPLAY_DECIMALS = 0`

这些数值是为显现方向关系而设的**归一化课堂模型参数**，不是考古测量值、临床营养值或跨食物通用效应量。主画面常驻“原始结构食物基准＝100”的说明。

设滑块值 `p` 为较多加工食物占比：

- `p = Lec.P.clamp(Lec.P.finiteNumber(input), Lec.P17.RAW_SHARE_MIN, Lec.P17.RAW_SHARE_MAX)`
- 较少加工占比：`rawShare = Lec.P17.RAW_SHARE_MAX - p`
- 可获得能量指数：  
  `energyIndex = Lec.P17.INDEX_BASE * (rawShare + p * Lec.P17.ENERGY_PROCESSED_FACTOR)`
- 咀嚼成本指数：  
  `chewingIndex = Lec.P17.INDEX_BASE * (rawShare + p * Lec.P17.CHEWING_PROCESSED_FACTOR)`
- 显示值统一经：  
  `Lec.P.round(Lec.P.finiteNumber(value), Lec.P17.DISPLAY_DECIMALS)`
- 百分比显示：  
  `Lec.P.round(p * Lec.P17.INDEX_BASE, Lec.P17.DISPLAY_DECIMALS) + '%'`

图表坐标范围从模型参数当场计算，不写死：

- 能量轴下界：`Lec.P17.INDEX_BASE`
- 能量轴上界：`Lec.P17.INDEX_BASE * Lec.P17.ENERGY_PROCESSED_FACTOR`
- 咀嚼轴下界：`Lec.P17.INDEX_BASE * Lec.P17.CHEWING_PROCESSED_FACTOR`
- 咀嚼轴上界：`Lec.P17.INDEX_BASE`

tooltip 必须同时显示：

- 当前较多加工比例；
- 当前指数；
- “方向性课堂模型，不代表所有食物具有相同幅度”。

## 必须点出来的一到三句

加工食物可能提高可获得能量，同时降低咀嚼成本，但效果会随食物与加工方式而变。

这是一组可能改变演化条件的成本—收益变化，不是按一下就让人“变聪明”的按钮。

## 交互（只有这一个）

**调整生熟食谱。**

- 学生拖动一条从“较少加工”到“较多加工”的比例滑块。
- 食谱盘中的两类食物面积同步变化；下方两条哑铃图同步更新可获得能量指数与咀嚼成本指数。
- 拖向“较多加工”时，学生应看到两个方向同时发生：可获得能量通常上升，咀嚼成本通常下降。
- 在滑块两端及中点停留时，图旁只反馈关系判断：“收益改变”“成本改变”“不能由此单独推出脑或智力变化”。
- 键盘支持方向键按 `Lec.P17.RAW_SHARE_STEP` 调整；`aria-valuetext` 朗读当前较多加工比例及两个指数。
- 不设置胜负、最佳比例、推荐区间或“正确食谱”；重置仅恢复 `Lec.P17.RAW_SHARE_DEFAULT`。

## 不许碰

- 不提供现代人的热量、蛋白质、碳水化合物、脂肪、维生素或每日摄入建议。
- 不把页面做成减肥、健身、烹饪卫生或膳食规划工具。
- 不声称熟食必然比生食“更健康”，也不比较具体饮食流派。
- 不把归一化指数解释为真实千卡、真实咀嚼分钟数或适用于所有食物的固定比例。
- 不把食物加工单独表述为大脑增大、智力提升或人类演化的充分原因。
- 不重讲 p11 的全身能量预算，也不展开 p16 的控火证据与年代争议。
- 不讨论烹饪的确定起源年代，不建立“用火—烹饪—大脑增大”的确定时间链。

## 版面提示

采用 `split-tb`：

- 上半屏约占页面高度的 `45%`：左、右两个对齐食谱盘，中间放唯一滑块；两盘使用相同容器面积，避免把面积差误读成总食物量变化。
- 下半屏约占 `55%`：两条共用标签列的水平哑铃图，上行为“可获得能量”，下行为“咀嚼成本”。
- 两项指标使用不同形状编码，并辅以文字“通常提高／通常降低”，不能只靠红绿颜色区分。
- 主张句固定在图表右下角，始终可见：“改变条件 ≠ 单一原因”。
