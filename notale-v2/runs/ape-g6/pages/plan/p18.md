# page-18 · 传着传着，步骤去哪了？ · **115 秒**

- Kicker：`CULTURAL RELAY`
- 主标题：**传着传着，步骤去哪了？**

## 知识结构：process

把“观察一个技能 → 凭记忆复现 → 复现结果成为下一棒范本 → 误差继续累积”的因果链显式化。

画面以从左到右的四张接力卡呈现四棒传递；卡片之间用单向箭头连接，箭头明确标注“上一棒的复现，就是下一棒看到的版本”。每张卡内部保持相同的六格步骤槽，以对齐的前后态显示步骤保留、换位、替换或遗漏。最右侧把初始版本与最终版本并排对齐，显示累计保真度。

主干过程：

**初始六步技能 → 第 1 棒观察与复现 → 第 2 棒只看上一棒 → 第 3 棒只看上一棒 → 第 4 棒只看上一棒 → 与初始版本比较**

这一页只显式化未经纠正的串行模仿如何累积误差，不在流程中加入教师、标准答案回看或反馈环。

## 表征形式

交互式接力小游戏。

“技能”表征为一套没有文字标签的六步抽象操作序列，例如翻转、敲击、旋转、穿入、拉紧、折叠；每一步使用动作图标和方向标记，不借助词语记忆。玩家在每一棒短暂观看当前版本，遮罩落下后，从八张动作卡中依次重建六步序列。

提交后不显示哪一步正确，也不允许回看初始版本；玩家刚提交的序列直接成为下一棒的示范。四棒结束后才统一揭示初始版与最终版，逐格标出：

- 保留：动作与位置均一致；
- 换位：动作仍在，但位置改变；
- 替换：该位置变成另一动作；
- 遗漏：初始动作未进入最终序列。

固定种子决定候选卡顺序、干扰动作和换组后的题组生成，保证重置时可复现。

## 六个 step 与四棒传递

### 初始六个 step

六个动作只承担“具有顺序依赖的复杂技能”这一抽象角色：

1. 翻转材料；
2. 敲击边缘；
3. 顺时针旋转；
4. 将细片穿入开口；
5. 向两侧拉紧；
6. 沿标记折叠。

动作名称只在最终揭示区作为无障碍文字出现；观察与复现阶段以图标、方向箭头和动作轨迹表示，避免把任务变成读词复述。

每一步的位置同样重要：动作相同但位置不同，计为换位，不计为完整保留。

### 箭头上的连接问题

每两棒之间固定显示一句问题：

**“如果下一棒只能看到这一版，它还能知道原版是什么吗？”**

箭头下方显示上一棒提交结果成为下一棒范本的缩略序列；不显示初始序列，也不提供正确性提示。

### 数值与生成规则

页面专用参数在初始化时写入 `Lec.P18`，所有可见数字均从以下来源计算，不在组件模板中写死：

- 初始步骤数：  
  `Lec.P18.stepCount = Lec.P.round(Math.sqrt(Lec.P.finiteNumber(Lec.K.COURSE_DURATION_SECONDS) / 150), 0)`  
  结果显示为 **6 步**。
- 每棒观察时长：  
  `Lec.P18.viewSeconds = Lec.P.clamp(Lec.P.round(Lec.P18.stepCount / 2, 0), 1, Lec.P18.stepCount)`  
  结果显示为 **3 秒**；倒计时显示“3、2、1”，单位为秒。
- 接力棒数：  
  `Lec.P18.relayCount = Lec.P.clamp(Lec.P.round(Lec.P18.stepCount * 2 / 3, 0), 2, Lec.P18.stepCount)`  
  结果显示为 **4 棒**。
- 每棒候选动作卡数：  
  `Lec.P18.optionCount = Lec.P18.stepCount + Lec.P.round(Lec.P18.stepCount / 3, 0)`  
  结果显示为 **8 张候选卡**。
- 每次需要提交的动作数：  
  直接读取 `Lec.P18.stepCount`，显示为 **选满 6 步后提交**。
- 达成保真目标所需完整保留数：  
  `Lec.P18.passCount = Lec.P18.stepCount - 1`  
  结果显示为 **至少保留 5/6 步**。
- 保真度：  
  `Lec.P18.fidelityPercent = Lec.P.round(exactPositionMatches / Lec.P18.stepCount * 100, 0)`  
  经 `Lec.P.finiteNumber()` 校验并由 `Lec.P.clamp(value, 0, 100)` 限制，单位为 `%`。
- 累计变化数：  
  `Lec.P18.changeCount = Lec.P18.stepCount - exactPositionMatches`  
  显示为“累计变化 X 步”。
- 当前进度：  
  从运行状态 `currentRelay` 与 `Lec.P18.relayCount` 生成，显示为“第 X/4 棒”。
- 页面默认随机种子：  
  `Lec.K.SIM_SEED_TRANSMISSION`，值为 `"apeman-spaceman-p18"`，不在主画面展示。
- “重置”重新调用 `Math.seedrandom(Lec.K.SIM_SEED_TRANSMISSION)`，恢复完全相同的初始序列、候选顺序与干扰卡。
- “换一组”以默认种子和换组计数生成新种子：  
  `Lec.P18.activeSeed = Lec.K.SIM_SEED_TRANSMISSION + "-" + groupIndex`；`groupIndex` 只在点击“换一组”时递增。主画面仅显示“题组 X”，不显示种子字符串。

结果区同时显示初始版、每棒提交版和最终版，但只在四棒全部完成后展开；过程中不得提前计算并展示对错。

## 必须点出来的一到三句

**模仿若有误差却没有纠正，复杂技能会在传递中迅速丢失。**

结果揭示时补一句：**每一棒只偏一点，最后看到的也可能已经不是原来的做法。**

## 交互（只有这一个）

**模拟信息接力。**

玩家先观看六步动作序列三秒；遮罩落下后，从八张候选动作卡中拖选并排列六步，提交为第 1 棒。此后重复同一核心动作，但每一棒只能观看上一棒提交的版本，不能回看原版，也不会收到正误反馈。提交四棒后，系统揭示整条接力链和最终保真度。

玩家动什么：

- 点击或拖动候选动作卡，填入六个顺序槽；
- 拖动已填动作调整顺序；
- 选满后提交，进入下一棒；
- 完成后可“重置”同一题组或“换一组”。

玩家看到什么变：

- 当前范本短暂出现后被遮住；
- 每次提交形成一张新的接力卡，并通过箭头成为下一棒输入；
- 最终逐格显示保留、换位、替换和遗漏；
- 保真度、累计变化数随最终比较结果更新。

胜负条件：

- 最终至少有 `Lec.P18.passCount` 个动作与初始版在动作和位置上完全一致，显示“接力保住了大部分步骤”；
- 少于该值，显示“技能在接力中失真”。

无论胜负，都必须继续显示逐棒变化链，避免把学习目标缩减为记忆成绩。玩家应形成的直觉是：串行传递会把每一棒的小误差变成下一棒的起点；缺少纠正时，复杂度和顺序信息都很脆弱。

## 不许碰

- 不讨论语言在何时起源，也不把这一接力模拟当作语言出现年代的证据。
- 不讨论某个古人类是否具有完整现代语言。
- 不提前展开主动示范、反馈、共享注意或教学如何提高保真度；这些归 p19。本页只能在结尾指出“这里刻意没有纠正”。
- 不综合创新、传播、保留三要素，也不引入“文化棘轮”模型；系统综合归 p21。
- 不把玩家失误解释为智力不足，不比较个人或群体的先天能力。
- 不宣称真实文化传递必然按固定速度退化；本页是隔离“串行模仿、存在误差、没有纠正”三个条件的教学模型。
- 不加入第二种传播网络、多人并行比较或教师模式，以免把唯一过程拆成多个问题。

## 版面提示

采用 `stage-cards` 横向舞台。上半区为四张等宽接力卡及其单向箭头；当前棒占据视觉中心，未到达的卡保持低对比空槽，已提交的卡缩为可辨认但不可编辑的记录。

下半区固定为操作台：左侧六个顺序槽，右侧八张候选动作卡；观察阶段操作台覆盖半透明遮罩并显示秒数，复现阶段范本卡翻面隐藏。

窄屏改为纵向接力轨道，但仍保持“上一棒输出紧接下一棒输入”的空间邻接。最终揭示时不另开弹窗，而是在原四卡之后展开“初始版 × 最终版”对齐比较，避免切断过程因果链。
