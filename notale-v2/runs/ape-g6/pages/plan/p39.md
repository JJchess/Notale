# page-39 · 舱内不是一个气泡 · **120 秒**

**Kicker：LIFE-SUPPORT TRIAGE**

**主标题：舱内危机，要对症处理**

## 知识结构：classification

把“太空环境很危险”拆成五类机制不同的威胁，并显式对应到各自的监测信号、首要对策与对策目标。

采用三层主干分支：

- 第一层：危机信号——舱内发生了什么。
- 第二层：威胁类别——真空与失压、温度失控、辐射、失重环境、二氧化碳积累。
- 第三层：对策系统——密封与压力控制、主动热控、辐射监测与遮蔽、固定与强制通风、空气循环与二氧化碳去除。

五张危机卡始终占据对齐位置；处理后展开卡片下半部，以箭头显示“信号 → 类别 → 对策 → 恢复目标”。分类依据是致害机制，不按警报颜色或设备外观分类。

## 表征形式

交互式 stage-cards 小游戏。

主画面是一座简化舱段控制台，中央依次弹出危机卡；周围固定放置五个对策模块。学生读取警报与局部状态变化，把最合适的对策模块拖到危机卡上。

每次提交后立即展开因果链：

- 正确：受影响状态由警报态回到稳定态，并显示该对策阻断了哪条致害路径。
- 错误：不直接判“设备无用”，而是说明它解决的是另一类机制，并把卡片退回待处理区。
- 完成全部分类后，五张卡并排形成一张“威胁—对策”总表。

舱压只显示参考压力；其余状态使用“低 / 稳定 / 高”“不足 / 正常 / 过量”等定性刻度，避免把课堂分类游戏伪装成真实飞行控制界面。

## 层级里的各项

### 真空与失压

- 危机信号：舱壁受损，舱压持续下降，外部为接近真空。
- 威胁类别：压力边界失效。
- 首要对策：隔离受损舱段，定位并封堵泄漏；在边界恢复后再恢复舱压。
- 对策目标：阻止舱内气体继续逸散，重建可维持呼吸的压力环境。
- 易混淆项：开启加热器不能修复泄漏；只增加供氧也不能替代密封。

### 温度失控

- 危机信号：热控回路异常，舱内温度持续偏离稳定区。
- 威胁类别：热量产生、转移与排散失衡。
- 首要对策：恢复主动热控回路，按状态启用加热、冷却或散热路径。
- 对策目标：把设备和乘员所在环境维持在可工作的温度范围。
- 易混淆项：不能把“太空很冷”当作唯一方向；真空中缺少空气对流，过热与过冷都可能发生。

### 辐射

- 危机信号：辐射监测报警，外部粒子事件使预计暴露升高。
- 威胁类别：高能粒子穿透与能量沉积。
- 首要对策：缩短暴露时间，进入由水、物资或舱体质量提供更多遮蔽的位置，并持续监测。
- 对策目标：降低累计暴露，而不是假定舱壁能完全消除辐射。
- 易混淆项：加压、加热或空气净化不能阻挡高能粒子。

### 失重环境

- 危机信号：人员、工具和液滴不会自行落向地板；自然对流不足，局部空气可能滞留。
- 威胁类别：缺少稳定“上下”与浮力驱动的流动。
- 首要对策：使用脚套、扶手和系带固定人员与物体；用风扇建立强制空气循环。
- 对策目标：避免漂浮物碰撞或进入设备，并让呼出气体离开面部附近。
- 易混淆项：这里处理的是舱内操作和流体行为，不展开骨骼、肌肉或体液的长期变化。

### 二氧化碳积累

- 危机信号：空气循环或去除装置异常，二氧化碳监测进入过量区。
- 威胁类别：代谢废气产生速度超过空气处理能力。
- 首要对策：恢复风扇与空气循环，启用或更换二氧化碳去除单元。
- 对策目标：把二氧化碳从乘员呼吸区带走并从舱内空气中去除。
- 易混淆项：补充氧气不等于去除了二氧化碳；两者必须分别监测和控制。

### 舱压参考值

画面只出现以下数值：

- 海平面标准压力参考：由 `Lec.K.SEA_LEVEL_PRESSURE_PA` 取得 `101325 Pa`，经 `Lec.P.finiteNumber()` 校验，除以页面当场计算的 `1000 Pa/kPa` 换算为千帕，经 `Lec.P.clamp()` 限制在压力表范围内，再用 `Lec.P.round()` 显示为 `101.3 kPa`。
- 外部空间教学近似：由 `Lec.K.SPACE_VACUUM_PRESSURE_PA` 取得 `0 Pa`，经 `Lec.P.finiteNumber()`、`Lec.P.clamp()` 与 `Lec.P.round()` 后显示为“接近 `0 kPa`”；旁注必须写明这是教学近似，不表示宇宙空间绝对没有粒子。
- 舱压相对外部压力倍数不显示，避免对接近零的分母进行无意义比较。
- 页面不得写死上述数值、换算结果或刻度端点；所有压力表标签均由常量和同一换算流程生成。

## 必须点出来的一到三句

太空中的危险不是同一种“缺空气”：压力、热、辐射、失重环境和空气成分失控，致害机制各不相同。

生命保障的关键不是某件万能设备，而是先识别威胁，再调用对症且没有明显短板的系统。

## 交互（只有这一个）

**处理舱内危机：**

学生依次处理五张危机卡。每张卡只给出一个可观察信号，学生把一个首要对策模块拖入卡片的处置槽；若首要对策正确，再从两个支持动作中点选一个，使系统恢复稳定。

- 真空与失压：选择“隔离并封堵”，支持动作选择“边界恢复后重新加压”。
- 温度失控：选择“恢复主动热控”，支持动作根据警报方向选择“加热”或“散热”。
- 辐射：选择“进入遮蔽区”，支持动作选择“持续监测并减少暴露时间”。
- 失重环境：选择“固定人员与物体”，支持动作选择“启动强制通风”。
- 二氧化碳积累：选择“恢复空气循环与去除单元”，支持动作选择“检查或更换去除单元”。

错误选择会消耗该卡的安全余量，但不引入倒计时数字；状态条只用颜色、长度和“稳定 / 警戒 / 危险”文字反馈。任一卡安全余量耗尽即告失败，反馈指出混淆了哪两类机制；全部危机恢复稳定即获胜。重置回到同一组固定危机，不使用随机事件。

学生应形成的直觉是：相似的“舱内警报”不能靠同一按钮解决；判断对策前，必须先问是哪一种物理或化学机制失控。

## 不许碰

- 不讲失重导致的骨量下降、肌肉萎缩、体液重新分布、视力变化或长期康复；这些归 p43。
- 不把失重本身说成短时间内必然致命，只处理它对固定、漂浮物和空气循环造成的舱内操作问题。
- 不展开辐射剂量、剂量单位、长期癌症风险或个体医学阈值。
- 不提供真实飞船的操作程序、警报代码、阀门顺序或应急手册替代品。
- 不把海平面标准压力说成所有载人航天器唯一正确的舱压。
- 不宣称宇宙空间压力绝对为零。
- 不把供氧与二氧化碳去除混为一件事，也不暗示增加氧气可以修复泄漏或清除二氧化碳。
- 不延伸到地面任务支持网络；该主题归 p41。
- 不重复多级火箭、轨道或发射窗口内容。

## 版面提示

采用 stage-cards 的“中央处置台 + 两侧模块架 + 底部分类总表”结构。

- 中央只显示当前危机卡，避免五个警报同时争夺注意力。

- 五张卡全部完成后，中央处置台淡出，底部总表扩展为主画面，作为进入 p40“系统不能有明显短板”的视觉过渡。
