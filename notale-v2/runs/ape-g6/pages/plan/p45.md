# page-45 · 碎片会生出碎片 · **120 秒**

**Kicker：SHARED ORBIT**

**主标题：一次碰撞，为什么会让下一次更可能？**

## 知识结构：process

用一条可循环的六步因果链显式化轨道碎片的正反馈：

在轨物体运行 → 轨迹接近 → 高速碰撞 → 产生更多碎片 → 交会机会增加 → 清理与协同降低风险。

主画布以“前后态 + 环形箭头”呈现：碰撞前轨道较稀疏；碰撞点闪现后，碎片沿不同方向散开；新增碎片继续进入其他物体的路径。学生清除高风险碎片后，画面回到较稀疏但不会自动归零的状态。流程重点是“碰撞如何改变下一轮碰撞条件”，不是展示真实轨道力学。

## 表征形式

交互式二维粒子模拟。

PixiJS 全屏画布显示地球截面、数条抽象轨道带、完整航天器、失效物体与碎片。所有物体持续沿各自轨道带运动；达到简化碰撞条件时产生碎片簇，并同步更新“碎片数”和“碰撞次数”。

右侧窄栏只保留流程节点、实时计数、风险状态和操作提示。风险通过轨道交会处的局部亮度与短暂预警环表达，不另做统计图表。

画面明确标注“课堂简化模型：位置、速度与碰撞概率不代表任务级预测”。

## 六个 step

1. **共享轨道**  
   完整航天器、失效物体和碎片同时占用有限的轨道带。物体不是静止障碍，而是在持续运动。

2. **轨迹接近**  
   两个物体进入同一简化交会区时，交会区出现预警环；预警表示存在碰撞机会，不表示必然相撞。

3. **发生碰撞**  
   固定种子的随机判定满足碰撞条件后，两物体在交会点消失或失效，页面“碰撞次数”增加。

4. **碎片增殖**  
   每次碰撞按确定性算法生成一簇新碎片；碎片继承碰撞点位置，并获得由种子决定的方向与速度扰动。

5. **风险反馈**  
   新碎片进入更多轨道交会区，使后续潜在接近事件增加；学生看到碎片数上升后，预警环出现得更频繁。

6. **协同清理**  
   学生优先移除穿越交会区最多的高风险碎片，减少后续碰撞机会。单次清理只能改善局部状态；要让风险持续下降，需要持续监测、规避、清理与共同规则。

### 模拟计数与常量

- **较大且可追踪碎片的课堂近似阈值：约 10 cm**  
  显示值来自 `Lec.K.ORBITAL_DEBRIS_TRACKED_MIN_SIZE_CM`，经 `Lec.P.finiteNumber()` 校验、`Lec.P.clamp()` 限制为正值，再用 `Lec.P.round()` 控制显示精度。正文必须保留“课堂近似”“较大且可追踪”，不得写成所有监测系统的统一硬边界。

- **当前碎片数：N 件**  
  `N` 由模拟状态中的活动碎片数组长度当场计算，经 `Lec.P.finiteNumber()`、`Lec.P.clamp()` 与 `Lec.P.round()` 后显示；不得写死初始值或上限值。

- **累计碰撞次数：C 次**  
  `C` 从本轮模拟开始后累计，每次有效碰撞只增加一次；显示前经 `Lec.P.finiteNumber()`、`Lec.P.clamp()` 与 `Lec.P.round()` 处理。

- **已清理碎片数：R 件**  
  `R` 为学生本轮成功移除的活动碎片数量；显示前经 `Lec.P.finiteNumber()`、`Lec.P.clamp()` 与 `Lec.P.round()` 处理。

- **风险变化：下降 / 持平 / 上升**  
  不显示虚构百分比。风险指标由当前状态当场计算：对未来一个固定模拟窗口内进入同一交会区的物体对进行计数，并与清理前基线比较。窗口长度、交会半径、粒子速度和碎片生成量均作为内部模拟参数按画布尺寸与刷新步长计算，不作为真实物理量展示。

- **固定页面种子**  
  初始随机过程调用 `seedrandom(Lec.K.SIM_SEED_DEBRIS)`。点击“重置”必须恢复同一初始状态与同一碰撞序列；点击“换一组”才从页面种子与递增组号生成新种子。组号只用于内部状态，不在主画面显示。

- **胜利条件**  
  以“风险指标低于本轮清理前基线，且连续一个完整评估窗口没有新增碰撞”为成功。页面只显示“风险已降低”或“仍有连锁风险”，不显示写死的目标件数、倒计时或虚构概率。

## 必须点出来的一到三句

高速碎片碰撞会制造更多碎片，让未来的碰撞机会继续增加。

轨道不是谁先到谁独占的空地，而是必须共同监测、规避和治理的公共空间。

## 交互（只有这一个）

**清理轨道碎片。**

学生用指针点击或短拖画布中的碎片，将清理光标对准目标；锁定完成后，该碎片退出模拟。大而醒目的碎片不一定最值得先清理，穿越多个交会区、即将接近其他物体的碎片会带来更明显的风险反馈。

每次清理后，学生立即看到三类变化：

- 目标碎片从轨道中消失；
- 当前碎片数与已清理数更新；
- 交会预警和风险趋势随模拟继续运行而改变。

若学生只清理偏远、低交会目标，碰撞链仍可能继续；若优先处理高交会目标，后续预警减少并达成“风险已降低”。由此形成直觉：治理目标不是把画面扫干净，而是打断“碰撞—增殖—更多碰撞机会”的反馈链。

控制仅包括“重置”和“换一组”。“重置”恢复固定种子的同一初始局面；“换一组”才生成另一组可复现局面。键盘操作须支持焦点移动、锁定目标和执行清理；暂停动画或启用减少动态效果时，仍可通过逐步推进完成任务。

- 不用真实在轨物体数量、年度碰撞率或碎片速度等未经共享数字口径规定的数值。

## 版面提示

采用 `canvas-full`。画布占页面主体，地球偏左下，轨道带跨越全场，右侧保留不超过画面四分之一宽度的信息栏。

信息栏从上到下固定为：六步流程缩略链、碎片数、碰撞次数、已清理数、风险状态、重置与换一组。发生碰撞时，只高亮当前对应的流程节点，不弹出遮挡画布的说明框。

完整航天器、失效物体和碎片必须在形状上可区分，不能只依赖颜色；高风险目标使用交会标记而非红色大小排序。减少动态效果模式下取消闪烁与高速拖影，改为离散位置更新和静态方向线。
