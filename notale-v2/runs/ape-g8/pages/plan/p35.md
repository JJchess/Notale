# page-35 · 消息抵达时，现场已经变了 · **145 秒**

Kicker：`SIGNAL IN TRANSIT`

主标题：消息抵达时，现场已经变了

## 知识结构：process

用一条双向时间账本显式化“事件发生 → 信息上行 → 地球判断 → 指令下行 → 月面执行 → 结果回传”。六步按真实先后展开；月面状态与地球所见并排，空白时段表示地球尚不知道现场发生了什么。

## 表征形式

动态交互时间账本。每轮先在月面生成固定种子的异常情境，信号沿地月连线传播；读者在地球收到旧状态后选择处置，随后看到指令抵达时的现场状态及回传结果。

## 六个事件

1. 月面出现异常，记录本地时间与状态。
2. 遥测从月球发往地球。
3. 信号在途期间，月面状态继续变化。
4. 地球收到带时间戳的旧状态，读者作出决定。
5. 指令抵达月面，本地人员按权限执行。
6. 结果回传地球，对齐“以为的状态”与“实际状态”。

调用 `Lec.K.EARTH_MOON_DISTANCE`、`Lec.P.communicationDelay`；往返时间由两段单程延迟计算，不另写公式。情境抽样使用 `Math.seedrandom('page-35')`，刷新后顺序一致。

## 必须点出来的一到三句

远距离决策依据的总是过去的现场，而不是此刻的现场。系统必须给月面人员明确的本地处置权限，并让地球端看见信息的时间戳与不确定区间。

## 交互（只有这一个）

读者处理三轮月面异常：查看本地规则和刚发出的遥测，在“进入预授权安全态并上报 / 等待地球指令 / 继续当前操作”中选择一项发送；信号传播、现场演变与回传随即实时展开，形成“反馈越迟，本地权限越重要”的直觉。

做对了立刻看到什么：所选处置吸附进正确时间槽，青绿连线接通；月面状态停在安全区，并标出“处置发生在地球回复之前”。

做错了立刻看到什么：选择卡回弹，风险区间闪琥珀色；提示“这项决定假定地球看到的是当前状态，但遥测已经过时”。

做到哪儿了怎么知道：账本顶部显示三个通信回合位，已完成位填亮，并标注“第 2 / 3 轮”。

做完了怎么收：六步压缩成一条完整往返链，月面本地处置段高亮；出现“一键重置”图标，重播同一固定种子序列。

## 场景构图

使用“地球弧线与生命支持管路”“环绕身体的环境参数刻度”。深炭黑画面左下露出地球弧线，右上是月面舱外轮廓；细青绿信号线横贯其间。中央不是普通表格，而是任务日志式双栏账本：上轨记录月面真实状态，下轨记录地球已知状态，传播中的空白被明确保留。琥珀色只标当前在途信号、待决策槽和风险区间。

## 动效

入场：地球弧线先从左下显现，月面轮廓随后从右上进入；六个事件槽沿信号方向依次点亮。

反馈：正确时信号脉冲穿过连线并锁入时间槽；错误时错误假设所在的旧状态行短促横向抖动，风险区间扩张一次后停住。

## 不许碰

不讨论人工智能是否能够或应该替代宇航员；不扩展到火星通信，不把延迟描述成通信故障，也不把“本地决策”讲成脱离团队或地面支持。只处理地月延迟下的时间戳、信息缺口与预授权处置。
