# 页面构建契约

## 1. 工作边界

- 只编辑分配给你的 `pages/page-NN.html`。
- 不读取、不修改、不复制任何其他 `page-*.html`。
- 可读取且应按需读取：`PLAN.md`、`assets/theme.css`、`assets/lec.js`、`assets/CHASSIS.md`、`assets/lib/LIBS.md` 及匹配的 Skill 技法文档。
- 不新建图片、脚本、样式、测试、说明或其他资源文件。
- 页面必须自包含；使用相对路径；直接以 `file://` 打开即可显示和交互；禁止 CDN、网络请求和在线字体。
- 交付物只有该 HTML 文件，不附文档、测试、总结或说明。

## 2. 固定骨架

保留以下结构与顺序。只替换 `NN`，向 `#stage` 写本页标题和正文，并在标记位置按需加入库、页内样式和脚本。`data-total` 固定为 `50`。

    <!doctype html>
    <html lang="zh">
    <head>
      <meta charset="utf-8">
      <link rel="stylesheet" href="assets/base.css">
      <link rel="stylesheet" href="assets/theme.css">
      <!-- 仅按需加入库 CSS 和本页少量布局样式 -->
    </head>
    <body data-page="NN" data-total="50">
      <div id="stage">
        <!-- 本页标题与正文 -->
      </div>
      <script src="assets/base.js"></script>
      <script src="assets/lec.js"></script>
      <!-- 仅按需加入库脚本，最后写本页脚本 -->
    </body>
    </html>

- `#stage` 必须存在且只能有一个；骨架中不加固定页眉、页脚，不调用 `Lec.mount()`。
- 标题位置、组件组合和页面结构由本页内容决定，不套统一仪表盘。
- 不移动、删除或替换 `base.css`、`theme.css`、`base.js`、`lec.js`。
- 底盘接口只读 `assets/CHASSIS.md`，不得在页面或本契约中另抄一份。
- `assets/lec.js` 只提供 `Lec.K` 与 `Lec.P`，不提供版面。

## 3. 受众与文案

- 受众是大学一年级通识课学生，文理混合；不预设微积分、生物学或专业术语基础。
- 首次出现的术语必须用一句通俗中文就地解释；不得用另一个未解释术语代替解释。
- 公式先说变量代表什么、变化意味着什么，再让读者操作；不用求导、积分或专业背景作为理解前提。
- 每个说明句原则上不超过 35 个汉字；一段只表达一个动作或结论。
- 提示语使用直接、平等、可执行的口气，如“拖动滑块，观察……”，不用考试口吻、幼儿化口吻或空泛的“探索一下”。
- 页面必须同时适合教师课堂指讲和学生课后独立重看：操作入口、当前状态、反馈含义和核心结论不能只靠教师口头补充。
- 不写长篇背景、重复结论、装饰性口号或无信息量副标题。

## 4. 版面与密度预算

画布逻辑尺寸固定为 `1600 × 900`。

硬上限：

- 正文说明总量不超过 280 个汉字；英文按空格分词，每词按 1 字计。标题、刻度、图例、按钮和短标签不计入正文。
- 可操作控件不超过 6 个；一个按钮、滑块、输入框、选择器或独立拖拽物各计 1 个。
- 页面文本元素总数必须为 20–70 个，计入标题、正文段落、标签、刻度、图例、按钮文字、读数和状态提示。
- 画面占用比必须 `≥45%`。
- 超预算时删除冗余信息或拆页；不得缩字号、压行高、叠放元素或把文字画进 canvas。内容确实无法满足时报告预算冲突，不提交违规页面。
- 低于密度下限时增加有教学意义的结构、比较维度或过程展开；不得靠放大字号、拉大间距或添加纯装饰撑满。

布局规则：

- `#stage` 是 flex 列。其顶层区域必须有固定高度或明确 `flex` 份额；主内容区使用 `flex:1`，不得让全部顶层区域仅按内容取高。
- 默认用 flex；仅矩阵、维度表等确需二维对齐时使用 grid。
- 一次性尺寸可写页内样式，不为每个一次性对象发明类名。
- 需要计算坐标才能对齐时应改 DOM 结构。拖拽用 `transform` 偏移并保留正常流位置，不持续修改 `left/top`。
- 禁止在缩放舞台内使用 `position:fixed`；需要悬置时用相对内容容器的 `position:absolute`。
- 不得删除 `lec-root`、`lec-page`、`min0`、`cv-fill` 等底盘或主题类，不得覆盖这些类的定位属性。

## 5. 字号地板

按逻辑 CSS 像素检查：

- 纯数字刻度：`≥12px`。
- 含词句的刻度、标签、图注、图例、轴名：`≥14px`。
- 正文、控件文字、提示、读数：`≥16px`。
- 正文行高：`≥1.35`。
- KaTeX 基准字号：`≥20px`。
- 不用缩放容器、`transform:scale()`、位图文字或 canvas 文字规避字号检查。

1366×768 屏幕相对 1600×900 舞台的缩放约为 `min(1366/1600,768/900)=0.853`，即约 `0.85`；逻辑 16px 显示时约为 13.6px，因此不得再降低上述地板。

## 6. 主题与数字

- 所有颜色、字体、圆角、阴影、边框和常用间距从 `theme.css` 的 token 与骨架类取得。
- 不另建配色体系，不写品牌色十六进制值，不引入外部字体。
- 页内 CSS 只处理本页布局、尺寸和必要状态；可视颜色须引用主题变量。
- 页面展示的教学数字、常量、数据点、计算结果和格式化结果一律来自 `Lec.K`、`Lec.P` 或由它们实时计算；禁止在 HTML、CSS 伪元素或 JS 文案中写死结果。
- 布局尺寸、页号、数组索引和库配置数值不属于教学数字。
- 交互改变参数后必须重新计算显示值，不得只替换预写文案。
- 随机样本或抽样必须引入 `seedrandom.min.js` 并使用固定种子，种子建议为本页文件名；禁止 `Math.random()`。

## 7. 库与加载

动手前先查 `assets/lib/LIBS.md`。已有库能完成的呈现工作，禁止从底层重写：

- 常规坐标轴、刻度、图例、折线、柱状、散点、面积、饼、热力图：ECharts。
- 可拖拽、需命中检测的二维场景：Konva。
- 三维结构、材质、光照：Three。
- 下落、碰撞、摆动、堆叠、约束：Matter。
- 节点连线、数据驱动矢量图：D3。
- 成千上万元素同时运动：Pixi。
- 分步动画：anime；多动画时间线：GSAP。
- 数学公式：KaTeX。
- 矩阵运算：ml-matrix。
- 页面逐帧训练小型二分类网络：`mlp.js`。
- 预训练模型、真实图片卷积或 GPU 大矩阵才使用 TensorFlow.js。

规则：

- 只加载实际使用的库；页面脚本放在依赖库之后。
- Three 必须先于 globe.gl、Vanta；GSAP 必须先于 ScrollTrigger。
- KaTeX 同时加载 `katex.min.css` 与 `katex.min.js`。
- 库版本以 `assets/lib/LIBS.md` 为唯一依据，不读取压缩文件查版本。
- ECharts 必须以 `echarts.init(el,null,{renderer:'svg'})` 初始化，并显式设置全局、轴、图例、tooltip 字号达到本契约地板。
- Konva 用于图形；常规标签用绝对定位的 DOM 叠加，不用 `Konva.Text`。确需随图形变换的短标注必须显式设置合规字号。
- KaTeX 使用 `{throwOnError:false}`；不手写公式排版。
- TensorFlow.js 每一步使用 `tf.tidy()` 或显式 `dispose()`，并确认 `tf.memory().numTensors` 不持续增长。
- 库只负责呈现或运算原语；教学计算必须真实执行，禁止预录动画、假数据或硬编码结果冒充计算。
- 需要清单外库时才可放入 `pages/` 本地引用；不得下载已有库的替代品。

## 8. Canvas、缩放与动画

- 手写 canvas 一律使用 `Deck.fit` 或 `Deck.autofit` 适配 CSS 尺寸、高分屏和舞台缩放。
- 手写 canvas 的指针坐标一律使用 `Deck.pt`；不得自己用 `getBoundingClientRect()`、`devicePixelRatio` 或比例公式换算。
- Konva 场景使用其自身舞台指针换算，不重复实现。
- 动画循环一律使用 `Deck.loop`，不得直接建立 `requestAnimationFrame` 循环。
- canvas 取色一律使用 `Deck.rgb`、`Deck.rgba`，颜色来源仍须为主题 token。
- canvas 尺寸变化后必须重绘；不得依赖初次加载时的固定屏幕尺寸。
- 不在 canvas 中绘制正文、控件标签、图例或关键读数；必须使用可检查、可选择、可读屏的 DOM 文字。

## 9. 交互与可达性

真交互必须同时满足：

- 用户可通过控件、拖拽、点击选择或键盘改变明确的模型状态。
- 状态变化触发真实计算、物理规则或数据筛选。
- 页面立即给出可见反馈，并让读者理解“改了什么、结果怎样、为什么值得看”。
- 可重复操作；有复杂累积状态时提供重置。
- 允许扰动范围内，说明句和结论始终为真。

以下不计为真交互：自动播放、淡入、悬停高亮、指针倾斜、粒子背景、纯装饰动画、点击后仅切换预写答案。

可达性要求：

- 操作用原生 `button`、`input`、`select`；非原生可操作元素必须有正确 `role`、`tabindex` 和可读名称。
- 所有鼠标操作必须有键盘等价方式；Enter/Space 可激活，连续量用方向键可调。
- 焦点样式清晰且不得被裁切。
- 状态不能只靠颜色区分；同步提供文字、形状或位置线索。
- 动态关键结果使用可读 DOM；必要时设置适度的 `aria-live`。
- 检测 `prefers-reduced-motion:reduce`。该分支停止连续、循环和非必要过渡，直接显示稳定状态；交互和计算仍可使用。
- 动画不得自动抢焦点，不得闪烁，不得成为理解内容的唯一途径。

## 10. 技法文档

- Skill 清单中有对应技法时，先用 Skill 阅读，再写页面。
- 不绕过已有技法自行重做缩放、拖拽、图表、动画、截图或检查流程。
- 清单中无对应项时才自行实现，并仍遵守库与底盘契约。

## 11. 完工自检

在 `pages/` 目录运行：

    python3 assets/selfcheck.py page-NN.html

对每个主要交互状态再运行：

    python3 assets/selfcheck.py page-NN.html --after "<触发该状态的 JS>"

至少覆盖初始状态、每类控件改变后的代表状态、极值状态、重置状态及动画稳定状态。

必须改到全部满足：

- 无 JS 报错、控制台异常或资源加载失败。
- 无元素越出 1600×900、被裁切或意外遮挡。
- 无文字叠压；有意叠加的图形不得压住文字和控件。
- 字号与行高达到地板；canvas 不藏关键文字。
- 画面占用比 `≥45%`。
- 文本块为 20–70 个。
- 无占比不足 1% 且没有信息作用的小容器。
- 所有交互在缩放后命中准确，键盘可用，读数与图形同步。
- reduced-motion 分支可用。
- 随机结果可复现。
- 连续动画无重复循环、明显掉帧或资源持续增长。

自检只报告、不修复。任何失败都必须修改页面并重跑，直到初始与触发后检查全部干净。
