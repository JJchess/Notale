# 首次 Check 截图：独立 Gemini 评审

## 方法

- Gemini 3.8 Flash low，Google profile `gemini38-google-low`，4 个全新上下文，无工具，无页面源码，无过去的模型回复。
- 同一 slide 的两个历史版本：181849（45轮长循环）与190702（18轮）。没有使用其他早期页面，因为缺少不可覆盖的首次截图证据。
- 每个版本取首次 Write 后紧随的首次 Check **初态原图**，校验归档图片 SHA；不重渲染、不用后来覆写的 .shots。首次 Write 的 HTML 仅保存作溯源，未送给模型。
- A：图片＋中性评审任务。
- B：相同图片和任务＋该版本实际记录的完整 instructions 和首次 Check 文本报告。两路均有相同的“只评审、不创作/调用工具”任务说明，B 放在历史 instructions 之后。
- 问题原文：请检查这张 slide 截图。只指出截图中有明确证据的问题，并给出具体修改建议；没有明显问题就说没有。无法从截图判断的内容请明确说明。
- B 的完整报告还包含未附图的 after 状态；共同任务说明明确只能看见初态。
- 每臂只有一次观测；B 同时增加两类信息，不能区分固定输入与报告的独立作用，也不能代表原创作 history 的完整回放。

## 结果

| 图片 | A：仅截图 | B：加固定输入与报告 |
| --- | --- | --- |
| 181849 | 指出右下角文字重叠、图底部小字难读 | 同样指出重叠，新增227>200字预算违规、卡片墙整改 |
| 190702 | 认为应把近直线边界改成S形；建议缩短损失图纵轴、加深小字 | 首要问题变为343>200字；要求删除侧边条、弱化卡片；也建议缩短纵轴 |

## 人工核对与限制

1. 181849 右下角标签挤压、换行是截图可见的具体缺陷，A/B 都能发现。说明不带 Builder 固定输入时 Gemini 也能提出可执行建议。
2. B 两次均把固定200字预算当主要整改目标；这是上下文明确存在的硬约束，而不是它从截图独立得出的设计判断。
3. 190702-B 把侧边粗描边称为“违反规范”。但其收到的 Check 指引明说局部底色/边框按构图判断、主题材质可用于分组，不能仅因分组就保留或删除容器。报告的测量项被升级成禁令，是本次可见的误读；并非已证明源码中仍存在一条绝对禁令。
4. 190702-A 把近直线等同欠拟合，提出“重新拟合或绘制”为S形。截图不能证明这点：形状是否足够取决于数据与实际误差，不存在“适度拟合必须S形”的一般要求。这条建议可能诱发此前的按预期改图，应拒绝直接采纳。
5. 损失图上部留白确实可见，但坐标范围是否应缩小还需看其他状态与比较尺度，不能仅凭初态自动截断。
6. 两路大体都承认交互和隐藏运行逻辑无法仅凭截图判断。181849-B 却沿报告措辞声称“当前内联截图有初态及after3”，实际此次只附一张；这是文本影响视觉证据边界的另一处不严谨。

结论：这次小样本支持“固定输入＋报告会改变评审重点”的怀疑，但不能断言二者之一是长循环根因。纯截图可提出具体建议，同时也会给出没有计算依据的强结论。暂不改生产提示、不删检查。下一步若继续，应固定同一张图，分别只加入固定输入/只加入Check报告，拆开作用；本次未启动该扩展。
