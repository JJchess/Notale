# page-04 · 两路输入，先乘再加 · **90 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `ONE NEURON · WEIGH & ADD` |
| 主标题 | 一个神经元先分别衡量两路输入，再把贡献相加 |
| 收束句 | 神经元先做两次乘法，再做一次加法。 |
| 下一问 | 加出的总分，要达到什么程度才回答“是”？ |

## 知识结构：process

**关系不变量**：两路输入必须同尺度、上下对齐，各自沿同一水平基线依次经过“输入值—固定重要程度—本路贡献”，随后两条路径汇入同一个合计框；乘法发生在汇合前，加法发生在汇合处。

**共享原语**：下区以 `.k-process` 的 `.step` 与 `.arw` 固定从左到右的计算顺序；上区用 `.panel` 承载两枚输入开关；重要程度使用不可操作的 `.knob`，让“参数”与可切换的“输入”在形状上明确分工。整套骨架落入 `.split-tb`：上区操作，下区同步展示计算。

## 表征形式

交互式双通道加权求和仪器：上方切换两个二值输入，下方两条并行算式实时汇入合计读数。

使用原生 DOM 与 SVG 更合适；关系仅含两条固定路径、箭头和四种离散状态，无需图表库。

## 主工作流

build-interaction ← 两个输入状态必须与逐路乘法、汇合加法和无障碍控制保持同步

## 四种输入状态

页面固定显示两个重要程度旋钮 `w₁=2`、`w₂=1`，标注“本页锁定”；所有数值无单位。

| `x₁` | `x₂` | 第一路贡献 `x₁×2` | 第二路贡献 `x₂×1` | 合计 |
|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | 0 | 0 |
| 1 | 0 | 2 | 0 | 2 |
| 0 | 1 | 0 | 1 | 1 |
| 1 | 1 | 2 | 1 | 3 |

默认画面写出：`1 × 2 = 2`、`0 × 1 = 0`、`2 + 0 = 2`。下表四行作为确定状态直接读取；本页无适用的 `Lec.P` 加权求和接口。

## 交互

学习者分别点击“输入 1”和“输入 2”的开关，在 `0（关）` 与 `1（开）` 间切换；默认 `x₁=1、x₂=0`。键盘可用 Tab 聚焦，空格或回车切换，控件读出当前值。

每次切换立即改写对应输入、乘法结果和合计；为 0 的路径仍保留轮廓并明确显示贡献 `0`，为 1 的路径使用实线蓝色信号。刚操作的开关短暂使用强调色。两枚重要程度旋钮不可拖动、不可聚焦，旁边持续标注“固定”。

交互要形成的直觉是：输入相同为 1 时，重要程度为 2 的一路对合计贡献更大。四种状态均可逆，无单独复位按钮；重新进入本页恢复默认状态。

## 动效

切换后，数值从输入端沿本路箭头向右脉冲一次，抵达贡献框后再进入合计框；每段 `180ms`，第二段延后 `120ms`。数字直接替换，不滚动计数，不循环播放。

## 核对

| 输入 | 期望算式 | 期望合计 |
|---|---|---:|
| `x₁=1, x₂=0` | `1×2 + 0×1` | 2 |
| `x₁=0, x₂=1` | `0×2 + 1×1` | 1 |
| `x₁=1, x₂=1` | `1×2 + 1×1` | 3 |

## 不许碰

不得开放重要程度旋钮，也不得让学生自由调任何参数；三枚参数的自由调节归 p10。不得加入偏置、门槛或“回答是/否”的判定机制；偏置直觉归 p05，概率压缩归 p06。
