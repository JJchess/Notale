# page-20 · 排好一次学习 · **100 秒**

本规格只锁定教学目标、事实、状态和边界；标题措辞、构图、组件、渲染器和动效由 Builder 按 workflow 决定。

## 页面任务

让学生把一次训练的四个动作排成正确顺序，并通过依赖解释确认：学习不是得到答案，而是用误差决定参数下一步怎样移动。

## 必须看见的关系

四步有严格的产物依赖：后一步使用前一步的结果。它们不是可任意旋转的循环；更新后的参数才进入下一轮预测。

## 内容与证据

| ID | 动作 | 为什么在这里 |
|---|---|---|
| A | 前向预测 | 输入经过权重、偏置和激活，得到预测 |
| B | 计算损失 | 把预测与目标的差距变成可比较的数 |
| C | 反向分配影响 | 从损失出发，算各参数应增大还是减小 |
| D | 按学习率更新参数 | `新值 = 旧值 − 学习率 × 影响量` |

正确顺序固定为 `A → B → C → D`；确定性初始顺序为 `C、A、D、B`。完成后应能读成：`预测 → 损失 → 反向 → 更新`，然后新参数进入下一轮。

## 交互状态

- 学生可拖动或用键盘、上移/下移操作重排；移动时不提前判分。
- 检查后若全对，展开四步依据并说明新参数进入下一轮。
- 未全对时保留排列，只指出第一处依赖断裂，不公布完整答案。
- 首次错误后可请求第一步，只把 A 移到首位。
- 重新排列恢复 `C、A、D、B` 并清除反馈。

## 主工作流

design-interaction ← 实现可拖放、键盘可达且能解释错误依赖的四步排序检验

## 边界

不讨论现实部署、公平性或安全性。泛化问题归 p21；不重复 p18 的训练曲线与动态边界。
