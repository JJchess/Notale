# page-09 · 曲线上的点：损失是能站上去的地形 · **100 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `ON THE CURVE` |
| 主标题 | 损失函数不是公式，是你能站上去的地形 |
| 收束句 | 拖这个点就是在改权重——曲线上每一个位置，都对应一个具体的失分程度 |
| 下一问 | 曲线有高有低，往哪边走才能更快地降下去？ |

## 知识结构：process

曲线路径（loss 随 w₁ 变化）与可拖动的橙色点必须共享同一套坐标轴：点的横向位置就是 w₁ 读数，纵向位置由曲线本身决定，两者不得脱节或异步。禁止把"当前权重"和"对应 loss"拆成互不联动的两块（滑块配一张静态数字卡）——点必须始终贴在曲线上，曲线形状本身就是答案来源。复用 `.k-process`：`.axis` 是横贯全图的 w₁ 数轴，拖动点是沿 axis 移动的唯一 `.step`；`.err-badge` 沿用 p07 起的右上角读数位显示当前 loss；`.panel.q` 承载 w₁、loss 两个等宽数字读数。

## 表征形式

静态层：预采样的 loss(w₁) 曲线，[-3,3] 每 0.05 取一点连成 SVG path，叠在方格底纹上，纵轴范围固定 [0, 3.2] 不随交互重缩放。动态层：橙色圆点沿曲线水平拖动，纵向坐标按当前 w₁ 查表/线性插值得出，不可脱离曲线自由移动。用原生 SVG 即可，无需 D3/ECharts：曲线数据一次性用 `Lec.P.activate('sigmoid', z)` 与 `Lec.P.bce` 算出并缓存；拖动通过 pointermove 更新 point 的 `cx/cy` 与两个数字读数，用 class 切换控制拖动态的 `.focus-ring`。

## 不许碰

不讲斜率/梯度怎么算，也不出现任何"往哪边走"的箭头或提示——那是 p10、p11 的内容；本页只做单一权重 w₁ 的位置–取值对应，w₂ 与 bias 固定不变，不展开"多个权重联动"的讨论。

## 曲线设定与取值

| 项 | 值 |
|---|---|
| 样本 A | x=(1,0)，目标 y=0 |
| 样本 B | x=(1,1)，目标 y=1 |
| w₂（固定） | 1.0 |
| bias（固定） | 0.0 |
| loss(w₁) | 对两样本的 `Lec.P.bce` 取平均 |
| 默认起始点 | w₁ = 1.5（loss ≈ 0.89，非最低点） |

| w₁ | -3 | -2 | -1 | -0.5(最低) | 0 | 1 | 2 | 3 |
|---|---|---|---|---|---|---|---|---|
| loss | 1.09 | 0.72 | 0.50 | 0.47 | 0.50 | 0.72 | 1.09 | 1.53 |

## 交互

橙色圆点只能沿曲线左右拖动，等价于拖动 w₁，范围 [-3.0, 3.0]，默认落在 w₁=1.5。拖动中，点的水平位置即时映射为 w₁，纵向位置查表得 loss，右上角 `.err-badge` 与左侧 `.panel.q` 数字同步刷新（两位小数）。目标不是找到"正确答案"，而是让学生亲手感受：远离低谷时曲线陡峭、loss 变化剧烈；靠近 w₁=-0.5 附近变化平缓。提供"回到默认"按钮复位到 w₁=1.5，无成功/失败判定。

## 核对

w₁=-0.5 → loss≈0.474（曲线最低点）；w₁=0 → loss≈0.503；w₁=3 → loss≈1.534（右端最高）。公式入口：`Lec.P.bce(0, Lec.P.activate('sigmoid', w1))` 与 `Lec.P.bce(1, Lec.P.activate('sigmoid', w1+1))` 取平均。
