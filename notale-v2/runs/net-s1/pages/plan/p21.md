## 知识结构：generalization

1. **关系不变量**：六张卡片分"能"与"不能"两组各三张，同尺寸、同网格基线并列，两组左右（或上下）对称呼应——它们是同一套训练机制（梯度下降 + 链式法则）引出的两类同等重要的结论，不能一组明显更大更醒目。
2. **禁止画法**：不能把"不能做什么"三条画成弱化小字、脚注或折叠角标——它们和"能做什么"权重相同，都是正式结论，不是免责声明式的附言。
3. **共享原语**：`.k-generalization` 的 `.claim`（主标题）→ `.trunk`（同一套训练机制）→ `.supports` → `.support` 映射到 `stage-cards` 的 `.card`；每卡用 `.tag` 标出"能/不能"语义，分别取 `--green` 与 `--red` 辅助色，不单独承担信息，只附着在卡片标题旁。

## 六张卡片

| 类别 | 标题 | 说明 |
|---|---|---|
| 能 | 逼近任意复杂边界 | 层数够、数据够时，小网络也能学出弯曲的决策边界（p18 已见） |
| 能 | 自动分配责任 | 链式法则算出每个权重该改多少，不必人工写规则（p14–p16） |
| 能 | 稳定收敛到"够用"的解 | 学习率选得合适，误差通常能降到很低（p19 三组对比已见） |
| 不能 | 保证找到全局最优 | 梯度下降只保证走到局部低点，复杂曲面上可能卡在半山腰 |
| 不能 | 保证新样本也对 | 训练集准 ≠ 新样本准，这是泛化问题，p20 已留下口子 |
| 不能 | 说清"为什么这么判" | 权重层数一多，人类很难逐一读出决策理由——这仍是开放问题 |

## 表征形式

静态 DOM 卡片网格，无需图表库。`stage-cards` 版式原生 `.card` 排成 2 行 3 列（或 3 行 2 列，两组各占一整行/一整列以保持对称），不使用 `.active` 态（本页无交互）。标题用 sans 字体，说明句 `--fs-sec`；`.tag` 使用小写文字"能 / 不能"配色块，颜色仅作语义提示，不改变卡片布局权重。
