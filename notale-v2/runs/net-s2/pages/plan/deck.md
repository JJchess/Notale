# 《神经网络是怎么学会的：从一个神经元到反向传播》 30 分钟互动讲义 · 总规划

## 0. 这套讲义的主线

神经网络的"学习"不是黑箱魔法，而是同一个可拆解的动作——测出错得多少、看清哪边更平坦地下坡、往那边挪一小步——从一个神经元到一整张网络反复执行，被反向传播自动化到每一层。

章｜页｜这一章要让读者信什么

I｜01–05｜一个神经元的判断可以拆成"按权重加总＋输出开关"，其对错也能被换算成一个具体数字
II｜06–08｜误差随参数变化会形成一片"地形"，沿坡度方向挪动参数就是"学习"的最小动作，步子大小直接决定学得快慢和成不成
III｜09–10｜一个神经元只能画直线分界，把神经元叠成多层才能把直线拧成复杂边界
IV｜11–16｜多层网络靠反向传播把下坡方向逐层分配到每个权重；训练效果好不好，既要看步长选得对不对，也要看边界能不能扛住没见过的新数据
V｜17–19｜从一个神经元到一整张网络，"学习"始终是同一个"测错—下坡—重复"的动作，只是被自动化和放大到了更大规模

证据链节点：

- E1：一个神经元＝按权重加总输入再送进一个决策开关，判断的对错可以换算成一个具体数字。
- E2：误差随参数变化构成一片地形，地形上存在"下坡"方向；沿下坡方向挪动参数、误差就变小——这是"学习"的最小动作。
- E3：一个神经元只能画一条直线分界，遇到弯曲/环绕的数据必须靠多层神经元叠加才能把直线拧成复杂边界。
- E4：多层网络的下坡方向不能一次算出，需要把输出端的误差从后往前逐层分配"责任"——反向传播就是把 E2 的下坡动作系统地重复到每一层。
- E5：步子大小（学习率）与训练好的边界能否在没见过的新数据上依然管用（泛化），共同决定"学会"是否真正发生。

## 0.5 视觉世界

- 现实参照：等高线地形图与徒步地图。理由：本课的核心比喻是"误差地形＋下坡"，等高线地图是这个比喻在现实中最常见的可指名视觉传统，教室里几乎所有学生都见过徒步/爬山 App 上的等高线，不需要额外解释就能读懂"线越密＝越陡＝该小步走"，比抽象坐标系更省认知带宽。
- 形状语言：①同心环状线表示误差地形的"等高线"，线越密代表越陡；②一个圆形"徒步者"标记表示参数/权重的当前位置，全程复用；③正向信号用圆头实箭头（浅色），反向传播信号用圆头虚箭头（强调色），只靠线型和方向区分，不依赖颜色深浅；④单层神经元的分界线用粗直线，多层网络的边界用同样线宽的弯曲曲线——形状本身就传递"表达能力"差异；⑤神经网络的层用略微错位叠放的"卡片"表示层叠结构，边缘留白、不做阴影渲染。
- 底色：明亮米白 `#F7F3EA`——像地形图纸张的底色，投影长时间显示不刺眼，与深色线条形成足够对比，适合文理混合学生长时间盯屏阅读。
- 主色相：深蓝 `#1B4B6B`，唯一代表"当前正确/稳定下降的路径"（等高线主线、下坡轨迹、参数当前值、正向传播箭头）。
- 强调色：橙红 `#E8622C`，只用于当前注意点（正在被拖动的滑块、当前样本、正在反向传播的那一层）。米白底上橙红与深蓝都能在教室远距离投影下第一眼被认出。
- 字体：无衬线字体承担正文与所有 UI 标签，笔画简洁、远距离辨认率高；衬线字体只用于少量"定义卡"标题（如"什么是学习率"），营造教科书式的庄重感，降低使用频率；等宽字体只用于展示具体数值读数（loss、准确率、权重值），保证数字对齐、方便学生一眼比较训练前后差异。
- 材质：扁平（flat）为主方向。教室投影亮度有限、观看距离远，扁平色块配清晰线条的可读性远高于渐变/光照拟真材质，且拖动滑块时需要实时重绘，扁平材质渲染成本最低，能撑住每帧交互的流畅度。
- 母题：①等高线圈（误差地形）；②徒步者圆点标记（当前参数位置）；③卡片叠层（网络层结构）；④圆头箭头（正向实线／反向虚线）；⑤空心圆点与实心圆点（两类数据样本）。

被否决的方向：

1. 赛博朋克/霓虹发光的"AI 感"插画——否决理由：这类视觉依赖深色背景与高对比发光特效，教室投影下容易过曝、文字糊掉；更重要的是它把"学习"包装成炫技特效而非可拆解的机械动作，和本课"学习是一步步可操作的动作"这一核心主张直接冲突，会给无编程基础的学生增加不必要的神秘感。
2. 严格的工程蓝图风格（白线蓝底、CAD 网格感）——否决理由：蓝图适合表达精确装配结构，但本课的核心比喻是连续、模拟的"地形与下坡"，蓝图的冷硬直线网格与此冲突；且大面积深蓝底色在长时间教室投影下对比度过强，容易造成文理混合、非专业学生的视觉疲劳。
3. 手绘水彩风格的实验插图——否决理由：水彩笔触的不精确边缘会让"决策边界"这种需要被精确拖拽、精确比较位置的图形显得模糊难判，而本课多个页面依赖学生亲手拖拽后立即读出准确的几何反馈，水彩质感会削弱这种精确感。

## 0.6 对这个受众的取舍

- 能用：生活中的加权判断直觉（选餐厅、要不要带伞、给菜打分）；看图比大小/比多少的直觉；拖滑块、点按钮等日常 UI 操作经验；看等高线地图爬山的经验；"数值越小越好/越大越好"的常识比较。
- 不用：不引入"导数""偏导""链式法则""梯度""矩阵""向量"的正式定义与符号运算；不写反向传播的公式推导（∂L/∂w 展开）；不讲 Adam/动量/正则化/dropout 等优化器变体；不讲卷积/RNN/Transformer 等具体架构；不要求学生读一行程序代码。
- 换算：所有抽象数值都换成可感尺度——"判断有多自信"用百分比/进度条呈现；误差先用"分对了几个点/总共几个点"这种可数形式，再过渡到连续 loss 数值；参数变化速度用"地图等高线的陡峭程度"呈现；训练轮数用"走了几步"代替"迭代了多少个 epoch"。
- 争议：①"学习率多大算合适"没有放之四海而皆准的答案，课堂演示的三档取值只是示意范围，不是普适阈值，需在 p15 明确提醒；②本课在几十到两百个二维点上看到的"泛化"效果，与真实大型模型（语音识别等）的泛化能力机制相通但规模、难度相差巨大，需在 p16–p18 之间提醒学生这是简化示意而非等比例缩小的真实系统。
