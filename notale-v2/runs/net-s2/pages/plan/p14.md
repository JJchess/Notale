# page-14 · 训练网络看误差下降 · **150 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `TRAIN-THE-NETWORK` |
| 主标题 | 点一下「开始训练」：同一个下坡动作，自动重复了上千次 |
| 收束句 | loss从2点几一路探底到0.05附近，决策边界从乱猜的色块收拢成包住圆形数据的曲线，准确率冲过0.97 |
| 下一问 | 但如果这一步（学习率）迈得不对，训练会变成什么样？ |

## 知识结构：process

关系不变量：loss曲线、决策边界热力图、准确率读数三处必须来自同一个训练计时器驱动的同一份权重快照——曲线走到第几步，边界和准确率就必须显示同一步的状态，不能各跑各的时间轴。禁止画法：不得把loss曲线动画和边界热力图动画拆成两条互不同步的独立播放（例如曲线已到800步、边界还停在第200步的画面）。共享原语：`.k-process` 的 `.step`/`.arw` 串联「前向→算loss→反向传播→更新权重→重画边界」五步循环，训练进行时依次高亮；卡片叠层母题（同p10/p12）常驻背景表示 [2,10,10,1] 网络结构；loss曲线沿用"深蓝＝当前路径"色语义；空心/实心圆点母题叠加在热力图上表示两类训练点。

## 表征形式

交互式，Canvas 2D 原生绘制：决策边界热力图（80×80网格）与loss折线共享同一个 `requestAnimationFrame` 循环，避免两套渲染管线不同步。loss曲线x轴为训练步数、y轴固定范围覆盖0–2.6；准确率用 `.big`/`.num`/`.unit` 等宽字体展示（如 `0.972`）。状态切换通过整页一个 class（`.training`/`.paused`）驱动五步高亮动画。

## 主工作流

simulate-2d ← 需要驱动真实的多层网络训练循环（前向/反向/更新/重画）在80×80热力图与loss曲线上逐帧同步呈现，且必须可复位、可重放、性能可控

## 不许碰

不讲学习率取值不当会怎样（留给 p15 的三档对比）；本页固定使用合适学习率跑通一次完整训练，不展示震荡或不收敛的对照。

## 显示常量与训练参数

| 名称 | 值 | 说明 |
|---|---|---|
| 网络结构 | [2,10,10,1] | 2输入→10隐藏→10隐藏→1输出 |
| 训练集规模 | 200 个点 | 环形/月亮分布双类点 |
| 每帧mini-batch步数 | 12 | mlp.js 实测基准 |
| 热力图分辨率/刷新 | 80×80网格，每8帧重算一次 | 控制渲染成本 |
| 学习率 | 0.3 | 本页固定为"合适档" |
| 起点loss | ≈2.5 | 随机初始化后 |
| 收敛loss | ≈0.05 | 约1000+步后 |
| 训练后准确率 | ≈0.97–0.995 | 数字口径基准 |

计算入口：每帧调用 `Lec.P.forwardNetwork(layers, x)` → `Lec.P.backwardNetwork(caches, dLossDOutput)` → `Lec.P.sgdUpdate(param, grad, 0.3)`，逐点用 `Lec.P.mse`/`Lec.P.mseGradient` 算loss与梯度，真实驱动、非预烤曲线。

## 交互

学习者可点按钮组：「开始训练」/「暂停」/「重置」。开始后loss曲线逐点延伸、热力图每8帧重画一次收拢边界、准确率读数实时跳动上升；暂停可随时定住当前状态细看；重置回到同一随机种子的初始权重，重新播放得到完全相同的曲线（确定性可复现，非每次随机不同）。无滑块，唯一变量是"是否在跑"。

## 动效

五步循环高亮：前向（浅色实箭头沿网络卡片正向点亮，约200ms）→算loss（loss曲线新增一点，橙红闪一下，约150ms）→反向传播（虚线箭头从输出卡片逆向点亮回权重，约250ms）→更新权重（卡片边框轻微闪一下，约100ms）→重画边界（热力图淡入过渡，约300ms，每8帧一次）。训练开始整体入场（按钮态切换、首帧绘制）不超过400ms，不重复播放已讲清的关系。

## 核对

固定随机种子下：训练前起点loss应落在2.3–2.6之间；训练到约300步、lr=0.3时准确率应已过0.9；训练到1000+步时loss收敛到0.05附近、准确率进入0.97–0.995区间；点击"重置"后重新训练，曲线与首次运行完全一致（同种子确定性）。

## 存疑

数字口径表中「默认学习率常量」写为0.3并标注来源"共享模块常量（DEFAULT_LEARNING_RATE）"，但计算接口给出的 `Lec.K.DEFAULT_LEARNING_RATE` 实际值为 0.1，与页表口径不一致。本页按数字口径表的0.3（p14/p15均以此为"合适档"基准）实现，未采用 `Lec.K` 的0.1，此处仅记录冲突，供上游核对源头。
