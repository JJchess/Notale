# page-16 · 撒新点测试网络 · **125 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `GENERALIZATION` |
| 主标题 | 这条边界，认得从没见过的点吗？ |
| 收束句 | 50个新点里约47个落在正确一侧——网络学到的是"规律"，不是死记住这200个训练点 |
| 下一问 | 从加权投票到能认新点，这条链上到底重复了几次同一个动作？ |

## 知识结构：generalization

**关系不变量**：训练时的200个旧点、固定不变的决策边界、新撒的50个点必须共享同一张坐标系、同一条边界线——边界只画一次，旧点新点都叠在它上面比对，不能各占一张图。
**禁止画法**：不得把"训练点＋边界"和"新点＋边界"拆成左右两张独立小图，那会暗示两条不同的边界，抹掉"同一条边界经受检验"这个核心主张。
**共享原语**：`.k-generalization` 承担 `.claim`（主标题的主张）+ `.trunk/.supports`（旧点是背景支撑、新点的正确/错误比例是关键证据）；`.legend` 标出空心/实心圆点（两类）与正确/错误环圈的含义；`.big/.num/.unit` 用等宽字体显示"47 / 50"这类计数读数。

## 表征形式

静态背景为一次性渲染的决策边界热力场（复用p14/p15训练完成后的固定权重，80×80网格，只算一次不必逐帧刷新）；训练用的200个旧点以低对比度小圆点常驻显示。新点撒落用原生 SVG（`<circle>` 逐个 append，无需额外库），点击按钮时批量插入50个新 `<circle>`，按真实类别取空心/实心形状，按预测是否正确套一层色环（深蓝环＝分对，橙红环＝分错）。计数用 DOM 文本节点更新，无需图表库。

## 主工作流

design-interaction ← 难点在"点击撒点→立即分类反馈→计数更新"这一循环的清晰设计，而非绘制边界本身

## 内容填充表

| 参数 | 值 | 说明 |
|---|---|---|
| 复用网络结构 | [2,10,10,1] | 与p14/p15训练完成的权重直接复用，本页不重新训练 |
| 训练集规模（背景旧点） | 200 | 小而淡，仅作参照，不参与本页计算 |
| 边界网格分辨率 | 80×80 | 一次性渲染，权重不变故无需逐帧重算 |
| 新撒点数量 | 50 | 每次点击"撒新点"重新随机生成，替换上一批 |
| 分类判定 | `Lec.P.forwardNetwork(layers, x).output ≥ 0.5` 记为该类 | 逐点比较预测类别与生成时的真实标签 |
| 学习率标注 | 0.3（口径值） | 沿用p15"合适"档结果对应的边界，仅作说明文字，不在本页调节 |

## 交互

学习者点击"撒新点"按钮，在与训练点相同的分布（同一环形/月亮形生成规则、不同随机种子）里生成50个新坐标点；每点立即调用固定权重的 `forwardNetwork` 得到预测类别，与生成时赋予的真实类别比较，用色环标出对错，同时更新页面上"X / 50 正确"的计数读数。可重复点击换一批新点观察比例是否稳定在类似区间，状态可逆，无需单独复位按钮。

## 不许碰

本页只用固定权重做前向判断和计数，不重新训练、不展示训练过程中的loss曲线（归属p14）；不展开更复杂网络结构或图像/文本等其他数据类型上的泛化情况——这类扩展留给p17之后的收束与迁移页处理。

## 存疑

数字口径表标注"默认学习率常量＝0.3（DEFAULT_LEARNING_RATE）"，但计算接口给出的 `Lec.K.DEFAULT_LEARNING_RATE` 实际值为 `0.1`。本页按口径表沿用 0.3 作为说明文字（对应p15"合适"档），未使用该常量做实际计算，故不影响本页交互，但两处数值不一致，留待全套统一核实。
