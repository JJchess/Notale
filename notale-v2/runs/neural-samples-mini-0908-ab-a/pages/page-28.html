Query、Key、Value 与位置编码

内容检索与顺序补偿

内容寻址：向量内积度量相似度
寻址角色：Query 是检索条件，Key 是被查索引，Value 是承载内容。
顺序补偿：无序集合与位置编码
归纳偏置补偿：注意力缺乏时序因果，必须通过编码刻入顺序。
在上一节中我们看到了注意力权重的动态计算。现在我们把这个过程抽象为标准的 Query、Key、Value 机制： Query 相当于我们在数据库里发出的查询词，比如代词“它”想要寻找它所指代的目标； Key 是每个候选词的索引标签，我们用 Query 和 Key 的向量点积并除以根号 d 得到相似度分数，经 Softmax 归一化后就是注意力概率； Value 是候选词真正包含的信息内容，输出向量就是所有 Value 的加权和。 但这里有一个核心问题：点积是一种集合操作，如果把输入句子的顺序打乱，两两之间的点积结果完全不变！ “我打他”和“他打我”如果只看词集合，计算出来的相似度矩阵是一样的。 CNN 靠局部窗口感知位置，RNN 靠一步步递推天然拥有时序；注意力机制必须在词嵌入上直接加上位置编码（Positional Encoding），把坐标信息显式刻进向量里。
