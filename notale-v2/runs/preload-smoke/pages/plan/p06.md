# page-06 · 平移并压缩 · **90 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `CALIBRATION · OUTPUT` |
| 主标题 | 偏置先挪动判断基准，sigmoid 再把得分压进 0–1 |
| 收束句 | 偏置改变模型从哪里开始倾向于“是”，sigmoid 则保证输出可读成 0–1 的预测。 |
| 下一问 | 有了 0–1 的预测，怎样用一个数比较它究竟错得多严重？ |

## 知识结构：classification

关系不变量：三栏必须共享水平基线，依次放“加权汇合值”“加入偏置后的得分”“sigmoid 输出”；前两栏嵌套在“内部得分”类别下，第三栏单独归入“预测”类别，分类归属不能被画成三个并列算法。

共享原语：`.k-classification` 用 `.lv` 和 `.bt` 区分“内部得分”与“预测”的归属；`.triptych` 让三个观察窗同宽并列；偏置控制使用 `.knob`，最终预测使用 `.big`，突出量的角色不同。

## 表征形式

交互式三联观察窗：固定加权汇合值、可调偏置、压缩前后读数并列；按钮在“压缩前／压缩后”之间切换当前观察焦点。原生 DOM 与 SVG 足以绘制单条 sigmoid 参照曲线和位置标记。

## 主工作流

build-interaction ← 将偏置平移与 sigmoid 压缩拆成两个可观察但连续的动作

## 三栏内容

| 栏位 | 画面文字 | 默认值或规则 |
|---|---|---|
| 左栏 | 加权汇合值 | 固定 `2.0` |
| 中栏 | 加上偏置 | 偏置默认 `−2.0`；内部得分 `2.0 + (−2.0) = 0.0` |
| 右栏 | sigmoid 输出 | `sigmoid(0.0)=0.500` |
| 旁注 | sigmoid | “把任意有限得分压到 0–1；得分为 0 时输出 0.5。” |
| 显示常量 | 判断基准 | `0.5`，来自 `BINARY_CLASSIFICATION_THRESHOLD` |

计算使用 `Lec.P.activationValue("sigmoid", value)`；页面不出现其他激活函数名称。

## 交互

偏置旋钮范围 `−6.0–6.0`，步长 `0.1`，默认 `−2.0`。调节时只改变中栏得分和右栏输出，左栏保持 `2.0`，从而隔离偏置作用。“看压缩前”突出中栏原始得分；“看压缩后”突出右栏 0–1 输出及曲线位置，两者只是观察切换，不改变计算。提供“回到基准”按钮恢复偏置 `−2.0`。

## 动效

偏置变化时，中栏数轴标记先水平移动 `200ms`；右栏曲线上的位置点延迟 `120ms` 更新，预测读数同时刷新。切换观察时只移动橙色粗框，不重播整条流程。

## 核对

| 偏置 | 加偏置后得分 | sigmoid 输出 |
|---:|---:|---:|
| `−2.0` | `0.0` | `0.500000` |
| `0.0` | `2.0` | `0.880797` |
| `−4.0` | `−2.0` | `0.119203` |

## 不许碰

不比较 sigmoid 与其他隐藏层激活，也不讨论隐藏层为什么需要不同响应；相关内容归 p15。不得在此页计算预测损失，损失归 p07。
