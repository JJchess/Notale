# 《神经网络的发展史》90 分钟互动讲义 · 总规划

## 0. 这套讲义的主线

神经网络不是一次发明，而是一条「表达力受限 → 找到突破口 → 撞上新墙 → 换一种资源破墙」反复循环的历史，每一次「寒冬」都不是败给了理论，而是败给了当时算不动、看不清、数据不够；今天能实时训练的那个小网络，正是历史上无数人求而不得的东西。

| 章 | 页 | 这一章要让读者信什么 |
|---|---|---|
| Ⅰ 神经元的初次尝试（1940s–1950s） | page-01 ~ page-05 | 感知机是真实可运行的电路，它能学，但它的能力有一条数学上硬性的边界 |
| Ⅱ 第一次寒冬（1969–1980s） | page-06 ~ page-09 | XOR 不是「难」而是「不可能」——这是几何事实，也是资金枯竭的直接导火索 |
| Ⅲ 反向传播与复兴（1980s–1990s） | page-10 ~ page-14 | 多层 + 反向传播解决了 XOR，但训练比想象的难，深层网络会「学不动」 |
| Ⅳ 第二次寒冬与坚守（1990s–2000s） | page-15 ~ page-17 | SVM 等方法在数据小、理论干净上赢过神经网络，少数人顶着质疑继续挖 |
| Ⅴ 深度学习爆发（2006–2012） | page-18 ~ page-22 | 让深度网络训练动起来靠的是三样具体资源：更好的初始化/激活、更大数据、GPU 算力 |
| Ⅵ 走向今天（2012–2020s） | page-23 ~ page-26 | 每一代突破都是「同一套反向传播 + 新的架构假设」，Transformer 也不例外 |
| Ⅶ 回望与练习台 | page-27 ~ page-28 | 把整条历史压缩成一张可操作的时间线与一个自由练习场，检验读者是否真的建立了直觉 |

### page-01 · 一个神经元能做什么
**章**：Ⅰ　**kicker**：`THE FIRST CELL`
**标题**：`神经元不是隐喻，是一个<em>可以算</em>的函数`
**take**：一个神经元 = 加权求和 + 一个阈值判断，仅此而已。

**内容**
- 用一个可拖拽权重滑块的示意，展示 $y = \text{sign}(w_1x_1+w_2x_2+b)$，读者拖动 $w_1,w_2,b$ 看输出的 0/1 如何随之翻转。
- 背景铺 8～10 个二维散点（两类点），拖动参数时同步画出分割直线的移动。
- 强调这条直线永远是直的——为后面 XOR 的不可能埋伏笔。
- 数值：分割线方程与散点分类结果用 `Lec.P.perceptronLine(w1,w2,b)` 现算，不写死坐标。

**采用的形式**：可拖拽的实物隐喻（滑块+散点+实时直线）
理由：读者需要亲手感受「权重变化 = 直线转动」这个线性代数事实，静态图看不出这种连续对应关系

**否决的形式**
- *视频讲解直线方程*：读者已学过线性代数，重复讲公式没有增益，动手拖才是增益
- *三维场景*：二维已经足够表达线性可分性，三维只会增加认知负担

**版式**：split-lr
**必用skill**：d3-viz
**独占**：单神经元的线性判别式与其几何意义（分割线）

### page-02 · 1943：麦卡洛克-皮茨神经元
**章**：Ⅰ　**kicker**：`MCCULLOCH-PITTS 1943`
**标题**：`第一次把神经元写成<em>逻辑门</em>`
**take**：最早的「人工神经元」诞生于试图解释真实大脑，而不是为了做机器学习。

**内容**
- 时间线卡片：1943 年论文的历史背景（沃伦·麦卡洛克是神经生理学家，沃尔特·皮茨是逻辑学家）。
- 交互：读者选择 AND / OR / NOT 三种逻辑门，页面用同一个 M-P 神经元结构（固定阈值规则）自动摆好权重，展示它确实能实现这些门。
- 强调：M-P 神经元的权重是手工设计的，不是学出来的——这是与下一页感知机的关键区别。

**采用的形式**：卡片式历史陈列 + 小型逻辑门模拟器
理由：门电路等价性用图表演示即可讲清楚，交互重点在于让读者亲自切换三种门、观察权重如何跟着变

**否决的形式**
- *三维神经科学动画（画真实神经元）*：这堂课讲的是数学抽象史，不是神经科学，画真实神经元会喧宾夺主
- *可训练的滑块*：M-P 神经元历史上权重是手工给定的，加入训练交互会制造史实错觉

**版式**：ledger
**必用skill**：无
**独占**：M-P 神经元与「手工设计权重」的历史定位；AND/OR/NOT 门电路等价展示

### page-03 · 1958：感知机与学习规则
**章**：Ⅰ　**kicker**：`ROSENBLATT'S PERCEPTRON 1958`
**标题**：`第一次让权重<em>自己</em>调整`
**take**：感知机学习规则每次只根据一个错分点的方向微调权重，这是史上第一个「学习算法」。

**内容**
- 交互核心：一批二维散点（两类），读者点击「单步训练」按钮，每次只处理一个样本，页面高亮当前样本、展示权重更新的箭头方向，分割线随之转动。
- 显示当前迭代次数、当前错误数，用 `Lec.P.perceptronStep(state)` 每步现算一次权重更新（用真实感知机学习规则，非预录）。
- 读者可以调整学习率，观察收敛快慢的变化。
- 最终这批点是线性可分的——收敛会在有限步内发生，页面会明确提示「已收敛」。

**采用的形式**：逐步执行的算法沙盘（点击一步看一步）
理由：感知机学习规则的精髓就是「看错哪个点、往哪个方向挪」，逐步交互能让读者对齐每一步与几何变化的因果关系

**否决的形式**
- *自动播放整个训练过程*：会略过关键的单点决策逻辑，读者看不清楚「为什么这一步权重要这样变」
- *用 mlp.js 训练*：mlp.js 是多层网络，这里刻意要展示最原始的单层感知机规则，用它自己实现的四十行代码更贴切也更透明

**版式**：split-lr
**必用skill**：d3-viz
**独占**：感知机学习规则的逐点更新过程（区别于 page-01 的静态展示与 page-04 的批量收敛全貌）

### page-04 · 感知机收敛定理
**章**：Ⅰ　**kicker**：`CONVERGENCE GUARANTEE`
**标题**：`只要数据线性可分，感知机<em>保证</em>收敛`
**take**：这不是经验观察，是可以证明的数学定理——这也是当年感知机被寄予厚望的原因。

**内容**
- 用三组不同的线性可分数据集（点击切换），读者观察无论初始权重多离谱，感知机总能在有限步内找到分割线。
- 侧边展示当前用了多少步收敛，用 `Lec.P.perceptronConverge(dataset, w0)` 跑出真实步数（不是预设数字）。
- 简短提示：收敛步数上界与「间隔（margin）」有关——间隔越小，步数上界越大，用一个可调的「挤压两类点间距」滑块直观展示。

**采用的形式**：多数据集切换 + 自动收敛演示
理由：定理的信心来自于「换几组数据都成立」，切换数据集比单一动画更有说服力

**否决的形式**
- *证明推导的公式滚动*：读者不是来推证明的，这门课要建立的是直觉与历史脉络
- *游戏化闯关*：定理性质不需要竞技感，会分散注意力

**版式**：triptych
**必用skill**：无
**独占**：收敛定理与间隔（margin）的关系

### page-06 · XOR：一个不可能的任务
**章**：Ⅱ　**kicker**：`THE XOR PROBLEM`
**标题**：`有一种简单的模式，单层网络<em>永远</em>学不会`
**take**：XOR 的四个点不存在任何一条直线能把它们正确分开——这不是训练不够，是几何上不可能。

**内容**
- 交互：把 page-03 同款的单层感知机训练器直接套在 XOR 的四个点上，读者点击「单步训练」，看权重不断调整、分割线来回摆动却始终无法把四点分对。
- 用 `Lec.P.perceptronStep` 跑真实的训练过程，让读者亲眼见证「越训练越不收敛」，而不是被告知。
- 页面下方放一个「错误率」曲线，长期在 0.5 附近震荡不降，用 `Lec.P.perceptronConverge` 拿真实数据算出的错误率序列画出来。

**采用的形式**：复用感知机训练器、但换上 XOR 数据集，让「训练不收敛」成为亲眼所见的事实
理由：比起被告知「XOR 线性不可分」，让读者看着同一个训练器在这里失败，冲击力和记忆点强得多

**否决的形式**
- *直接展示几何证明*：证明本身简短，但这堂课要的是「亲眼看着它失败」的体验，证明放在下一页作为解释而非开场
- *换成一个新奇的交互控件*：复用同一个训练器强化「这不是能力问题，是问题本身的问题」的对比效果

**版式**：split-lr
**必用skill**：d3-viz
**独占**：XOR 数据集上的单层感知机训练失败演示（与 page-03/04 的成功案例形成呼应）

### page-07 · 为什么不可能：线性可分性
**章**：Ⅱ　**kicker**：`LINEAR SEPARABILITY`
**标题**：`一条直线能分开的世界，就这么<em>大</em>`
**take**：单层感知机的表达力被严格限定在「用一个超平面切一刀」——这是可以证明的数学边界，不是工程缺陷。

**内容**
- 交互画布：读者可以自由添加/拖动红蓝两类点，页面实时判断「当前这批点是否线性可分」（用简单的凸包相交检测或用 `Lec.P.isLinearlySeparable(points)`），可分时显示分割线，不可分时高亮冲突区域。
- 引导读者主动摆出 XOR 形状，亲手验证「摆成这个形状就是不可分」。
- 简明呈现感知机的表达力边界 = 半空间（half-space）这一几何事实。

**采用的形式**：自由拖拽点位的实时可分性检测器
理由：让读者自己「造出」不可分的例子，比被动看别人造好的例子更能建立起「这是一整类问题」的认识，而不是「XOR 恰好特殊」

**否决的形式**
- *固定展示几个例子*：读者的探索空间被限制，容易误以为只有 XOR 这一种特例
- *公式推导凸包分离定理*：定理背后的几何直觉比公式推导更适合这堂课的读者水平

**版式**：canvas-full
**必用skill**：d3-viz
**独占**：线性可分性的一般几何定义与自由验证工具

### page-10 · 多层网络与反向传播
**章**：Ⅲ　**kicker**：`BACKPROPAGATION 1986`
**标题**：`链式法则，用在<em>千百个</em>参数上`
**take**：反向传播不是新数学，是把微积分链式法则系统性地应用在多层网络的每一个权重上。

**内容**
- 交互：一个 `[2,3,1]` 的迷你网络示意图（节点+连线），读者点击某个权重，页面高亮从输出到该权重的完整链式求导路径，并显示该权重的梯度数值。
- 用 `MLP.create({sizes:[2,3,1], act:'tanh'})` 真实跑一次前向+反向，把 `net.layers` 中的激活值和梯度实时读出来显示在对应节点/连线上，而不是预先算好写死。
- 强调：梯度的计算是从输出向输入「反向流动」的，这也是名字的由来。

**采用的形式**：可点选的计算图 + 真实网络反向传播过程可视化
理由：链式法则的抽象公式对读者而言不难，难的是想象它在一个多层网络里如何逐层传播——把真实梯度数值贴在连线上能把抽象过程落到实处

**否决的形式**
- *公式推导逐行展示*：读者学过微积分，链式法则本身不是难点，难点是「规模化后如何组织计算」，这需要图示而非公式罗列
- *视频动画预录梯度流动*：与本课"每个交互背后要有真实算法"的要求冲突，且预录动画无法让读者自主点选探索

**版式**：canvas-full
**必用skill**：d3-viz
**独占**：反向传播的链式法则在计算图上的逐权重展示

### page-11 · 亲手训练一个多层网络攻克 XOR
**章**：Ⅲ　**kicker**：`SOLVING XOR AT LAST`
**标题**：`多加一层，就能画出<em>弯曲</em>的边界`
**take**：一个隐藏层就足以让网络画出非线性的决策边界，XOR 从此不再是不可能。

**内容**
- 交互核心：用 `MLP.create({sizes:[2,4,1], act:'tanh', lr:0.3})` 在 XOR 数据集上实时训练，读者点击「训练」按钮，页面每帧调用 `net.step(trainSet,12)`，同步用 `net.field(...)` 画出决策边界热力场的演变。
- 显示实时 `net.evaluate(valSet)` 得到的 loss/acc 曲线。
- 读者可以调整隐藏层神经元数量（2/4/8），对比收敛速度与最终边界形状的差异——亲眼验证「够用的容量」这一概念。

**采用的形式**：实时可训练的小型神经网络 + 决策边界热力场
理由：这是全课的情绪转折点——XOR 从「不可能」到「几秒钟内解决」，唯有让读者亲手点下训练按钮、看着边界从直线变成弯曲曲线包住四个点，才能真正体会到这次突破的分量

**否决的形式**
- *用 tf.js 训练*：按文档实测数据，这个规模的网络手写 mlp.js 每帧 0.66ms 远快于 tf.js 的 102.7ms，实时交互体验会有天壤之别

### page-13 · 梯度消失：深层网络学不动
**章**：Ⅲ　**kicker**：`THE VANISHING GRADIENT`
**标题**：`层数越深，最前面的权重<em>越难</em>更新`
**take**：sigmoid 的导数最大只有 0.25，链式相乘经过几层后梯度会指数级缩小到几乎为零——这是深层网络在 90 年代长期训不动的真正原因。

**采用的形式**：多深度/多激活函数并行训练对比 + 逐层激活强度条形图
理由：梯度消失是一个「历时性」现象，必须通过真实训练过程中的收敛速度差异才能体会，静态图表无法传达这种「越往前推越难」的时间维度感受

**否决的形式**

**版式**：split-lr
**必用skill**：无
**独占**：梯度消失现象的实时训练对比演示；`activationLevels()` 逐层强度可视化
