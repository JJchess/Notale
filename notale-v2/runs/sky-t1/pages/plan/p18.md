## 知识结构：classification

1. **关系不变量**：日志字段按“何时—何方—何物—靠谁”自上而下嵌套；候选必须与两颗邻近亮星写在同一条记录中，不能脱离恒星背景单列。
2. **禁止画法**：不得把日期、时刻、方向和邻星拆成互不相连的装饰卡片，使“候选”看似可以独立确认。
3. **共享原语**：`.k-classification` 将日志组织成证据层级；`.ledger` 承担可抄写的整张观测记录；`.panel.q` 框出当前待填写字段，不与已完成字段混淆。

## 表征形式

交互式纸质观测日志表单：左侧是一条已填写的示例记录，右侧是学生完成的同构记录；底部保留一行“明天复看”提醒。

使用原生 DOM 与 SVG 更合适：字段、候选环和两颗邻星关系无需图表库。候选亮点使用 SVG 黄环，恒星与连线使用 `--map`；日期、时刻、方向采用 `--font-mono`，可抄写的完整记录采用 `--font-serif`。字段完成状态通过切换 class 更新，候选与邻星连线同步高亮。

## 主工作流

design-interaction ← 将“记录字段”变成一次可完成、可检查的观测日志填写

## 不许碰

不讲手机拍摄、曝光、对焦或用手机替代纸图的设置（p20）。不重新解释隔日相对恒星位移为何能确认行星（p17）；本页只留下复看所需的记录位置。

## 一条可复查日志

| 字段 | 示例记录（画面写入） | 学生填写目标 |
|---|---|---|
| 日期 | `____-__-__` | 观测当天日期 |
| 时刻 | `__:__` | 看见候选的本地时刻 |
| 方向 | `西南` | 面向候选时的方向 |
| 候选 | `候选 A：黄道附近的亮点` | 圈出的候选编号或简短描述 |
| 邻近亮星 1 | `亮星甲：候选左上方` | 一颗图样中的亮星及相对位置 |
| 邻近亮星 2 | `亮星乙：候选右下方` | 第二颗图样中的亮星及相对位置 |
| 明天复看 | `仍从亮星甲、乙之间找候选 A` | 留给下一次观测的定位线索 |

## 交互

学生依次点选或键入五个必填字段：日期、时刻、方向、候选、两颗邻近亮星。默认显示空白日志与一条灰色示例；填写“候选”后，右侧小星图只显示黄环，填写两颗邻星后才出现两条青蓝定位线。

每完成一个字段，字段左侧出现记录勾；缺少两颗邻星时，反馈为“这还只是一次印象：明天无法从恒星背景找回它。”六项齐全后，反馈为“可复查：明天先认亮星甲、乙，再比较候选 A 的位置。”

“清空重填”恢复空白日志；示例记录始终保留，不作为真实当晚天象数据。
