# 全套页面构建契约

## 1. 工作边界

- 只编辑分配给你的 `pages/page-NN.html`。
- 不读、不搜索、不比较任何其他 `page-*.html`。
- 只交付该 HTML；不新建说明、测试、总结或页面专属资源。
- 页面必须自包含，可由浏览器通过 `file://` 直接打开并完整显示、交互。
- 资源一律使用相对路径；禁止 CDN、网络请求和动态下载。
- `PLAN.md` 决定本页教学任务；不得重复第一讲已经讲过的观测手段与尺度。

## 2. 固定骨架

骨架已经存在。只改 `NN`、`TT`、`kicker`、`title`、`take` 和 `#stage` 内正文；按需在指定位置加入本地库。不得删除、改名、重排其余节点和基础资源。

```html
<!doctype html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="assets/base.css">
  <link rel="stylesheet" href="assets/theme.css">
  <!-- 所需库的 CSS 放这里 -->
</head>
<body data-page="NN" data-total="TT">
  <div id="stage">
    <!-- 本页正文只放这里 -->
  </div>

  <!-- 所需库的 JS 放这里，依赖在前 -->
  <script src="assets/base.js"></script>
  <script src="assets/lec.js"></script>
  <script>
    Lec.mount({
      index: NN,
      kicker: "栏目",
      title: "标题",
      take: "本页一句话结论"
    });

    // 本页逻辑
  </script>
</body>
</html>
```

- 页面只向 `#stage` 添加内容。
- 页眉、页脚、舞台和进度由 `Lec.mount()` 生成；不得自行创建 `.lec-header`、`.lec-footer`、`.lec-stage`、`.lec-main`、`.lec-progress` 或重复创建 `#lec-header`、`#lec-footer`、`#main`。
- 页眉页脚的外观和占位由 `theme.css` 负责；不得覆盖其尺寸、定位和布局。
- 内容区高度是 `#stage` 扣除页眉页脚后的剩余区域；具体高度读取 `theme.css`。
- 底盘接口只读 `assets/CHASSIS.md`，不得把它转抄进页面或契约。

## 3. 版面预算

画布固定为 `1600 × 900`。以下均为硬限制：

- 画面占用比：`≥45%`。
- 页面文本块总数：`20–70` 个，包含标题、正文、按钮、控件标签、刻度、图例、图注、提示和动态读数。
- 正文：`80–260` 个汉字；公式、数字、标点不计入汉字数。
- 独立控件：最多 `6` 个；同组单选或分段按钮按实际可操作项计数。
- 同时展示的动态读数：最多 `6` 个。
- 连续说明文字：每段最多 `70` 个汉字，每页最多 `4` 段。
- 超过任一上限必须删减、合并或拆页并明确报告“本页内容超出契约预算”；禁止缩字号、压行高、遮挡、裁切或把文字画进 canvas 规避检查。
- 文本块少于 20 或占用比低于 45%，必须增加真实教学结构、比较维度或过程步骤；禁止靠放大字号、装饰图形或拉大间距撑满。
- 太满应拆页；太空应补足教学内容或与相邻页合并。

默认使用 flex。只有矩阵、维度表等确需二维对齐时使用 grid。需要计算坐标才能对齐时，应调整 DOM 结构；拖拽位移使用 `transform`，不改 `left/top`。刻度与控件分区排布，不用绝对坐标硬凑。

禁止在缩放画布内使用 `position: fixed`；需要固定在内容区时使用相对容器内的 `position: absolute`。

## 4. 字体与主题

- 纯数字刻度：`≥12px`。
- 标签、带文字刻度、图例、图注：`≥14px`。
- 正文、按钮、提示、tooltip、动态读数：`≥16px`。
- KaTeX 基准字号：`≥20px`。
- 所有正文行高：`≥1.35`。
- 禁止通过 `transform: scale()`、`zoom`、canvas 缩放或库内部比例把文字缩到下限以下。
- 设计基准是 `1600 × 900`；在 `1366 × 768` 上舞台缩放约为 `min(1366/1600,768/900)≈0.853`。字号下限按 1600 逻辑画布内的 CSS 像素检查，仍须保证缩放后可读。
- 颜色、字体、字号层级、间距、边框、阴影和圆角只使用 `assets/theme.css` 已有变量与类。
- 不自创主题，不建立平行的颜色或间距系统，不覆盖主题类的定位属性。
- 不得移除底盘或主题提供的类，包括 `lec-root`、`lec-page`、`min0`、`cv-fill`；禁止以 `classList.remove()` 或重写 CSS 的方式破坏这些类。

## 5. 内容与语言

- 面向大学一年级通识课学生，文理背景混合；不假定微积分、天文学或编程基础。
- 每页只承担一个明确问题，并给出一个可复述的结论。
- 新术语首次出现必须就地用一句短定义展开；每页新增核心术语最多 `3` 个。
- 公式出现前先用自然语言说明量与关系；不得把推导作为理解前提。
- 数学只使用中学代数、比例、图像和定性变化；必须使用更高内容时给出直观解释，不要求学生自行推导。
- 说明句每句最多 `35` 个汉字；一个句子只表达一个判断或动作。
- 提示语使用直接、平等的课堂口吻，如“拖动观察”“比较两条曲线”；禁止幼儿化、卖弄术语、反问施压和空泛鼓励。
- 教师带讲时，静态首屏必须能说明问题与结论；学生课后独看时，控件标签、状态和反馈必须自足。
- 不复述第一讲的观测手段、尺度建立过程；仅在本讲推理确实依赖时用一句话调用既有结论。
- 任何允许用户改变的状态下，页面说明都必须成立；禁止让固定文案与动态结果矛盾。

## 6. 数据与计算

- 天文常量、对象属性、单位换算、轨道量、比例、时间和页面导航一律取自 `Lec.K(...)`、`Lec.P(...)`。
- 页面不得写死可由 `Lec` 得到的数值，也不得复制 `lec.js` 中的数据。
- 展示值由原始值实时计算，再用 `Lec.P.round` 或 `Lec.P.significant` 格式化。
- 交互背后的结果必须真实计算；禁止预录动画、假数据或用写死结果冒充计算。
- 随机数据必须引用 `assets/lib/seedrandom.min.js`，使用稳定且包含页号的固定种子。
- 页面数字、图表、读数和讲解必须来自同一数据源。

## 7. 库与技法

动手前先按任务读取 `assets/lib/LIBS.md`。已有库能完成的呈现工作，禁止从底层重写：

| 任务 | 必用库 |
|---|---|
| 常规坐标轴、刻度、图例、折线、柱、散点、面积、饼、热力 | ECharts |
| 可拖拽、需命中检测的二维场景 | Konva |
| 三维场景 | Three.js |
| 下落、碰撞、摆动、堆叠、约束 | Matter.js |
| 节点连线、数据驱动矢量图形 | D3 |
| 成千上万元素同时运动 | PixiJS |
| 多动画时间线 | GSAP |
| 数学公式 | KaTeX |
| 矩阵运算 | ml-matrix |

- 库直接以 `<script src="assets/lib/xxx.js"></script>` 引入；CSS 用本地 `<link>`。
- 依赖库在扩展库之前：Three 在 Globe/Vanta 前，GSAP 在 ScrollTrigger 前。
- 库必须在本页初始化代码之前加载；`base.js` 必须在 `lec.js` 前。
- 版本只按 `assets/lib/LIBS.md`；禁止扫描压缩文件查版本。
- 禁止加载未使用的库。
- ECharts 必须 `echarts.init(el, null, {renderer:'svg'})`；显式设置全局正文 `≥16px`、标签和图例 `≥14px`、纯数字刻度 `≥12px`。
- Konva 负责图形；普通标签用绝对定位的 DOM 覆盖层。必须使用 `Konva.Text` 时显式设置合规字号。
- KaTeX 必须同时引入 `katex.min.css` 与 `katex.min.js`，基准字号 `≥20px`。
- 小型实时二分类网络使用 `mlp.js`；预训练模型、真实图像卷积或 GPU 大矩阵才使用 TensorFlow.js。使用 TensorFlow.js 时每步必须 `tf.tidy()` 或显式 `dispose()`，并确认 `tf.memory().numTensors` 不持续增长。
- 清单中存在对应技法文档时，先用 `Skill` 读取再实现；没有对应文档才自行设计。

## 8. Canvas、缩放与动画

- 所有 canvas 尺寸适配必须使用 `Deck.fit` 或 `Deck.autofit`。
- 所有手写 canvas 指针坐标必须使用 `Deck.pt`。
- 所有逐帧动画必须使用 `Deck.loop`。
- canvas 颜色必须使用 `Deck.rgb` 或 `Deck.rgba`。
- 禁止自行实现 `devicePixelRatio` 缩放、`getBoundingClientRect()` 指针换算或 `requestAnimationFrame` 循环。
- Konva 的指针换算使用其原生 `stage.getPointerPosition()`，不得二次换算。
- 容器尺寸改变后，画布、渲染器、相机和交互命中区必须同步更新。
- 页面必须实现 `prefers-reduced-motion: reduce` 分支：停止持续运动和自动播放，直接显示稳定且完整的教学状态；功能和结论不得缺失。
- 动画不得成为读取结论的唯一途径。

## 9. 交互标准

真交互必须同时满足：

- 用户能通过按钮、滑块、选择、拖拽、键盘或指针改变一个有教学意义的输入或状态。
- 页面即时重新计算或更新图形、读数和结论反馈。
- 改变前后能比较，且变化直接服务于 `PLAN.md` 的本页问题。
- 控件有可见标签、范围、当前值和明确反馈。
- 可操作元素使用原生表单控件或按钮语义；支持 Tab 聚焦、Enter/Space 激活，拖拽操作必须提供键盘等价操作。
- 焦点样式可见；禁止只靠颜色表达选中、对错或变化。
- 触控目标逻辑尺寸至少 `44 × 44px`。

仅悬停发光、自动播放、装饰粒子、视差、倾斜、淡入、无结果变化的拖动均不算交互。装饰不得占用控件预算，也不得替代教学内容。

## 10. 完工自检

在 `pages/` 目录运行：

`python3 assets/selfcheck.py page-NN.html`

对每个关键交互状态再运行：

`python3 assets/selfcheck.py page-NN.html --after "<触发该状态的 JS>"`

必须检查首屏、每个控件边界值、重置状态和至少一个组合状态。判据：

- 无 JavaScript 错误。
- 无资源加载失败或外部请求。
- 无元素越出 `1600 × 900`。
- 无元素被裁切。
- 无文字叠压。
- 字号和行高全部达标。
- 画面占用比 `≥45%`。
- 文本块总数为 `20–70`。
- 无占比不足 `1%` 的无意义小容器。
- 交互后图形、标签、tooltip、读数仍在画布内且不重叠。
- 键盘可完成全部核心操作。
- reduced-motion 下页面稳定、完整、可操作。
- 随机结果刷新后保持一致。
- ECharts 文字存在于 SVG/DOM，可被字号检查检测。
- 所有动态数值来自 `Lec` 或真实计算。

任一项失败都必须修改并重跑，直到所有首屏和交互状态报告干净。最终只交付 `page-NN.html`。
