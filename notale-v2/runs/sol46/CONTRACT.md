# 页面构建契约

## 1. 工作边界

- 只创建或修改分配给你的 `pages/page-NN.html`。
- 不读取、搜索、比较、复制或修改任何其他 `page-*.html`。
- 只交付该 HTML；不创建资源、文档、测试、截图或总结。
- 页面必须自包含，使用相对路径，直接以 `file://` 打开即可显示并交互；禁止 CDN、网络请求和构建步骤。
- 只往既有 `#stage` 内加入本页标题、正文、图形、控件、库引用和脚本；骨架其余部分一字不动。
- 页面内容以 `PLAN.md` 为准；本契约与 `PLAN.md` 冲突时，以本契约为准。

## 2. 固定 HTML 骨架

必须保留以下结构，只替换 `NN`、`TT`，并只在 `#stage` 内增加内容：

    <!doctype html>
    <html lang="zh">
    <head>
      <meta charset="utf-8">
      <link rel="stylesheet" href="assets/base.css">
      <link rel="stylesheet" href="assets/theme.css">
    </head>
    <body data-page="NN" data-total="TT">
      <div id="stage"></div>
      <script src="assets/base.js"></script>
      <script src="assets/lec.js"></script>
    </body>
    </html>

- 骨架只有空的 `#stage`；不得添加统一页眉、页脚，不得调用 `Lec.mount()`。
- 标题放在哪里、是否有页眉、组件如何组合，由本页内容决定。
- 不改 `<head>`、`body` 属性、底盘脚本或其顺序。所需库及本页脚本放在 `#stage` 内，先写内容节点，再按依赖顺序加载库，最后执行本页脚本。
- `#stage` 必须保留且作为 flex 列使用。其顶层区域必须有固定高度或 `flex` 份额，主内容区必须 `flex:1`；禁止所有顶层区域都按内容取高。
- 一次性尺寸可写内联样式；不要为一次性对象制造类名。

## 3. 受众与文字

- 面向大学一年级通识课学生，文理兼有；不假定微积分、天文学或编程基础。
- 本讲是第二讲，不重复第一讲“观测手段与尺度”；只可用一句必要承接，不得重新讲授。
- 第一次出现的必要术语必须就地用一个短句解释；非必要术语删除。
- 先说可观察的现象或结论，再给机制；公式必须同时给出变量的日常语言含义。
- 不使用未解释的英文缩写、行话、反问式卖关子或“显然、容易知道、你应该记得”。
- 正文句子原则上不超过 35 个汉字；操作提示使用直接、平和的祈使句，如“拖动滑块观察变化”，不命令学生“答对”。
- 教师可在课堂上顺着页面讲，学生课后不听口述也能理解页面结论；关键因果不得只藏在动画里。
- 页面主结论只保留一个；辅助说明不得与主结论争夺视觉层级。

## 4. 可计算的版面预算

按最终初始状态及所有可触发状态检查：

- 正文文字：80–260 个汉字；标题、单位、刻度、图例、按钮文字和代码不计入。超过 260 必须删减或报告本页超预算，不得缩字号硬塞。
- 交互控件：0–6 个。一个按钮、滑块、输入框、选择框或可拖对象各计 1 个；一组单选项按选项数计。
- 页面文本块总数：20–70 个，标题、正文段、标签、刻度、图例、控件文字、读数、公式分别计入；动态状态取最大值。
- 画面占用比必须 ≥45%。
- 超过上限：减少刻度、合并读数、删除冗余图例或拆页；禁止压字号、压行高、遮挡或滚动藏内容。
- 低于下限：增加与主结论相关的结构、比较维度或过程展开；禁止靠放大字号、拉大间距、复制装饰撑满。
- 页面不得出现纵向或横向滚动条。

## 5. 字号与可读性

以下均为 1600×900 舞台中的 CSS 计算字号硬下限：

- 纯数字刻度：≥12px。
- 带词句的刻度、标签、图注、图例、单位、短标注：≥14px。
- 正文、提示、控件文字、tooltip、读数说明：≥16px。
- 正文行高：≥1.35。
- KaTeX 基准字号统一 ≥20px。
- 禁止用 transform 缩小文字规避下限。
- 1366×768 屏幕的舞台缩放系数为 `min(1366/1600, 768/900)≈0.853`；上述地板已考虑缩放后的课堂可读性，不得再下调。

## 6. 主题与布局

- 所有颜色、字体、阴影、圆角、边框和常规间距从 `assets/theme.css` 的 token 与骨架类取；禁止另造配色、字体系统或整套间距标尺。
- 使用主题提供的语义类；局部几何尺寸才可内联。
- 不得删除 `lec-root`、`lec-page`、`min0`、`cv-fill` 等底盘或主题类，不得覆盖这些类的定位属性。
- 禁止在缩放舞台内使用 `position:fixed`；需要固定位置时，在内容容器内使用 `position:absolute`。
- 默认使用 flex；只有矩阵、维度表等确需二维对齐时才用 grid。
- 需要计算坐标才能对齐时，先改 DOM 结构。拖拽用 `transform` 偏移并保留正常流位置，不用动态 `left/top` 凑位。
- 不以装饰性背景、无信息图标或大面积空色块替代内容。

## 7. 数据与计算

- 所有课程事实、常量、天体数据、单位换算、比例、派生结果和页面显示的内容数字必须来自 `Lec.K` 或 `Lec.P`；禁止在 HTML、CSS 文本或脚本中写死。
- 页码、库版本、CSS 几何尺寸、动画时长和枚举索引不属于课程内容数字。
- 先读给定的 `Lec` 接口清单；不得为已有 `Lec.P` 函数重写公式。
- 显示值由原始结果格式化，计算仍使用未舍入值。
- 随机数据必须引入 `seedrandom.min.js` 并使用固定且页面专属的种子。
- 交互背后的结果必须实时计算；禁止预录动画、假数据、查表伪装计算或把预期结果写死。
- `assets/lec.js` 只提供数据与函数，不提供版面。

## 8. 底盘、canvas 与动画

- 开工前读取 `assets/CHASSIS.md`；底盘接口以该文件为唯一真相，不在页面内复制实现。
- canvas 一律使用 `Deck.fit` 或 `Deck.autofit` 适配 CSS 尺寸、设备像素比和舞台缩放。
- 手写 canvas 的指针坐标一律经 `Deck.pt` 换算。
- 动画循环一律使用 `Deck.loop`。
- canvas 颜色一律使用 `Deck.rgb` 或 `Deck.rgba`。
- 禁止自行实现 `devicePixelRatio` 缩放、`getBoundingClientRect` 指针换算或 `requestAnimationFrame` 主循环。
- resize 后必须重新适配并重绘；不得拉伸旧位图。
- 必须实现 `prefers-reduced-motion:reduce` 分支：停止持续运动和自动播放，直接显示稳定且完整的关键状态；交互仍可用。
- 页面失焦、隐藏或组件销毁时不得继续无意义计算。

## 9. 库的强制使用

开工前先读 `assets/lib/LIBS.md`。已有库能完成的呈现工作，禁止从底层重写：

| 任务 | 必用库 |
|---|---|
| 常规坐标轴、刻度、图例、折线、柱、散点、面积、饼、热力 | ECharts |
| 可拖拽、需命中检测的二维场景 | Konva |
| 三维场景 | Three.js |
| 下落、碰撞、摆动、堆叠、约束 | Matter.js |
| 节点连线、数据驱动矢量图 | D3 |
| 成千上万元素同时运动 | PixiJS |
| 分步动画 | anime.js |
| 多动画时间线 | GSAP |
| 数学公式 | KaTeX |
| 矩阵运算 | ml-matrix |
| 页面实时训练小型二分类网络 | `mlp.js` |

- 引用格式为 `<script src="assets/lib/xxx.js"></script>`；只引实际使用的库。
- 依赖库先引：Globe/Vanta 在 Three 后；ScrollTrigger 在 GSAP 后；本页初始化脚本最后。
- API 版本以 `assets/lib/LIBS.md` 为准，禁止读取压缩文件查版本。
- ECharts 必须 `echarts.init(el,null,{renderer:'svg'})`，并显式设置全局、坐标轴、图例、tooltip 字号达到本契约地板。
- Konva 图形可用 canvas；普通文字标签必须用绝对定位 DOM 覆盖。确需 `Konva.Text` 时显式设置合规字号。
- KaTeX 必须同时引本地 CSS 与 JS，基准字号 ≥20px。
- 小型逐帧训练用 `mlp.js`，不得用 tf.js 或手写替代；只有预训练模型、真实图片卷积或 GPU 大矩阵才可用 tf.js，且每步必须 `tf.tidy()` 或显式 `dispose()`。
- 非呈现层计算可自行实现，但已有 `Lec.P`、`mlp.js` 或 `ml-matrix` 能完成时不得重复实现。
- 确需未预置库时才可放入 `pages/` 本地引用；仍只交 HTML 的任务下不得新增该库，因此应改用现有能力。

## 10. 技法文档

- 动手前检查可用 Skill 清单；有对应技法文档时必须先用 `Skill` 阅读并照其约定实现。
- 没有对应文档时才自行设计。
- 不得因未读文档而另造已有的缩放、拖拽、图表、动画、公式或自检方案。

## 11. 交互标准

真交互必须同时满足：

- 用户可通过按钮、滑块、拖拽、选择或键盘改变至少一个有意义的输入或状态。
- 可视结果、读数或解释随输入实时变化，且变化来自真实计算。
- 页面给出简短操作提示，并明确变化说明了什么。
- 可恢复初始状态；随机过程恢复到同一种子状态。
- 鼠标操作必须有键盘等价路径：原生控件优先；自制控件需可聚焦、具备合适 ARIA、支持 Enter/Space 或方向键，并显示焦点。
- 拖拽不得是唯一操作方式，需提供键盘调整或等价控件。
- 状态变化不能只靠颜色表达。

只有悬停发光、视差、自动播放、元素跟随指针、装饰粒子、无输入的循环动画、点击后仅播放预录片段，均属装饰，不算交互。装饰不得占用本页交互控件预算，也不得成为核心内容。

## 12. 完工自检

在 `pages/` 目录执行：

    python3 assets/selfcheck.py page-NN.html

对每个按钮、滑块端点、选择项、拖拽边界、重置状态及 reduced-motion 状态，再用：

    python3 assets/selfcheck.py page-NN.html --after "<触发状态的 JS>"

交付判据：

- 无 JS 报错、资源加载失败、外部请求。
- 无超出 1600×900、被裁元素、滚动条或文字叠压。
- 字号与行高全部达到地板；canvas/Konva 内文字也须人工核对。
- 画面占用比 ≥45%。
- 文本块为 20–70 个，正文与控件不超预算。
- 初始及交互极端状态均无布局跳坏。
- 鼠标、触摸/指针和键盘均可操作；焦点可见。
- reduced-motion 下无持续动画且内容完整。
- 数字来源、随机种子、库选择和真实计算逐项复核。

任一项失败就修改同一个 HTML 并重跑；必须改到所有状态报告干净后才交付。
