# 页面构建契约

## 1. 工作边界

- 只修改分配给你的 `page-NN.html`。
- 不创建或修改资源、文档、测试、脚本及其他页面。
- 绝不读取任何 `page-*.html`；页面之间只共享本契约、`PLAN.md`、`assets/theme.css`、`assets/lec.js`。
- 先读 `PLAN.md` 中本页要求，再读 `assets/CHASSIS.md`。底盘接口以该文件为唯一准则，不在此转抄。
- 只交付这一个 HTML 文件，不附说明、总结或测试报告。

## 2. 固定骨架

保持以下骨架及现有标签顺序。只替换 `NN`、`TT`，并向 `#stage` 加入本页内容；需要库时仅增加规定的本地引用，页面脚本放在所有依赖之后。

```html
<!doctype html>
<html lang="zh">
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="assets/base.css">
  <link rel="stylesheet" href="assets/theme.css">
</head>
<body data-page="NN" data-total="TT">
  <div id="stage"></div>
  <script src="assets/base.js"></script>
  <script src="assets/lec.js"></script>
</body>
</html>
```

- 骨架只有空的 `#stage`；没有固定页眉、页脚或 `mount()`。
- 标题位置、是否设页眉、组件布局由本页内容决定。
- `#stage` 必须保留，且保持主题规定的 flex 列布局。
- `#stage` 的每个顶层区域必须有固定高度或 `flex` 份额；主内容区用 `flex:1`。禁止所有顶层区域都按内容取高。
- 一次性尺寸可写内联样式，不为单个元素发明类名。
- 每页可通过 `file://` 直接显示和交互；所有资源使用相对路径，禁止 CDN、网络请求和构建步骤。

## 3. 受众与讲解语言

- 面向大学一年级通识课，默认无微积分、天文学和编程基础。
- 这是第二讲；不得重复第一讲已经讲过的观测方法和尺度背景，除非只用一句话连接本页论点。
- 新术语首次出现时，用一句日常语言解释；不能只给术语或公式。
- 不要求学生读代码，不用微积分符号作为解释前提。
- 每个说明句尽量不超过 45 个汉字；一句只承担一个判断或动作。
- 先说现象或问题，再给名称、关系和结论。
- 提示语使用直接、中性的课堂口气，如“拖动并比较”“选择后观察”；禁止责备、卖萌、考试式恐吓和“显然”“很简单”。
- 页面既要便于教师带讲，也要让学生课后仅凭页面文字复看；不得把关键结论只留给口头补充。
- 公式必须同时有自然语言释义；符号首次出现必须就近解释。

## 4. 版面与密度预算

画布逻辑尺寸固定为 1600×900。

- 正文总量：不超过 240 个汉字；标题、短标签、刻度和数值不计入正文。
- 可操作控件：不超过 6 个；一个滑块、按钮、选择框或可拖拽物各计 1 个。
- 页面文本块总数：20–70 个。独立标题、句子、标签、刻度、图例项、按钮文字、读数各计 1 个；SVG 图表文字也计入。
- 画面占用比必须 ≥45%。
- 超过预算时删减、合并或拆页；禁止缩字号、压行高、遮挡、裁切或把文字画进 canvas 逃避检查。
- 低于密度下限时增加有教学意义的结构、比较维度或过程展开；禁止靠放大字号、加装饰或拉大空隙撑占用比。
- 若 `PLAN.md` 的本页要求无法在预算内完成，明确报告预算冲突，不提交硬塞版本。

## 5. 字号地板

以下均指 1600×900 逻辑画布中的 CSS 字号：

- 纯数字刻度：≥12px。
- 带词句的刻度、标签、图注、图例、轴名：≥14px。
- 正文、提示、控件文字、tooltip、动态结论：≥16px。
- 正文行高：≥1.35。
- KaTeX 基准字号：统一 ≥20px。
- 1366×768 屏幕的舞台缩放约为 `min(1366/1600,768/900)≈0.85`；因此逻辑字号不能再向下试探。
- 禁止使用 transform 缩小文字，或将说明文字放进 canvas、位图来绕过字号检查。

## 6. 主题与布局

- 所有颜色、字体、圆角、阴影和常规间距从 `assets/theme.css` 的 token 或现有类取得。
- 禁止另建配色、字体体系、间距体系；禁止硬编码十六进制颜色或自造近似主题色。
- canvas 取色一律使用 `Deck.rgb` / `Deck.rgba`。
- 默认使用 flex；只有矩阵、维度表等确需二维对齐时才用 grid。
- 需要计算坐标才能对齐时，先改 DOM 结构。拖拽用 `transform` 偏移并保留正常流位置，禁止靠持续改 `left/top` 凑布局。
- 禁止在缩放舞台内使用 `position:fixed`；需要覆盖层时用相对内容容器的 `position:absolute`。
- 不得删除 `base.css` 或主题提供的类，不得 `classList.remove()` 掉 `min0`、`cv-fill`、`no-pan` 等类，也不得覆盖其关键定位属性。

## 7. 数据与计算

- 页面展示的天文常量、物体属性、换算值和可由课程数据推导的数字，一律从 `Lec.K` 或 `Lec.P` 取得并实时计算；禁止把结果写死在 HTML、CSS、图表数据或提示语中。
- 页号、布局尺寸、控件步长、动画时长等非知识数据不受上一条限制。
- 显示值可用 `Lec.P.round` 格式化；内部计算保留原精度。
- 交互后的读数、结论和图形必须由当前状态真算，禁止用预录动画、假数据或固定答案冒充。
- 随机样本必须引入 `seedrandom`，使用固定且与页号相关的种子；禁止 `Math.random()`。
- 小型逐帧二分类训练使用 `mlp.js`；矩阵原语使用 `ml-matrix`。不得重写已有实现。
- TensorFlow.js 只用于预训练模型、真实图像卷积或确需 GPU 的大矩阵；使用时每步必须 `tf.tidy()` 或 `dispose()`，并检查张量数不持续增长。

## 8. 库的强制使用

动手前先查 `assets/lib/LIBS.md`。凡已有库能完成的呈现工作，禁止从底层重写：

| 任务 | 必用库 |
|---|---|
| 常规坐标轴、刻度、图例、折线、柱、散点、面积、饼、热力 | ECharts |
| 可拖拽、需命中检测的二维场景 | Konva |
| 三维场景、光照、材质 | Three.js |
| 三维地球、球面点线区块 | globe.gl |
| 下落、碰撞、摆动、堆叠、物理约束 | Matter.js |
| 节点连线、数据绑定矢量图 | D3 |
| 成千上万元素同时运动 | PixiJS |
| 分步动画、路径描绘、形变 | anime.js |
| 多动画时间线编排 | GSAP |
| 滚动绑定动画 | GSAP + ScrollTrigger |
| 数学公式 | KaTeX |
| 矩阵计算 | ml-matrix |
| 可复现随机 | seedrandom |
| 页面内小型二分类网络训练 | mlp.js |

- 使用 `<script src="assets/lib/xxx.js"></script>`；KaTeX 还必须在 `<head>` 引入 `assets/lib/katex.min.css`。
- 保持 `base.js`、`lec.js` 的现有顺序；库脚本置于页面初始化代码之前。
- `globe.gl`、`vanta.net` 必须在 Three.js 之后加载。
- `ScrollTrigger` 必须在 GSAP 之后加载。
- 页面初始化脚本最后加载。
- 精确版本只看 `assets/lib/LIBS.md`，禁止搜索压缩库文件猜版本。
- ECharts 必须使用 `echarts.init(el,null,{renderer:'svg'})`，并显式设置各类文字字号达到本契约地板。
- Konva 主要画图形；标签优先用绝对定位的 DOM 叠加。确实必须使用 `Konva.Text` 时显式设置合规字号。
- KaTeX 使用 `throwOnError:false`，基准字号不得低于 20px。
- 不需要的库不引用；需要清单外库时只能本地放置，但不得因此修改或新建本页之外的文件。

## 9. Canvas、缩放与交互

- 自有 canvas 一律用 `Deck.fit` / `Deck.autofit` 处理 CSS 尺寸、逻辑尺寸和高分屏像素比。
- 自有指针坐标一律用 `Deck.pt` 换算；禁止自行读取 `getBoundingClientRect()` 后换算。
- 动画一律用 `Deck.loop`；禁止自建 `requestAnimationFrame` 循环。
- canvas 颜色一律经 `Deck.rgb` / `Deck.rgba` 取得。
- Konva 指针事件使用其自身舞台坐标 API，不再叠加手写换算。
- 容器尺寸改变或舞台缩放后，图形、命中区域和指针位置必须仍对应。
- `prefers-reduced-motion:reduce` 时停止持续运动和自动循环，直接显示稳定终态；任何关键信息不得只靠运动表达。
- 优先使用原生 `button`、`input`、`select`。自定义控件必须可 Tab 聚焦，有可见焦点、可读名称和正确角色。
- 点击动作必须支持 Enter/Space；连续值支持方向键；拖拽必须提供键盘等价操作。
- 不得把 hover、颜色变化或自动播放当作唯一交互入口。

## 10. 真交互标准

满足以下全部条件才算交互：

1. 学生能改变输入、参数、选择或对象状态。
2. 页面据此重新计算真实数据或模型。
3. 图形、读数或结论立即产生可辨认变化。
4. 当前状态有文字反馈。
5. 可以恢复初始状态，或操作本身可逆。
6. 指针和键盘均可完成核心任务。

仅有淡入、漂浮、倾斜、hover 高亮、自动播放、装饰粒子或按钮触发预录动画，均只算装饰，不算交互。

- 清单已有方案时不得另造一套。

## 12. 完工自检

在 `pages/` 目录运行：

`python3 assets/selfcheck.py page-NN.html`

对每个核心交互状态，再使用：

`python3 assets/selfcheck.py page-NN.html --after "<触发交互的 JS>"`

交付判据：

- 0 个 JavaScript 错误。
- 0 个资源加载失败。
- 0 个越出 1600×900 画布的元素。
- 0 个被意外裁切的元素。
- 0 个文字叠压。
- 字号和行高全部达到地板。
- 画面占用比 ≥45%。
- 文本块总数为 20–70。
- 无占比不足 1% 且无教学作用的小容器。
- 初始态及关键交互态均无布局跳动、遮挡或失配。
- 1366×768 缩放下指针命中、tooltip、拖拽和读数正确。
- 键盘可完成核心操作，焦点始终可见。
- reduced-motion 分支无持续动画，信息仍完整。
- 随机结果可复现，所有知识数字来自 `Lec` 或实时计算。

任何一项不满足都必须修改并重跑，直到报告干净为止。
