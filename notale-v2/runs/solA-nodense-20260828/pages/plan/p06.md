# page-06 · 把“错了多少”变成一个数 · **120 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `ACT II · 误差记分` |
| 主标题 | 同一个正确答案，预测越偏离，损失越大 |
| 收束句 | 损失就是“错题分”：它把预测与正确答案的不一致压成一个可比较的数。 |
| 下一问 | 只知道哪边损失更低，怎样决定权重往哪边走？ |

## 知识结构：comparison

关系不变量：正确答案 1 固定在上区；下区的 90% 与 10% 两列必须同宽、同行并共享同一损失刻度，竞猜时只遮住损失读数，不遮住预测与答案。

共享原语：`.k-comparison` 组织两列同尺度比较，`.mark-pred` 与 `.mark-target` 用形状区分预测和答案，`.error-scale` 在揭晓后标出两个损失位置。整体落入 `.split-tb`：上半区提出竞猜，下半区揭晓数值与定义。

## 表征形式

交互式双列竞猜：学生先选哪一个预测的损失更大，再同时揭晓两列错题分和损失定义。原生 DOM 与 SVG 足够，便于保持选项、公式和误差刻度的精确对齐。

## 主工作流

build-interaction ← 管理竞猜、统一揭晓与可访问反馈状态

## 两个预测的记分

| 项目 | 预测 90% | 预测 10% |
|---|---:|---:|
| 正确答案 | 1 | 1 |
| 预测 \(p\) | 0.9 | 0.1 |
| 揭晓损失 | 0.105 | 2.303 |
| 刻度短标 | 很接近答案 | 远离答案 |

画面显示定义：`损失 L = −[y ln(p) + (1−y) ln(1−p)]`。紧邻公式写明：`y 是正确答案，p 是预测；ln 由计算器完成，不要求手算。`

## 交互

初始只显示目标 1、两个预测和问题“哪一个错题分更高？”，提供“预测 90%”与“预测 10%”两个 `.opt`。任一选择后，两列同时展开损失读数；答案属性只用中性双线，反馈固定为“10% 离正确答案 1 更远，因此损失更大”。“再猜一次”恢复遮罩和未选择状态。

运行时通过 `Lec.P` 中接收预测与目标的二分类交叉熵公开入口计算读数，不硬编码推导结果；计算时按 `LOSS_CLIP_EPSILON = 1e-12` 裁切预测。页面只显示三位小数。

## 动效

揭晓时两个损失标记沿同一竖直刻度从 0 向上移动：0.105 用 320ms，2.303 用 520ms，后者延迟 80ms；数字同步使用 `[data-anim="count"]`，不播放循环动画。
