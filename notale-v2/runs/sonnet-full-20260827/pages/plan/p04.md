# page-04 · 错多少，是一个数 · **100 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `THE-ERROR-NUMBER` |
| 主标题 | 「错多少」也能算成一个数字 |
| 收束句 | 这个数字叫损失：目标和输出差得越远，损失越大；权重一变，损失立刻跟着变 |
| 下一问 | 知道错多少了，那该往哪个方向改权重，才能让这个数变小？ |

## 知识结构：process

关系不变量：权重读数、神经元输出读数、目标读数、损失读数必须在同一条记录带上按固定顺序左右排列、同基线对齐，权重每变化一次，右侧三个读数必须同步刷新，形成「改—算—见」的单向链条，不可断开或乱序。

共享原语：用 `.k-process` 骨架把「权重→输出→损失」串成一条 `.step` 序列，`.axis` 承担从左到右的时间/因果轴，`.arw` 标出「权重变化」如何驱动「输出变化」再驱动「损失变化」；每一步用 `.panel` 装一个 `.big` 读数（权重、输出、目标、损失各一个），损失读数额外套 `.tag` 标出「烫/凉」状态。ledger 版式下，上导语条放本页主张一句话，下方多栏读数区正好承接这条 `.k-process` 序列，每栏一个 `.panel`。

## 表征形式

交互，DOM + 原生 SVG 手绘箭头（沿用 p02/p03 已建立的读数框与箭头组件，不引入新图表库）。核心是几个可拖拽的 `.big` 数值读数联动重算，数据量极小（1个神经元、4组AND输入之一），不需要 ECharts/D3/Konva 这类可视化库，原生 DOM 绑定 `Lec.P.neuronForward` 与 `Lec.P.mse` 的返回值即可实时刷新。

## 主工作流

build-interaction ← 拖拽权重滑块后，输出、损失两个读数必须同步、正确地重算并给出「变好/变差」的视觉反馈，这是本页唯一实现难点

## 不许碰

只呈现损失这个数字本身怎么算、怎么随权重变化，不展示损失如何指导权重调整方向（梯度概念留给 p05）；不出现学习率或「挪一步」的动作（p05、p08）。

## 输入与损失表

| 项 | 值 | 说明 |
|---|---|---|
| 逻辑门 | AND | 沿用 `Lec.K.AND_TARGETS` |
| 输入集合 | `Lec.K.LOGIC_INPUTS` = [[0,0],[0,1],[1,0],[1,1]] | 本页固定展示其中一组，默认取 `[1,1]` |
| 目标值（当前输入） | 1 | `Lec.K.AND_TARGETS[3]` |
| 权重 w1、w2 | 默认各 0.4（可拖拽，范围 -2~2） | 学习者操纵对象 |
| 偏置 b | 默认 -0.5（可拖拽，范围 -2~2） | 学习者操纵对象 |
| 激活函数 | sigmoid | 沿用 p02/p03 的默认设置 |
| 前向计算 | `Lec.P.neuronForward([1,1], [w1,w2], b, 'sigmoid')` → `{z, a}` | a 即当前输出 |
| 损失 | `Lec.P.mse(a, 1)` | 显示为等宽数字，配「烫→凉」`.tag` |

## 交互

学习者拖动 w1、w2、b 三个滑块（范围 -2 到 2，默认 0.4 / 0.4 / -0.5），每次拖动即时调用 `Lec.P.neuronForward` 得到新输出 `a`，再调用 `Lec.P.mse(a, 1)` 得到新损失。四个读数框（w1、w2、b 合并显示 / 输出 a / 目标 1 / 损失）实时刷新，损失读数根据数值大小从「烫」（红铅笔色高亮，向上凸起阴影）过渡到「凉」（钢笔蓝，向下坡度阴影）。无需目标态或成功判定，滑块是观察仪器：学习者应形成「权重变，损失就变，且变化幅度不均匀」的直觉。状态随时可逆，无需专设复位按钮，拖回默认值即恢复初始画面。

## 核对

- 参数 (w1=0.4, w2=0.4, b=-0.5)，输入[1,1]：z = 0.4+0.4-0.5 = 0.3，a = sigmoid(0.3) ≈ 0.5744，损失 mse(0.5744,1) ≈ 0.1812。
- 参数 (w1=2, w2=2, b=-2)，输入[1,1]：z = 2，a = sigmoid(2) ≈ 0.8808，损失 ≈ 0.0142（明显更「凉」）。
- 参数 (w1=-2, w2=-2, b=-0.5)，输入[1,1]：z = -4.5，a ≈ 0.0110，损失 ≈ 0.9780（接近最「烫」）。
