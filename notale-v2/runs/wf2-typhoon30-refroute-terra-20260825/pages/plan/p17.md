# page-17 · 初值会长成路径扇 · **140 秒**

## 照这个写

| 元素 | 文字 |
|---|---|
| kicker | `FORECAST / INITIAL CONDITIONS` |
| 主标题 | 只差一点的初值，五天后会散成一组路径 |
| 收束句 | 观测位置和环境风的微小差异，经过逐步积分会形成明显分散的集合路径。 |
| 下一问 | 这么多条可能路径，怎样压缩成一眼能读懂的范围？ |

## 知识结构：process

1. **关系不变量**：左侧“观测—初值扰动”与右侧“0–120 h 路径积分”必须由同一箭头相连；31 条路径共享地图范围、起报时刻和时间节点，初始散点与对应路径保持同一成员身份。
2. **禁止画法**：不得把31条路径拆成独立小卡片或自动挑出一条“正确路线”，否则会掩盖同源初值逐渐发散的过程。
3. **共享原语**：`.split-lr` 左侧承载观测照片、初值放大窗和控件，右侧承载统一尺度地图；`.k-process` 用 `.step` 与 `.arw` 固定“观测→扰动→积分”的因果顺序；`.cvbox` 裁切照片及路径画布。

## 表征形式

交互式集合路径图：左侧显示观测来源、初始位置与风矢量的局部放大；右侧以经纬度坐标绘制控制路径、30条扰动路径及24小时节点。

使用 ECharts，采用 SVG renderer；所有成员共享线性经纬度轴，地图范围固定为 `122–136°E、15–32°N`，路径不因播撒后自动缩放。控制路径为深青蓝实线，扰动成员为低不透明度细线，刚生成的成员短暂使用强调色。交互状态通过 `setOption` 增量加入 series；照片与按钮使用原生 DOM。

## 主工作流

visualize-data ← 在统一时空尺度上可复现地生成并辨认31条集合路径

## 不许碰

不把控制路径或任一扰动成员称为唯一真相，也不判定哪条“最准”。不绘制或定义路径锥、覆盖概率、云系大小与危险区；这些归 p18。

## 集合与积分口径

| 画面项目 | 文字或数值 |
|---|---|
| 控制初值 | `18.0°N, 132.0°E` |
| 集合规模 | `31 条＝1 条控制路径＋30 条扰动路径` |
| 位置扰动 | `东西、南北方向 σ＝20 km` |
| 环境风扰动 | `东西、南北分量 σ＝0.8 m/s` |
| 预报时效 | `0–120 h；每 6 h 积分一次` |
| 0–48 h 控制风 | `东向 −3.2 m/s；北向 +2.0 m/s` |
| 48–120 h 控制风 | `东向 +1.5 m/s；北向 +3.5 m/s` |
| 图例 | `控制初值`、`微扰成员`、`24 h 节点` |
| 口径注记 | `固定种子的教学集合；不代表业务系统配置或实时观测误差。` |

30组扰动由固定种子 `170417`、Mulberry32 与 Box–Muller 正态变换生成。位置偏移按局地切平面换算为经纬度；每个成员的风分量扰动在120小时内保持不变。每6小时调用 `Lec.P.advancePosition(latitudeDeg, longitudeDeg, eastVelocityMps, northVelocityMps, 6)`，下一步以上一步返回位置继续积分。核对结果不印入画面。

## 交互

初始只显示控制路径和起点放大窗。点击主按钮“播撒30个微扰初值”，左侧先出现位置散点与风矢量差异，右侧随后加入对应路径；计数器从 `1 / 31` 增至 `31 / 31`。

提供“重新播撒”按钮：清空扰动成员后用同一种子重放，结果必须完全一致。按钮支持键盘焦点与 Enter/Space；交互目的不是找到正确成员，而是观察初始差异如何随时效展开。

## 动效

初始散点在200 ms内由控制点向外展开；30条路径按成员每隔20 ms绘入，每条从0 h延伸至120 h，单条600 ms。强调色只跟随正在加入的成员，完成后恢复深青蓝低不透明度。减少动态模式下直接显示完整集合，不逐条描线。

## 核对

- 控制成员从 `18.0°N, 132.0°E` 出发，按上述风场每6小时积分，120 h终点应约为 `29.3°N, 130.5°E`，容许球面推进与舍入造成约 `±0.2°` 差异。
- 单个风分量扰动 `+0.8 m/s` 持续120 h，对应额外位移约 `345.6 km`；不得误写为34.6 km或3456 km。
- 固定种子重播后，30组初值、路径坐标与绘制顺序必须逐项一致。
