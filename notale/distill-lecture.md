  ---
  Scrimba 和 Manim 各给了一条硬性质

  Scrimba 的内核不是「视频里能写代码」,是「任何一帧都是活的」。
  它录的不是像素,是一个真实编辑器的状态流。所以暂停不等于停,暂停等于交出控制权。
  这条性质叫「可接管」。

  Manim 的内核不是「数学动画好看」,是「画面是算出来的,不是画出来的」。 一个
  Transform(A, B) 说的是「这两个东西是同一个东西的两种看法」——那是教学原语,动画
  只是它的副产品。这条性质叫「可重算」。

  这两条合起来其实是同一件事:

  ▎ 画面 = f(概念状态, t)
  ▎ Manim 保证 f 存在,Scrimba 保证你能改 f 的输入。

  一旦承认这个等式,「互动视频」就不再是视频加了浮层的互动。它根本没有视频文件。
  交付物是一个程序加一条时间轴,渲染发生在播放时。这是我认为唯一称得上颠覆的地方—
  —其余所有「互动视频」产品都是在成片上贴热区,那种东西一改参数就崩,因为底下没有
  f。

  ---
  三个原语

  轨道 rail        作者铺的一条状态轨迹 s(t)。这是「视频」的部分。
  接管 takeover    任意时刻学习者改写 s。这是「互动」的部分。
  归位 reconcile   改完之后怎么办。 ← 全部难度在这里

  前两个是 Scrimba 和 Manim 各自已经证明可行的。第三个谁都没解决,因为 Scrimba
  只能分叉(你一改就脱离录像,回不去了),Manim 根本不接受输入。

  归位至少有三种答案,选哪个决定整个产品:

  ┌─────┬────────────────────┬──────────────────────────────────────────────┐
  │     │        做法        │                     代价                     │
  ├─────┼────────────────────┼──────────────────────────────────────────────┤
  │ 分  │ 你改了就是你的副本 │ 最简单,但学习者一旦偏离就再也没人讲解了      │
  │ 叉  │ ,原轨道还在        │                                              │
  ├─────┼────────────────────┼──────────────────────────────────────────────┤
  │ 吸  │ 下一个关键帧强制拉 │ 保住叙事,但「我改的东西被抹了」体感很差      │
  │ 附  │ 回作者状态         │                                              │
  ├─────┼────────────────────┼──────────────────────────────────────────────┤
  │ 自  │ 讲解跟着你的状态重 │ 唯一真正兑现「学习发生在视频中」,但讲解必须  │
  │ 适  │ 写                 │ 是参数的函数,不能是录好的话                  │
  │ 应  │                    │                                              │
  └─────┴────────────────────┴──────────────────────────────────────────────┘

  我认为你要的是第三个,理由是你那句「让所有学习都发生在视频中」——如果学习者一接
  管就没人陪他了,学习就又跑到视频外面去了。

  而第三个有个立刻可以推出的硬约束:讲解不能是配音,至少不能全是配音。一句「注意这
  里振幅是 2」在学习者把振幅拨到 5 之后就是假话。所以讲解要么参数化生成,要么必须
  写成在允许扰动下恒真的句子。这一条会直接决定 agent 
  要产出什么格式的东西,是最该在新对话里先钉死的。

  ---
  和 notale 的关系(这条对你迁移上下文有用)

  notale 的一页是空间的:所有状态同时在场,学习者自由探索,没有先后。

  互动视频加进来的唯一新东西是时间,而时间买到的是注意力编排——控制你什么时候知道
  什么。一页讲义把答案和问题一起摊在你面前;视频可以先让你猜。

  所以一句话:

  ▎ 互动视频 = 状态空间 + 一条作者标注的路径 + 随时下车的权利

  notale 的页是这个东西关掉时间轴之后的样子。这意味着新仓库里的「页」大概率能被
  复用为「场」,不必从零发明可视化层——但时间轴、接管、归位是全新的,没有任何现成经
  验,那三块必须重新用测量去推。

  ---
  「所有学习发生在视频中」的几条推论

  这句话是强约束,把它一路推到底会砍掉很多设计:

  - 没有旁边的代码编辑器 → 编辑发生在画面本身上
  - 没有课后练习 → 练习就是「我把 s 拨坏,你拨回来」,发生在时间轴上的某个点
  - 没有跳出去搜索 → 追问也得在里面接住
  - 没有进度条外的「学完了」判定 →
  是否学会,由学习者在轨道上的接管行为来判定,而不是另开一张卷子

  最后一条我觉得是最有意思的:传统课程里评测是外挂的,这个形态里评测可以内生——你在
  哪一帧接管、拨向哪、拨对没有,本身就是答题。

  ---
  顺带一提:这个形态天然可测,harness 好办

  我们在 notale 上吃过的亏是「selfcheck
  只验渲染,不验交互是否真的活着」。这个形态里,三条判据是从定义直接掉出来的:

  1. 可 scrub 决定性 —— 跳到 t 得到的状态,和顺序播到 t 一样吗
  2. 接管有响应 —— 每个可接管点,改了之后画面/读数真的动了吗
  3. 讲解与状态一致 —— 接管之后,讲解还成立吗

  第三条是新的,也是最难自动验的,但它正是这个形态的立身之本。

  一、唯一的颠覆点:把时间解冻

  产品设计 §3.2 把「分支时间冻结在 T₀」当成巨大简化,§6
  明确不做分支内播放。理由是怕双时钟和 spring/decay 的积分不确定性。

  但这个担心在你们自己的架构里不成立。

  evaluate 是 (t, p) → FrameState,状态不是累积出来的,是求出来的。这正是 Manim
  相对于逐帧模拟的全部优势,也是你们文档里写的「可靠支持任意
  seek、倒序跳转」。既然如此,分支往前播根本没有第二个时钟:

  主线画面 = evaluate(t, p_author)
  分支画面 = evaluate(t, p_user)     ← t 照样往前走

  同一条时间轴、同一张 scene graph、同一个 t。只是换了个参数。
  没有双时钟,因为只有一个钟。

  一旦解冻,产品的定义整个翻过来:

  ┌────────────┬───────────────────────┬────────────────────────────────────┐
  │            │   冻结版(当前设计)    │               解冻版               │
  ├────────────┼───────────────────────┼────────────────────────────────────┤
  │ 分支是什么 │ 某一帧的参数沙盒      │ 用你的参数重播整部视频             │
  ├────────────┼───────────────────────┼────────────────────────────────────┤
  │ 分享出去的 │ 一个快照              │ 一部会播的、和作者那部不一样的视频 │
  │ 是         │                       │                                    │
  ├────────────┼───────────────────────┼────────────────────────────────────┤
  │ 学习者得到 │ 「我拨了拨,看到画面变 │ 「我改了初始条件,然后我看着后果一  │
  │            │ 了」                  │ 路发生」                           │
  └────────────┴───────────────────────┴────────────────────────────────────┘

  第二列才是 Scrimba 的东西。Scrimba 里你改了代码,课继续在你的副本上跑;你不是在
  一个静止的编辑器里玩。冻结版丢掉的正是这一点。

  而且这才是可传播的:一张参数快照没人会转发,一部「同一节课在我的数字下播成了另一
  个样子」的视频会。

  二、解冻之后,四件事自动掉出来

  1. 讲解必须也是 f(t, p)

  这是解冻的账单,也是最值钱的一笔。

  一句录好的「注意这里振幅是 2」在学习者把振幅拨到 5 之后就是假话。所以
  CaptionCue 不能是字符串常量,它得和 Visual 一样是求值结果。

  你们已经把字幕做成了一等时间轨道、和 DOM
  解耦(FIRST_CLASS_CAPTION_TRACK.md),只差最后一步:让它吃 FrameInput。

  director.caption(p => `振幅 ${p.amp} 时,包络在 ${envelope(p).toFixed(2)}
  处相切`, { at: 0 })

  做到这一步,「所有学习发生在视频中」才真正成立 ——
  否则学习者一接管,讲解就开始说谎,他必须跑到视频外面去问人。

  2. Beat 应该带前提条件

  这条是我看到 NARRATIVE_AUTHORING_MODEL.md
  才想到的,而且我认为它是你们独有的、别人抄不走的东西。

  你们的 Beat 记录的是意图:

  director.beat({ id: "turn", intent: "揭示关闭位置的局部梯度等于零" })

  意图是命题。命题可以为假。学习者要是把激活函数从 ReLU 换成 tanh,这个 Beat
  的讲解就整段崩了 —— 而因为意图被显式声明了,系统能在播到它之前就知道:

  director.beat({
    intent: "揭示关闭位置的局部梯度等于零",
    holds: p => p.activation === "relu",     // ← 加这一个字段
  })

  有了 guard,前面遇到冲突有三条路,而第三条是我认为整个产品最有杀伤力的一幕:

  - 改写 —— 讲解换一版
  - 跳过 —— 这一拍在你的参数下不成立,略过
  - 点破 —— 「你刚刚做的改动让接下来这段论证不成立了。我们来看为什么。」

  第三条是把学习者的破坏变成教学内容。没有任何现有教育产品能做这件事,因为没有人
  把论证的前提写成机器可判定的东西。你们因为要做 Manim
  式的语义作者模型,顺手把前提写下来了。

  3. 预测题:视频自己批改

  时间一解冻,一个机制立刻成立,而在冻结版里它根本不存在:

  ▎ 播到关键处停下 → 「你猜三步之后会怎样?」→ 学习者把猜测拨进参数里 → 继续播 → 
  ▎ 画面本身就是批改。

  没有选择题、没有对错弹窗、没有跳出去做题。判分是 FrameState 上的一个断言。评测
  内生在时间轴上,这是「所有学习发生在视频中」最锋利的一处兑现。

  而且因为分支可序列化、有 hash、可重放 ——
  全班的猜测就是一棵分支树,老师能看见谁在哪一帧拐错了弯。Scrimba
  那个「老师能看到学生的 fork」的野心,你们这边因为确定性是白送的,做得比它严格。

  4. 桌宠的回答形式应该是分支,不是话

  §6 排除了「AI 运行时生成/修改分支内容」,理由是保住共享 scene
  graph。这个理由只挡住 scene graph patch,挡不住 action log。

  AI 生成一串 action(只改 parameters,不改场景图)完全不破坏确定性、可重放、可分享
  —— 它产出的东西和用户手拖出来的一模一样。

  所以桌宠不该用一段文字回答「如果学习率再大一点会怎样」,它应该:

  fork 一条分支 → 把 lr 拨到 0.9 → 从 T₀ 播给你看 → 「你看,它开始震荡了」

  答案是一段视频,不是一段话。 这是把「所有学习发生在视频中」贯彻到问答环节的唯一
  方式,而且你们的边界本来就允许它,只是当初画紧了一格。

  ---
  三、一个顺带的简化:主线不再特殊

  解冻之后,主线就是 p = 作者默认值 的那条分支。不是「一条线性视频 +
  挂在上面的沙盒」,而是一族视频里作者选中的那一个取值。

  BranchTree 里 main 本来就是根节点、也带 action
  log,所以代码几乎不用动。但概念上省掉了整个「主线 vs 分支」的二元对立,以及 §3.5
  那种「主线进标准导出、用户分支不进」的分级承诺 ——
  导出的判据变成单一的一条:给定 (videoId, 
  actions),就能确定性地渲染成片。用户的分支和作者的主线在这条判据下没有区别。

  ---
  四、代价,和围栏

  解冻不是白拿的,诚实说清:

  作者的责任从「一条曲线」变成「一块参数邻域」。 每个 Beat 都必须在学习者能拨到
  的整个区间里成立,而不只在默认值上成立。这是真实的、显著的作者成本。

  围栏很简单,而且必须做:每个可交互参数由作者显式声明合法区间,超出区间拨不动。
  作者授权的是一个邻域,不是整个参数空间。holds guard
  是这个邻域的形式化表达,analyzeStoryboard() 那一层顺手就能在编译期扫出「哪个
  Beat 在哪个参数子区间会失效」——把作者成本从运行时踩雷变成编译期告警。

  这也顺带回答了 §7
  的风险表:分支不会被噪声淹没,因为邻域是有界的、可枚举的、可预验证的。

  ---
  五、给新仓库 harness 的三条判据(形态直接掉出来的)

  我们在 notale 上最大的教训是 selfcheck
  只验渲染、不验交互是否真活着。这个形态里判据是从定义推出来的,不用发明:

  1. 决定性     seek 到 t 的状态 == 顺播到 t 的状态
  (你们已经写成设计不变量)
  2. 可接管     每个声明为 interactive 的 Visual,
                改它的参数后 FrameState 真的变了              (对照 notale
  的死控件闸)
  3. 讲解自洽   参数邻域内采样,每个 Beat 的 holds 在其
                时间范围内恒真;字幕求值不抛错、不留占位符    ←
  这一条是这个形态独有的

  第三条是别人没有的,因为别人没有 Beat

  互动视频的产品形态

  一句话

  ▎ 一部会因为你而播成另一个样子的讲解视频。你随时可以按下暂停、改掉画面里的某个
  ▎ 数、然后让它继续播完——讲解也跟着改口,说的永远是你眼前这一版。

  ---
  使用现场

  这是唯一需要被完整想象出来的东西:

  ▎ 一段讲阻尼振动的视频。播到第 40 秒,画面上一条曲线正在衰减,口播说:「阻尼系数 
  ▎ 0.3,振幅每过一个周期减到约七成。」
  ▎
  ▎ 你按暂停。画面里那个「0.3」是可以拖的。你把它拖到 0。
  ▎
  ▎ 你按继续。视频从第 40 
  ▎ 秒往下播,但播的是你那一版:曲线不再衰减了,一直荡。口播这时说的是:「阻尼为 
  ▎ 0,能量不再流失,振幅恒定。」——它没有念作者写死的那句话。
  ▎
  ▎ 再往后,作者原本安排了一拍叫「找出振幅降到一半的时刻」。在你的参数下,这个时刻
  ▎ 不存在。视频停下来,对你说:「你刚刚让接下来这段论证失效了——阻尼为零时不存在半
  ▎ 衰时刻。这正是为什么衰减必须是指数的。」
  ▎
  ▎ 你把这一版存下来,发给同学。他打开的是一部完整的视频,从头能播到尾,和你看到的
  ▎ 一模一样。

  这一整段里,你一次都没有离开播放器。

  ---
  五条形态性质

  判断一个东西是不是我们要的,看这五条。缺任何一条它就退化成别的产品。

  一、画面是算出来的,不是录下来的。
  任何一帧的样子,完全由「这是第几秒」加「此刻的一组数」决定。没有预渲染的像素,没
  有成片文件。同样的秒数和同样的数,永远画出同样的一帧;跳到任意时刻和顺着播到那个
  时刻,结果必须一致。

  二、任何一帧都可以被接管,而且接管之后视频继续播。
  暂停不等于停,暂停等于交出控制权。学习者改的是画面里的数,不是画面里的东西——他不
  能新增、删除对象,只能拨动作者授权的那些量。改完之后视频从这里继续往下播,而不是
  停在一张静止的沙盒图里。

  ▎ 这一条是整个产品的分水岭。「暂停之后能玩一玩,玩完回主线继续」是市面上已有的
  ▎ 东西;「暂停之后视频在你的数字下播完剩下的部分」不是。

  三、讲解跟着学习者走。
  口播和字幕不是录好的音轨,是和画面一样被算出来的。学习者把振幅改成
  5,讲解就不能再说「振幅是 2」。做不到这一条,学习者一接管,讲解就开始说谎,他就必
  须跑到视频外面去问人——「所有学习发生在视频中」当场破产。

  四、作者的论证带前提,前提被破坏时视频知道。
  作者写下的每一拍讲解,背后都有一个成立条件。学习者拨到某个位置让这个条件不成立
  时,视频不能装作没事继续念。它有三种反应,按优先级:换一种说法讲、跳过这一拍、或
  者直接点破——「你刚刚让这段不成立了,我们来看为什么」。

  ▎ 第三种是这个产品最锋利的一幕:把学习者的破坏变成教学内容。这是别的形态做不到
  ▎ 的,因为别人没有把论证的前提写下来。

  五、学习者那一版是一部完整的、可分享的视频。
  不是一张截图、不是一个参数快照。发出去的链接打开就能从头播到尾。因为第一条保证
  了确定性,所以「同一个链接在任何人机器上播出同一部片子」是成立的。

  ---
  四种学习动作,全部在视频里发生

  「让所有学习都发生在视频中」这句话的操作定义,就是这四件事都不用离开播放器:

  ┌─────┬────────────────────────────────────────────────────────────────────┐
  │ 动  │                                形态                                │
  │ 作  │                                                                    │
  ├─────┼────────────────────────────────────────────────────────────────────┤
  │ 看  │ 播作者那一版。这是普通视频的部分。                                 │
  ├─────┼────────────────────────────────────────────────────────────────────┤
  │ 试  │ 暂停、改数、继续播。看后果一路发生。                               │
  ├─────┼────────────────────────────────────────────────────────────────────┤
  │ 猜  │ 播到关键处停下:「你猜三步之后会怎样?」——学习者把猜测拨进画面里,然  │
  │     │ 后继续播。画面本身就是批改。没有选择题,没有对错弹窗。              │
  ├─────┼────────────────────────────────────────────────────────────────────┤
  │ 问  │ 学习者提问,回答不是一段文字,是系统当场拨出一版参数、播给他看:「你  │
  │     │ 看,学习率到 0.9 它就开始震荡了。」                                 │
  └─────┴────────────────────────────────────────────────────────────────────┘

  第三行是解冻时间之后才成立的机制,也是我认为最值钱的一个:评测内生在时间轴上。学
  习者在第几帧、拐向哪、拐对没有,本身就是答题记录,不需要另开一张卷子。

  ---
  边界:它不是什么

  这几条必须写进给实验 agent 的任务里,否则它一定会漂移到最省事的那个形态去。

  - 不是「视频 + 浮层」。 不是在成片上贴热区、贴弹窗测验、贴侧边栏练习。一旦底下
  是录好的像素,前四条性质全部落空。
  - 不是一个「带时间轴的网页」。 时间是主叙事:默认自动播放,有节奏,有讲解,作者控
  制你什么时候知道什么。把所有东西同时摊开让人自由探索的,那是讲义,不是这个。
  - 不是无限沙盒。 作者授权的是一小块参数邻域,不是整个参数空间。超出邻域拨不动。
  作者要为整个邻域里讲解都成立负责——这是真实的作者成本,靠把邻域画小来控制。
  - 学习者改的是数,不是内容。 他不能往画面里加东西。这条守住了,「他那一版仍是一
  部确定的、可复现的视频」才成立。

  ---
  从外部怎么判断它是真的

  不看代码,只看行为。这三条也是后面 harness 的种子:

  1. 一致性 —— 拖动进度条跳到任意时刻,和从头顺播到那个时刻,画面完全一样。
  2. 接管有效 —— 每一个看起来能拨的东西,拨了之后画面和后续的播放真的不一样了。存
  在一个拨了没反应的控件,就不算过。
  3. 讲解不说谎 —— 在作者授权的邻域里随机取若干组参数,从头播到尾,不能出现任何一
  句和画面矛盾的讲解,也不能出现没被填上的占位符。

  第三条是这个形态独有的,也是最难自动验的,但它正是产品的立身之本。

  一、先给一把刀:什么叫「低级交互」

  需要一个能一刀切干净的判据,否则 agent 一定会退化成滑块。

  ▎ 如果这个交互控件可以被搬到画面外的一个面板里,而不损失任何东西——它就是低级的
  ▎ 。

  滑块可以搬走(旁边放个 阻尼: [====○==] 完全等价)→ 低级。
  下拉框、按钮、复选框,全部可以搬走 → 全部低级。

  高级交互是长在画面里的、搬出去就不成立的动作。

  - 拖动曲线上的那个切点沿曲线滑 → 搬不走,因为「沿这条曲线」是画面的一部分
  - 把等式里的 +3 拖过等号 → 搬不走,那个动作的意义完全由它在式子中的位置决定
  - 在图上画一条你以为的切线 → 搬不走
  - 剪断网络里的一条连接 → 搬不走

  这把刀要直接写进任务书。它比任何正面描述都管用,因为它堵死了那条最省事的退路。

  ---
  二、Manim 的丝滑和高级交互是同一个要求

  这一点我一开始没看清,现在看清了:

  Manim 之所以丝滑,是因为画面里没有像素,只有有身份的对象。一个式子里的每一项、曲
  线上的每一个点、网络里的每一条边,都是可指名、可定位、有生命周期的东西。所以它
  能做形变、能做匹配、能让 a=Wx+b 变成 a-b=Wx 时只有那一项飞过去,其余原地不动。

  而一个东西之所以能被抓住,前提也正是它有身份和几何。

  所以:

  一切皆语义对象
      ├── 所以它能被动画变形       → Manim 的丝滑
      └── 所以它能被学习者抓住     → 高级交互

  对象即控件  ⟹  画面上不需要任何控件  ⟹  画面保持 Manim 的干净

  这三件事是一件事。
  你想要的丝滑和你想要的高级交互不是两个需求,是同一个架构的两个侧面。一旦画面里
  出现一根滑块条,说明那个东西没有被建模成对象——丝滑和交互会同时垮掉。

  这条推理链本身,就是我最想看 Opus 5 能不能自己走通的地方。

  三、交互形态谱系

  按「学习者的手落在哪」分,不按控件类型分。

  1. 抓住对象本体

  拖切点沿曲线滑;捏住向量的箭头改方向和长度;抓住 3D
  曲面翻过来看背面;拽住一个粒子把它扔出去看轨迹;拉住弹簧的一端。

  对象在等你抓的时候,它自己会告诉你——不是加个圆圈标注,而是它开始极轻微地呼吸/发
  光。这是画面语言,不是 UI。

  2. 在画面上作图

  学习者自己画:一条他以为的切线、一条辅助线、一个圈出的区域、一条分类边界、一个
  自由手绘的函数图像。

  因为画面是矢量语义空间,他画的东西会被吸附成语义对象——手抖的线自动理直,端点自动
  吸到该吸的点上。吸附的那一下动画本身就很爽,而且它在说:「我听懂你要画什么了。」

  3. 操作公式本身

  这是我认为最惊艳、也最只有这个形态能做的一类,而且 Manim 的
  TransformMatchingTex 生来就是干这个的:

  - 移项 —— 把 +3 拖过等号,它在飞越的过程中翻成 -3
  - 约分 —— 把分子分母上两个相同的因子对着一拖,它们相互湮灭、消失
  - 代入 —— 把整个式子 B 拖到式子 A 里的变量 x 上,x 原地膨胀展开成 B
  - 展开/合并 —— 双击一个括号,它自己乘开;把同类项拖到一起,它们合并

  学习者在用手做代数。每一步都是一次形变动画,所以「做题」和「看讲解」在视觉上是
  同一种东西。

  4. 剪、连、放置

  改变结构而不是数值:剪断神经网络的一条连接看它怎么退化;在电路里插入一个元件;在
  地图上放一个障碍再看路径重算;在网络图里加一条边。

  5. 预测标记

  时间轴还没播到的地方,先让学习者在画面上放一个记号:「我猜曲线从这里穿过」「我猜
  它会收敛到这」。

  然后视频往下播。他的标记留在画面上不动,真实的曲线一路长过来,从他的标记旁边擦过
  去,或者正好穿过。

  不需要任何对错提示。差距是被看见的,不是被告知的。这比任何弹窗都狠。

  6. 接管镜头和时间

  时间本身也是可抓的对象:把某个瞬间捏住慢放;倒着拖看逆过程;推近镜头看一个细节;把
  两个时刻并排锁在一起对比。

  学习者不只是改变世界的参数,他还能改变观看这个世界的方式——而观看方式恰恰是理解
  的一部分。

  7. 鼠标即连续参数

  不需要点击。指针在画面上的位置本身就是一个活的量:横坐标决定采样点、决定光源位
  置、决定切面在哪里。移动即探索,零操作成本。

  ---
  四、反馈的形态:让你的答案变形成正确答案

  这是整套设计里我认为最重要的一条,单独拿出来说。

  学习者画了一条他以为的切线,画歪了。

  不要打红叉。不要弹「不对,再试一次」。

  让他画的那条线,用一个 Manim 式的形变动画,一点点被掰正到正确的切线上去。他亲眼
  看着自己的线怎么转、转多少、绕着哪个点转。

  ▎ 反馈 = Transform(你的答案 → 正确答案)

  这个动画本身就是完整的讲解——它同时告诉了你「错了」「错在哪个方向」「差多少」「
  怎么改」。四件事,一次动画,零句解释。

  而这件事只有在一切都是语义对象时才可能:因为要做形变,系统必须同时持有「你的那条
  线」和「对的那条线」两个对象,并且知道怎么把前者匹配到后者。

  同一个模式可以套在所有地方:
  - 你写错的式子 → 形变成对的式子(只有错的那一项在动)
  - 你放错的预测点 → 沿一条路径滑到真实位置
  - 你连错的边 → 松脱、飘走、重新连到该连的地方

  这一条应该是硬要求:整个视频里不允许出现任何「打叉/打勾」式的判分反馈。所有反馈
  必须是形变。

  五、minigame 怎么嵌进视频里

  你提到的 minigame 形式我认为完全成立,但嵌入方式必须钉死一条:

  ▎ 游戏不切换到另一个世界。

  它用的是这一帧已经在屏幕上的那些对象,目标由这一帧正在讲的模型定义。播放器不进
  入「游戏模式」、不弹全屏、不换 UI。

  发生的只是:时间轴走到这里 → 镜头推近 → 规则用一句字幕说出来 → 该动的对象亮起来
  → 你开始玩 → 达成条件 → 镜头拉回 → 视频继续播。

  一关就是时间轴上的一拍。

  游戏的目标必须是模型本身定义的,不能是外加的分数:
  - 「把这三个权重调到让这批点被分对」——判定条件是真的在跑分类
