# Playable Visual Essay

Turn the subject into a visual world whose objects, geometry, and changes carry the argument. Do not
imitate The Pudding branding, proprietary fonts, exact artwork, project assets, or distinctive
compositions. Apply only the assigned profile and invent an original subject-specific expression.

## Make the model the composition

Choose one dominant world, object, field, path, or mechanism. Let labels, evidence, and controls attach
directly to it instead of surrounding it with dashboard chrome. Keep object identities and spatial logic
stable when the page changes state.

- Prefer direct annotation, meaningful crop, scale changes, and persistent geometry.
- Use HTML for copy and controls, SVG for exact semantic geometry, and Canvas only for dense or
  performance-sensitive fields.
- Use one decisive composition grammar. Read `references/composition-grammars.md` when choosing among
  a visual world, hero model, state sequence, data field, annotated model, or statement with evidence.
- Treat the assigned profile as the page's material and motion vocabulary, not as a template to copy.

## Invite meaningful action

Add interaction only when the reader's action can become evidence, understanding, or narrative state.
Read `references/interaction-grammars.md` when the page supports prediction, tuning, ranking,
classification, allocation, construction, navigation, path choice, optimization, or trace drawing.

When useful, keep a page-local in-memory reader trace and reflect an observed action or derived result
back into a later state on the same page. Ground every personalized statement in captured events; never
infer personality, emotion, diagnosis, identity, or another sensitive trait. Do not require localStorage,
server persistence, or another page to complete the experience.

## Compose motion and copy

Use semantic motion such as trace, isolate, stack, scatter, flood, replay, zoom, crop, or return. Motion
must reveal an information change, not decorate the page. Keep controls visually subordinate to the
world and label them with short domain actions. Prefer one headline, direct labels, and compact evidence
over explanatory prose.

Reject generic card grids, detached KPI panels, decorative icons, fake game controls, sliders that do
not affect the model, and animation without information change.
