# theme.css 生成契约

`base.css` / `base.js` 是冻结层,里面只有「换任何主题都不会想改」的机制:
固定画布缩放、canvas 与替换元素的既有坑、grid 收缩、可访问性地板、指针坐标
换算、token 读取、动画循环。**没有任何颜色、字体、字号、间距、组件外观。**

所以每次跑一个新 topic,视觉部分是完整地重新设计的 —— 这份文档就是喂给
「设计并生成 theme.css + 组件层」那一步的规格。

```html
<link rel="stylesheet" href="assets/base.css">
<link rel="stylesheet" href="assets/theme.css">   <!-- 这次生成的全部视觉 -->
<script src="assets/base.js"></script>
```

底盘提供哪些类和哪些 `Deck.*`,看这两个文件自己的顶部注释,那里是唯一出处,
这份文档不再抄一遍。只说一句这两个文件里没写的:底盘**不提供**顶栏、页码、
导航、进度指示、按钮、滑块、面板、卡片、标签、图例、版式模板 —— 这些全是
这次设计的一部分,要自己造。

## 1. 必须定义的 token

`base.css` 只硬依赖三个:`--bg`、`--text`、`--font-sans`(缺了页面会明显裂开,
这是有意的)。但下面这张完整的表仍然是**硬要求**,原因不是底盘要用,而是:
这批页面由多个并行的 subagent 分头写,**没有一套共同词汇,它们会各调各的色**,
拼起来就是十四种审美。这张表就是那套共同词汇。

```css
:root{
  /* 颜色 */
  --bg:            ...;   --bg-hi:         ...;   /* 主背景 / 背景高光 */
  --surface:       ...;   --surface-hi:    ...;   /* 卡片/面板背景 / 高光态 */
  --border:        ...;   --border-soft:   ...;   /* 边框 / 更弱的边框 */
  --text:          ...;   --text-dim:      ...;   --text-faint: ...;  /* 三级文字灰阶 */
  --pos: ...;  --neg: ...;  --neutral: ...;        /* 语义色:正/负/中性 */
  --accent:        ...;   --accent-dim:    ...;   /* 强调色 / 弱化版(透明底用) */
  --focus:         ...;   /* 可选。不给就用当前文字色,任何配色下都可见 */

  /* 字体 */
  --font-ui:   ...;   /* 标签/编号/按钮 */
  --font-sans: ...;   /* 正文 */
  --font-mono: ...;   /* 数值/代码 */
}
```

`--pos`/`--neg`/`--neutral` 即使这次内容用不上正负对比也要给出合理值,
下次要用时不必回头补契约。

## 2. 生成前必须先做的两件事(不是可选项)

这两条来自 `frontend-design` skill 原文,是它明确要求的:

> Work in two passes. First, brainstorm a short design plan... Then review that
> plan against the brief before building... **Only after** you've confirmed the
> relative uniqueness of your design plan should you start to write the code.

**第一步:出方案,不写代码。** 方案必须包含四样,而且要以**看得见的文字**产出
(不要让这一步只发生在模型的 thinking 里 —— 那样方案好不好、有没有真的自我
批评过,事后完全审计不了):

- **配色**:4–6 个具名 hex,按语义命名(填进上面的 token 表)
- **字体**:2 个以上角色(展示体 + 正文体,可选一个数据/代码等宽体)
- **版式概念**:一句话描述 + 可选 ASCII 线框图
- **签名元素**:这次主题独有、别的主题不会重复出现的一个视觉细节
  (nn-01 那次是「工程纸底纹 + 面板四角机加工刻线」,服务于「电路板/工程图」
  这个具体主题 —— 见 `examples/nn-01-components.css` 末尾。换主题要重新设计
  一个完全不同的,不要复用)

**第二步:自我审查,对照下面这张清单,不合格就打回重做。**

## 3. 打回重做清单

### 3.1 三种「AI 通用脸」——命中任意一种都要重新设计

同样来自 `frontend-design` 原文,是它明确点名的默认脸:

1. 暖米色背景(接近 `#F4F1EA`)+ 高对比衬线体 + 赤陶色强调色
2. 近黑背景 + 单一亮酸绿或朱红强调色
3. 报纸式版式:细线分隔、零圆角、密集分栏

如果方案落进以上任意一种、而 brief 本身并没有要求这个方向 —— 退回第一步
重做,并说明「改了什么、为什么」。

### 3.2 互动形态覆盖检查

nn-01 实测:组件库在造底盘那一步就定死了,后面 100 多次页面构建全在同一套
按钮/滑块/canvas 里循环,互动形态从未超出四种。这不是模型能力问题,是这一步
没被要求覆盖更多形态。

设计组件层时至少覆盖以下 6 类,每类给出一套可复用的类或组件外壳(不要求每页
用满,但这一步必须把「能用」的选项造出来):

- [ ] 拖动/滑动类(滑块、可拖拽元素)
- [ ] 画布/矢量可视化容器(canvas 或 svg 承载区,配 `.cv-fill` + `.no-pan`)
- [ ] 输入/判断类(文本输入、单选多选、猜测-反馈)
- [ ] 悬停/展开类(tooltip、详情展开、hover 态)
- [ ] 切换/对比类(tab、多态按钮组、前后对照 —— 需要一套表达「选中」的离散状态类)
- [ ] 步进/播放类(页内逐步展开、播放-暂停、拖动定位到某一步;区别于跨页翻页)

某个主题确实用不上某一类,在方案里写明原因,而不是默认略过。

### 3.3 字号下限与内容密度

`frontend-design` 对字体只有一句定性要求,**没有任何数字下限,也没有任何
「每页别塞太多字」的要求**,所以这块必须单独规定。

这套架构是固定 1600×900 逻辑画布整体缩放,真实窗口下 `--s` 几乎总是小于 1
(1600 宽已经大过大多数笔记本视口),CSS 里写的字号还会被**再缩一轮**:

| 常见窗口 | `--s` | 逻辑 14px 实际渲染 | 逻辑 11px 实际渲染 |
|---|---|---|---|
| 1920×1080 全屏 | 1.20 | 16.8px | 13.2px |
| 1440×900(13 寸全屏) | 0.90 | 12.6px | 9.9px |
| 1366×768 | 0.85 | 11.9px | 9.4px |
| 1280×800(分屏) | 0.80 | 11.2px | 8.8px |

**要求(按最坏情况 `--s≈0.85` 倒推,代码里写逻辑 px)**:

- 正文类:逻辑 px ≥ **17px**(缩小后 ≈14.5px)
- 标签/编号类:逻辑 px ≥ **13px**(缩小后 ≈11px)
- 任何承载实际信息的文字:不得低于 **12px**(缩小后 ≈10px,可读下限)

nn-01 那次的标签/脚注低到 9.5–11px,就是没有这条约束的结果。

**内容密度**——按栏宽给硬上限,超了就拆页,不要继续往同一个容器里塞:

| 容器宽度 | 上限 |
|---|---|
| ≤ 400px 的窄栏 | 正文 ≤ 70 字,或要点 ≤ 4 条 |
| 400–480px 的窄栏 | 正文 ≤ 90 字,或要点 ≤ 5 条 |
| 图表/面板内的说明文字 | ≤ 40 字。更长的内容应该改成图来承载 |

这两条不是审美要求,是可程序化检查的硬约束:一页生成完,量一下实际 computed
font-size 和 innerText 长度,超限就打回要求精简或拆页,不要留给「看着办」。

### 3.4 机制不许退化(这条是从第二轮的真实退步里来的)

nn-03 那轮把可访问性丢了:`prefers-reduced-motion` 没写、canvas 拉伸修复没写,
而这两条 nn-01 都有。退步是**无声的** —— 没有报错,只有前庭敏感的读者在 14 页
满是动画的内容前难受。

CSS 那两条底盘已经冻住了。剩下的风险全在 **JS 那一侧 —— CSS 的 media query
管不到自己写的动画**,而这类退化不会报错,只能靠检查发现。

所以这不是一份"记得做"的清单,是**生成完一页之后在文件上跑的正则**。命中
即打回,不是提醒:

| 命中即打回 | 为什么 |
|---|---|
| `requestAnimationFrame` 出现,但全文没有 `Deck.loop` 也没有 `Deck.reduced` | 动画不理会 reduced-motion |
| `\.client[XY]` 出现,但同一处附近没有 `Deck.pt` | 缩放下点击判定整体偏移 |
| `\.width\s*=` 出现在 canvas 变量上,而没走 `Deck.fit`/`Deck.autofit` | 高分屏/大屏发虚 |
| `#[0-9a-f]{3,8}` 出现在 `<script>` 段里 | 画布颜色写死,不跟主题走 |
| 有 `pointerdown`/`mousedown` 的元素,class 里没有 `no-pan` | 触屏拖拽被当成滚动手势 |
| `display:\s*(grid\|flex)` 的容器,子项没有 `min0` 且内含 canvas 或长文本 | 子项不肯收缩,顶开整列被裁掉 |

前四条是纯文本正则,直接对 HTML 跑;后两条要读 DOM,放在截图自检那一步
(反正那时已经开了浏览器)顺手查。

判据的价值在于它**便宜且无声**:六条全查一遍不到一秒,而漏掉任何一条,
你要等到有人在 2560 宽的屏幕上、或者用触屏、或者开着"减少动态"打开这一页,
才会发现。

## 4. 页面之间的叙事

`Deck.init()` **不再生成任何外观** —— 顶栏、导航轨道、进度、跨页视觉线索,
现在全部属于这次设计,要自己造。它只剩键盘翻页:

```js
Deck.init({ index: 3, total: 14 });     // 通常只需要这一行
```

如果这批页面之间有内在顺序(时间线、流程步骤、难度递进……),把这条叙事母题
**设计成一个具体的视觉机制**,并在所有页面上一致地实现。做法参考
`examples/nn-01-deck.js`(那次是:底部时间轴 + 跨页贝塞尔接线 + 强调色按年代
由冷转暖)—— 参考的是**手法**,不是那几个数值,更不是照搬那套时间轴。
换一个主题,这条线索该长什么样是要重新回答的问题。
