OVERVIEW

端到端总览：单向主流程，异常规则独立表达

L0 把材料变成只描述语义、不描述像素的内容包；设计基调是三件人工策划的静态资产（不是阶段，没有生成步骤）； L2 三步——装配输入 → 文生图产出构图草案 → 参考构图写 reveal <section> 内的完整 HTML/CSS/SVG； L3 在真浏览器里量测截图；L4 装订交付。 主图只保留从上到下的正常路径，层间使用短下箭头交付；失败处理移到右侧异常策略面板，通过步骤编号指向 HTML 重写，不再用跨层回边缠绕主流程。参考图只启发生成，不定义验收目标。

L0 内容底座 设计基调（配置） 文生图 · 构图草案 L2 AI 撰写 硬闸 / 红线 软闸（虚框 = 能力未就位） 层间短交付 异常规则见右侧
SEAM · 最关键的一处接缝迁移 V1 的 schema 同时描述内容与呈现——所以它既要有 items[] 也要有 layout.kind， 既管"讲什么"也管"长什么样"，结果两边都不称职：内容侧表达不了一棵带边的树，呈现侧又锁死了 22 种块型。 V2 把这条缝重切：content-pack.json 只描述语义（含真实 graph 邻接），HTML 只描述呈现，两者由 L2 的一次聚焦生成连接。

语义侧只做轻校验（能 parse + 边指向存在的节点），不再宣称"强校验"——真正的风险是 一棵结构自洽但语义错误的树，而那恰恰是 schema 抓不到的。呈现侧的强校验交给真机探针：那一侧的失败模式（溢出、裁切、对比度）本来就是可测量的。 把校验强度放在各自真能测的那一半上，是这次精简的原则。
