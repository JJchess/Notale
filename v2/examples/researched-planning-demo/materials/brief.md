# 任务背景

我们要向产品负责人、内容设计师和工程负责人解释：一套可信的 AI 讲义生成流水线，为什么不能从一句主题直接跳到文生图。

# 我们自己的工作语言

- 研究任务单：明确受众真正需要回答的问题，并把问题拆成互补查询。
- 来源账本：保存本地材料、搜索查询、网页来源、抓取时间和内容指纹。
- 叙事地图：决定整套讲义如何从问题推进到判断，而不是罗列主题。
- 页面合同：每页只承担一个沟通任务，所有事实、数字和关系都能回到来源。
- 设计桥：把页面的语义结构、视觉机会和真值风险交给图像模型，但不提前指定模板。

# 必须证明的观点

1. 联网搜索必须产生可检查的查询和来源，不能只在提示词里声称“已研究”。
2. 内容规划必须先于视觉设计，否则图片模型只能放大上游内容的空洞和错误。
3. 设计自由来自开放的沟通任务，而稳定性来自证据、技术探针和最小范围修订。
4. 图片模型负责视觉完成度；精确文字、数字和图结构仍需要验证。

# 演示要求

- 生成 8 页中文宽屏讲义。
- 面向非算法专家，但允许出现必要的工程合同和流程概念。
- 页面文字简短，标题要表达判断，不使用“背景介绍”“关键能力”这类空标题。
- 视觉风格应像高水平知识杂志和系统设计展览的结合，清楚、成熟、有明显的视觉命题。
- 不出现任何被参考系统的产品名称、界面或专有术语；所有机制统一转换成上述工作语言。
